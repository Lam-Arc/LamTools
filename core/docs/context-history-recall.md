# 原始上下文搜索与召回

<!-- user:“ok，那就这么做”+(保留现有压缩路线，补齐通用原始历史搜索和精确召回)。 -->

`search_context` 与 `recall_context` 读取当前运行所属会话的原始历史，
包括被压缩视图隐藏的内容，无需先创建记忆。宿主在执行边界绑定会话，
工具参数和模型提供的元数据不能将读取范围改为其他会话。

```json
{"query":"UTF-8","limit":10}
```

上述参数传给 `search_context`。检索按原始消息序号从前向后进行，
使用忽略大小写的字面匹配；返回小段预览、`history_seq`、`message_hash`
与来源地址。每次至多扫描 2,000 条消息、返回 20 条命中。
若 `next_after_seq` 非空，下一次将其作为 `after_seq`，即可继续检索。
原文索引包含用户文字、助手文字、工具结果及工具调用参数；
系统提示和之前的搜索／召回工具结果不参与搜索。

```json
{"start_seq":12,"end_seq":14,"expected_hash":"搜索返回的 message_hash","max_chars":12000}
```

上述参数传给 `recall_context`；实际 `expected_hash` 使用返回的 64 位哈希，
作用于 `start_seq`。一次可读取最多 100 个消息位置。
回退可能重用消息序号，因此来源哈希同时校验原始内容与消息身份，
拒绝将该位置的新消息当成旧来源。缺失位置列在 `missing_seqs` 中。
`lamtools-context://sessions/.../messages/...?sha256=...` 是来源定位符，
不提供桌面页面跳转。

召回返回原文文字，工具调用的参数以 JSON 表示，媒体内容标记为省略；
提供方内部状态、签名和宿主私有元数据不返回。`offset` 是投影文字的字符位置。
默认序列化结果上限为 12,000 字符，允许范围为 1,024–32,000 字符。
长消息按预算分段，使用返回的完整 `next` 参数继续读取，
以免遗漏或重复文字。分页结果直接作为模型工具结果返回，
避免通用输出截断再次破坏 JSON 和续读位置。

数据库按会话与序号索引分批读取，每页至多 200 条；旧的单体历史记录
通过 SQLite 的 JSON 投影分页，不将整个记录加载到 Python。
检索与读取均为本地操作，不调用模型，不改写历史或压缩状态。
模型读取工具结果后的继续回答属于正常模型调用。
所有工具结果标记为历史证据，当前用户要求具有优先权。

<!-- user:“用户消息那个也许可以取消？”+(取消近期用户原话常驻附录，保留当前请求与历史可追溯性)。 -->

新一次成功压缩不再附加最多 50 条近期用户原话。最后一条真实用户请求
保留为原始 `user` 消息，旧约束和决策进入结构化摘要，详细原话可按需召回。
当前请求本身超过目标预算时，在请求摘要模型前失败，避免静默丢失它。
旧摘要仍可加载；只有下一次成功压缩才移除旧附录，避免在既有压缩周期内
直接改写已冻结的上下文。原始档案始终保留。

工具定义遵循既有权限、模式白名单和工具组冻结规则。既有会话需要在
下一次工具组刷新（例如成功压缩或新会话）后，模型才能看到新工具。

代码验收覆盖搜索与召回闭环、真实数据库分页、旧记录兼容、长文字续读、
跨会话隔离、回退来源校验、权限拒绝、模型结果完整性、提示与工具定义稳定性，
以及取消附录后当前请求的保留。仅使用本地测试和模拟模型。
