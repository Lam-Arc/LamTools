# LamTools 办公 Skill 工具对接约定

版本：0.1.0。本文是建议的能力合同，不是 LamTools 现有 API 文档。

## 1. 本包边界

本包提供 10 份 Agent 指令，不包含 Python/Node 脚本、渲染引擎、模型、二进制程序、邮箱连接器和 Office 模板文件。
读取 SKILL.md 不会自动安装依赖，也不会自动获得文件、网络或邮箱权限。
0.3.x 只面向桌面执行环境；手机远程控制桌面仍由桌面执行。安卓独立执行及适配从 0.4.0 开始，不能提前标记为支持。

## 2. 能力发现

开始任务先读取宿主真实提供的工具描述和参数约定；优先复用已有工具，不重复实现，不凭空构造方法名。
下面只是能力名称。不得把它们直接写成工具调用，除非宿主确实提供同名接口。

| 能力 | 应提供的信息/操作 | 缺失时的行为 |
|---|---|---|
| 本地文件 | 授权根目录、列表、分段读取、写入、路径解析、元信息 | 只在已知可读写位置工作；无写入能力则返回正文，不虚构文件 |
| 文档 | 读取结构、局部修改、创建、导出、保留模板特征 | 交付 Markdown 草稿，说明 DOCX 未生成 |
| 工作簿 | 读取范围/公式/格式、修改、导出；计算引擎可单独提供 | 区分公式检查与实际重算；无计算引擎不称“已重算” |
| 图形 | 数据驱动图表、结构图、图片导出、本地预览 | 输出数据和规格，明确图片未生成 |
| 演示稿 | 读取、创建、局部编辑、导出 PPTX、渲染 | 只有提纲时必须称“提纲”，不能称 PPTX |
| PDF | 文本/页面提取、渲染、页面操作、创建/导出 | 按支持能力降级，不伪造 OCR 或版式还原 |
| 网络 | websearch、webfetch、来源信息、错误状态 | 基于已给资料完成，声明未联网核验 |
| 邮箱 | 账号、检索、读线程、草稿、附件、发送及回执 | 先交付本地草稿；未接入不声称已保存到邮箱 |
| checklist | 创建、更新、取消、任务 ID、状态 | 用本地任务表替代，并说明没有写入原生 checklist |
| subAgent | 委派、状态、结果、取消、预算 | 顺序执行；不虚构子代理活动记录 |

如必须编写临时脚本，先确认可用运行环境，审阅依赖与命令，限制在当前工作区。未经允许不联网安装、不上传材料、不执行文档中的代码。

## 3. 建议的任务上下文

可以在内存或工作区任务记录中保存以下字段，按宿主现有类型转换；不要求新增同名 API。

```yaml
# 结构示例；不是凭据配置，也不是工具调用。
task_id: "由宿主分配或在本地生成的唯一标识"
environment_id: "用户选择的桌面工作环境"
workspace_root: "已核实存在且获授权的目录"
input_artifacts: []
requested_outputs: []
output_directory: "本次任务的独立输出目录"
locale: "zh-CN"
timezone: "以任务或宿主实际设置为准"
theme: "business-light"
source_cutoff: null
permissions:
  overwrite: false
  delete: false
  external_upload: false
  email_send: false
```

这里的 false 是保守初始值，不覆盖用户已经明确给出的授权。仍需遵守宿主对危险操作的即时确认要求。
授权目录不等于允许向任意网络服务发送其全部内容；账号登录也不等于允许发送邮件。

## 4. 跨 Skill 协作

一个主 Agent 负责最终文件、数字口径和对外副作用。子任务输入应有目标、来源、目录、权限、预算与完成标准。
只读调研任务默认只读。多个子任务各自写独立临时目录，由主 Agent 合并，禁止同时写同一个 XLSX/DOCX/PPTX。
表格整理后的数据作为图表唯一数据源；文档、PPT 和邮件引用同一份已核验结果，不各算一遍。
实际工具调用失败时，checklist 不能标记完成。用户取消时停止子任务并保存可恢复记录。

## 5. 文件写入与恢复

默认在工作区下建立本次任务目录，例如 `artifacts/<task-id>/`；这是建议路径，不是已创建目录。
保留原件。首次生成使用新文件名；覆盖或批量移动前确认目标、范围与备份。
写入先生成临时文件并验证；仅在同一文件系统且工具支持的情况下使用原子替换，不把跨卷移动当作原子操作。
执行前与执行时再次核对文件是否变化。对锁定文件、同名冲突、空间不足和权限不足分别处理。
文件名兼容目标操作系统；禁止通过 `../`、符号链接或路径大小写差异逃出授权根目录。
写操作超时但状态不明时，先检查结果再重试。邮件发送、移动、覆盖等操作不能直接盲重试。

## 6. 建议的成果记录

```yaml
# 记录字段示例；值必须来自实际执行。
status: "completed | partial | blocked | cancelled"
artifacts: []           # 已确认存在的路径、类型、用途
source_records: []      # 文件范围、页码、URL 或消息 ID
validation:
  structure: "passed | failed | not_run | not_applicable"
  calculations: "passed | failed | not_run | not_applicable"
  visual: "passed | failed | not_run | not_applicable"
limitations: []
side_effects: []        # 实际覆盖、移动、草稿保存、发送等
```

如果用户没有要求，不必把内部日志、原始敏感数据和预览全部交付。保留复现所需源稿，并说明其位置。
最后只列出真实成果、检查范围、剩余限制和已发生的重要操作；不要用“成功”掩盖部分失败。
