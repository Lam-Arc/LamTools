# LamTools 办公视觉规范

版本：0.1.0。用途：为本包桌面办公 Skill 提供统一的设计默认值；不是已实现的主题引擎。

## 1. 使用优先级

用户明确要求 > 用户提供的品牌或原文件样式 > 项目已选主题 > 本规范默认值。
修改现有文件时先保留其视觉语言；用户只要求修改数字，不应顺带改字体、母版和配色。
颜色、尺寸、页数均为默认建议，不是压倒用户要求的硬限制。
每个 SKILL.md 已包含独立运行所需的基础规则；本参考用于需要精细排版时补充，不是必装依赖。

默认使用简洁商务。数据分析可以使用数据汇报。深色演示默认用于屏幕展示，不用于需要大量打印的正文和明细表。
不要机械地把主题表中任意两种颜色组合成文字与背景；在实际背景、字号和导出结果上检查可读性。
状态不只用颜色表达，还应提供文本、形状、线型或符号。

## 3. 字体与间距

优先使用项目品牌字体；其次检查机器已安装且具备中文字形的字体。可按实际可用性选择微软雅黑、思源黑体或 Noto Sans CJK 等候选，不能假设一定存在。
全套成果尽量保持一个中文正文字体、一个兼容的西文字体。不得将未获分发授权的字体文件打包交付。

| 产物 | 推荐默认值 |
|---|---|
| Word / 文字型 PDF | A4；页边距约 20–24 mm；正文 10.5–12 pt；一级标题 18–22 pt；行距约 1.25–1.5 |
| PPT | 16:9；四周安全区约 5%；标题 28–36 pt；正文 18–24 pt；来源通常不低于 11–12 pt |
| 表格 | 正文 10–11 pt；表头略加粗；输入/计算/汇总区通过位置与标签区分 |
| 单张图表 | 根据最终展示尺寸设字号；至少分别检查标题、坐标轴、标签与来源，不以高分辨率代替足够字号 |
| 信息图 | 节点标题层级统一；每节点尽量只放一条短解释；长说明移入配套文本 |

建议用 4、8、12、16、24、32 的间距节奏，但按实际输出单位换算，不把像素数直接当成 Word 磅值。
空间不足的处理顺序：删冗余 → 改为合适版式 → 拆页/拆图 → 最后才小幅调整字号。

## 4. 数据图表设计

先写一句图表要回答的问题，再选择图型。结论必须来自已核验数据，不先定结论再挑数据。
同一指标、部门或系列在一份交付中保持同色；强调色集中用于主角，其他系列适度弱化。
类别多时优先横向条形图、小多图、分页或合并为“其他”；任何聚合和筛选都在注释中说明。
同一可比较组保持坐标口径一致。主刻度线清晰，非必要边框和网格线弱化；不用 3D 效果制造体积错觉。
金额、比例、数量都标单位。增长率与百分点分开表述。缺失不自动补零，预测使用不同线型并标出起点。
来源、时间范围、样本量或筛选口径放在可读位置，不堆入标题。
正式数值图表使用数据驱动渲染；生成式配图只能作为装饰，不能承担精确数值、坐标或业务标签。

## 5. PPT 版式配方

| 页面目的 | 版式 | 约束 |
|---|---|---|
| 定义议题 | 封面 + 一句副标题 | 不使用无关装饰占满页面 |
| 给出结论 | 结论标题 + 2–3 条证据 | 结论不能超过证据支持范围 |
| 展示变化 | 大图表 + 一条关键标注 | 保留单位和时间范围 |
| 比较方案 | 相同维度的双栏/三栏 | 不故意用布局偏袒某一方案 |
| 展示进度 | 时间线/里程碑 | 区分计划、实际、未定日期 |
| 解释过程 | 流程图/泳道图 | 箭头方向与业务关系一致 |
| 提出行动 | 行动、负责人、期限、依赖 | 未确定内容标记待确认 |
| 放置细节 | 附录/明细页 | 不把细节强塞到主讲页 |

同套 PPT 共享边距、标题位置、配色和页码，但不要求每页同一布局。
文字、标题、表格优先保留原生可编辑对象；只在照片、复杂插画等适当位置使用图片。
将 SVG 放入 PPT 不等于各元素都能在 PowerPoint 内编辑，交付时准确说明编辑粒度。

## 6. 视觉验收

检查最终导出文件的真实页面，而不是只看生成脚本或结构文本。
所有新建或修改页面都要检查：缺字、裁切、重叠、溢出、模糊、边距漂移、对齐和颜色可读性。
长文档允许先用缩略图发现异常，再逐页检查；不能把抽样检查写成“全页通过”。
文件正确性与视觉检查分别记录。无法预览时标记“视觉未验证”，交付可检查的草稿，不宣称已完成排版验收。
