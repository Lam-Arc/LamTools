# 数据图表

## 目标与边界

把已核实数据转成清晰、准确、适合实际展示尺寸的图表，保留数据和可再生成的源配置。
默认桌面本地执行。Office Skills bundle 内置确定性校验/渲染程序，但不内置图表创作引擎，也不默认调用任何第三方图表 API。
正式数值图表应由数据驱动渲染，不用生成式图片替代真实坐标、数值或标签。

## 输入与默认值

需要数据来源、字段、单位、时间范围、用户想回答的问题、目标载体与尺寸。
来源可以是文件、表格范围或用户明确给出的数字；只给结论没有数字时先找实际来源，不编样本补齐。
默认中文、白底、深色文字、蓝色强调、克制网格；优先继承文档/PPT 的主题。
只有“做得好看”但没有更细约束时，直接采用清晰的商务设计，不反复追问颜色。

## 工具与安全

核实文件读取、数据处理、图表渲染和图片预览能力；运行命令时只使用实际已提供的执行工具。
优先本地渲染，数据不外传。外部图表服务、在线字体和远程脚本都应先评估数据及网络权限。
存在可用的专业图表生成工具时优先使用；读取其真实参数定义，不猜接口和图型枚举。
源文件只读；图表、数据副本和配置写入本次任务目录。

## 工作流程

需要精细排版时读取[共享办公视觉规范](../references/office-design-system.md)，先确定最终载体尺寸、绘图区和标签区，再生成图表。复杂或多文件任务同时读取[工具对接约定](../references/tooling-contract.md)的执行收敛规则。任何数据图表生成前读取[Office 数据与渲染合同](../references/office-renderer-contract.md)，先写唯一 `office-data.json` 并绑定稳定 dataset ID，在任意项目目录运行 `py -3.14 -m lamtools_core.cli office validate ...`，通过后再运行同入口的 `office render`。

### 1. 检查数据

确认列类型、单位、重复项、缺失、极值、总量和时间顺序；金额单位、币种及统计口径保持一致。
所有清洗、筛选、分组、Top N 和“其他”合并规则都记录下来；不能静默删除不利数据。
缺失不自动填零。只有图像而无底层数字时，标记提取值为近似，不能声称精确还原。
计算派生指标可委派 `office-spreadsheets`，把核验后的汇总表作为唯一绘图数据源。

### 2. 选择图型

先写一句问题，再选最简单且不歪曲数据的图型。

| 要表达的问题 | 优先图型 | 关键限制 |
|---|---|---|
| 随时间如何变化 | 折线图 | 真实时间顺序；缺失处断开或明确插值 |
| 谁更高、差多少 | 横向条形/柱状图 | 条柱原则上从零起；排序有业务逻辑 |
| 各部分占多少 | 100% 堆积条形；少量类别可用环形 | 非负、分母一致；组成应完整 |
| 数值如何分布 | 直方图/箱线图 | 说明样本与分箱/分位规则 |
| 两个指标是否相关 | 散点图 | 相关不写成因果；必要时标样本量 |
| 哪些因素带来增减 | 瀑布图 | 正负贡献与起终值能对账 |
| 类别随时间的差异 | 热力图/小多图 | 色阶或坐标在可比较图间一致 |

默认不使用 3D 图、无意义仪表盘和过多饼图。不同单位优先拆成对齐图，不滥用双轴制造相关性。
雷达图、桑基图等仅在问题与工具支持都适合时使用，不为展示“高级”而强行使用。

### 3. 设计视觉

每图突出一个主问题。结论式标题必须有数据支持，否则用中性问题/描述标题。
同一系列在所有成果中保持同色；建议一个强调色加中性色，多系列使用可区分且适配主题的色板。
优先直接标注关键系列、峰谷或目标差；不对每个点都加标签。单位、图例、来源必须可读。
长类别名优先横向图或合理换行，不靠极小字号塞入。
需要截断数轴、使用对数轴、归一化或变换时明确标注；不借变换夸大趋势。
增长率与百分点、累计与当期、实际与预测必须分清；预测用不同线型和明显分界。

生成柱状图前明确零线与增长方向。纯正值柱状图和条形图默认必须包含零基线，不得用截断轴夸大小幅差异；确需聚焦窄幅变化时改用点图或折线图，并在图内明确标注轴范围。竖向正值必须从底部零线向上增长，横向正值必须从左侧零线向右增长；手工 SVG/Canvas 坐标使用 `y = plot_bottom - scaled_value`。不要直接把正值高度从页面顶部向下绘制。含负值时以零线为界向相反方向延伸。

先按最终嵌入尺寸计算标签空间：长类别名优先横向条形图；类别过多时拆图或小多图。禁止把多个包含完整坐标、图例和标签的图表压成一张图后再缩小到文字不可读。

### 4. 创建并导出

根据真实渲染器构造配置；记录渲染器名称与已确认的版本/依赖，不能声称跨引擎通用。
建议保留 `chart-data.csv`、原生 `chart-spec` 或生成脚本、以及最终 SVG/PNG；是否交付数据副本遵守用户保密要求。
SVG 适合矢量使用，但不承诺所有目标软件都能逐对象编辑；PPT 内可编辑图表需通过对应演示稿工具生成。
输出尺寸按目标载体决定；默认独立图可用约 1600×1000 像素预览，嵌入时检查最终缩放后的字号。
文字和数字不能直接拼接为可执行 HTML/脚本；对外部标签做转义，限制外部资源加载。

### 5. 一次生成与必要验证

数据验证：总量、比例、时间范围、轴范围与原始记录一致；汇总值用独立计算核对。
视觉验证：实际打开图，检查文字、中文字体、颜色、图例、刻度、重叠和裁切。
默认一次生成完整图表后批量预览一次；只有数据或图形发生实质变化才重新导出对应图，不重复读取未变化的预览。
只有配置没有渲染能力时交付“绘图配置/草稿”，明确图片未生成；不可把未打开的 URL 当作已验收成果。

## 输出约定

交付最终图表，配一句基于数据的解释及必要的来源/口径。
保留源数据与源配置以便修改；用户只需图片时，内部保留复现材料并说明位置，不额外泄露原始表。
同一任务多图使用统一编号和主题；图表插入 Word/PPT 后还要检查嵌入后的清晰度。

## 验收清单

- [ ] 图型对应实际问题，数据来源真实可追溯。
- [ ] 单位、分母、范围、缺失和筛选规则明确。
- [ ] 比例、总数和趋势可与数据对账。
- [ ] 主次清楚，不通过轴、面积或配色歪曲结论。
- [ ] 中文、图例、刻度和标注在最终尺寸下可读。
- [ ] 图表真实生成，源配置与数据关联保留。
- [ ] 办公数据未未经授权发送至第三方。

## 示例与自测

**用户：**“把月销售数据做成适合汇报的图，突出变化。”
执行：读数据 → 区分当期/累计 → 按日期排序 → 生成趋势图 → 标注有证据的变化 → 保留来源和配置。
通过条件：缺失月份不自动连成假趋势；标题不把相关事件写成已证实原因。

**异常自测：**占比数据含负数、总和不等于整体。
正确行为：不用饼图强行归一化；解释口径问题并改用能表示正负差异的图型。
