# 工具过程项行式视觉重设计

## 目标

将 Core 与 Writer 聊天过程中除 `run_command` 外的工具项统一为克制、简洁、易扫读的行式界面。彻底移除普通工具的卡片分割和卡片式按钮，同时保留文件差异、测试结果等必要专业内容结构。`run_command` 的现有头部与终端输出完整保留。

## 范围

- 共享聊天组件中的实时工具调用和历史工具记录。
- 普通工具、文件工具、测试、Git、Web、子 Agent 和失败结果。
- 工具展开与收起、运行状态、错误状态、键盘焦点和窄屏布局。
- Core 与 Writer 使用同一套共享实现。

审批项沿用已经确认的简洁审批样式，不重新设计其业务交互。
`run_command` 明确排除在本次视觉修改之外。

## 设计方案

### 默认状态

每个工具使用一条约 32 像素高的无卡片行：

1. 状态标记。
2. 工具名称。
3. 单行核心参数摘要。
4. 结果状态。
5. 可展开提示。

工具行不使用独立背景、圆角外框或阴影。相邻工具通过节奏间距或极淡分隔线区分，不形成卡片堆叠。

### 色彩与状态

- 工具类别统一使用中性色，不再为读、写、Git、测试和 Web 分配不同强调色。
- 颜色只表达运行、成功、失败和待处理状态。
- 状态必须同时由文字、图形或动画表达，不能仅依赖颜色。
- hover 只增加轻微背景反馈；focus-visible 使用清晰焦点环。

### 展开内容

展开区使用统一缩进、间距、标题层级和代码底色，但保留以下专业结构：

- 文件操作：差异行、行号、增删语义和换行切换。
- 测试：通过、失败、跳过、耗时及详细输出。
- 普通工具：输入预览、结构化元数据和结果正文。

展开区是工具行的从属内容，不再嵌套成另一张装饰卡片。

### 响应式与动效

- 窄屏时优先保留工具名和状态，参数摘要允许截断。
- 展开内容可横向滚动或按现有换行开关显示，不撑破聊天区。
- 展开过渡控制在 150 至 200 毫秒，只表达状态变化。
- 减少动态效果设置下取消脉冲和展开动画。

## 实现边界

- 优先复用现有工具数据、展开逻辑和专业结果组件，不新增平行投影或状态。
- 收敛共享组件内重复的实时、时间线和历史工具模板；至少共享相同的结构类和设计令牌。
- 不修改审批协议、工具执行逻辑、消息投影或后端数据结构。
- 不借此重构无关的聊天消息、侧栏或输入区。

## 验收标准

1. 除 `run_command` 外，所有工具默认态看起来属于同一套行式系统，不再呈现彩色卡片集合。
2. `run_command` 的头部、间距、终端结构和视觉表现与改动前一致。
3. 实时、历史、Core 和 Writer 的工具样式一致。
4. 文件差异、终端、测试结果和普通输出仍完整可用。
5. 展开、复制、换行切换和错误查看行为不回退。
6. 键盘操作、焦点、对比度和减少动态效果满足共享 UI 要求。
7. 桌面和窄屏截图中无文字溢出、嵌套卡片或过度分割。

## 验证

- 扩充共享聊天组件测试，覆盖统一结构、状态语义、展开内容和窄屏约束。
- 运行 Core UI 测试和构建。
- 运行 Writer 共享组件相关回归。
- 在真实 Core 工作台中检查实时与历史工具项，并进行截图对比。
