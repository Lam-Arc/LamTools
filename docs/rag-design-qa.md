## 一、十三域 Q&A

### 域一：文档解析与预处理

1. **为什么有解析？直接灌文本不行吗？**
   PDF 是版面格式不是文本格式。三类损失：**版式**（阅读顺序、多栏串行）、**表格**（二维关系拍平）、**扫描件**（无文本层）。解析就是索引前把损失补回来。

2. **解析/清洗/结构化？**
   解析 = 从二进制提文本（pypdf/python-docx）；清洗 = 去噪音（页眉页脚/页码/水印/样板文字）；结构化 = 提取语义单元挂元数据（标题链/表格/页码）。

3. **表格怎么处理？**
   信息在单元格二维对应关系里，纯文本必丢。Markdown/HTML 转写（便宜、保留结构）vs 渲染成图 VLM 描述（贵、复杂版式强）。结构规整走前者。
   【v2 共识】表头 + 摘要 + markdown 化，按文本索引；引用回原表格（citation target）；不做多模态向量。

4. **元数据？**
   标题链、页码、来源、权限。用途：引用（页码校验）、过滤（时间/部门/权限）、父子块关联（parent_id）。

5. **图片图表怎么进 RAG？**
   VLM 文字描述走文本管线（默认）vs 多模态 embedding（索引和模型都要多模态，规模成本高）。语义是检索主需求才选后者。

6. **企业级解析管线？**
   类型识别（magic bytes，非扩展名）、去重（sha256 内容寻址）、增量摄取（mtime+指纹）、失败重试（退避+死信）、状态可观测（indexed/ocr_failed/unindexed）。

7. **代码库？**
   语义单元是函数/类不是句子——AST/函数边界切分，符号级检索（"parseConfig 定义在哪"）。

8. **解析错误如何定位？**
   取"答非所问"样例，查 gold chunk 在不在解析产物文本里：不在=解析层；在但检索不到=检索层；检索到但没用=生成层。

### 域二：分块策略

1. **为什么分块？**
   整篇一个向量 = 100 页平均语义压成一个点，粒度失配。本质权衡：块小 = 语义纯定位准但上下文残；块大 = 完整但向量被稀释。

2. **固定长度的问题？**
   句子腰斩、语义单元破碎、关键词被劈开。适合均匀无结构文本。

3. **size/overlap 怎么定？**
   300-500 tokens 是经验区间，**必须自建评测集定**（面试官问"依据是什么"就是在测拍没拍脑袋）。领域结构优先：合同"第X条"整条一块（宁可 800 tokens 不切半条）。

4. **固定/语义/结构感知？**
   有结构锚点（标题/条款/表格）用结构感知；没有退语义切分（embedding 相似度突变处）；最后才是固定长度。

5. **overlap？**
   10-15%，防句子骑在边界上。副作用：检索冗余（Top-10 被同内容占两条）、存储膨胀。**是补救不是目标**——结构感知切分做好，overlap 需求就小。

6. **small-to-big（父子块）？**
   小块检索（精）、父块返回（全）。解决"检索要精、回答要全"矛盾。代价：映射表 + 注入上下文变大。

7. **换 chunk 策略，1TB 索引怎么灰度？**
   **不能原地改**（新旧表示混用 = 语义空间互剪，召回被污染）。双索引影子切换：新策略并行建 → 影子查询对比 → 原子切流 → 旧索引可回滚。索引策略变更一律"影子→切流→可回滚"。

8. **Contextual Retrieval？**
   LLM 给每块生成文档级上下文再嵌入。"all amounts in thousands" 这种文档级信息在别的块里，**纯切块永远解决不了**。成本：每块一次 LLM 调用，可选增强。

### 域三：Embedding 与向量

1. **什么是 embedding？与 one-hot 区别？**
   稠密向量，语义相近向量相近；one-hot 稀疏、无相似度、"猫"与"狗"正交。相似性变成距离是检索成立的前提。

2. **模型怎么选？中文注意什么？**
   中文 bge-zh 系列/m3e。**MTEB 榜单是起点不是终点**——在自己的语料上测 recall@k。体积/维度也是选型参数（打包约束）。

3. **余弦/内积/欧氏？**
   归一化后：**余弦排序 == 内积排序**，且 cos = 1 - d²/2（欧氏单调函数）。没归一化时内积被长文本带偏——新人最常见的坑。

4. **embedding 短板？**
   否定语义、时序推理、精确符号（E1042 与 E1043 在向量空间几乎一样近——token 身份被平均掉了）。**精确符号是词面问题，归 BM25。**

5. **换模型依据？**
   recall@k 对比，不是直觉。代价 = 全量重建索引，先算清收益。

6. **模型升级旧向量怎么办？**
   必须全量重建（不同模型不同语义空间，混用等于硬拼坐标系）。影子切换 + 原子切流 + 回滚保留。

7. **稀疏 vs 稠密？SPLADE？**
   稠密 = 语义；BM25 = 经典稀疏词面。SPLADE = 学习型稀疏（模型预测词项权重 + 扩展同义词），兼得精确与语义。定位：比 BM25 更聪明的词法腿。

8. **MRL vs 量化？**
   MRL 截维（结构性的省，模型天生支持）；PQ 码本压缩（最省但损失最大）；int8 标量（4 倍省、损失小）；二值（32 倍省、损失大）。**量化掉的召回统一用 rerank 补**——检索腿省内存，rerank 腿保精度。

### 域四：向量数据库与检索

1. **为什么需要向量库？几千条也要吗？**
   几千条不需要（暴力扫描毫秒级）。价值：规模、元数据过滤、持久化工程化。**选型先问规模。**

2. **与传统库核心区别？**
   数据模型：精确匹配 vs 相似度排序（距离度量 + ANN 索引）。

3. **ANN？为什么接受近似？**
   精确 kNN = O(N) 扫描；ANN 用图/倒排/量化结构换次线性，接受"偶尔漏真近邻"。损失用 recall@k 量化。

4. **HNSW/IVF/PQ？调参？**
   HNSW：分层小世界图，M（连接数，↑召回↑内存）、ef_search（查询光束，↑召回↑延迟）、ef_construction（建图）。IVF：聚类+倒排，nprobe。PQ：向量压缩。**recall@20=0.86 先动 ef_search**（便宜、无损、只加延迟），不够再动 M（加内存）。**调参从便宜的先动。**

5. **Milvus/Qdrant/pgvector/FAISS 选型？**
   FAISS = 库非服务（自建持久化/元数据）；pgvector = SQL 扩展（有 PostgreSQL 时最顺）；Qdrant = 独立服务（过滤强）；Milvus = 分布式（亿级）。**100 万与 1 亿的选择会变**（内存装不下是拐点）。

6. **100 万 → 1 亿动什么？**
   内存（量化/分片）、索引类型（HNSW 全图装不下 → IVF-PQ）、分片路由、查询路径（分布式聚合+融合）。

7. **预过滤 vs 后过滤？**
   后过滤：先 ANN 再滤，过滤选择性高（滤掉 99%）时 top-k 崩坏。**过滤越严越要预过滤**（分区/过滤感知索引）。多租户：按租户分区/分索引首选。

8. **手算 50M×1536 维？**
   裸向量 307GB（50M×1536×4B），HNSW 图开销 ×2-3 → 600-900GB 单机不可能。降：MRL 截维 / int8（76GB）/ PQ，召回损失 rerank 补。

### 域五：混合检索

1. **为什么混合？**
   向量死穴 = 精确符号/稀有词/否定语义。**词面与语义两条腿，缺一条总有查询瘸。**

2. **BM25 赢什么、向量赢什么？**
   BM25：精确码（E1042）、型号（ACME-X200）、条款编号（第三十条）；向量：同义改写（"怎么解除合同" vs "合同终止条件"）。**判断口诀：查询里是"符号"还是"意思"？**

3. **BM25 vs TF-IDF？**
   k1 = 词频饱和（出现 10 次 ≈ 2 倍不是 10 倍，防刷分）；b = 长度归一化强度。**两个防刷分旋钮。**

4. **RRF 为什么稳健？**
   `score = Σ 1/(k + rank)`——只依赖排名。BM25 分数与余弦量纲不可比，加权等于把不可比的数相加；RRF 两边压成排名倒数天然可比。加权融合要评测集校准且随数据漂移，**默认 RRF**。

5. **权重怎么调？动态路由？**
   网格搜索 + 评测集校准。动态路由可行：精确码 → BM25；语义问句 → 向量；模糊 → 混合 + rerank。**每条查询只付需要的检索成本。**

6. **"ACME-X200" 召回不到？**
   90% 是 **analyzer 把连字符切碎**，查询与文档 token 流不一致。排查：看索引的 token 流；修复：keyword 字段/自定义分析器/n-gram。

7. **混合没涨指标？**
   消融：BM25-only / 向量-only / 混合分开跑——**每条腿独立达标再谈融合**。混合不是把坏腿变好。

### 域六：Rerank

1. **为什么还要 rerank？**
   bi-encoder 粗排（独立编码、可预计算、可索引）；cross-encoder 精排（联合编码，看到词级交互）——精度提升来自交互式计算。

2. **为什么 cross-encoder 不能全库跑？**
   联合编码无法预计算，全库 = 每查询 N 次联合前向，延迟成本不可行。**标准架构：bi-encoder 粗筛 top-50 → cross-encoder 精排 top-5。**

3. **放哪？候选多大？延迟？**
   检索后生成前；50→5 常见平衡点；rerank 预算 50-150ms（量化/蒸馏/只 rerank top-N/缓存）。

4. **recall@50 坏了，rerank 能修吗？**
   **不能。** cross-encoder 只见过 top-50，gold 不在里面精排再准也没用。**rerank 修排序不修召回**——回去修检索（改写/embedding/混合）。

5. **训练数据？**
   正样本 + **难负样本**（表面相似但无关，最有价值）+ 易负样本（信息量低，别淹没难负样本）。hard negative 挖掘：用 BM25/向量召回的未标注相关结果。点击日志：位置偏差用逆倾向加权。

6. **通用 vs 微调？bge-reranker 注意？**
   术语密集领域才微调。注意：**长度截断**（长块截/分段）、**分数不可比**（reranker 分数与 cosine 不同量纲，只在候选集内做相对排序，别混用阈值）。

7. **延迟成本优化？**
   四板斧：量化、蒸馏、只 rerank top-N（50 不是 500）、结果缓存。**先砍输入规模，再动模型。**

### 域七：查询改写 / 多跳检索

1. **改写解决什么？**
   多轮指代（"它"指什么）+ 查询过短（"违约金"召回全库）。改写 = 上下文补进 + 口语变检索友好。

2. **multi-query？**
   改写 3-5 个变体各检索再合并——召回是措辞的并集。代价：检索次数 ×N。成本换召回。

3. **HyDE？反噬？**
   先 LLM 生成假设答案，用假设答案的向量检索——"假设答案比问题更接近文档语言"。**反噬：假设是幻觉**（编出不存在的实体），检索被带偏。HyDE 是"用生成赌召回"，赌输加倍亏。

4. **Self-Query？**
   从自然语言抽结构化过滤条件 + 语义查询 → 结构化检索。**错误模式不是"答错"，是"在错误子集里答对"**——过滤条件要返回给用户可见。

5. **step-back vs 分解？**
   step-back = 抽象（"为什么 X 失败"→"X 失败的一般原因"，概念层）；分解 = 拆分（多部件问题拆子问题）。**一个往上走，一个往下拆。**

6. **为什么向量不擅长多跳？**
   第二跳需要的是第一跳的结果，不是原查询——向量空间里没有对应方向。设计：FLARE（低置信句子触发检索）、Self-RAG（反思 token）。**终止：max iterations + 置信度阈值 + 步骤预算，必须写死不能靠自觉**；成本兜底：预算上限 + 结果缓存 + 轻模型做决策。

7. **改写改变意图怎么防？**
   评估改写质量（意图一致性 + 人审抽样）；只在该改写时改写（有指代/过短才动）；原查询与改写都记 trace。

### 域八：幻觉与引用溯源

1. **RAG 为什么还有幻觉？**
   四来源：检索缺失（gold 没召回，只能编）、检索噪声（不相关块带偏）、生成偏离（上下文有但没照说）、超上下文（用记忆补）。**RAG 不消除幻觉，它改变幻觉分布**——从"随便编"变"基于证据的偏差"。

2. **引用粒度？张冠李戴怎么兜底？**
   chunk 级（便宜粗）/句子级（贵准）。兜底：**逐断言核对**——答案拆原子断言，每条断言与引用块做蕴含判定（NLI/LLM judge）。这就是答案闸门的设计原型。

3. **幻觉三层归因？**
   ① gold chunk 在不在索引里（缺失）；② 在不在 top-k 里（召回失败）；③ 单独喂 gold 还错（生成偏离）。一套消融，三层归因。

4. **工程手段？拒答代价？**
   grounding 指令（"只用上下文回答"）、不确定就明说、输出 schema 强制引用、答案闸门。**拒答代价 = 该答没答；错答代价 = 该对说错**——阈值按领域：医疗/法律拒答（错答是诉讼），客服倾向答（拒答是流失）。

5. **Lost in the Middle？**
   长上下文中间位置注意力衰减（Liu et al. 2023）。缓解：重要证据放开头/结尾、压缩长度、证据高亮。

6. **Faithfulness 评测局限？**
   数字类（"1.2 亿" vs "1.21 亿"）和多跳断言退化。实现：claim extraction（拆原子断言）+ NLI 蕴含判定。**断言越原子，核对越可靠。**

7. **多文档矛盾怎么裁决？**
   信号：来源可靠性（原件 > 摘要）、时效（新版 > 旧版）、检索分数、多数一致性。**采信最强信号 + 答案里披露矛盾**（"A 说 X，B 说 Y"）。裁决是信号加权，不是选边站。

### 域九：RAG 评测指标

1. **为什么分段评测？**
   检索质量和生成质量是两条独立故障面，混在一起分不清修谁。检索段（recall@k/precision@k）管"找没找到"，生成段（faithfulness/relevancy）管"用得对不对"。

2. **recall@k vs precision@k？**
   recall = 真正相关的进没进 top-k（漏没漏）；precision = top-k 里多少相关（干净不干净）。审计/全覆盖看 recall；用户只看前几条看 precision。

3. **MRR/MAP/NDCG？手算 NDCG@5？**
   MRR = 第一个相关的倒数（只认第一个，多相关场景失效）；MAP = 相关文档位置的平均精度（二值）；NDCG = 分级相关 + 位置折扣。
   手算：相关性 [3,0,2,1,0]：
   DCG = 3/1 + 0 + 2/log₂4 + 1/log₂5 = 3 + 0 + 1 + 0.431 = 4.431
   IDCG（理想序 [3,2,1,0,0]）= 3 + 2/log₂3 + 1/2 = 4.762
   NDCG@5 = 4.431 / 4.762 = **0.93**

4. **RAGAS 四维？哪些 reference-free？**
   context precision（召回的块多少相关，ref-free）——检索精度；context recall（黄金上下文召回多少，**要标注**）——检索召回；faithfulness（答案断言被上下文支持多少，ref-free）——防幻觉；answer relevancy（答没答到点上，ref-free）——生成相关性。

5. **Golden Set 怎么建？LLM 生成 QA 的坑？**
   从真实查询日志建。三坑：泄漏（LLM 用自己的知识出题）、过易（chunk 抄一段就能答）、答案可见。**黄金上下文必须来自线上检索的真实结果**——手工挑的 chunk 评测 0.91，真实管线 0.40：评测上下文与线上不一致，分数是空气。

6. **LLM-as-Judge 偏差？校准？**
   位置偏差（先出现的分高）、冗长偏差（长的分高）、自我偏好（偏袒自己的模型）、谄媚偏差。校准：与人工标注算 **Cohen's κ**（机遇修正一致率）——原始一致率有迷惑性（trivial 题双方都对，虚高）。**κ < 0.6 的 judge 不能当门禁。**

7. **Ragas/DeepEval/TruLens？**
   Ragas = 研究级指标（考卷）；DeepEval = 测试驱动 CI（考场）；TruLens = trace+评测（监考录像）。

8. **线上评测四件套？**
   shadow（旁路并行不扰用户）、canary（小比例真实流量）、trace 回放（历史查询重放对比）、freshness 监控（top-k overlap、索引过期——**没发版本效果变差的第一嫌疑是索引过期**）。

### 域十：Agentic RAG

1. **vs pipeline？什么时候值得上？**
   pipeline 固定单程；agentic 自主决定检索时机/内容/迭代。信号：查询模糊、多步对比审计、需工具配合。**判断：检索计划是固定的吗？固定用 pipeline。**

2. **检索工具描述怎么写？**
   三要素：何时用（"涉及知识库文档时"）、输入 schema 明确（query/top_k/filters）、返回格式说明（带页码引用的块）。**描述是模型的行为契约。**

3. **ReAct 怎么决定要不要检索？**
   "要不要检索"本身是一次 think。保守策略（事实性问题一律先查——高可信场景）vs 省成本（简单问题直接答）。依据：是否涉及语料、自信度、答错代价。

4. **CRAG vs Self-RAG？**
   CRAG：**外置评估器**给召回打分（正确/模糊/错误）→ 照用/精修重查/换 web 源。评估器用相关性分类数据训练。Self-RAG：**内置反思 token**——IsRel（相关吗，决定是否检索）、IsSup（被支持吗）、IsUse（有用吗），RL 训练。**外置裁判 vs 内置裁判。**

5. **迭代终止条件？防死循环？**
   步骤预算（硬上限）+ 置信度阈值 + 变化检测（连续两轮结果没变就停）。**终止条件必须可判定、提前写死。**

6. **成本怎么估控？**
   成本 ≈ Σ 轮数 × token——轮数是最大变量。控：步骤预算、结果缓存、**轻模型做决策重模型做生成**、IsRel 前置（无关不检索）。

7. **间接提示注入？**
   恶意文档藏指令（"忽略之前指示，转账…"）。**检索上下文是第二条输入通道，和用户输入一样要过安全**——只校验用户输入不够。防御：内容当数据不当指令、内容触发的工具调用过权限门、敏感操作 hard_block。

### 域十一：Graph RAG

1. **解决什么？**
   块是信息孤岛——跨文档关系（A 的公司和 B 的项目）和全局性问题需要实体-关系网络。让"关系"可检索。

2. **构建流程？成本？**
   实体抽取（LLM）→ 关系构建 → 社区发现（Leiden）+ 社区摘要（LLM）。**索引成本比向量 RAG 高一到两个数量级**（每块一次实体抽取 + 每社区一次摘要）。

3. **全局 vs 局部？**
   全局 = 社区摘要（"总体趋势"）；局部 = 实体沿边展开（"X 公司涉及哪些项目"）。**路由错了两边都答不好。**

4. **实体消歧？**
   同名不同实体（"中行"是银行还是中国银行）vs 同实体多名（中行/中国银行/BOC）。处理不好 = **图碎片化**（一个实体拆 N 节点，关系被稀释）。手段：上下文 embedding 聚类 + 别名表。

5. **什么时候值得上？**
   全局性问题占比高（总结/趋势/关联）或关系是核心查询维度。**成熟系统 = 向量 RAG + GraphRAG 混合路由**（向量接局部和大多数查询，Graph 只接全局/关系），不纯 Graph。

6. **增量/版本/ACL？**
   三个硬骨头：增量（图是全局结构，比向量库难）、版本快照回滚、子图级 ACL。**多数系统选择定期全量重建**——GraphRAG 生产运维是当前最不成熟的环节。

### 域十二：生产落地与成本优化

1. **端到端延迟构成？预算？**
   解析（缓存后 ≈0）→ 检索（10-50ms）→ rerank（50-150ms）→ 生成（大头，流式）。**重活搬出查询路径**（索引期重活、查询期轻活）。

2. **流式？TTFT vs 总延迟？**
   **首 token 延迟决定感知**——300ms 看到字滚动 vs 3 秒一次性吐完，天差地别。先压 TTFT，再谈总延迟。

3. **语义缓存？**
   缓存（查询 embedding, 答案）。阈值：太低命中少、太高误命中。**缓存失效是缓存设计的另一半**（索引更新按 doc 失效）。跨租户不共享（答案隔离是底线）。

4. **Token 成本？输入/输出定价差异？**
   输入:输出 ≈ 1:4（输出贵 4 倍）→ **prompt 长答案短**比 prompt 短答案长便宜。控：KV 缓存复用、检索结果裁剪（只注入真正相关的）、闸门减少返工轮次。

5. **trace 记什么？合规场景？**
   查询原稿+改写、检索集（chunk id+分数）、rerank 分数、prompt 版本、模型版本、生成、引用、各段延迟、grounding 分数。**合规不能看内容 → 哈希+版本+分数**（定位靠版本和分数变化，不靠读内容）。

6. **增量 vs 全量？为什么不能只增不删？**
   追加走增量；**策略变更走全量**（影子切换铁律）。**只增不删 = 旧内容还在索引里被召回 = 线上事故**。多版本同时召回：按 recency/优先级信号加权裁决。

7. **多租户权限为什么必须检索时过滤？**
   **prompt 里的权限约束不可靠**——检索上下文进了 prompt，"模型看到了"就是泄漏。必须检索时用元数据 ACL 过滤（确定性）。预计算 ACL vs ReBAC（读时决策）：预计算组变更滞后（移除权限还看得到）；ReBAC 实时但每查询一次策略计算。敏感场景：**检索时过滤 + 生成后二次校验**。

8. **没发版本效果变差？**
   三嫌疑：供应商静默升级模型（pin 版本 + 输出分布漂移监控）、索引过期（freshness 监控）、数据漂移（新文档分布变了）。抓法：canary 指标 + faithfulness 趋势 + 版本固定。

### 域十三：开放设计题

1. **10 万用户 RAG 从哪讲起？**
   **从需求开始**：量级（QPS/文档量/查询分布）→ 延迟预算（首 token 目标）→ 成本模型（单价×长度×日活）→ 才到架构。**先问需求的人才是做系统的。**

2. **Silo/Pool/Bridge？**
   Silo（每租户独享，隔离最强成本最高）、Pool（共享池，成本最优靠逻辑隔离）、Bridge（核心共享+敏感租户独立）。**先定合规约束，再定隔离模型。**

3. **5 万文档每日更新 + 必须拒答？**
   更新机制（增量+变更检测+灰度回滚）、矛盾处理（信号加权+披露）、拒答路径（置信度阈值+答案闸门+转人工）。**"答不出就承认"是设计目标不是口号——靠闸门机制强制，不靠模型自觉。**

4. **Agentic 研究助手？**
   规划（分解）→ 检索（按需）→ 验证（相关性评估闸门）→ 引用（逐断言+页码）。防污染：每轮检索结果过验证闸、已确认结论固化（不被后续噪声改写）、溯源链（断言绑定来源）。**坏检索不可怕，坏检索无闸门地流向下游才可怕。**

5. **反杀题？**
   诚实 + 补课：承认边界 + 当场补出选型对比推理（域四第 5 题框架）。**面试官要的不是"你都会"，是"你承认边界且能推理边界之外"。**

## 二、设计辩论记录（2026-08-15，本仓库设计实战）

### 辩论 1：VLM 读图 vs 文本提取（文档解析路线）

- **用户方论点**：整页渲染喂 VLM 语义损耗最小；语义模型天然契合 VLM 架构；多图拼接不丢前后文；8 页/批成本可控（1w 页 = 1250 次调用）；本地部署 120 tok/s，8 页 ~30s，单机 1w 页 ~10 小时，个人用户常见 30 页 ~1.5 分钟；结构化输出直接规定元数据，不用多调一次模型做前后文摘要。
- **采纳点**：① 版面保真（版式/表格/阅读顺序无损）；② 扫描件由 VLM 直读，**独立 OCR 环节取消**；③ 结构化输出一次到位（正文结构+表头+摘要+元数据+页码，删掉独立摘要 pass）；④ 成本量级确实可控。
- **保留例外**：文本层完好的数字 PDF 走 pypdf 确定性提取。理由：**引用校验的确定性**——闸门校验"引用 vs 索引文本"的前提是索引文本忠实于原件；pypdf 是确定性事实（100% 无损），VLM 是概率性读取（"违约金 30%"读成"3%"，闸门照样通过，错在源头下游全白）。有免费无损路径时不用有损路径。
- **结论：format router（按文档类型路由）**——数字 PDF 文本层 → 确定性解析；扫描件/图表密集/复杂版面 → VLM 页面图批量理解。
- **残余风险（诚实记录）**：扫描件场景 VLM 输出是唯一事实源，**引用校验存在循环性**（模型读的 → 模型校验的）。缓解：抽样人工核对（首月每 100 页抽 1 页）+ 可选高相关块二次 VLM 复核。

### 辩论 2：表格处理

- **用户方论点**：不需要多模态向量；表格保留表头 + 生成摘要 + markdown 化，按文字处理；引用时回到原表格。
- **采纳**：citation target 指针（chunk → extractions.structured（markdown/JSON）→ 原页图/原文件位置）；向量化统一（无多模态 embedding）、评测统一（表格检索 = 文本检索）、引用可落到"原表格"。

### 辩论 3：会话历史检索（DB 内查询）

- **需求**：rag 搜索除工作区文档外，还支持存储的 db 内查询（会话历史、附件/产物元数据）。
- **粒度决策**：**按消息分块 + turn_index 关联**（而非按模型调用：中间调用含工具参数可能含密钥、工具结果可能巨大，安全与成本双风险，且搜索语义不落在中间调用；而非整轮一块：user/assistant 揉一起角色过滤做不到）。
- **索引规则**：user 消息 + assistant 最终回答入库（保留引用标记）；带 tool_calls 的中间消息只记工具名元数据；tool 角色消息不入库；`last_message_id` 水位增量；会话 Stop（插件 hook）触发。
- **工具形态**：独立 `rag_search_sessions` 工具，**不用正则路由**（正则识别"之前/上次"脆弱）——工具描述驱动 LLM 自主选用（工具描述即行为契约）。与 `rag_search`（工作区文档 + artifact 元数据 scope）分工写进两个工具的描述。
- **覆盖范围（用户拍板）**：会话历史（核心）+ 附件/产物元数据；记忆（core_memories）不纳入（已有加载进 prompt 的机制）。

## 三、考点速记表（复盘最后一遍）

| 域 | 一句话考点 |
|---|---|
| 解析 | 格式路由：确定性优先、无损优先；扫描件/复杂版面交给 VLM，独立 OCR 取消 |
| 分块 | 结构锚点优先于固定长度；预算必须评测集定；策略变更走影子切换 |
| Embedding | 符号归词法、语义归向量；归一化后余弦==内积；换模型 = 全量重建 |
| 向量库 | 规模定选型；内存装不下 = 扩容拐点；过滤选择性高必须预过滤 |
| 混合检索 | RRF 只认排名所以稳健；消融定位坏腿；连字符坑在 analyzer |
| Rerank | 修排序不修召回（recall@50 坏了 rerank 白搭）；分数与 cosine 不可比 |
| 改写/多跳 | 多跳需迭代检索；终止条件必须写死；HyDE 赌输加倍亏 |
| 幻觉/引用 | 证据强制 > 谎言检测；三层归因消融；拒答阈值按领域 |
| 评测 | 分段评测；黄金上下文必须来自真实管线（0.91 vs 0.40）；κ<0.6 不能当门禁 |
| Agentic | 轮数 = 成本；工具描述 = 行为契约；检索上下文 = 第二条输入通道 |
| Graph RAG | 索引成本高一两个数量级；混合路由不纯 Graph；增量/ACL 是硬骨头 |
| 生产 | TTFT 决定感知；缓存失效是另一半设计；权限必须检索时过滤；pin 模型版本 |
| 开放题 | 先问需求再答架构；诚实边界 + 现场补推理 |
