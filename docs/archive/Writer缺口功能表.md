# Writer 缺口功能表

## 核心原则

补的是 Writer 自身的通用能力。任何复杂任务都能因这些能力而受益。LLM 研发只是压力测试用例，不是目的。

Writer 当前最核心的缺口就一句：**能干活，但不能自己把事想清楚、推到底、推错了能回头。**

---

## 一、Writer 自身需补的功能

| 序号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| W1 | 模糊意图 → 执行计划拆解 | 用户说"开发一个 XX"，Writer 能自己产出：目标、分步、每步产出什么文件。不再依赖用户在消息里写文件名才能启动 | P0 |
| W2 | 强制计划阶段 | runtime 中插入计划阶段：接到任务必须先出计划、经确认，再进入执行。模糊任务不能跳过计划直接动手 | P0 |
| W3 | 失败后重规划 | 某步执行失败时，不是继续盲跑或卡住，而是重新评估：当前路线是否成立、要不要回退、要不要换方案。产出修订计划 | P1 |
| W4 | 执行中迷失检测 | 自动检测"读了 N 轮没产出""不停探索不停想""偏离原目标"。检测到后触发重新对齐或介入 | P1 |
| W5 | 多阶段进度状态 | WriterSessionState 增加"当前处于哪个阶段 / 已完成哪些里程碑 / 下一步是什么"。支持跨 turn 维护目标感 | P1 |
| W6 | 计划级 self-review | self-review 增加"计划质量审查"维度：覆盖是否完整、步骤是否可验证、是否有遗漏。不只是事后审代码 | P1 |
| W7 | 验收条件自动生成 | 根据计划自动产出每步验收条件（文件存在、测试通过、命令成功），执行后逐项核对 | P2 |
| W8 | 关键上下文锁定 | 复杂任务时将原始目标、当前阶段、关键约束锁定在 context 中，不因 tool output 膨胀而被冲刷丢失 | P2 |
| W9 | 委托其他成员 | WriterAction 新增 delegate_to_member 类型：turn 中能把子任务派给其他 LamTools 成员，拿回结果后继续 | P2 |
| W10 | 阶段自适应交互模式 | 规划阶段自动切 BRAINSTORM、执行阶段切 EXECUTE、验收阶段切 REVIEW。不再所有阶段用同一个模式 | P2 |
| W11 | 任务拆解质量自检 | 拆出来的计划是否可执行、每步是否有明确产出、边界是否清晰。拆完后先自检，不合格则重拆 | P2 |

## 二、平台级能力归属（非 Writer 缺口）

以下能力 LLM 研发场景需要，但不属于 Writer 应内置的功能。按现有 LamTools 成员职责边界归属：

| 能力 | 归属 | 说明 |
|------|------|------|
| 训练任务提交与监控 | **Butler** | Butler 已有的内感就是监控成员脉搏——训练任务只是被执行体从 Writer 换成了训练进程。提交/启动/心跳/挂掉检测/重启，全是职能 01（掌控节奏）+ 职能 11（错误恢复）的自然延伸 |
| Checkpoint 注册与恢复 | **Butler** | 职能 02 明确写了"工作现场还原"——checkpoint 就是训练现场的还原点。哪个是 best、从哪个恢复、保留策略，本质是 Butler 的执行状态管理 |
| Metrics 采集与存储 | **Sage** | Sage 核心循环"搜集→鉴别→整理→入库"。Metrics 就是实验过程中产生的结构化知识——需要采集、校验、入库、供全员查询 |
| Benchmark 注册与运行 | **Butler**（调度运行）+ **Sage**（注册与结果库） | 跑 benchmark 是任务执行（Butler 调度）。套件注册、得分入库、多 run 对比分析是知识管理（Sage） |
| GPU 资源调度 | **Butler** | 职能 02"环境打理"已覆盖"环境始终就绪"——GPU 就是计算环境的一部分。哪些卡空闲、谁在用、排队策略，纳入 Butler 的资源管理 |
| 数据集版本管理 | **Sage** | 数据集是全家桶的知识地基。版本 hash、split、预处理参数、数据血缘追踪——和 Sage 管知识版本是同一件事 |

## 三、Creator 的角色

这 6 项基础设施能力**没有 Creator 的事**。它们全是执行面和知识面的基础设施，不是 Creator 的创新合成领域。

Creator 在整个 LLM 研发体系里的位置在**上层**——不在怎么跑、怎么记，而在**下一步该想什么**。

但ler 职能 12 描述的三方协作：

```
Sage 提供已验证原料 → Creator 大胆合成候选方案 → Butler 准入验证
```

| 层 | 谁 | 做什么 |
|----|-----|------|
| 基础设施层 | Butler + Sage | 怎么跑、怎么记、怎么恢复 |
| 执行层 | Writer | 把活干出来（代码/文本） |
| 创新层 | Creator | 从已有事实跳出，想出没人想到的组合 |

---

## 四、汇总

### Writer 自身：11 项

| 优先级 | 数量 | 核心主题 |
|--------|------|----------|
| P0 | 2 | 补规划能力——模糊意图拆解 + 强制计划阶段 |
| P1 | 4 | 补执行韧性——重规划、迷失检测、阶段状态、计划审查 |
| P2 | 5 | 补工程完备性——验收条件、上下文锁定、委托、模式切换、拆解自检 |

### 平台级归属：6 项

| 归属 | 数量 | 核心主题 |
|------|------|----------|
| Butler | 4（训练监控、Checkpoint、GPU 调度、Benchmark 调度） | 执行面：提交、监控、恢复、资源 |
| Sage | 3（Metrics 存储、Benchmark 结果库、数据集管理） | 知识面：搜集、鉴别、入库、查询 |
| Creator | 0 | 不在基础设施层；位置在创新层 |
