# Writer 跨会话记忆系统设计

> 目标：让 Writer 越用越顺手，但不因为自动记忆变得自作主张。

## 1. 业务目标

跨会话记忆不是保存聊天记录，也不是扩大 prompt。

它要解决的是：

- 下次少问重复问题。
- 少重复读相同文档。
- 自动遵守用户长期偏好。
- 自动遵守项目长期规则。
- 复用已经验证过的解决路径。
- 避免反复犯用户指出过的错误。

核心原则：

**默认谨慎，不确定不写；能短不长；有来源；可撤销；可复核。**

## 2. 和会话内记忆的边界

会话内记忆：

- 当前任务的完整过程。
- 工具输出全文。
- Git checkpoint、diff、错误、临时判断。
- 当前步骤、当前分支、当前修复路径。

跨会话记忆：

- 只沉淀长期有效的偏好、规则、项目事实和已验证经验。
- 不保存完整 tool output。
- 不保存完整 diff。
- 不保存一次性任务细节。
- 不直接保存未经验证的猜测。

一句话：

**会话内可以全，跨会话必须精。**

## 3. 可以写入的内容

跨会话允许写入以下内容。

### 用户长期偏好

例如：

- 中文交流。
- 业务语言汇报。
- 非必要不说函数名。
- 喜欢先筛范围，再谈方案。
- 不喜欢硬预算式限制。

写入条件：

- 用户明确表达；
- 或多次稳定出现；
- 或用户在纠正中明确强调。

### 项目长期规则

例如：

- 不得使用 mock 测试。
- Writer 和 OpenCode 使用同一个 GLM5.1 模型。
- Git 分支规则是 `writer/{category}/{slug}`。
- Writer runtime 不受 LamTwo 影响。

写入条件：

- 来自 `AGENTS.md`、设计文档、计划文档；
- 或用户明确确认；
- 或代码/测试反复证明。

### 稳定项目事实

例如：

- 关键模块职责。
- 启动命令。
- 测试命令。
- 重要文档入口。
- 已完成的架构边界。

写入条件：

- 有文件路径或 commit 作为来源；
- 不是临时分支上的未确认状态；
- 没有和当前代码冲突。

### 已验证的修复经验

例如：

- 某类测试失败通常由某个模块引起。
- 某个 prompt 结构会导致 Writer 读循环。
- 某个修复路径已经通过测试。

写入条件：

- 有失败现象；
- 有修复动作；
- 有验证结果；
- 最好有关联 commit 或测试输出引用。

### 用户经常指出的错误

这是必须写入的跨会话学习维度。

例如：

- 用户多次指出“不要 mock 测试”。
- 用户多次指出“不要硬预算，灵活性太差”。
- 用户多次指出“旧 tool output 不能只保留摘要，还要能索引到全文”。
- 用户多次指出“业务语言汇报，不要堆函数名”。
- 用户多次指出“跨会话记忆一定要谨慎”。

这类记忆不是普通偏好，而是 **纠错记忆**。

作用：

- 下次遇到类似场景时提前避开。
- 排序时优先进入 prompt。
- 计划阶段作为约束检查项。
- 任务结束时检查是否再次违反。

写入条件：

- 用户明确纠正一次，先写入候选。
- 同类纠正重复出现，升为高置信。
- 如果用户说“以后都这样”，可直接写入长期偏好。

## 4. 禁止写入的内容

跨会话默认不写：

- 一次性任务细节。
- 未验证原因。
- 半成品方案。
- 大段日志。
- 完整 diff。
- 敏感信息。
- 用户临时情绪。
- 某次对话里的猜测。
- 已被后续推翻的信息。
- 只在当前分支有效的临时状态。

尤其注意：

**不能因为 LLM 自己认为有用，就写入长期记忆。**

## 5. 写入流程

跨会话写入分四步。

### 第一步：会话内先记录

所有事实先进入会话内记忆：

- 工具输出。
- Git 事件。
- 错误。
- 决策。
- 用户纠正。
- 自检结论。

### 第二步：生成候选记忆

任务结束或阶段结束时，从会话内记忆提取候选：

- 用户偏好候选。
- 项目规则候选。
- 项目事实候选。
- 修复经验候选。
- 用户纠错候选。

### 第三步：谨慎筛选

每条候选必须判断：

- 是否长期有效。
- 是否有来源。
- 是否验证过。
- 是否会污染其他项目。
- 是否可能过期。
- 是否需要用户确认。

### 第四步：写入长期记忆

写入时必须带：

- 作用域。
- 类型。
- 内容。
- 来源。
- 置信度。
- 创建时间。
- 最近验证时间。
- 过期或复核策略。

## 6. 作用域

每条跨会话记忆必须明确作用域。

### 用户级

适合：

- 沟通风格。
- 长期工作偏好。
- 用户经常指出的通用错误。

风险：

- 容易影响所有项目。
- 写入必须更谨慎。

### 项目级

适合：

- LamWriter 架构事实。
- 项目测试规则。
- 项目 Git 策略。
- 项目文档入口。

风险：

- 项目演进后容易过期。

### 仓库级

适合：

- 当前 repo 的命令、目录、模块职责。
- 特定代码库的错误经验。

风险：

- 换 repo 后不能复用。

### 临时级

适合：

- 分支策略。
- 当前实验路线。
- 当前任务阶段。

默认不升跨会话。

## 7. 记忆状态

跨会话记忆不要只有“存在/不存在”。

建议状态：

- `candidate`：候选，还不能强约束。
- `confirmed`：用户确认或证据充分。
- `high_confidence`：多次验证有效。
- `needs_review`：可能过期，需要复核。
- `deprecated`：已废弃，不能召回到 prompt。

用户经常指出的错误可以从 `candidate` 快速升到 `confirmed`，但仍然要保留来源。

## 8. 召回策略

跨会话召回顺序：

1. 当前项目明确规则。
2. 用户长期偏好。
3. 用户经常指出的错误。
4. 当前任务相关项目事实。
5. 已验证修复经验。
6. 工作流习惯。
7. 低置信候选。

进入 prompt 时只给短结论：

- 结论。
- 作用域。
- 置信度。
- 来源引用。

详细来源按需取回。

## 9. Prompt 组装原则

跨会话记忆不能破坏缓存命中。

建议顺序：

1. 稳定系统规则。
2. 项目固定约束。
3. 高置信长期偏好。
4. 用户经常指出的错误。
5. 当前任务相关项目知识。
6. 会话内动态上下文。
7. 当前用户输入。

动态、低置信、长内容都靠后。

## 10. 自学习闭环

每次任务结束后做轻量复盘：

- 哪些长期记忆被命中。
- 哪些命中帮上忙。
- 哪些命中是噪声。
- 哪些旧记忆被当前事实推翻。
- 用户有没有纠正 Writer。
- 是否产生新的可复用经验。

如果用户纠正 Writer：

- 先写入会话内纠错记录。
- 判断是否属于长期偏好或常见错误。
- 如果重复出现，升为跨会话纠错记忆。

## 11. 过期和清理

跨会话记忆必须定期清理。

清理目标：

- 删除重复记忆。
- 降权低命中记忆。
- 标记过期项目事实。
- 合并相似用户偏好。
- 废弃与当前代码冲突的旧事实。

项目事实如果来源文件已变化，应进入 `needs_review`。

## 12. 用户控制

用户必须能控制长期记忆。

至少支持：

- 查看当前记住了什么。
- 删除某条记忆。
- 禁止某类记忆写入。
- 把某条候选提升为长期记忆。
- 把某条长期记忆标记为错误。

跨会话记忆不能偷偷变成不可见规则。

## 13. 验收标准

真实任务中重点观察：

- 是否减少重复解释。
- 是否减少重复读文档。
- 是否自动遵守用户偏好。
- 是否避开用户经常指出的错误。
- 是否没有把临时判断当长期事实。
- 是否能说明每条长期记忆的来源。
- 是否能在错误时撤销或降权记忆。

最终目标：

**Writer 不是记得更多，而是更少打扰、更少犯旧错、更贴合用户习惯。**
