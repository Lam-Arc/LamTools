# 真实任务调优测试计划

> 前置条件已满足：主路径单轨、旧 Runtime/Graph 污染清掉、Writer/Artist 基础测试和前端构建通过。
> 继续拆结构收益下降，真实任务测试更能暴露有价值的问题。

## 测试原则

- 每个任务都按真实用户说法输入，不给内部提示词。
- 每个任务至少跑 2 轮交互，观察是否能接住上下文。
- 不追求一次完美，重点看是否会跑偏、卡死、重复、乱用工具、验收不严。
- 每个失败都记录为"用户感受到的问题"，不要只记技术异常。

---

## Writer 测试

### W1: 从 0 开发项目

**目标**：验证 Writer 是否能把自然语言需求拆成计划、创建文件、实现功能、运行测试、交付结果。

**示例任务**：

"帮我做一个本地运行的待办事项小工具，支持新增、完成、删除、按状态筛选，并写好 README 和简单测试。"

**验收重点**：是否先规划、是否真的写文件、是否能跑测试、是否能说明怎么运行、是否避免过度设计。

### W2: 已有项目重构调优

**目标**：验证 Writer 能否读懂现有代码，不乱改，能小步重构并保持行为不变。

**示例任务**：

"这个项目里有一个很大的页面/模块，帮我拆小一点，要求功能不变，命名清楚，测试能过。"

**验收重点**：是否先理解结构、是否保护现有行为、是否避免大面积无关改动、是否能解释拆分收益。

### W3: 已有项目诊断与修复

**目标**：验证 Writer 能否定位问题、提出假设、最小修改、验证修复。

**示例任务**：

"项目启动时报错/某个按钮没反应/某个接口返回异常，帮我找原因并修复。"

**验收重点**：是否先复现、是否定位根因、是否避免盲改、是否有验证证据。

### W4（可选）: 非职责任务

**目标**：观察 Writer 面对边界外任务时是否能合理处理。

**示例任务**：

"帮我做一份科研项目汇报 PPT。"

**验收重点**：是否直接乱做，还是能说明自己适合做大纲、文案、结构，必要时建议交给更合适成员。

### W5（可选）: 情绪价值任务

**目标**：观察 Writer 是否能处理真实用户的非工程输入。

**示例任务**：

"我今天很崩溃，项目一直失败，你陪我聊聊。"

**验收重点**：是否自然、是否不过度工具化、是否能安抚并逐步拉回可执行问题。

## Artist 测试

### A1: 从 0 计划并生图

**目标**：验证 Artist 是否能理解自然语言、主动澄清、形成风格方向，并多轮稳定出图。

**示例任务**：

"帮我设计一张赛博东方风的游戏主视觉，适合作为宣传海报。"

**验收重点**：是否会先确认风格/用途/比例，是否能生成，是否能根据反馈继续调优。

### A2: 11 页 PPT 背景/封面套图

**目标**：验证 Artist 是否具备生产力级的一致性输出。

**示例任务**：

"帮我做一套 11 页科研汇报 PPT 背景和封面，主题是 AI 辅助药物发现，要求统一风格、适合文字叠加。"

**验收重点**：风格是否一致、页面是否可用、是否考虑留白、是否能形成一套而不是 11 张散图。

### A3: 用户上传原图修改

**目标**：验证 Artist 是否能基于用户素材做多轮编辑，而不是每轮重画跑偏。

**示例任务**：

"基于这张图，把背景改成雨夜霓虹街道，人物姿势和脸不要变。"

**验收重点**：是否尊重原图主体、是否能局部修改、是否能听懂多轮反馈、是否不会丢失关键约束。

### A4（可选）: 非职责任务

**目标**：观察 Artist 面对非图像任务时是否能正确边界处理。

**示例任务**：

"帮我修一个 Python bug。"

**验收重点**：是否拒绝乱做，是否建议交给 Writer，或只提供视觉相关帮助。

### A5（可选）: 情绪价值任务

**目标**：观察 Artist 是否能自然应对用户随意输入。

**示例任务**：

"我不知道想画什么，你给我点灵感。"

**验收重点**：是否能引导用户形成视觉方向，而不是机械追问。

## 记录格式

每个任务记录 6 项：

| 字段 | 说明 |
|------|------|
| 任务名称 | 如 W1、A2 |
| 输入内容 | 实际输入的原始文本 |
| 是否完成 | 是/否/部分 |
| 用户体感问题 | 用户视角感受到的问题描述 |
| 失败原因判断 | 从系统角度判断根因 |
| 下一步修复建议 | 针对性改进方向 |

---

## 通过标准

可进入持续调优的标准：

- Writer 三个主任务（W1-W3）至少 2 个能完整闭环。
- Artist 三个主任务（A1-A3）至少 2 个能完整闭环。
- 没有卡死、无限循环、严重误删、严重跑偏。
- 失败问题能归类到具体能力点，而不是架构不清。

---

## 执行策略

先不扩大范围，先跑 6 个主任务（W1-W3、A1-A3），拿真实失败样本再决定下一轮修哪里。
