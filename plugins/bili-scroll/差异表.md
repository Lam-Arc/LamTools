# DSH 2.2.2 → LamTools 2.3.0 能力对照

对照来源：[c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll)，提交 `4af98392ee078e02f50a7fd0bf0491033f4675ed`。本体和内置 bilibili-mcp 均为 MIT，许可证与署名保留。DSH 原版前端与 CSS 直接复用，文件为 `vendor/dsh-client.js`；宿主业务按行为移植，DSH 服务端宿主代码未原样执行。

| 原版能力 | LamTools 对应与差异 | 验证 |
|---|---|---|
| 内置 MCP，34 工具及参数 | 保留同一服务器源码，增加宿主配置执行闸；调用经宿主 `mcp` | 真实子进程枚举、参数与数量检查 |
| 搜索、视频信息、字幕、评论、封面、画面帧 | 同名 MCP 工具 | 登录后六项真实联网成功，演示视频字幕 75 段 |
| 推荐、弹幕、榜单、用户与收藏读取等 | 原版工具完整保留 | 工具注册/协议验收；未逐个做真实网络调用 |
| 环境安装与扫码 | 独立环境、镜像安装、唯一二维码、原子凭证与 Windows 权限 | 实际安装与扫码登录成功 |
| 配置、四页签、视频墙 | 原版 React 组件与 CSS；四页签、开关、档位与状态筛选、分页均保留 | 原版源码哈希一致；DOM、严格 CSP 浏览器布局验证 |

| 定时、私信监听、停止 | asyncio 任务，停止等待清理与 I/O 完成 | 受控时钟/业务测试 |
| 日报、判重、归档、单视频笔记 | 原版文件口径与 MCP `duty_*`；轮后生成单视频笔记 | 真实 MCP 文件写入、操作回读 |

| 私信双向及分享卡片 | 提取正文/卡片，主人消息去重、日限额，子代理回复 | 模拟消息验收；未读写真实私信会话 |
| 昵称解析收件人 | 自动解析并保存 UID；展示已解析收件人 | 模拟 API 验收 |
| 自动收藏、90 秒评论复核 | 轮后任务接回报告 | 轮后调度模拟验收；手动真实收藏成功并回读，评论公开可见 |

| 诊断与健康检查 | 状态、环境、日志、报告、独立窗口操作通道 | 宿主操作/HTTP 验收 |

| 宿主生命周期 | 单一实例管理、调用排空、MCP 清理、代际隔离、失败回滚与中断恢复 | 新增宿主验收测试 |

能力实现已补齐旧移植中的缺项；追加授权后真实评论、私信和收藏已完成并回读。长期无人值守及自动投递策略尚未真实实测，不能据此声称所有外部行为已验证。页面验证限代码与 DOM，没有使用 Computer Use。

真实收藏发现原版边车使用当前依赖不存在的 `FavoriteListResource`。保留 vendor 来源，新增适配边车使用 `Video.set_favorite`；同时修复外部 Python 环境被本地安装标记误拦、Windows 中文子进程回执解码失败。

用户要求直接移植原版界面后，已移除之前重画的页面。原版 `client.js` 不做正文修改，静态作用域包装仅连接宿主；原版升级按钮的安装源仍需使用宿主兼容包，不能把 DSH 宿主包直接覆盖进来。
