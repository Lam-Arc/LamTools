# DSH dsh-qqbot 0.5.3 → LamTools qq-bot 0.1.0 能力对照

对照来源：[`tencent-connect/dsh-qqbot`](https://github.com/tencent-connect/dsh-qqbot/tree/d998f72)，固定提交 `d998f72`，版本 0.5.3。原版本体 MIT（Tencent Connect）；本插件按行为重写，未原样执行 DSH 宿主代码。协议参考 MIT 的 `@tencent-connect/qqbot-nodejs` 1.0.5；扫码连接器 1.2.0 为 UNLICENSED，未复制源码。

## 一、能力对照

| 原版能力 | LamTools 对应 | 状态 | 说明 |
|---|---|---|---|
| 访问令牌、WebSocket 网关、identify/resume/心跳/重连 | `qqbot/protocol.py` | ported | Python 重写；真实 q.qq.com 绑定已验证，网关未用真实凭据连接 |
| 私聊/群聊消息、markdown、键盘、event_id、msg_seq | `QQApi.send_raw` / `send_markdown` | ported | 请求体与上游 SDK 一致 |
| C2C 流式消息 | `StreamSession` | ported | 500ms 节流、全量替换、失败降级静态 |
| 小文件媒体上传 | `QQApi.upload_media` | ported | base64，20MB 上限 |
| 5MB 以上分片上传 | `QQApi._upload_chunked` | ported | upload_prepare / COS PUT / part_finish / complete；整文件读入内存 |
| 14 个入站中间件位置 | `qqbot/middleware.py` + 运行时管线 | ported | 顺序与上游 `setupMiddlewares` 一致；错误兜底、命令/问答截获、并发合并在运行时管线；限流默认关闭 |
| 9 个聊天指令 | `qqbot/commands.py` | ported | `/new` 别名、`/stop` 隐藏、帮助分组与点击指令 |
| `/compact` | 宿主 `runner.compact` / `preset_service("compaction").compact_now` | ported | 手动压缩子会话历史；优先使用 preset 作用域的压缩服务 |
| `/preset` | 宿主 `agent_presets` 注册表 + per-preset service | ported | 预设由宿主注册表提供；插件可注册/解析 preset 作用域服务 |
| `/model` | 宿主 `model_catalog` + per-peer 覆盖 | ported | 通过稳定模型目录解析 provider/model；下一轮带同一份历史换模型 |
| 持久会话 | 稳定 agent 名称 + 宿主状态库 | ported | 私聊/群聊各自一份历史；闲置回收只释放内存 |
| 每个会话独立机器人 | `QQBotManager` + 每 bot 独立目录/密钥/网关 | added | 每个 Sunday 会话创建独立 AppID 机器人；旧单机器人迁移为 default；右侧栏按当前会话查找/创建 |
| 目标会话模式 | `targetProjectId` / `targetSessionId` + `SessionTargetClient` | added | 私聊/群聊都注入选定 Sunday 会话；空闲走 `turn.start`，运行中走即时 `inject_guidance`，不走排队；目标会话审批/提问转 QQ，回答后 `approval.respond` 续跑；`/stop` 中止目标回合 |
| 气泡拆分 | `bubbles.py` + `OutboundRouter` | added | 先解析 Markdown 内容块再切气泡；默认 `full` 保留表格/代码块，`safe` 转表格行卡片/代码引用；Sunday `:::` 样式块去掉容器标记后退为标题/正文；流式增量、工具结果和中间提示共用规则 |
| 审批通道 | `pending_approval` + `resume_approved` | ported | 允许一次/拒绝两个按钮；拒绝通过 `resume_question` 清理挂起 |
| 问答通道 | `pending_approval(request_kind=question)` + `resume_question` | ported | 宿主 `question` 工具支持 `questions` 数组；插件逐题展示、合并回答后一次续跑 |
| 子会话分叉 / 历史 | `runner.fork` / `session_info` + `/fork` `/history` | ported | 分支切换当前 peer；历史命令显示最近消息与状态 |
| 工具结果展示 | `runtime.tool.finished` 格式化 | changed | 没有 `presentResult`；按 content/error/artifacts 展示 |
| 交付物 `present` | 工具 artifacts + `qqbot_send_file` | changed | 轮末按 `sendPresentedFiles` 投递 artifacts |
| 富媒体下载、SSRF、TTL 清理 | `qqbot/media.py` | ported | HTTPS、私有地址阻断、大小/超时、按 mtime 清理 |
| 视觉工具 | 无独立工具 | changed | 附件落盘后用 `@路径` 交给模型；不再暴露描述工具 |
| 文件发送工具 | `qqbot_send_file` | ported | 当前会话自动定位 + 路径白名单 |
| 扫码绑定 | `qqbot/binding.py` | ported | q.qq.com 任务、轮询、AES-256-GCM、SVG 二维码 |
| 手动凭据 / 解绑 | 绑定操作 + 宿主密钥库 | ported | AppID 写配置；AppSecret 写宿主 `secrets`（Windows DPAPI），旧明文启动时迁移；解绑同时清除 |
| 设置页 / 侧栏 / 配置面板 | 页面 + 窗口 + 右侧区域 + schema | changed | 复用原版 CSS 类；React 组件改为原生 DOM |
| 端内绑定 HTTP 路由 | 插件操作 + 页面 RPC（宿主另有 `http.routes`） | changed | 绑定状态、刷新、手动、解绑、配置全部走操作；宿主现在支持声明式 HTTP 路由，QQ 当前不需要 |
| HMR 热重载 | 进程内重启网关 + 配置监视 + `plugin.system.reload` | changed | 改配置即时生效；改插件代码调用显式重载，不需要重启整个应用；没有自动文件监视 |
| 环境变量凭据 | `QQBOT_APPID` / `QQBOT_SECRET` | ported | 只在内存回退，不写入配置 |
| 频道/频道私信 | 解析但不产生回复目标 | ported | 与上游 `deriveReplyTarget` 一致 |
| 原始事件 | 调试日志 | ported | 上游转发 `rawEvent`，插件本身不消费 |
| `ensureVisionInputModal` 改 settings.yaml | 无 | missing | 宿主模型配置没有 `input` 模态字段；附件能力路径自行处理图片 |
| token 用量 / 导出 | `/cost` / `/export` | ported | 上游有实现但没有指令；本插件补了指令（只多不少） |
| 三层限流 | `rate_limiter` | ported | 上游 `rateLimiter()` 未传参数，实际不限制；本插件保持默认关闭 |

## 二、三类问题

### 第一类：宿主问题（LamTools 侧）

| 编号 | 问题 | 证据 | 处理 | 状态 |
|---|---|---|---|---|
| H1 | 宿主没有 agent preset 注册表，插件只能自己拼 mode/tools/prompt | 原 `KernelSubAgentRunner` 只有 `allowed_tools` / `mode` / `late_context` | 新增 `plugin_system/agent_presets.py`；清单 `agentPresets` + 配置目录；运行器 `preset=` 应用 | 已补 |
| H2 | 宿主没有系统提示词瀑布，插件无法按会话注入系统提示词 | `CoreBaseAgentKit._compose_system_prompt` 只拼内置块 | 新增 `plugin_system/prompt_waterfall.py`；kit 在拼装末尾调用；插件启动注册/停用注销 | 已补 |
| H3 | 宿主没有 DSH 的 `userQuestions` 服务与 `approval/request` 瀑布 | 宿主用 `pending_approval` 结果 + `resume_*` | `question` 工具支持 `questions` 数组；插件逐题展示并合并回答，审批/问答统一续跑 | 已补 |
| H4 | 子会话没有 fork / 手动 compact / 历史 API | `KernelSubAgentRunner` 原来只有 `run` | 新增 `compact` / `fork` / `session_info` 与 preset 作用域压缩服务；插件补 `/compact` `/fork` `/history` | 已补 |
| H5 | 插件不能给运行器单独指定 cwd | 运行器 `work_root` 由宿主项目决定 | `sub_agent_runner_factory(work_root=...)`；QQ 配置 `cwd` 直接作为子代理工作目录 | 已补 |
| H6 | 插件不能注册 webServer 路由 | 插件宿主原来只暴露操作/页面 RPC | 新增清单 `http.routes`：宿主挂到 `/api/core/plugin-http/<plugin>/<path>`，默认 token 鉴权，只允许 `auto_allow` 操作；QQ 当前仍用操作 + 页面 RPC | 已补 |
| H7 | 宿主没有 DSH 的 `settings.section` / 侧栏槽位 | 宿主 UI 是页面/窗口/区域（含 `settings` 区域） | 用导航页面 + 独立窗口 + 右侧区域承载；原版 CSS 复用 | 差异 |
| H8 | 宿主没有 DSH 的 HMR | 插件更新原来只能停用/替换/重启 | 新增 `plugin.system.reload`：停后端、清模块缓存、重载、重挂操作；仍是显式操作，不是文件监视 | 已补（显式重载） |
| H9 | 宿主没有稳定的模型目录服务 | 原来只能导入内部 `ModelStore` | 新增 `plugin_system/model_catalog.py`；插件只依赖 `model_catalog` 服务 | 已补 |
| H10 | 宿主没有 `deliverables/presented` 事件 | 宿主工具结果原来只有 `artifacts`，通用 channel runtime 却已在消费该事件 | 内核和子代理在工具产物产生后发出 `deliverables/presented`；通道按路径去重后投递 | 已补 |
| H11 | 宿主没有 preset `serviceFor`（如 compaction） | 预设原来只是数据组合 | `AgentPresetRegistry.register_service/service_for`；运行器 `preset_service`；内置压缩服务 | 已补 |
| H12 | 插件工具没有逐调用会话上下文 | `ToolCall` 只有 id/name/arguments/metadata | 用 `contextvars` 标记当前 QQ 会话；失败时按当前任务反查 | 插件适配 |
| H13 | 网关重启时 `lifecycle_tasks` 可能看到已完成的旧任务 | 宿主按属性读取关键任务 | `lifecycle_tasks` 返回当前网关任务；重启替换引用 | 已处理 |
| H14 | 手动复制安装不会创建宿主 `plugin-data` 隔离目录 | 宿主安装事务负责 | 本插件数据写在自身 `data/`；正式安装仍走插件页/CLI | 说明 |
| H15 | 宿主没有可复用的聊天通道运行时 | 每个 IM 插件都要自己写会话、审批、问答、合并、流式 | 新增 `lamtools_core.channel`（`ChannelRuntime` + `ChannelAdapter` + `ChannelHost`）；QQ 插件仍保留自己的桥接层 | 已补（插件迁移待做） |
| H16 | 宿主只能托管 Python 插件后端，Node 插件没有受支持的外部进程方式 | `load_plugin_backend` 只找 `backend` 入口 | 新增 `runtime.kind=process` + JSON-RPC stdio；工具、操作、健康检查和启停都由宿主托管 | 已补 |
| H17 | 宿主没有插件密钥存储，凭据只能明文写在插件配置里 | 插件配置由插件自己读写 | 新增 `PluginSecretStore`：Windows 用 DPAPI，按插件隔离，后端通过 `context.service("secrets")` 访问；QQ 的 AppSecret 已迁移 | 已补 |
| H18 | 插件无法驱动桌面 live 会话：`operation_catalog` 的 `turn.start` 不写 live 用户消息投影，也不发 live 事件 | 目标会话回合跑了、模型也回复了，但 Sunday 没有用户消息、插件读不到最终回复 | 新增宿主服务 `live_turn_service`，直接调用 live `turn.start` / `approval.respond`；插件上下文按需取用 | 已补 |
| H19 | live `turn.resume` 按 `seq` 取“最新回合”，暂停回合记录没有 `seq`，会被后一个已完成回合覆盖并误报 `latest turn is not resumable` | 目标会话 paused 在 `ca924...`，resume 却选到已完成的 `d0a...` | 新增 `_resume_target_turn`：优先使用 `SESSION_PAUSED` 返回的 turn_id，其次从 top-level/core 投影里找真正的 paused 回合；补 4 个宿主回归测试 | 已补 |

### 第二类：移植问题（Node→Python / DSH→LamTools）

| 编号 | 问题 | 处理 |
|---|---|---|
| P1 | 原版依赖 Node SDK 与 `ws` | 用 Python 重写令牌、REST、WebSocket 网关、心跳、重连、流式与媒体上传 |
| P2 | 原版中间件是 Koa 洋葱模型 | Python 版用 `(ctx, next)` 链复刻顺序；命令与待答问题在并发守卫之前 |
| P3 | 宿主审批结果没有「拒绝后继续」接口 | 拒绝作为一次工具结果交给 `resume_question`，清掉挂起并让模型改道 |
| P4 | 提问/审批超时会留下挂起记录 | 超时/取消后同样走 `resume_question(skipped=True)` 清理 |
| P5 | 预设提示词在 DSH 是系统提示词段落 | 宿主新增 `agent_preset_prompt`，作为顶层系统提示词独立块；调用方补充上下文仍在尾部 |
| P6 | 原版设置页是 React + DSH 槽位 | 原生 DOM 页面，复用原版 `imqb-*` / `imqb2-*` 类与布局；不依赖 React 运行时 |
| P7 | 原版凭据写 `cordis.patch.yml` | 写入插件 `data/config.jsonc`；绑定操作保存后立即重启网关 |
| P8 | 扫码连接器是 UNLICENSED 的 Node 包 | 按公开端点与载荷格式用 Python 重写；未复制连接器源码 |
| P9 | 工具处理器拿不到 QQ 会话 | `contextvars` + 当前任务反查；`qqbot_send_file` 默认发回当前会话 |
| P10 | 宿主工具结果没有 `presentResult` 视图 | 按 content/error/artifacts 格式化；错误始终展示，成功按开关 |
| P11 | 大文件分片上传需要哈希与 COS PUT | 已实现 prepare/part/complete；整文件读入内存，未做流式分块 |
| P12 | 模型列表来自 DSH 的 `ctx.llm` | 改用宿主 `model_catalog` 服务；失败回退配置中的 provider/model |
| P13 | 会话持久化原本在 DSH session | 用稳定 agent 名称 + 宿主运行时状态库；`/new` 递增代际 |
| P14 | DSH 瀑布是异步的 | 宿主提示词组装是同步的；插件处理函数必须同步，返回 awaitable 会被拒绝 |
| P15 | 并发合并时原版只保留幸存者的附件 | 合并上下文会拼接所有消息的文本与附件；引用解析在合并后统一执行 |
| P16 | 原版事件是 `session/event` | 映射 `runtime.reply_delta/reply/tool.*/usage/done/failed/cancelled` |
| P17 | 原版有 `getTokenUsage`/`exportMarkdown` 但没有命令 | 插件维护会话 transcript，补 `/cost` 与 `/export` |
| P18 | 原版命令文案含 DSH 名称 | 改为 LamTools/qq-bot 名称；命令集合与分组保持原版 |
| P19 | 目标会话注入最初调 agent `turn.start` 并读 `session_store.list_messages`，与桌面 live 投影不是同一条链路 | 改用宿主 `live_turn_service` 启动/续跑，并从 live 事件总线取最终回复和审批请求；旧路径保留给没有该服务的宿主 |

### 第三类：原版也存在（不是移植引入）

## 四、架构验证结论

这次移植不只是交付一个 QQ 插件，也验证了「宿主缺什么、插件该自己做什么」的边界。结论按可复用程度排序：

### 已经沉淀为宿主契约的能力

| 契约 | 位置 | 为什么值得放在宿主 |
|---|---|---|
| 智能体预设 + 预设作用域服务 | `plugin_system/agent_presets.py` | 预设是运行配置，不是 QQ 特有；子代理、运行档、其他聊天插件都能复用 |
| 系统提示词流水线 | `plugin_system/prompt_waterfall.py` | 所有插件都需要按会话注入提示词，不能让每个插件改宿主拼装代码 |
| 模型目录 | `plugin_system/model_catalog.py` | 模型来源和默认值属于宿主，插件只应读取，不应复制配置解析 |
| 子会话压缩 / 分叉 / 历史 | `tool/sub_agent_runner.py` | 会话状态在宿主状态库，插件没有能力安全地自己复制或压缩 |
| 通用聊天通道 | `channel/` | 会话映射、合并、审批、问答、流式是所有 IM 插件的共同部分 |
| 多问题交互 | `question` 工具 + kernel 挂起记录 | 多题状态机属于内核协议，放在插件里会各写一套 |
| 外部进程后端 | `plugin_system/process_runtime.py` | 启停、健康、重启和操作代理是宿主生命周期职责，不是插件职责 |
| 每插件工作目录 | `sub_agent_runner_factory(work_root=...)` | 工作目录影响工具执行和路径白名单，必须由宿主统一传入 |
| 插件密钥存储 | `plugin_system/secrets.py` | 凭据保护属于宿主安全边界；按插件隔离，插件拿不到别人的命名空间 |
| 插件 HTTP 路由 | `plugin_system/plugin_http.py` | 鉴权、路由匹配和审批边界属于宿主；插件只声明路径和操作 |
| 插件代码重载 | `plugin.system.reload` | 停后端、清模块缓存、重挂操作是宿主生命周期职责 |
| 预设目录查询 | `plugin.system.presets.list` | UI 和工具需要统一读取宿主注册表，而不是各自解析配置文件 |
| 交付物事件 | `deliverables/presented` | 工具产物由内核统一发事件，通道/UI 不必各自扫描 `runtime.tool.finished` |

### 仍然存在、但优先级不同的宿主缺口

| 缺口 | 价值 | 当前处理 | 建议优先级 |
|---|---|---|---|
| 插件代码自动监视 | 保存文件后自动重载，不必手动调用 | 已有 `plugin.system.reload` 显式重载；没有文件监视器 | 低；避免半写入触发重载循环 |
| 异步提示词流水线 | 异步准备提示词片段 | 宿主拼装同步，异步处理函数会被拒绝 | 低；同步契约清晰，异步收益有限 |
| 预设管理界面 | 用户可视化编辑预设 | 新增 `plugin.system.presets.list` 供 UI 使用；没有专门编辑页 | 中；属于前端工作 |
| DSH 式侧栏/设置槽位 | 原样挂载其他宿主的 UI 组件 | 用导航页面 + 窗口 + 区域 + `settings` 区域承载 | 低；现有 UI 面已够用 |

### 这次实验暴露的设计规则

1. **宿主负责「状态和生命周期」，插件负责「协议和表现」。** 会话、审批、问题、模型、压缩、进程启停都应该在宿主；QQ 的 OpenID、按钮、markdown、分片上传应该在插件。
2. **缺口先分类，再决定改谁。** 同一句「没有这个能力」可能是宿主缺契约、移植写法不对，或原版本身就有边界；这次 17 个宿主问题里，13 个补成了可复用契约，1 个保留为明确差异，3 个是插件适配、已处理或安装说明。
3. **不要用插件私有实现掩盖宿主缺口。** 私有实现能跑通，但下一个插件会再写一遍；这次 preset、waterfall、model catalog、channel、process runtime、secret store 都是先补宿主再让插件使用。
4. **契约要有验收测试。** 新增的 41 个宿主测试覆盖了预设/瀑布、模型目录、子会话、聊天通道、外部进程、密钥存储、HTTP 路由和交付物事件；没有测试的「宿主能力」不算补齐。
5. **保留原版边界。** 原版默认限流不生效、白名单为空时放行、多选不生成按钮等行为被保留，并在第三类问题里标注，避免把「移植差异」误报成「宿主缺陷」。
