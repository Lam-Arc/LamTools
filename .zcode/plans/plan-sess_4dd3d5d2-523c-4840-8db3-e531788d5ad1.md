# 动画、展开逻辑、与排版优化 方案

## 目标

1. 正文按时序全量展示，不折叠
2. 思考块/工具块：开始时自动展开，结束后 3 秒自动折叠
3. 展开/折叠有轻量 CSS 过渡动画（平滑让位）
4. 工具重试时复用同一行，显示"重试中 x/X"，点击展开可查看/复制错误
5. Sub-agent 子时间线正确继承以上行为

---

## 改动文件

### 1. `core/ui/src/appServer/selectors.ts` — 正文不再被"劫持"

**改动**：`selectChatMessages()` 中 `isFinalAssistantContentItem()` 逻辑调整。当前只有最后一个 `agentMessage` 成为 `content`，前面的塞进 `parts`。改为：所有 `agentMessage` 一律进 `parts`，`content` 仅保留纯文本无工具调用场景。

`content` 仍保留一个兜底值（最后一条 agentMessage 的文本），用于无 parts 的简单问答场景。

### 2. `core/ui/src/components/ChatThread.vue` — 核心重构

#### 2a. 渲染结构合并

**删除**：
- "查看过程/收起过程"切换按钮（第 686-698 行、279-291 行）
- 独立答案区（`assistant-answer`，第 666-683 行、1056-1071 行）
- `processParts()` / `answerContent()` 中分离 body part 的逻辑

**重构**：非 timeline 消息统一用内联时间线渲染，对齐 timeline mode（第 78-276 行）：

- **直播态**：每个 part 按 `partType` 直接流式渲染（model_text 就地流式输出，工具/思考就地显示状态）
- **完成态**：始终展开所有 parts，不再有 toggle；parts 按时序依次渲染

两种态的 part 类型分发使用统一的 dispatch（当前有三份重复代码，合并为一）。

#### 2b. 自动展开/折叠逻辑（新增）

```typescript
// 响应式状态
const autoExpandedPartIds = ref<Set<string>>(new Set())
const manualToggledPartIds = ref<Set<string>>(new Set())
const partCompletionTimers = new Map<string, ReturnType<typeof setTimeout>>()

// 监听 parts 状态变化
watch(parts, () => {
  for (const part of parts) {
    if (part.status === 'running') {
      autoExpandedPartIds.value.add(part.id)
      clearCompletionTimer(part.id)
    }
    if (part.status === 'completed' || part.status === 'error') {
      // 启动 3 秒定时器
      const timer = setTimeout(() => {
        if (!manualToggledPartIds.value.has(part.id)) {
          autoExpandedPartIds.value.delete(part.id)
        }
      }, 3000)
      partCompletionTimers.set(part.id, timer)
    }
  }
})

function isPartExpanded(part: MessagePart): boolean {
  if (manualToggledPartIds.value.has(part.id)) return !collapsedByManual(part.id)
  if (autoExpandedPartIds.value.has(part.id)) return true
  return false
}
```

适用范围：`reasoning`（思考块）和 `tool_call`/`tool_result`（工具块）。`model_text` 始终可见不参与折叠。`error` 保持默认展开。

#### 2c. 重试显示（新增）

工具调用失败重试时：
- 不新增行，在当前工具行显示 `（重试中 x/X）` 
- 点击工具行展开查看最近一次错误详情
- 错误详情面板内的"复制"按钮可复制错误文本

依赖：工具 part 的 `metadata` 中需携带 `retry_count`、`max_retries`、`last_error` 字段（如后端未提供则前端仅显示"重试中"）。

#### 2d. Sub-agent 继承

Sub-agent 通过递归 `<ChatThread>` 渲染，自动继承：
- 正文内联展示（不需要改动，递归的 ChatThread 使用相同逻辑）
- 工具/思考自动展开/折叠（同上）
- 过渡动画（同上）

子时间线的 `subLineProcessCollapsedIds` 状态管理保持不变。

#### 2e. 清理

- 移除 `processSummary()` 调用（不再需要"查看过程"汇总文本）
- 简化 `isProcessExpanded()`（始终返回 true 或直接移除）
- `processParts()` 移除 body part 过滤逻辑

### 3. CSS 动画 — `core/ui/src/styles/layout.css` + `ChatThread.vue` scoped

**展开/折叠过渡**（工具卡片体、思考块体）：

```css
  opacity: 1;

              padding 0.28s cubic-bezier(0.2, 0.8, 0.2, 1);

.tool-card-body--collapsed,

  max-height: 0;
  opacity: 0;
  margin-top: 0;
  margin-bottom: 0;
  padding-top: 0;
  padding-bottom: 0;
}
```

**实现方式**：将当前的 `v-if` 切换改为始终渲染 + CSS class 切换（或 `v-show`），确保过渡动画生效。

**重试状态动画**：
```css
.tool-retry-indicator {
  animation: retry-pulse 1.2s ease-in-out infinite;
  color: var(--orange);
}
@keyframes retry-pulse {
  0%, 100% { opacity: 1; }
  50% { opacity: 0.5; }
}
```

**`prefers-reduced-motion`**：展开/折叠过渡和重试脉冲均提供降级。

## 风险与待确认

1. **重试数据依赖**：`retry_count`、`max_retries` 字段需要确认后端是否已提供。如未提供，前端仅显示"重试中"不显示具体计数。
2. **模板重复代码**：三份 part 分发代码（timeline live、timeline completed、non-timeline completed）是否在本次一并合一？建议做，但增加风险。可先只改 non-timeline 路径。
3. **`isFinalAssistantContentItem`** 的修改需验证纯文本问答（无工具调用）场景不受影响。
4. **CSS max-height 动画**：`max-height: 800px` 为预估上限，超出内容会被裁剪。替代方案是用 JS 计算实际高度后设置 `height`，但复杂度更高。800px 覆盖绝大多数场景。
