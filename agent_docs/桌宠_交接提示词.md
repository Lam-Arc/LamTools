## 提示词正文

你在 `E:\LamTools` 这个 Sunday 项目里继续做「Sunday 桌宠」。桌宠功能已经有大量实现，**不要重新设计、不要重写已有模块**，你的任务是让它稳定跑起来。

### 0. 绝对红线

1. **不许结束、重启、覆盖 `E:\setuptest\constant\lamcore.exe`**。那是用户正在使用的 Sunday，也是当前会话的宿主进程，杀了就断线。
2. 只允许操作你自己启动的开发实例：进程名 `Sunday.exe`，路径必须在 `E:\LamTools\core\desktop\src-tauri\target\debug\`。动手前先查路径：`powershell -NoProfile -Command "Get-Process Sunday | Select Id,Path"`。
3. 测试一律用隔离数据：临时 `LAMTOOLS_HOME` / `LAMTOOLS_CORE_DATA_DIR` / `LAMTOOLS_PROJECTS_ROOT` + 随机端口。`core/ui/tests/pet-isolated-e2e.test.ts` 已经是这么做的，照它抄。
4. 不向用户要素材、不向用户要视觉确认。素材自己找（许可要干净），界面好不好看留给用户判断。

### 1. 现状

- 桌宠是独立覆盖窗口：`core/desktop/pet.html` + `src/pet.ts`，逻辑在 `core/ui/src/pet/**`，系统能力在 `core/desktop/src-tauri/src/pet/{mod,platform}.rs`。
- 渲染：Canvas 2D（静态图/序列帧/图集）+ Three.js（glTF/GLB/VRM）+ 内置方块人（Minecraft 皮肤网格，程序化骨架）。
- 交互：Ping 轮盘、框选标注、流式会话卡片（复用 `MessageView`）、桌宠气泡（真实审批/提问）、两套会话绑定、多桌宠、物理/地形/A*。
- 测试现状：`cd core/desktop && npm run pet:verify` → 105 条通过。Rust：`cargo test --bin Sunday pet::` → 4 条。
- 文档：`agent_docs/sunday_pet_v1.md`（架构、参数、格式、缺口、风险），`agent_docs/02_Sunday_桌宠_V1.0_功能清单_已填写.md`（逐项真实状态）。

### 2. 必须先修的两个故障（用户实测反馈）

**故障 A：点击托盘「打开桌宠」后整个应用无响应，窗口也不能拖动。**

已知信息：
- 托盘菜单项在 `src-tauri/src/main.rs` 的 `setup_tray`，事件在 `handle_tray_menu` 的 `TRAY_PET_ID` 分支，直接调用 `pet::pet_overlay_open(app.clone())`。
- `pet_overlay_open` 里会 `WebviewWindowBuilder::new(...).build()` 建一个横跨虚拟桌面的透明置顶窗口，然后 `place_overlay`、`set_ignore_cursor_events(true)`、`platform::configure_overlay_window`、`show()`。
- 症状是"卡死"，不是报错，所以优先怀疑主线程阻塞/死锁，而不是逻辑错误。

排查顺序（按这个来，别乱猜）：
1. 在 `TRAY_PET_ID` 分支、`pet_overlay_open` 内部关键点加 `eprintln!`，用 `npm run pet:dev` 跑，点托盘后看终端停在哪一行。日志同时写到 `core/desktop/.lamtools/background/*.out.log`。
2. 若停在 `build()`：改成不在菜单事件里同步建窗。把调用挪到主线程队列：
   ```rust
   let app_handle = app.clone();
   std::thread::spawn(move || {
       let _ = app_handle.run_on_main_thread(move || {
           if let Err(e) = pet::pet_overlay_open(app_handle_for_main) { eprintln!("[pet] {e}") }
       });
   });
   ```
   或者更简单：菜单里只 `app.emit("pet://open-requested", ())`，由主窗口前端收到后再 `invoke('pet_overlay_open')`（IPC 线程建窗，不占 UI 线程）。
3. 若 `build()` 通过、停在 `configure_overlay_window`：`SetWindowDisplayAffinity` 需要窗口已创建完成，加一个 `std::thread::sleep(120ms)` 或等 `page load` 回调后再调用。
4. 若窗口出现了但仍然卡：检查轮询线程 `poll_loop` 是否在 `set_ignore_cursor_events` 上反复翻转（`cursor_inside` 抖），加节流：状态稳定后 500ms 内不再改。

**故障 B：主窗口不可拖动。**

- 主窗口是 `decorations:false` + 自绘标题栏，拖动依赖前端 `data-tauri-drag-region` 或 `startDragging()`，权限来自 `tauri.conf.json` 的 `core:window:allow-start-dragging`。
- 用 `tauri.pet-dev.conf.json` 启动时，**该文件里的 `app.windows` 会覆盖基础配置的窗口定义**，如果覆盖项丢了必需字段（label、transparent、minHeight…），自绘标题栏的拖动行为会失效。
- 修法二选一：把 dev 配置里的 `app.windows` 整段删掉，只保留 `productName` 与 `identifier`（推荐，让窗口定义完全走基础配置）；或者补齐字段并确保 `label` 仍是 `"main"`。
- 验证：拖动标题栏能移动窗口，双击标题栏能最大化。

### 3. 打开桌宠的三种入口（都要能用）

1. **托盘**：右键托盘 →「打开桌宠」。修好故障 A 后必须可用。
2. **CLI**：给 `main.rs` 加参数解析，`Sunday.exe --pet` 启动时自动打开覆盖层（后端就绪后再开）。实现建议：在 `setup` 里读 `std::env::args()`，命中 `--pet` 时置一个标志，等 `start_backend` 成功后调用 `pet_overlay_open`。这样可以用命令行一条命令验证「窗口能不能建出来」，不依赖点击托盘。
3. **自动恢复**：已有 `pet_autostart`，当 `{lam_home}/pet/config.json` 里 `enabled=true` 且 `pets` 非空时，主窗口启动后会调它。首次运行没有配置，所以必须靠入口 1 或 2 打出第一只。

### 4. 自动化：WebDriverIO

目标：用脚本验证「能启动、能打开桌宠、能点托盘/命令、窗口存在、页面无报错」，不依赖人眼。

Tauri v2 的标准做法：

1. 安装 `tauri-driver`（cargo），以及 `msedgedriver`（与系统 WebView2 版本匹配）。
2. 在 `core/desktop` 的 devDependencies 里加 `webdriverio` 与 `@wdio/cli`。
3. 用 `tauri-driver --native-driver <msedgedriver.exe>` 起 WebDriver 服务（默认 4444）。
4. `wdio.conf` 的 capabilities 用 Tauri 形式：
   ```js
   capabilities: [{
     maxInstances: 1,
     'tauri:options': {
       application: 'E:\\LamTools\\core\\desktop\\src-tauri\\target\\debug\\Sunday.exe',
       args: ['--config', 'tauri.pet-dev.conf.json', '--pet'],
     },
   }],
   ```
5. 断言顺序：`browser.$('#app')` 存在 → 主页面无 `[error]` 级 console → 桌宠覆盖层窗口出现（用 `browser.getWindowHandles()` 数窗口，或直接截屏存证）→ 桌宠页面里 `document.querySelector('[data-region="pet-stage"]')` 存在 → 预览器能打开。
6. 覆盖层是**另一个 webview 窗口**，切换窗口用 `browser.switchToWindow(handle)`；它没有 DOM 截图意义（透明），断言元素存在与 `console` 干净即可。
7. 不要用真实后端跑对话（会花用户额度）。会话链路已有隔离 E2E 覆盖，WebdriverIO 只验 UI 启动面。
