## 一、做法（最朴实版·按用户口径修正）

**展示位不换**：官网现有的那块展示位（真实界面实时预览 + 模拟数据）保留，只做两件事：

1. **更新 UI**：展示位挂的是真实的 `core/ui`（`preview.html` + `src/preview-main.ts` 里的 `LamToolsApp`），把它更新到当前版本——组件、样式、布局都跟产品一致，不再停留在旧的一版。
2. **更新模拟数据**：模拟数据改成下面三个场景（编码 / 办公 / 日常），按真实的 `CoreMessage` / `MessagePart` 形状驱动；场景之间用切换（换数据，不放动画）。

原则不变：**不加动画、不做编排图形、不手绘仿造**——展示位里出现的每一处都是产品自己的界面。

## 二、三个场景的内容

| 场景 | 用户那句话（界面里显示的原话） | 界面里要看得见的过程 | 结果 |
|---|---|---|---|
| **编码** | 在当前目录创建 game/index.html：一个单文件、双击就能玩的经营建造小游戏 | 读项目目录 → 写 js/sim.js 等真实文件 → 真实工具行 → 答案里的真实源码 | 一个小游戏工程（真实文件树 + 真实游戏画面） |
| **办公** | 资料库里有 8 月的经营复盘，照那个格式把 9 月的也做一份，做完存回资料库 | 读 8 月口径 → 核算 9 月明细 → 出 11 页复盘与汇总表 → 登记进资料库 | 真实 11 页 PPTX + 真实汇总表，落进资料库对应层 |
| **日常** | 帮我把这个软件装到 D 盘（下载到 D:\…）＋ 帮我看一下邮箱，把需要回的挑出来 | 搜索/下载 → 落到 D 盘指定目录 → 校验；读邮件 → 分类 → 起草回复 | D 盘上的真实文件（路径与体积）+ 邮件分类与草稿（真实界面呈现） |

- 编码 / 办公两条链路，素材已在（演示实例真跑过、产物真实）；出图即可。
- 日常类准备两条子场景（下软件到 D 盘、管邮箱）：
  - **下软件到 D 盘**：在隔离演示实例的工作目录里真跑（下载到该实例的 D 盘路径），用真实工具行与真实文件结果；
  - **管邮箱**：演示实例没有真实邮箱，界面用真实形状的数据呈现（邮件列表/分类/草稿），并在文案里只承诺"能管邮箱"这一能力，不编造真实收发记录。
