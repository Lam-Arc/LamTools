# dsh-qwen-paint 拆解与可借鉴清单

调查对象：https://github.com/wonderandyou/dsh-qwen-paint
调查时间：2026-11-10，仓库版本 0.1.2，MIT，84 星，6 次可见功能迭代共 17 个提交，最近一次推送 2026-10-08。
代码体量：host 半边 1384 行，client 半边 1747 行，自测 1192 行，安装与打包脚本约 1000 行，纯 JS 无构建。

## 一句话结论

这是个把本机 ComfyUI 包装成对话工具的 DSH 双半插件，功能简单但工程手法成熟：安装留了兜底路径、可选能力全部失败软着陆、关进程有两道识别闸、打包前扫隐私、自测用假宿主把整条链路真跑一遍。它的前端部分则是靠操作宿主 DOM 硬凑出来的，105KB 客户端里躺着二十多次"第 N 次修正"注释。另外我从源码里查出 4 个真实缺陷，其中一个让文章里主打的「A 卡零配置」整条路线实际不生效。

关于出图质量，读完第二节能得到一个不太直觉的结论：它没有任何画质闸门，画面质量全靠用户措辞加一个 8B 文本编码器，工作流参数全部写死。它真正做扎实的是保证这一张就是这次要的那一张。

## 一、它怎么运转

一条出图请求的完整链路，每一步都能在源码里对上：

1. 用户说"画一只柴犬"，模型调 `draw_image`，参数走标准 JSON Schema，定义在 `lib/index.js:919` 起。
2. 工具一进来就先记一次活动时间，堵住"空闲计时器正好在这一刻把后端关掉"的时间窗，`lib/index.js:952`。
3. 探活，不通就后台隐藏启动 ComfyUI。启动绕开 bat、直接用 `python.exe -WindowStyle Hidden`，因为 bat 里有一句 `start http://127.0.0.1:8188` 会弹浏览器，`lib/index.js:269-395`。
4. 组装工作流。文生图与图生图两套节点，图生图要额外给编码节点塞 vae、把参考图挂到 `images.image_1`、latent 取该节点第 2 号输出并删掉空 latent，`lib/index.js:644`。
5. 有参考图就先走 `/upload/image` 上传。理由是 ComfyUI 的 input 目录可能被 `--input-directory` 改过，自己复制过去会放错地方，`lib/index.js:703`。
6. 提交 `/prompt` 拿 prompt_id，轮询 `/history`，超时、取消、执行错误三种失败分开报，`lib/index.js:759`。
7. 取图**先走 `/view`**，本地目录只做兜底。这条是事故换来的：两个 ComfyUI 实例的 SaveImage 编号都从 00001 开始，旧目录里的同名文件会被当成这次的成果，`lib/index.js:819` 有完整复盘。
8. 落盘前读 PNG 头校验尺寸，请求 832x1216 却拿到 992x992 当场报错，不静默产出错图，`lib/index.js:848`。
9. 落盘到桌面「千问1生图」，回绝对路径，同时 append 一条 `deliverables/presented`，客户端另有一张自绘卡片负责渲染。

## 二、生图质量到底由谁保证

先给结论：它不保证画面好看。它保证的是三件工程事实：拿到的是这一次任务的图、宽高等于请求值、一次只出一张且种子可复现。画面质量被完整地交给三样东西：用户自己的措辞、Qwen3-VL 8B 那个文本编码器的语言理解、一套写死的 25 步工作流。

### 1. 提示词写法，全部内容就一句配方

唯一指导是参数说明那一行，`lib/index.js:865`：建议写成一段完整、具体的话，主体 + 外观细节 + 环境 + 光线 + 风格 + 画质词。README 第 106 行原样复述了一遍。

要注意这句话写在哪里：它在**参数说明**里，模型决定填参数时才读得到。而常驻的 systemPrompt 两条段落里一个字都没提怎么写提示词，反而明确禁止斟酌，原文是"不要先写分析、不要先列参数""不要长篇分析画什么风格、用什么构图、参数怎么设"，`lib/index.js:1117-1132`。

所以真实链路是：用户原话，模型回一句极短的话，直接进提示词框。没有改写、没有扩写、没有二次反查。用户说"画只猫"，进模型的提示词就是"画只猫"这个量级。这是它质量上限的第一个约束。

### 2. 工作流参数，一个都不给模型调

`buildWorkflow` 里能动的只有提示词、宽高、步数、种子，其余全部固定，`lib/index.js:644-700`：

- cfg 写死 1.0。这一条直接决定负面词是死的：KSampler 的 negative 接的是同一个编码节点的第二号输出，cfg 等于 1 时引导项退化为纯条件项，负面词不参与计算。作者没有掩饰，参数说明里就写着"负面词基本不生效，一般别填"，`lib/index.js:891`。这是这批量化权重应当用的设置，不是 bug，但等于主动放弃了最常用的净化手段。
- 采样器固定 euler 加 simple，步数默认 25，夹在 1 到 60 之间，`lib/index.js:679`。
- 出图尺寸由 megapixels 推算，1MP 就是 992x992，按 32 对齐。这是拿分辨率换速度，8GB 显存上几乎是唯一选择。
- 编码节点的 resolution 在文生图时写死 1024，不跟画幅走；只有图生图时才换成宽的高的几何平均，`lib/index.js:657`。也就是说出 1344x736 的 16:9 时，编码器仍按 1024 的尺度理解画面。
- 没有二次放大、没有高清修复、没有 LoRA、没有构图或姿态控制。工作流照抄主人机器上跑通的那份，作者的原则是节点与连线一个字不改，`lib/index.js:634`。

### 3. 结果层只有一道尺寸闸，没有画质闸

- 取图先问 ComfyUI 要 `/view`，本地目录只做兜底，`lib/index.js:819`。这条不是画质问题，它救过一次"把昨天的旧图当成这次成果"的事故，性质上属于交付正确性。
- 读 PNG 头核对宽高，不符当场报错，且只对文生图做，因为图生图的输出尺寸本来由公式决定。
- 只取第一张，代码层强制 `slice(0,1)`。
- 没有任何判断"这张图是不是废图"的逻辑。作者自己在 README 里给 A 卡划了红线：可能静默出错，跑完必须人眼看图。真正的质检闸是人的眼睛。

### 4. 三个影响观感却被放掉的点

- 配方里的"画质词"是 SD1.5 时代的习惯。这款模型的文本编码器是 Qwen3-VL 8B，吃的是自然语言写实的场景描述，堆 masterpiece、8k 这类词基本是在浪费编码预算，拉开差距的是光线、镜头、材质、氛围这些具体名词。插件没有教模型这件事。
- 负面词既然无效，干净的做法是把它从参数表里删掉，把"不要出现什么"反写进正面描述。现在留着一个开关又写着别用，属于半措施。
- 它的模型很擅长中文文字渲染，但工具描述、参数说明、系统提示三处都没有一句"画面里要有文字就把字形和位置写清楚"。这是白白丢掉的能力。

### 5. 有一处它做对了，而且正好是质量相关

种子。默认随机，但会随结果返回，也写进结果文本里，README 还专门教用户说"用同样的种子再画一遍刚才那张"。这是唯一一条真正让用户能逐步逼近期望画面的机制：固定种子、微调措辞、看差异。相比之下"一次只生一张"砍掉了并排挑选的可能，两条规则实际上在互相摩擦。

### 6. 如果要做同一件事，这一段我会怎么改

- 提示词展开放到调工具之前，一次轻量改写就够，把"画只猫"补成主体、动作、环境、光线、镜头、风格六段。它现在禁止这一步，等于把提质空间关掉了。
- 编码分辨率跟着实际宽高走，成本为零。
- 既然 cfg 恒为 1，就把负面参数从 schema 里删掉，避免模型误用。
- 加一道极轻的废图检测：文件过小、解码后接近纯色或全黑，自动重试一两次再返回。这比让人眼看图便宜得多。

## 三、值得直接学的 7 个做法

### 1. 插件本体零外部依赖

不 import 宿主自带的工具包，自己把参数写成标准 JSON Schema。理由是插件加载失败会让整个宿主起不来，这个代价太大，`lib/index.js:8-16`。对我们写宿主侧插件同样成立：依赖越少，装坏的概率越低。

### 2. 可选能力全部失败软着陆

systemPrompt、webServer、ctx.effect、ctx.inject、样式注入、菜单挂载，每一处都单独 try/catch 后 warn，失败只降级不加崩。注释里写得很直白：宿主缺服务时插件必须照常出图，只是少个状态点。`lib/index.js:1088-1100` 与 `lib/index.js:1220-1240`。

### 3. 空闲关停的三道闸

要求是"五分钟不生图就关掉后端"，实现上过了三道关才动手：计时起点只在出过图、预热确认在线、用户改档位这三种时候设定；到点先确认后端在线且 `/queue` 为空，有任务就续期；最后只杀"监听该端口且命令行同时含 comfy 与 main.py"的进程，认不出来就跳过，绝不按端口盲杀。`lib/index.js:500` 与 `lib/index.js:531`。宁可留着占显存也不误杀别人的进程，这个取舍值得抄。

### 4. 安装脚本的备份、验证、回滚

改 profile 前先备份 package.json 到时间戳目录，改完**真的 import 一次插件入口**，ESM 语法错和依赖解析失败当场暴露，复核不过自动回滚，且绝不重启宿主。`scripts/install.mjs:56`。这套顺序可以直接搬到我们的插件安装器上。

### 5. 打包前的隐私扫描与逐字节复核

打包脚本先扫"本机用户名、真实用户目录、临时目录、会话路径、疑似 Key"，带尖括号的占位符放行；然后 `node --check` 全量语法检查；压缩后解压到临时目录逐文件比字节数；最后打印 SHA256。任一环不过就不产出 zip。`scripts/pack.mjs:113-199`。

### 6. 自测用假宿主真跑链路

263 条断言，不需要真 ComfyUI、不联网、不占显存：起一个假 ComfyUI HTTP 服务器，配一个假 cordis 上下文，把探活、提交、轮询、取图、落盘、交付事件整条链路真跑一遍。客户端半边更巧，用 `new Function('window','document', code)` 当沙箱，喂假 window 和假 document，再用假 React 把组件函数调一次，直接断言渲染出来的 vnode 里有没有 `img`、src 是不是 `api/file?path=`。`scripts/selftest.mjs:277-460`。这套手法让我们不用启动整个应用就能验前端行为。

### 7. 用 systemPrompt 段落约束模型行为

出图后必须内联展示、识别到生图意图第一个动作就调工具、一次只生一张、思考过程保持极简，这四条都写在 `systemPrompt.section` 里并给了 order 9100 与 9101，紧跟内核自带的成果引用段落。`lib/index.js:1096-1130`。把"模型该怎么做"从工具描述里提到系统提示层，比指望模型读懂 description 稳。

## 四、查出来的 4 个真实缺陷

### 缺陷 1：`fs` 没导入，A 卡零配置路线是死的（严重）

`lib/index.js:43` 只导入了 `promises as fsp, readFileSync, writeFileSync`，而 `isAmdSetup()` 用的是 `fs.existsSync`，`readAmdMarker()` 用的是 `fs.readFileSync`。ESM 下引用未声明标识符抛 ReferenceError，两处都被自己的 catch 吞掉，结果是永远返回 false 和 null。

影响链：`setup.mjs` 装完 A 卡会给 `$DSH_HOME/qwen-paint-amd.marker` 写标记，里面有那套 ComfyUI 的三个路径和两个必需启动参数，但插件读不到。于是 A 卡用户启动的是 N 卡便携包的默认路径 `D:\ComfyUI\...`，也拿不到 `--disable-dynamic-vram` 与 `--use-pytorch-cross-attention`，而这恰好是作者在 README 里反复强调、A 卡最依赖的两件事。

能溜过去的原因很值得记：自测第 18 节对 A 卡的全部断言都是"源码里有没有这个字符串"，`scripts/selftest.mjs:903-960`，从来没有真正执行过这两个函数。字符串断言给了假信心。

### 缺陷 2：`workflowFile` 是死配置

`cordis.patch.yml:9` 明确写了「自定义 workflow JSON 的路径；留空则用内置模板」，但 `lib/index.js` 的 DEFAULTS 里没有这个键，`buildWorkflow` 也不读它。用户照着文档填了完全没反应，也不报错。

### 缺陷 3：文档漂移三处

- README 说状态指示器在 `conversation.composer.dock`，代码实际注册在 `conversation.input.right`，`lib/client.js:71` 的注释解释了原因：dock 平时零高度，注册成功但看不见。
- README 的参数表里没有 `reference`，也就是图生图这个功能整条没写进文档，只能在源码 `lib/index.js:960` 看到。
- README 说自测 138 项，实际 263 条 `check()`。

### 缺陷 4：每次启动往用户目录写一个已经没人用的动图

`prepareLoadingGif` 在每次 apply 时把 `assets/loading.webp` 复制成 `<输出目录>/_正在生成图片.webp`，`lib/index.js:70`。但注释同时说明这个动图"不再进正文"，动画已经改成客户端 DOM 实现，而客户端全文没有任何地方引用它。等于每次启动都在用户的图片目录里留下一份几百 KB 的残留，还没有清理。

另外有个低危问题：状态端点用 GET 的查询参数改配置，`?idleMinutes=` 改关停档位、`?flowStyle=` 改动画并落盘，`lib/index.js:1260-1280`。它放行了本机请求校验，但本机浏览器里任何一个页面都能用 `<img>` 打到这个端点，等于本地跨站改配置。改成 POST 加个一次性 token 就干净了。

## 五、不该学的部分：客户端 DOM 手术

`lib/client.js` 有 105KB，其中很大一块在做这些事：

- 用 `document.querySelector('[data-composer-card]')`、`[class*="flowItem"]` 抓宿主内部结构。
- 用正则匹配文字判断"这是不是思考块"，`lib/client.js:574`，再做隐藏。
- 用 `!important` 覆盖宿主布局，包括 `.dshqp` 之外的 `[data-composer-card]{padding-top:6px!important}`，以及一条按 `:has()` 匹配宿主根节点的规则直接改 `justify-content` 与 `padding-top`，`lib/client.js:1134` 与 `lib/client.js:1170`。
- `MutationObserver` 被 DOM 变化唤醒导致界面卡死，最后退回低频轮询，`lib/client.js:855-890`。
- 菜单被 composer 祖先的 `overflow` 裁掉，翻方向、限高、滚动全部无效，最后只能挂到 body 上自己算 fixed 坐标。

这些注释里写成"第 N 次修正"的东西，本质都不是插件作者的问题，而是宿主没给插槽、没给 API 的代价。学到的东西应该反过来用：**插槽和宿主动作 API 要先补齐，否则插件一定去啃 DOM，最后两边都买单。**

## 六、对 Sunday 的落点

### 现成的部分

"出图后把图直接显示在对话里"这条路我们已经通了。正文 Markdown 里的本地绝对路径会先经过路径恢复再渲染成图片，缺失时还会在 `.lam/artifacts` 下按同名查找，规则见 `agent_docs/file_reference_resolution.md`。也就是说这个插件最重要的一条显示通道，落到 Sunday 上成本很低，只要工具的返回值里给准路径。

### 缺的部分

`core/src/lamtools_core/plugin_system/dsh_compat/surface.json` 里，这个插件用到的三个插槽全是 `gap`：

| 插槽 | 用途 | 现状 |
| --- | --- | --- |
| `tool.call.toolview` | 给单个工具调用画一张自己的卡片，这是插件显示生成图的唯一可靠通道 | gap |
| `conversation.input.right` | 输入框工具行右侧的状态点 | gap |
| `conversation.composer.dock` | 输入卡片下方的常驻条目 | gap |

结论很直接：这类插件装到 Sunday 上，工具能跑、正文图能显示，自绘卡片和状态点会全部消失。要跑通同类插件，优先级是 `tool.call.toolview` 先做，它是 keyed 单格、语义最干净，收益也最大。

### 想抄的四件工程件

1. 进程安全关停：先认进程命令行再杀，队列非空就续期。我们后台服务、ComfyUI 集成、下载器都用得上。
2. 安装器四步：备份、改写、真加载一次、不过就回滚。
3. 打包前隐私扫描加解压复核，含"占位符放行"这个细节。
4. 假宿主自测：假服务加 `new Function` 沙箱跑前端脚本，不启动应用就能断言渲染结果。

### 一条测试纪律的提醒

缺陷 1 是被"只断言源码里有这个字符串"放过去的。我们自己的兼容层里也有不少契约文本型断言，值得抽一批改成"真的调用一次看行为"。行为验证的成本没有想象中高，这个仓库第 277 行已经示范了做法。

## 七、安全面核对

- 全部出网目标只有 ComfyUI 本机 8188、ModelScope 官方模型仓库、AMD 官方 ROCm 仓库与博客、ComfyUI 官方 GitHub release。没有中转站，源码里明确断言不许出现 `gh-proxy`、`hf-mirror` 这类镜像。
- `package.json` 没有任何 scripts，不装依赖，不存在 postinstall 钩子。
- 子进程只有 curl、powershell、python、reg、dxdiag、where，全部参数数组传参，没有拼 shell 字符串执行远程脚本。
- 模型文件带 SHA256 与字节数，校验不过一律删除；ComfyUI 本体因为官方不公布哈希，默认不自动下载。
