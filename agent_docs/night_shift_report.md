## 4. 新发现的架构问题

**P1：审批策略与权限档位被混为一谈（27 项失败的唯一机制）**

`ApprovalGate.check()` 的免问线取 `AUTO_APPROVE_LEVELS[permission_preset]`，
`permission_preset` 默认 `"ask"` → 免问线 1。而 27 个用例用
`build_core_toolbox(approval_policy="auto_approve")` 构造后，期望 tier-2 写操作直接放行。

事实：`approval_policy`（谁来回答）与 `permission_preset`（放到第几级）是两个正交维度，
当前产品行为自洽；`default_toolbox.py:1125` 那句 `auto_approve bypasses the gate` 是过时注释。

**结论：测试契约过期，不是产品缺陷。** 若改成"auto_approve 隐含档位 auto"，
等于把免问线从 1 抬到 2 —— 属于放宽安全语义，明确不予采纳。
