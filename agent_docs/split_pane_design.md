# Split Pane · 分屏设计方案

状态：已按确认方向实现首版；仅面向桌面端。旧静态示意保留为结构草案，不作为最终视觉验收图。

用户补充：“主区无需标签”“更精美（但是不要繁杂，保证视觉密度）”。主区保留原有标题栏，只在辅助分屏中呈现标签；实现使用统一外轮廓与柔和分隔，移除内部交点重复圆角。

> user:“CoreSubAgentPane，rename to **Split Pane**  分屏”——将现有子代理专用分屏升级为通用内容容器。
> user:“第一版就支持多个分屏，左右 / 上下自由组合”——第一版支持递归拆分、跨屏移动标签和布局恢复。
> user:“尽可能的精致优雅，柔和不突兀”——沿用现有主题，以内容为主，收敛边界和常驻工具。

## 1. 核心体验

分屏属于主界面。一个工作区只有一条 App Rail；主界面内部可以左右、上下拆成多块，每块有自己的标签、导航、滚动和内容状态。

典型场景：左侧保持聊天，右上查网页，右下编辑文件；也可以在聊天旁打开资料库或设置。子代理过程只是其中一种内容。

“多个界面”与“多块屏”同时支持：同一块屏能用标签切换多个界面，多块屏能同时显示不同界面。

## 2. 验收场景（实现前先编写对应测试）

1. 聊天正在回复时，从资料库入口选择“在分屏中打开”；主聊天继续更新、输入草稿不丢失，资料库独立导航。
2. 右侧分屏向下拆分后打开设置；三块屏同时存在，设置目录出现在设置分屏内部，左侧栏仍显示原聊天列表。
3. 将编辑器标签拖到网页分屏左边缘，形成左右组合；拖到网页标签栏则合并到同一块屏，草稿、滚动和网页历史保持。
4. 两块屏打开同一份文件，保存后数据一致；未保存冲突有明确提示，不静默覆盖。
5. 收起分屏只隐藏布局；再次展开恢复标签、比例及草稿。关闭子代理标签不会停止运行。
6. 缩小桌面窗口至无法容纳原布局，进入单屏聚焦并保留原布局；放大后恢复，不丢弃任何屏。
7. 全程可用键盘新增、移动、切换与关闭标签，调整分隔位置；菜单关闭后焦点返回触发位置。
8. 深浅主题、长文件名、标签溢出、加载失败、文件删除、网页无法打开和未保存关闭都有可读状态。

## 3. 入口：容易发现，平时安静

### 主入口：主界面标题栏右侧

标题栏右侧保留一个细线分屏图标，与系统窗口按钮保持距离；不占用 App Rail 的导航位置。图标默认透明，鼠标进入该区域或键盘聚焦时浮现，不加底色（第 16 节）。

点击图标只切换分屏开关：没有辅助屏时打开一块；已经展开时收起；已经收起时恢复。布局预设、聚焦、关闭整屏等低频动作移到标签栏右键菜单（第 17 节）。

第一次使用可用一行帮助文字解释“同时查看其他界面、网页或文件”，不做引导遮罩。

### 就地入口：内容在哪里，就从哪里打开

| 位置 | 动作 | 结果 |
|---|---|---|
| App Rail 中资料库、设置等入口的右键菜单 | 在分屏中打开 → 右侧 / 下方 | 相对当前屏新增对应界面 |
| App Rail 普通点击 | 原有主界面导航 | 切换主屏内容，保留其他分屏 |
| 文件或链接菜单 | 在分屏中打开 | 在最近使用的辅助屏中新增标签；不存在时向右新建屏 |
| 子代理入口 | 查看过程 | 在辅助屏打开该子代理标签；重复打开定位已有标签 |
| 每块屏标签栏的“＋” | 打开内容 | 在这块屏内新建标签 |
| 标签右键菜单 | 移到右侧 / 下方的新分屏、移到其他屏 | 不依赖拖放也能完成布局 |
| 现有命令入口 | 搜索“分屏”“向右分屏”等 | 与按钮执行相同动作 |

首版不绑定未经全局核对的快捷键，尤其不抢占现有 Ctrl+K、Ctrl+B、Ctrl+Tab。快捷键确认后统一出现在命令入口和提示中。

## 4. 屏的结构与视觉

辅助分屏只保留两层：一条紧凑标签栏 + 内容区。主区不添加标签，保留原有标题栏。辅助标签本身承担标题职责，不在上方再堆一个“Split Pane”标题。浏览器地址栏、编辑器路径和设置内页导航属于内容自身。

标签栏高 36px，使用现有字体；标签文字 12px、中等字重，标签图标 13px，头部动作图标 14–15px。标签以内容名命名，例如“资料库”“模型与供应商”“README.md”“网页标题”，类型由小图标表达。

标签属于 main 区：活动标签用主区文本色 12% 的柔和底色并保持全文色，非活动标签用 65% 文本色；不把 control 区的深色文字直接铺在主区深色底上，也不使用会形成白块的 control 软底色。不做凸起的文件夹标签、不铺满彩色胶囊，不画选中下划线。未保存文件显示小圆点；子代理保留运行、等待、失败等非纯颜色状态。

标签栏右侧常驻“＋”和“×”，左上/左下角用单层圆角 L 形角铁拖出分屏（第 17、18 节）。标签关闭按钮只在该标签激活、悬停或键盘聚焦时显示；关闭仍可通过菜单使用。标签栏右键菜单提供拆分、聚焦、移动、关闭当前屏。关闭整块屏不与关闭单个标签混用同一个按钮。

各屏继承主界面的背景和文字，不增加磨砂玻璃底色。外侧沿用主界面已有圆角；内部交点不重复画大圆角，避免四格中心出现深色花瓣或厚重接缝。整个工作区外轮廓只保留一套边框和阴影。

分隔带视觉宽 2px，命中区域覆盖相邻两侧至约 8px。平时以柔和中性色与背景融合；悬停或键盘聚焦出现短而清楚的把手，拖动时显现分隔线。交叉位置不显示额外按钮。

当前屏只在标签栏上作轻微强调；不画整屏彩色描边。所有按钮、菜单、空白状态沿用 LamTools 现有组件配方。

### 主题和动效约束

- 内容映射 main 区域；按钮与菜单映射 control 区域；地址输入等文本输入映射 composer 区域。
- 使用现有 `--theme-*`、`--space-*`、`--radius-*` 和阴影，不另建色彩系统。
- 中性悬停与选中分别使用 `--alpha-hover` 8% 和 `--alpha-active` 12%。
- 打开与关闭建议 160–200ms ease-out，先让出空间，再淡入内容；拖动分隔不加缓动，保证跟手。
- 切换标签不做滑动动画；减少动态效果开启时停用位移和布局动画。
- 键盘焦点必须可辨认；菜单按现有行高亮配方，文本输入不另加描边。

## 5. 自由组合与拖放

布局按递归二分组织：每次可把任意一块屏向右或向下拆成两块；新分隔默认居中。其他屏保持不动。默认首次从主屏右侧打开，新辅助屏约占可用主界面宽度的 40%。

拖动标签时，目标屏出现五个区域：中央为合并，四边为向左、右、上、下新建屏。预览直接描出分割后的两块区域和分隔线，不显示文字或遮罩；不铺永久十字控件。

落入中央：把标签移动到目标屏；落入边缘：带着该标签创建新屏；拖回原位或按 Esc：取消。源屏失去最后一个标签时，移除空屏并让相邻屏接管空间。首个主屏保留，最后一个内容关闭后显示对应起始页。

双击分隔带等分它连接的两个区域。布局预设重排现有屏，不删除标签；屏数不足时补空屏，超过预设格数时保留溢出屏为标签，并在执行前给出明确预览。

空屏中只显示“打开内容”，下方是“界面 / 浏览器 / 文件 / 文件树 / 子代理”的紧凑列表；不使用大插画或大块功能卡片。

### 空间约束

按实际内容区域计算，扣除 App Rail、钉住的左侧栏及其他保留空间，不直接按整个窗口宽度估算。

初始建议：聊天最小宽 420px、高 320px；一般内容最小宽 320px、高 240px；独立文件树最小宽 220px、高 240px。数值在实现时通过实际内容验证。

左右分割的最小宽为子区域宽度之和加分隔带，最小高为二者较大值；上下分割反之。新增分屏放不下时，该方向禁用并说明原因，仍可在当前屏新建标签。

已有布局因缩窗放不下时，聚焦当前屏，顶部轻量入口“查看其他屏 · 4”提供切换；保留布局树，空间恢复后自动回到原组合。用户手动聚焦则只由用户退出，不能因放大窗口自动退出。

## 6. 各类内容的呈现

| 内容 | 屏内结构 | 必须保留的体验 |
|---|---|---|
| 子代理 | 过程正文；任务与运行状态；底部资源统计 | 保留现有决策操作、过程展开、回到最新；关闭只影响显示 |
| 浏览器 | 标签栏下方为后退、前进、刷新与地址输入；再下方网页 | 每个网页独立历史；加载和错误就地显示；不能内嵌时明确提示并提供外部打开 |
| 文本编辑器 | 路径与保存状态；正文；必要的底部状态 | 未保存标识、保存失败保留草稿、外部修改提示；打开文件不自动执行 |
| 文件树 | 项目路径；可折叠目录树；轻量筛选 | 单击预览、双击固定为标签；默认在最近使用的编辑器屏打开文件；没有则在相邻屏创建 |
| 资料库 | 屏内搜索、分类和详情导航 | 不借用全局左侧栏；返回只影响当前屏 |
| 设置等 App Rail 界面 | 屏内目录与设置正文；窄时目录变成下拉 | 修改与整版界面共用数据；局部导航独立；草稿离开检查 |

所有已适配的 App Rail 页面可由统一“界面”列表打开；未适配的插件界面明确显示不可用原因，不显示无效入口。

分屏是完整内容宿主，不复制全局 App Rail、左侧栏或右侧栏。聊天的输入栏归属于聊天屏，随该屏缩放，不悬浮在其他屏之上。各屏自己的弹出菜单定位在触发控件旁；全局确认仍使用现有统一弹窗。

## 7. 导航、状态与关闭

- App Rail 高亮始终表示主屏所在界面。打开辅助屏的资料库不会把主屏标成资料库；辅助屏的身份由标签表达。
- 每个标签独立保存路由、选中项、滚动、草稿；底层项目数据、设置和文件内容共用，禁止两份相互失联的数据。
- 同一内容在同一屏重复打开时定位已有标签；需要第二份视图时，通过标签菜单“在新分屏中查看”。编辑器共享文档状态、独立光标与滚动。
- 切换主会话不清掉浏览器、文件、资料库等标签。子代理绑定原会话身份，切换后仍能查看并标明来源，不能改为读取新会话的同名代理。
- 新建屏后聚焦新内容；收起后回到主屏原焦点。Esc 优先取消拖放、关闭菜单，不直接销毁屏或草稿。
- “聚焦当前屏”临时放大；“收起分屏”保留辅助布局；“关闭当前屏”释放该屏及标签。三者文案和行为分开。
- 未保存内容关闭时，使用现有确认组件提供“取消 / 保存并关闭”；主动放弃草稿通过明确的“不保存并关闭”菜单动作再次确认。保存失败停留原屏。
- 当前屏关闭后聚焦相邻屏；最后一个辅助屏关闭后回到单主屏。运行中的子代理、任务不会因此终止。
- 同一项目恢复布局、打开内容身份和比例；临时令牌等敏感数据不作为布局存储。重启恢复时重新检查路径和访问能力，不存在的文件显示可关闭的错误标签。

## 8. 实现边界与命名迁移

不只把文件名换成 `CoreSplitPane.vue`。应拆出以下职责，避免把网页、文件和设置逻辑全塞入原子代理组件：

| 名称建议 | 职责 |
|---|---|
| `CoreSplitWorkspace` | 布局树、当前屏、尺寸约束、聚焦、恢复 |
| `CoreSplitPane` | 通用标签栏、内容承载、屏内动作 |
| `CoreSplitDivider` | 分隔拖动、键盘调整、等分 |
| `CoreSubAgentView` | 从旧组件保留子代理过程、决策与统计 |
| 各内容适配器 | 浏览器、编辑器、文件树、资料库、设置的内容与状态 |

布局描述包括：拆分方向、比例、子区域，或屏 id、标签列表和活动标签；内容通过稳定身份和类型引用。布局变化不重建正在编辑的文档或网页宿主。

现有 `fullAreaView` 只有一份全局状态，且打开整版页面就关闭子代理分屏；需改为主屏和各标签独立导航。现有单一宽度变量与固定定位仅适合一块右侧屏，应由统一布局容器负责几何关系。

CSS 与状态采用 `split-*`，主区域标识可使用 `data-region="split"`。右侧栏里的 `CoreSubAgentPanel` 继续表示子代理运行清单，不改成分屏容器。

图形操作与命令共用布局动作，后续 CLI 通过同一动作接口打开、拆分、移动和聚焦，避免出现只能点击的功能。

## 9. 落地顺序

第一版完整范围包含自由组合，不将多屏能力推迟：先写第 2 节验收测试；实现通用布局、标签、独立导航及子代理迁移；接入资料库和设置；再依次接入文件树、编辑器和浏览器。

内容接入可以逐项交付，但分屏底座从第一版就支持递归左右 / 上下组合。浏览器需先确认桌面 WebView 宿主能力，不用任意网页 iframe 作为可靠性的前提。

## 10. 首版实现与验证

- 通用宿主为 `CoreSplitWorkspace`、`CoreSplitPane`；旧子代理内容迁至 `CoreSubAgentView`，旧导入保留兼容适配器。
- 布局、内容标签、文档状态、来源聊天读取和键盘作用域分别位于 `core/ui/src/split/`。
- 主应用中的整版页面提取为 `CoreAppPage`，页面数据适配单独放入 `useCorePageBindings`，供主区与分屏复用。
- 左右 / 上下递归拆分、边缘拖放、合并标签、布局预设、尺寸拖动、聚焦、收起与恢复已接入。
- App Rail 右键菜单、标题栏分屏按钮、文件 / 链接菜单及现有搜索命令入口已接入。
- 文件树与编辑器通过独立桌面原生命令访问项目内文件；UTF-8 文本上限 4 MB，目录单次读取上限 5000 项；保存校验外部修改并保留失败草稿。
- 浏览器使用独立原生子 WebView，支持地址输入、前进 / 后退 / 刷新；菜单、模态确认、右侧栏浮卡及拖动时暂时隐藏网页宿主，避免遮挡操作。
- 来自其他聊天的子代理读取原聊天记录；提问 / 审批留在来源聊天处理，避免向当前聊天发送错误决定。历史页不包含该子代理时明确提示。
- 文件树点击文件会打开持久标签；富媒体与 Office 文件进预览分屏（图片、音视频、PDF、Word、Excel、PPT），普通文本仍进编辑器。设置等页面的内部导航保留在分屏内。
- 新增前端测试 16 项与桌面测试 2 项已通过；应用及新增测试的类型检查通过，前端生产构建通过。
- 按用户要求未使用 Computer Use，未进行实际桌面网页加载或视觉验收；当前结果不应表述为已经实机验证。

## 12. 交互与动效精修

<!-- user:“样式优化：动画、交互体验、圆角策略等”+(统一边界策略，补全标签与分隔线的细节反馈)。 -->
- 共享外轮廓沿用主区圆角，内部窗格与内容交界保持直角；标签、控件和停靠预览使用小圆角。
- 标签、按钮和分隔线使用短时缓出反馈；内容轻淡入，停靠提示淡入并平滑切换目标。原生浏览器不参与内容淡入；减少动态效果时关闭所有相关动画。
- 活动标签在切换、恢复与栏宽变化后自动显露；滚轮支持横向浏览标签，到达边缘时释放页面滚动；支持中键关闭标签。
- 点击或键盘进入标签工具栏会激活对应窗格。分隔线显示抓手与调整提示，拖动保持即时响应，Esc 撤回本次拖动，退出时清理捕获和全局监听。

## 13. 辅助对话与选文功能整合

<!-- user:“价值一致就行，不必逐项功能对齐，或者你认为可以简化也完全没有问题”+(保存位置、快速理解与深入讨论分工清楚，辅助对话承接多轮追问)。 -->
- 分屏内容新增 `conversation`；入口为分屏操作菜单、内容菜单和搜索命令。主区保持无标签，辅助对话可以移动、拆分及恢复。
- 每个辅助对话复用独立 Workbench 与独立认证连接，沿用正常会话的持久历史、流式回答、停止/继续、审批和历史翻页。创建后使用现有会话查询、继续及导出能力，不另建聊天数据库。

- 标记仍负责保存原文位置和已有结果；旧问答完整保留。选文及其已有结果作为独立附加信息传递，问题正文与辅助会话自身历史保持清晰。

- 本轮新增 13 项前端测试及 260 / 360 / 620px × 300 / 700px 的无界面布局检查；包括引用折叠后仍保持真实来源偏移的验证。验证以模拟运行时和静态布局夹具为限，未实际请求模型或操作桌面应用。

## 14. 主聊天助手与 consider 只读能力

<!-- user:“做成真正的“主聊天助手””“工具组可以用consider模式（只读）”“选中以一个“附加信息”传入”+(来源上下文由服务端读取，选文独立传入，写入能力在执行层阻断)。 -->

- 验证覆盖真实数据库绑定与读取、模型请求组装、来源刷新、只读工具箱、长消息分页、审批/队列恢复及前端问题与附加信息分离；仅运行本轮新增相关测试，未请求真实模型或进行桌面操作验收。

## 15. Blender 式拖拽分屏与标签栏收敛（已由第 17 节修订）

<!-- user:“其实主要要调整的是交互方式以及动画...希望是：1. 能够通过单个“加号”...在分屏内选择分屏类型和标签页，并在旁边添加一个“加号”来添加标签页。2. 拉起其他分屏的时候...通过拖动拉起，而不是点击按钮。就类似 blender”+(分屏手柄可拖拽，加号只加标签，低频动作移出常驻按钮)。 -->

## 17. 分屏入口最终收敛：标题栏开关 + 角柄拖拽

<!-- user:“只有在主区的右上角会有那个分屏键，那个分屏的意思是打开分屏和折起分屏...其他的分屏怎么开呢？是像 Blender 一样从分屏的角进行拖拽，来起一个新的分屏。比如这是一个正方，这是一个矩形，摁住它的边是调整它的范围，摁住它的角是出现一个新的分屏，对于分屏的右上角，只需要留一个加号来新增标签页即可，一个 x 来关闭此分屏，不需要再有一个分屏键了”+(标题栏只做开关；辅助屏头部只留加号与关闭；拆分从角部拖拽)。 -->
- 标题栏右上角的分屏键是唯一的“分屏键”：平时透明，鼠标进入该区域才浮现，无背景；点击打开 / 收起 / 恢复分屏，不再弹菜单、不再创建额外分屏。
- 辅助屏标签栏右上角只保留两个按钮：“＋”在当前屏新增标签页，“×”关闭整屏（沿用未保存内容的关闭确认）。原先的独立分屏键/方向菜单从面板头部移除。
- 每个辅助屏有两个可见角柄（左上、左下，和 Blender 的可见角柄一致），造型是单层圆角 L 形角铁（用一条 SVG 遮罩画两条外沿线，无内斜线或填充；左下由同一路径旋转 90° 得到）；右上角只放 ＋/×，右下角保留一条短的无可见柄动作区。按住角柄朝屏内拖：主拖动轴决定左右/上下分割，起始角决定新屏贴哪一侧，分割线位置跟随鼠标（指针到该侧边的距离），有最小尺寸限制；向外拖不触发。预览直接描出分割后的两块区域和分隔线，不显示文字或遮罩；松手落屏，Esc 取消。底部角柄在原生网页宿主下会被网页盖住，顶部角柄始终可用。
- 分隔带仍然只负责调整相邻区域范围：视觉线保持贯通，但只有中段约 10px 宽的命中带接收拖动；顶部标签栏区域和两端 18px 角区不参与缩放，留给角柄拉屏。悬停/聚焦显示抓手，拖动即时跟手，双击均分，Esc 撤回。
- 标签栏右键菜单保留布局预设、聚焦、收起、关闭整屏等低频动作，也是键盘/精确操作的兜底入口。
- 测试覆盖：标题栏开关的打开/收起/恢复、头部只有加号/关闭、左上角柄拖拽落屏、起始角决定新屏方向、分隔线中段命中区，以及角柄真实排版预览与入场动画。
- 角柄拖到相邻兄弟分屏上时两块区域同时描边，松开合并；分隔线右键提供合并/交换；Ctrl 拖动分隔线按 1/12 吸附。
- 左下角铁显式 `pointer-events: auto` 并抬到输入栏（`--z-composer`）之上，避免被聊天输入栏或内容层盖住导致拖不动；右下无可见柄的动作区仍留在内容层下方，避免抢输入栏按钮。
- 尚未实现 Blender 的 Shift 联动对齐、Shift 新窗口、区域右键分割位置指示线和角拖分割+合并/替换；这些是后续可选。
