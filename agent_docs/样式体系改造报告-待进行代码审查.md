## 一、结论

三批改造已全部完成并自测通过。核心变化是把散落的按钮、开关与动效收成基础件，把四份大文件按区域拆开，把令牌补齐，并让图表跟随明暗模式。代码减了六千五百多行，功能面不再各自重写几何与配色。

自测口径：类型检查三套配置通过，构建通过，直接受影响的十个测试文件二百零五项通过；全量测试与改动前基线逐项对比，失败数量未增加。

## 八、需要人工确认的视觉变化

1. 次要按钮统一为 32 像素高、13 号字；引导向导按钮原为 34 像素，现在与全站一致。
2. 权限开关由自绘按钮换成统一开关，轨道外观改变，文案仍在行内。
3. 纯文字按钮的配色改由基件负责，只有成果面板保留本区取色。
4. 聊天里的图表在浅色主题下变为浅色；切换主题时会原地重渲染，可能有短暂重绘。
5. 焦点环颜色仍为品牌蓝，只是改为令牌取值，观感应无变化。

以上五点建议在四套主题、深浅两种模式下各走一遍，重点看设置页、成果面板、消息区图表。

## 九、未合并的边界

空态、卡片、列表行没有强行合并。它们在不同区域分别是横排提示、居中说明、虚线卡片与列表行，意图不同，合并会改版面，而本轮没有运行时截图可验收。已在样式说明书与 wiki 词条的“已知问题”中记录。

## 十、审查建议清单

1. 核对 `sunday-controls.css` 的按钮基件是否覆盖了所有既有场景，特别是危险按钮的禁用态。
2. 核对设置页权限开关的交互：整行可点、禁用时不可切换、危险预设下的文案。
3. 抽查三个拆分组件的样式顺序是否与拆分前一致，可对比 `git diff` 中被删除的原文。
4. 抽查图表在浅色主题下的可读性，以及切换主题时的重渲染。
5. 确认删除的组件导入确实没有隐蔽调用，尤其是附件托盘与附件卡。
6. 确认测试改动没有掩盖真实缺陷，重点看设置页那七处。

## 十一、回滚方式

- 只回滚按钮：恢复 `layout.css`、`core-settings-base.css`、`sunday-controls.css` 与对应模板。

- 只回滚动效：还原四个动效文件与更新卡片。
