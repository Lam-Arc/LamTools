# 实用教程：把资料整理成一份可核对的报告

**调研报告教程**（Research report walkthrough）是一套把项目资料、网页来源和写作串起来的流程：先确认材料范围，再组织结论与证据，最后保存并验收。

| 前置条件 | 模型可用、项目中有资料；查公开信息时网页搜索可用 |
| 步骤数 | 3 |
| 相关功能 | 附件、文件读取、网页搜索、成果库 |
| 关键原则 | 每条结论都能回到来源 |

## 概述

这个例子把项目、文件读取、网页搜索、写入和成果检查串起来。以下任务是写法示例，不承诺每次模型输出完全相同。<sup>[1][2]</sup>

## 第一步：先确认材料范围

把相关文件放进项目，或添加为附件，然后发送：

> 请先列出你能读取的资料，说明每份资料大致讲什么。暂时不写报告，不改原文件。遇到无法读取的格式，直接列出来。

检查文件清单是否与预期一致。

图片或扫描件的识别条件与普通文字不同，必要时检查[附件](attachments.md)和[子代理](sub-agents.md)。

## 第二步：组织结论与证据

发送：

> 根据这些资料，按“背景、主要发现、分歧、待确认问题”列出报告提纲。每项发现标注它来自哪个文件。需要补充公开信息的地方，先列出搜索问题。

需要补充网页材料时：

- 明确要求优先原始发布者。
- 要求准确版本。
- 保存原文链接。
- 打开关键来源核对，不要只看搜索摘要。

## 第三步：保存与验收

确认提纲后发送：

> 按确认的提纲写报告，保留不确定之处，不编造数字。保存为新的“调研报告.md”，不要覆盖原资料。完成后列出保存路径、引用来源和仍未核实的内容。

核对审批中的写入路径。

打开生成文件，检查三件不同的事：

| 检查点 | 方法 |
|---|---|
| 文件能打开 | 用文本编辑器或系统默认应用打开 |
| 结构正确 | 标题、段落、引用是否符合提纲 |
| 来源可靠 | 抽查两三条核心结论能否回到原文 |

再看缺失项是否被诚实列出。

## 常见偏差

| 偏差 | 调整 |
|---|---|
| 内容太散 | 明确读者和篇幅 |
| 来源不足 | 要求补证据，不要继续润色 |
| 资料太长 | 先分主题整理，再写报告 |
| 数字对不上 | 要求标注来源并核对原文 |
| 不确定处被写得很确定 | 要求单列“待确认问题” |

## 提示

- 先列资料清单，再写提纲，最后写正文。
- 每条核心结论都要能指出出处。
- 重要的术语和限制写进项目上下文，避免长对话中遗失。

## 已知问题

- 扫描件和图片可能无法完整识别。
- 搜索摘要不能替代原文。
- 报告质量仍取决于资料质量与模型能力。
