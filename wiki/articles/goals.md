# 目标状态

**目标**（Goal）是 Sunday 给当前工作设置的一条持续完成约束。它记录“要达成什么”和“怎样算完成”，并在模型准备结束这一轮时检查是否真的达到。目标本身不执行任务，也不创建定时任务。

| 信息框 | |
|---|---|
| 类型 | 持续完成约束 |
| 入口 | 对话中的目标工具；存在活动目标时显示在输入框上方 |
| 记录位置 | 本机持久记录，绑定到会话 |
| 状态 | 进行中、已暂停、已归档 |
| 继续方式 | 回合自然结束时起新回合并追加提醒 |
| 结束方式 | 模型标记完成，或用户/模型取消目标 |

## 概述

普通任务在模型给出最终答复时结束。目标改变的是这个结束条件：只要目标还绑定在当前会话上，模型准备结束时就要先证明完成条件已经满足。<sup>[1][2]</sup>

目标解决的是“看起来做完了，其实没做完”。它不提高模型能力，也不替代检查，只是不允许在没有依据的情况下自然收尾。

## 目标的作用

目标会做：

- 保存一个明确的目标描述。
- 保存一组可观察的完成条件。
- 在模型结束回合时决定是否继续。
- 继续时自动起一个新回合，并追加一条提醒。
- 在模型标记完成或取消后停止继续。

目标不会做：

- 自动执行任务。
- 创建定时任务。
- 代替文件检查、测试结果或用户确认。
- 让模型跳过审批或权限。

## 创建后会发生什么

可以要求 Sunday 建立目标。它使用的目标工具支持以下动作：<sup>[3]</sup>

| 动作 | 作用 | 是否需要确认 |
|---|---|---|
| 创建 | 建立目标并绑定到当前运行 | 否 |
| 列出 | 查看已有目标 | 否，只读 |
| 查看 | 读取某个目标的详情 | 否，只读 |
| 完成 | 标记目标达成并归档 | 否 |
| 取消 | 结束目标 | 否 |

创建后依次发生：

1. 目标写入持久记录，并绑定到当前会话。
2. 聊天输入框上方出现目标状态条，显示目标描述与当前状态。
3. 模型在后续步骤里能看到这条目标。
4. 模型结束回合时，如果目标仍在进行中，系统自动起一个新回合。
5. 新回合追加一条独立消息：“存在目标：…… 未完成，请继续。”
6. 模型认为目标已经达成时，调用目标的“完成”动作，归档后不再继续。

目标必须属于当前会话。绑定到其他会话的目标不会在这里生效。

同一个会话中可以重新启用或继续一个目标；结束后的目标不能直接改回进行中，需要新建。

## 回合如何继续

继续的判定很简单：**回合自然结束、执行成功，且目标仍在进行中**。<sup>[2]</sup>

以下情况不会触发续跑：

- 模型调用服务报错，或供应商返回错误。
- 正在重试、等待审批或等待提问。
- 用户停止、取消或暂停了回合。

只有模型自己给出最终答复、这一轮正常收尾时，才会为仍然激活的目标起新回合。这样不会因为 API 一直失败而反复起回合。

系统不会另找模型判卷，也不会解析完成条件。它只做三件事：

1. 读取当前会话绑定的目标。
2. 如果目标仍在进行中，准备下一条提醒。
3. 起一个新回合，把提醒作为一条独立消息追加进去。

如果此时还有用户排队的消息，两者会进入同一个新回合，但保持为两条独立消息：排队消息是用户原文，提醒是系统追加。压缩上下文时只剔除提醒，不影响用户消息。

这条提醒每回合都会出现，直到：

| 结束方式 | 结果 |
|---|---|
| 模型调用“完成” | 目标归档，不再追加提醒 |
| 用户点击取消 | 目标归档，不再追加提醒 |
| 模型调用取消 | 目标归档，不再追加提醒 |

提醒消息会进入模型可见的历史，但不会进入上下文压缩的摘要输入。

## 状态含义

| 界面状态 | 含义 |
|---|---|
| 进行中 | 目标仍绑定在当前会话，完成检查会继续生效 |
| 已暂停 | 目标当前不能继续推进，需要补充信息、处理阻塞或取消 |
| 已归档 | 目标已完成或被取消，不再显示在状态条上 |

“进行中”表示目标没有被取消，不表示后台一定有一个进程在持续运行。实际执行仍受模型、工具和权限约束。

## 取消目标

点击目标条上的“取消”，或让 Sunday 取消目标，都会把目标归档。

取消目标：

- 使目标不再出现在活动目标中。
- 不会自动删除会话。
- 不会删除项目文件。
- 不会撤销已经完成的操作。
- 不会停止正在进行的单轮运行。

执行前先确认目标文字对应的确实是希望停止的事项。

## 与单次运行、清单、定时任务的区别

| 功能 | 管什么 | 什么时候结束 |
|---|---|---|
| 单次运行 | 这一轮正在做的事 | 模型给出最终答复 |
| 目标 | 这件事算不算真的做完 | 完成检查通过、受阻或取消 |
| 任务清单 | 做到第几步 | 清单被更新或任务结束 |
| 定时任务 | 什么时候自动开始 | 任务运行结束 |

目标与清单可以同时存在：清单记录步骤，目标约束结束条件。

定时任务不需要目标。目标也不会让任务在指定时间启动。

## 状态异常时

- **看不到目标条**：确认是否真的存在活动目标；已归档的目标不会显示。
- **显示内容与最近工作不一致**：检查目标描述与状态，再回看相关会话记录。
- **显示已暂停**：回到会话补充信息，或取消目标。
- **把目标条当成审批面板**：目标条不负责确认工具调用，审批在独立的审批卡中处理。
- **目标一直让运行继续**：说明完成条件还没被满足；补充证据、缩小目标或取消目标。

## 提示

- 目标只写最终要达成的事，不要把每一步都写成新目标。
- 完成条件要能被看到或检查，例如“文件已生成且包含三节内容”。
- 目标不再有意义时及时取消，避免后续轮次继续围绕旧目标推进。
- 长任务把目标与任务清单一起用：目标管结束，清单管过程。

## 已知问题

- 只要目标仍在进行中，每个自然结束的回合都会再起一个新回合；模型不标记完成时会持续循环。
- 提醒只包含目标描述，不包含完成条件；完成条件仍需模型自己对照。
- 目标描述过长时会被截断显示。
- 目标绑定会话，不能跨会话复用。

## 历史

- **2026 年 10 月**：目标结束改由模型显式标记完成；移除单独的判卷调用。
- **2026 年 10 月 22 日**：目标激活时，回合结束自动起新回合并追加独立提醒；提醒不进入压缩输入。
