# 审批

**审批**（Approval）是 Sunday 在执行受权限控制的工具调用前，请求用户批准或拒绝的交互。普通批准只作用于当前请求；“批准并信任”还会保存该精确操作的降级记录。两者都不能解除插件、MCP 或敏感路径的硬性阻断。<sup>[1][2]</sup>

| 信息框 | |
|---|---|
| 类型 | 决策交互 |
| 作用域 | 主会话与子代理会话 |
| 触发者 | 权限闸门、命令策略、工具声明 |
| 入口 | 聊天待处理面板、输入框接管区 |
| 记录位置 | [决策池](decision-pool.md) |
| 当前状态 | 启用 |

## 概述

工具调用是否需要审批，由权限闸门在调用执行前统一判定。判定结果只有三种：直接允许、请求用户决定、直接阻断。只有“请求用户决定”会进入决策池并显示为卡片；阻断不会生成可作答的卡片。<sup>[1]</sup>

审批卡与普通聊天消息分离。卡片由决策池保存和排序，回答通过持久续跑任务执行，因此断线、重启或窗口切换不会让已经接受的决定丢失。<sup>[3][4]</sup>

## 触发条件

### 操作等级

审批根据本次操作判断，不再把同一工具的全部行为归为一个等级。判定依次检查硬禁止、基础等级、已保存的信任、能力上限和免问线。<sup>[1][9][10]</sup>

| 等级 | 典型操作 | 默认结果 |
|---|---|---|
| 0 | 被禁用、声明硬禁止或写入敏感路径 | 直接拒绝 |
| 1 | 查看状态、列出内容、查询参数 | 在能力范围内直接执行 |
| 2 | 普通文件修改、构建任务 | 按权限预设决定 |
| 3 | 删除、重置、未声明等级的 MCP 调用 | 询问和自动模式需要确认 |

同一个命令入口中，查看 Git 状态为 1 级，普通构建为 2 级，重置工作区为 3 级。定时任务的列表查询与创建任务也可具有不同等级。<sup>[9]</sup>

### 权限预设

免问线表示能够自动执行到哪个等级；能力上限表示允许使用到哪个等级。超过免问线会询问，超过能力上限会拒绝。

| 预设 | 免问线 | 自动执行的等级 |
|---|---|---|
| 询问 | 1 | 1 级 |
| 自动 | 2 | 1、2 级 |
| 完全访问 | 3 | 1、2、3 级 |

| 能力范围 | 上限 |
|---|---|
| 只读 | 1 |
| 有限编辑 | 2 |
| 完全编辑 | 3 |

两个限制分别生效。“完全访问”不会把只读能力上限自动改为完全编辑。切换预设时，只有落在新免问线内的待审批操作可以自动继续；切到“自动”不会自动批准 3 级操作。<sup>[1][9][11]</sup>

### 危险命令

删除、重置以及无法静态判断的 shell 结构通常为 3 级。命令分类是一种调用前的判断，不能保证脚本或第三方程序内部没有其他行为。MCP 调用通过命令入口执行时，仍使用其声明的实际操作等级。<sup>[9]</sup>

### 精确信任

“批准并信任”允许本次执行，同时把完全匹配操作的有效等级永久降低一级：3 降到 2、2 降到 1，最低为 1。后续请求先应用信任，再比较能力上限与免问线。<sup>[10]</sup>

| 操作 | 信任匹配范围 |
|---|---|
| 本机命令、MCP 命令 | 当前项目与完整命令原文；更换参数不会沿用 |
| 写入和编辑文件 | 当前项目与目标绝对目录 |
| 网页读取 | 当前项目与目标站点 |
| 其他工具 | 当前项目、工具与具体动作 |

信任保存在统一账本中，重启后仍有效。在“设置 → 权限 → 已信任操作”中可以查看和撤销；撤销后恢复默认等级。硬禁止和当前不可用的操作不能通过信任解除。<sup>[10][12]</sup>

### 硬性阻断

硬性阻断不是“待审批”，而是不可通过点击卡片放行的限制。典型来源包括插件或 MCP 的工具声明，以及写入敏感路径的尝试。界面不会为这类调用提供批准按钮。<sup>[1]</sup>

工作目录边界自 2026-09-27 起不再作为审批阻断条件。旧配置中的相关开关仍会被读取以保持兼容，但当前实现不以工作目录限制工具访问。<sup>[2]</sup>

## 决策种类

| 决定 | 含义 | 后续行为 |
|---|---|---|
| 批准执行 | 允许当前工具调用执行 | 续跑任务继续，工具结果返回模型 |
| 批准并信任 | 批准本次并将精确操作永久降一级 | 后续匹配请求使用保存的等级 |
| 拒绝执行 | 不允许当前工具调用执行 | 拒绝结果交回模型，由模型选择替代路径 |
| 其他处理方式 | 用文字说明希望怎样处理 | 文字作为引导回传模型，不视为批准 |

审批卡不提供“跳过”作为默认答案。超时也不会自动批准：审批是安全边界，只有用户或用户显式配置的权限策略可以放行。<sup>[5]</sup>

## 生命周期

审批卡遵循决策池的统一阶段：

1. **出现**：权限闸门判定需要用户决定，交互入池，卡片显示为待处理。
2. **处理中**：回答被持久续跑任务接受，卡片显示“处理中”，重复点击不会创建第二个任务。
3. **结束**：决定落库后卡片立即从池中移除；模型的后续输出不会让卡片重新出现。

若卡片所属的回合已经暂停、结束或不再持有对应的运行时请求，回答会被拒绝或把卡片标记为已取代。重复点击已经回答的卡片会返回成功并清理旧卡，不会重复执行工具。<sup>[4]</sup>

## 归属与路由

审批请求的标识由会话、运行和工具调用共同组成，避免不同代理重复使用同一个工具调用编号时发生冲突。子代理发起的审批带有自己的会话范围与投递者信息；回答按请求标识路由回该子代理，而不是默认交给父会话。<sup>[4][6]</sup>

父会话时间线上显示的子代理审批卡，仍属于子代理的决策池行。回答后，续跑任务登记在子代理会话上，两个子代理不会互相阻塞。拒绝子代理的审批会结束该子代理，而不是终止父回合。<sup>[4]</sup>

## 提示

- 批准前核对工具名称、命令文本、目标路径和请求原因。
- 重复点击同一张卡是幂等的；卡片没有立即消失时，应先确认决定是否已经进入处理中，而不是连续点击。
- 卡片消失表示决定已落库，不表示工具已经执行完成。
- 切换会话预设可能立即放行当前待审批的普通操作；逐项检查时应保持“询问”。

## 已知问题

1. 同一会话的多张审批卡按顺序展示，但续跑以会话为串行单位；回答一张后不会并行推进多个等待步骤。
2. 旧快照可能保留已经解决的历史请求记录；当前界面以决策池为准，不会把这些记录重新显示为待处理卡。
3. 工作目录外访问不再被审批阻断，因此审批卡不能当作文件系统沙箱使用。

## 历史

- **2026 年 10 月 25 日，0.3.22-a3**：改为按操作的 1/2/3 级判定；新增持久信任、设置中撤销，并补齐审批恢复。
- **2026 年 9 月 27 日**：产品决定不再以工作目录边界限制工具访问，相关字段保留兼容。
- **2026 年 10 月**：审批回答改为持久续跑任务；交互入池并获得顺序、哈希和归属字段。
- **2026 年 10 月 22 日**：回答落库即结束卡片；重复事件不能重新打开已回答的请求；子代理审批按 owner 会话路由。
