# 实用教程：安排一项重复任务

**重复任务教程**（Recurring task walkthrough）是一套把一次性任务变成定时任务的步骤：先手动做成功，再添加定时规则，最后检查运行记录。

| 前置条件 | 模型可用、项目目录正确、所需工具可用 |
| 步骤数 | 3 |
| 相关功能 | 定时任务、工作流、审批 |
| 关键原则 | 先手动验证，再自动化 |

## 概述

定时任务适合周期性的资料整理、检查和内容生成。先验证任务能手动做成，再增加定时规则，能避免每天重复同一个错误。<sup>[1][2]</sup>

本教程以“整理项目内新资料”为例。

## 第一步：先做一次

在普通会话里说明输入目录、输出位置和判断标准：

> 检查项目里“待整理”目录中的资料，生成一份清单；把尚未确认的地方列出来。不要删除、移动或覆盖原文件。

核对实际结果。

如果任务依赖登录网站、人工输入或一次性权限，先想清楚到时由谁处理。定时触发不能替你创造外部账号的授权。

## 第二步：创建定时任务

1. 打开“定时任务”。
2. 选择一次性、间隔或日历规则。
3. 填写时区、指令、项目与模型。
4. 设置较小的运行次数限制做试运行。
5. 核对页面给出的下一次运行时间。

重复执行时，指令必须处理“上次已经做过”的情况：

| 写法 | 效果 |
|---|---|
| 每次保存到新的日期文件 | 不覆盖历史 |
| 只更新指定汇总文件 | 结果集中 |
| 只处理未处理过的资料 | 避免重复劳动 |

不写清楚就可能重复覆盖、重复生成或反复整理同一批资料。

## 第三步：检查运行记录

使用“立即运行”验证配置，再检查：

- 任务历史。
- 文件结果。
- 等待事项。

记录显示“等待审批”或“等待答案”时，应按对应卡片处理，不能当成自动完成。

桌面进程退出、电脑关机、断网或外部服务故障，都可能影响执行。“保持电脑运行”只处理支持范围内的空闲休眠，不是全天候服务器保证。

## 什么时候换成工作流

| 情况 | 选择 |
|---|---|
| 一条自然语言任务就能完成 | 定时任务 |
| 需要固定多步骤、条件分支、人工审核 | 工作流 |

无论哪种形式，自动化都应有清楚的输入、输出和失败判断。

## 常见偏差

| 偏差 | 调整 |
|---|---|
| 第一次运行就覆盖旧结果 | 改为按日期命名 |
| 到点没有运行 | 检查调度器与应用是否在运行 |
| 停在审批 | 调整权限或安排人工处理 |
| 结果重复 | 在指令中加入去重条件 |

## 提示

- 先用小运行次数试跑。
- 指令里写清“不要动什么”，比只写“做什么”更重要。
- 重要任务每次运行后抽查一次结果。

## 已知问题

- 应用完全退出时，依赖应用内调度的任务不会运行。
- 自动化不会跳过审批。
