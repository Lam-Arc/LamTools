# 定时任务

**定时任务**（Scheduled task）是 Sunday 按时间、间隔或事件自动运行指令的功能。任务可以关联项目、会话和模型，并保留运行历史。

| 信息框 | |
|---|---|
| 类型 | 自动化任务 |
| 入口 | 应用侧栏“定时任务”；对话中的 `arrange` 工具 |
| 计划类型 | 单次、每天、每月、间隔、事件 |
| 时区 | 创建时选择，默认 Asia/Shanghai |
| 运行次数 | 可限制，留空表示不限制 |

## 概述

定时任务把一个可以独立执行的指令交给调度器，在指定时间或事件发生时启动。它适合日报、定期检查、重复整理这类不需要人当场补充信息的任务。<sup>[1]</sup>

定时任务仍然是正常的一次运行：模型、工具和权限照常生效，需要审批的操作不会因为“自动”而跳过。

## 创建任务

在“定时任务”页面新建任务，填写：

1. 标题。
2. 要执行的指令。
3. 计划类型与时间。
4. 关联的项目、会话与模型。
5. 可选的最多运行次数。

保存前核对触发时间、时区与指令内容。指令应当能在无人补充信息的情况下说明目标、范围和预期结果。

## 计划类型与时间

| 类型 | 需要填写 |
|---|---|
| 单次 | 日期与时间 |
| 每天 | 每天的开始时间 |
| 每月 | 每月几号与时间 |
| 间隔 | 间隔秒数 |
| 事件 | 事件类型 |

时区决定“几点”按哪里计算。把本地时间误填成另一时区，会让任务提前或延后数小时。

## 通过对话管理

除了在页面里操作，也可以直接让 Sunday 管理和查看任务。它使用的 `arrange` 工具支持以下动作：<sup>[4]</sup>

| 动作 | 作用 | 是否需要确认 |
|---|---|---|
| 创建 | 新建一个定时或事件任务 | 是 |
| 列出 | 查看当前已有任务 | 否，只读 |
| 查看 | 读取某个任务的详情 | 否，只读 |
| 暂停 | 暂时停止触发 | 是 |
| 继续 | 恢复触发 | 是 |
| 取消 | 结束任务 | 是 |

创建任务时必须能确定所属项目的工作目录；不知道时应先询问用户，而不是猜一个路径。

每次运行时可以使用当前会话，也可以新建一个会话。需要保留上下文时选择当前会话；希望每次从干净状态开始时选择新建会话。

事件触发还可以配合工作区内的观察脚本来产生事件，但需要先加载对应的观察技能，并按脚本要求配置。

## 项目、会话与模型

- 选择项目后，可以进一步选择该项目的会话。
- 尚未登记项目时，表单可能要求直接填写项目目录。
- 模型选项来自当前配置，默认使用系统首选模型。

任务运行时会沿用所选会话的上下文与权限。指令要写清“在哪个目录、做什么、不要做什么”，避免无人值守时扩大改动范围。<sup>[1]</sup>

## 查看与排错

任务列表提供状态筛选。打开任务可以查看：

- 任务设置。
- 运行历史。
- 当前可用的操作。

常见问题：

| 现象 | 先检查 |
|---|---|
| 列表为空 | 状态筛选是否过窄 |
| 保存失败 | 目录权限、必填项、时间格式 |
| 到点没有运行 | 调度器提示、应用是否在运行 |
| 运行失败 | 模型连接、目录、事件名称 |

页面出现调度器状态提示时，先处理提示，再重新刷新任务列表。

## 提示

- 让 Sunday 创建任务时，先确认它的工作目录、触发时间和运行次数。
- 无人值守的任务要把范围写死，例如指定目录和文件类型。
- 涉及写入时，在指令中要求先备份或只输出到新文件。
- 重要任务先手动运行一次，确认结果符合预期再交给调度器。

## 已知问题

- 应用完全退出时，依赖应用内调度的任务不会运行。
- 定时任务不会跳过审批，需要人工确认的操作可能导致任务停在等待状态。
