# 连接外部工具（MCP）

**MCP**（Model Context Protocol）是 Sunday 连接外部工具服务的方式。配置并启用服务后，模型可以看到该服务提供的工具，并在需要时调用。

| 信息框 | |
|---|---|
| 类型 | 外部工具连接 |
| 前提 | 服务已配置并运行 |
| 使用流程 | 启用服务 → 读取工具 → 调用 |
| 常见用途 | 浏览器控制、企业内工具、专用数据源 |
| 权限 | 调用前可能等待审批 |
| 安全责任 | 由服务提供方与应用配置共同决定 |

## 概述

MCP 服务把外部能力包装成工具，交给模型调用。Sunday 本身不限定这些工具做什么；实际能力取决于安装并配置的服务。<sup>[1][2]</sup>

服务未启用时，模型看不到它的完整工具列表。

## 使用流程

1. 在应用设置或 MCP 配置中添加服务地址、启动方式和所需凭据。
2. 在对话中提出具体目标。
3. Sunday 启用服务并读取工具说明。
4. 调用匹配的工具。
5. 根据返回结果继续或报告。

示例：

> 用已配置的浏览器工具打开这个公开网页，提取页面标题。

每个服务的工具参数和结果格式可能不同。工具名或参数不匹配时，应重新读取服务定义，不要反复猜参数。

## 权限和数据

MCP 工具可能访问网页、文件、账户或执行其他动作。

- 调用前留意审批提示、目标服务和传入参数。
- 不要把密码或 API 密钥放进普通提示词。
- 向外部服务发送文件或账户信息前，确认发送范围和用途。
- 服务端代码与其权限由提供方决定，Sunday 不能替第三方服务保证安全。

## 连接失败怎么办

| 现象 | 先检查 |
|---|---|
| 找不到服务 | 名称是否与配置完全一致 |
| 服务未运行 | 启动方式、进程与日志 |
| 工具列表为空 | 配置是否保存、服务是否发布工具 |
| 认证失败 | 凭据是否有效、是否过期 |
| 网络失败 | 代理、地址、端口 |
| 参数不匹配 | 重新读取工具定义 |

未知或不稳定的服务应先在低风险任务中试用。

## 与技能、插件的区别

| 能力 | 作用 |
|---|---|
| 技能 | 提供任务做法 |
| 插件 | 提供工具、界面与配置，可包含 MCP |
| MCP | 连接外部工具服务 |

一个插件可以带 MCP 服务，但 MCP 也可以单独配置。不要因为装了插件就认为对应服务一定已连接。

## 提示

- 先用只读工具验证连接，再使用会写入或提交的工具。
- 工具说明要读，不要只根据名字推断参数。
- 服务变更后，重新启用并刷新工具列表。

## 已知问题

- 第三方服务的可用性与安全性不受 Sunday 控制。
- MCP 工具的变化要等到压缩、新会话或重启才进入工具数组；期间调用尚未进入数组的工具，会收到“当前工具组未更新”的提示。
