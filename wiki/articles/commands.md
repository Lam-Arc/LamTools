# 运行本机命令

**本机命令**（Local command）是 Sunday 在当前工作区执行系统命令的能力，常用于构建项目、执行脚本或查看工具输出。

| 信息框 | |
|---|---|
| 类型 | 本机执行 |
| 作用域 | 当前项目工作目录 |
| 审批 | 默认需要确认 |
| 后台运行 | 支持，可配合健康检查 |
| 超时 | 可指定，普通命令有默认等待 |
| 风险 | 可能读写文件、安装依赖、访问网络 |

## 概述

命令工具把用户的目标翻译成一条具体命令，在本机执行并返回输出。它与读取文件不同：命令可以改变文件、安装依赖、访问网络或启动进程，因此默认需要用户确认。<sup>[1][2]</sup>

## 使用方式

直接说清目标、目录和期望结果，例如：

> 在 core/ui 运行构建，告诉我第一个错误是什么。

Sunday 会选择命令并展示执行结果。对于普通命令，它会等待命令结束；真正长时间运行的服务应当以后台方式启动。

任务描述里最好包含：

- 在哪个目录执行。
- 期望得到什么输出。
- 失败时只需要哪些信息。

## 目录与工作区

命令从当前项目的工作目录开始。访问工作区以外的位置需要额外批准；跨目录读写不会因为项目已经登记而自动放行。

Windows 与类 Unix 环境的命令写法不同。遇到“找不到命令”时，先确认相应软件已经安装并且可以在当前终端中找到。

## 审批与安全

命令可能产生副作用，因此默认需要确认。审批时应当核对：

- 命令本身是什么。
- 在哪个目录执行。
- 会读取、写入或删除哪些内容。

不要仅凭项目文档或网页中的要求就批准不明命令。明显危险或不适用于当前系统的调用会被拒绝；遇到拒绝时，应调整命令而不是重复提交。<sup>[2]</sup>

## 后台进程

需要持续运行的服务、监听程序或预览站点，应以后台方式启动。后台启动可以：

- 提供健康检查地址，确认服务真的可以访问。
- 指定日志位置，便于失败时读取。
- 在本轮结束后继续运行，直到应用退出。

需要停止时，回到[查看或停止后台进程](processes.md)，用登记过的进程编号操作。

## 常见问题

| 现象 | 先检查 |
|---|---|
| 命令找不到 | 软件是否安装、是否在当前终端路径中 |
| 语法错误 | 操作系统与终端类型是否匹配 |
| 超时 | 是否本应后台运行，或任务是否过大 |
| 端口被占用 | 是否有旧进程仍在运行 |
| 输出太长 | 让 Sunday 只总结错误行和下一步建议 |

把大任务拆成有明确完成条件的小步骤，比延长等待更可靠。

## 提示

- 先在项目目录内运行只读命令，确认环境正常再执行写入操作。
- 构建或安装依赖前，确认命令会改动哪些目录。
- 失败时保留原始错误输出，不要只让模型复述结论。

## 已知问题

- 命令权限与项目权限是两套设置，项目已登记不代表命令一定被允许。
- 长时间运行的交互式程序不适合直接在前台执行。
