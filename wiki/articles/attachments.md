# 附件

**附件**（Attachment）是随消息一起提交的本机文件或图片。附件在发送前会先进入待发送区，可以预览、重试上传或移除。

| 信息框 | |
|---|---|
| 类型 | 消息附件 |
| 入口 | 输入框“添加附件”；拖放到聊天区域 |
| 支持内容 | 本机文件、图片 |
| 发送前操作 | 预览、重试、移除 |
| 生效方式 | 随同一条消息一起提交 |

## 概述

附件解决“把文件带进对话”的问题。它与读取项目文件不同：附件是随消息提交的一份副本或引用，项目文件则由文件工具从工作目录读取。

选择文件后，附件先出现在输入框附近，不会立刻成为一条消息。用户确认发送后，附件才和文字一起提交。<sup>[1]</sup>

## 添加附件

两种方式：

1. 点击输入框旁的“添加附件”，在系统文件选择器中选择文件。
2. 把文件拖到聊天区域。

可以一次准备多个附件，并在同一条消息里写说明，告诉 Sunday 每个文件要用于什么。只拖入文件而不说明任务，通常得不到有用的结果。

## 检查、重试和移除

发送前可以：

| 操作 | 行为 |
|---|---|
| 预览 | 图片显示缩略图；其他文件显示类型信息 |
| 重试 | 上传失败后重新提交该附件 |
| 移除 | 从待发送内容中删除，不影响磁盘原文件 |

上传失败的卡片会标出错误状态。无法读取或路径失效时，从有效位置重新选择文件。图片预览空白但文件仍可发送，通常是本地缩略图不可用。

## 常见限制

- 附件需要经桌面端上传能力送到当前会话；应用退出或文件被移动后，未完成的上传不能依赖原路径恢复。
- 文件大小与格式是否可处理，取决于后端接收能力和模型能力；超出限制时以界面返回的错误为准。
- 照片库、相机来源属于其他平台界面，不是桌面端能力。

## 附件与图片清晰度

图片附件产生后的第一次请求以原图发送，之后的请求可能改用低分辨率副本。需要看清细节时，可以重新附加或重新读取原图。

附件是否写入会话记录，与图片在请求中的降级是两件事：记录保留原图，请求层按轮次决定发送哪一版。<sup>[2]</sup>

## 提示

- 在同一条消息里说明每个附件的用途。
- 上传失败时先重试，不要重复添加同一文件。
- 大文件优先放进项目目录，让文件工具按需读取。

## 已知问题

- 附件预览依赖本地缩略图，空白预览不一定代表文件损坏。
- 应用退出后，未完成的上传不会自动续传。
