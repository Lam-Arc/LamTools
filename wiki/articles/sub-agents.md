# 子代理

**子代理**（Sub-agent）是主代理按需创建的独立子会话，用于把范围明确的工作分开执行并把结果交回主会话。子代理有独立名称、类型、模型、思考等级、会话记录和消息邮箱；它发起的审批与提问会显示在主会话时间线上，但归属仍属于子代理。<sup>[1][2][3]</sup>

| 信息框 | |
|---|---|
| 类型 | 委派会话 |
| 作用域 | 父会话 |
| 入口 | 子代理工具、右侧 Sub Agent 列表、命令行 |
| 记录位置 | 本机持久记录 |
| 当前状态 | 启用 |

## 概述

主代理通过子代理工具创建、关闭或删除子代理。创建后，子代理以自己的名称和会话记录运行，主代理可以继续当前工作，也可以向它发送补充消息。子代理不能继续创建子代理，也不能向另一个子代理转发消息；它只能把消息交回主代理。<sup>[1][4]</sup>

子代理是主代理的受限变体：工具范围、权限、模型和思考等级由创建时的配置决定。父会话结束不自动关闭仍在工作的子代理；子代理的审批与提问也不会改变父回合的状态。<sup>[2][3]</sup>

## 创建与复用

创建参数包括动作、类型、名称、模型和思考等级。动作分为创建、关闭和删除。<sup>[1]</sup>

| 参数 | 规则 |
|---|---|
| 名称 | 小写字母开头，后续为小写字母、数字或下划线，最长 64 个字符 |
| 类型 | 调研型或执行型 |
| 模型 | 优先使用已配置模型的准确 ID；显示名称只有在唯一对应一个模型时才可用 |
| 思考等级 | 关闭、轻、中、高、极高、最大 |

同一父会话中，名称相同的活动子代理会被复用；复用要求类型、模型和思考等级完全一致。配置不一致时不会静默改写，而是拒绝创建。已关闭、已中断或失败的子代理可以重新打开，但也必须使用完全一致的配置。<sup>[2]</sup>

## 类型与配置

| 类型 | 含义 | 工具范围 |
|---|---|---|
| 调研型 | 偏调查、分析和方案比较 | 使用对应工具模式允许的工具 |
| 执行型 | 偏实际执行和交付 | 使用对应工具模式允许的工具 |

类型与[工具模式](tool-modes.md)中的同名类型对应。子代理继承父会话的权限与运行参数，但在每次运行时重新解析工作目录、模型、工具、插件和 MCP 配置，不冻结第一次创建时的环境。<sup>[2][3]</sup>

子代理不能使用子代理工具或子代理消息工具继续委派；子代理可以通过自己的消息工具向主代理发送消息。<sup>[1][4]</sup>

## 委派策略与角色

委派策略决定主代理是否创建子代理：

| 策略 | 行为 |
|---|---|
| 禁止 | 不委派 |
| 低 | 只在大范围调查或探索时委派 |
| 中 | 保持默认委派策略 |
| 高 | 先制定计划并取得用户确认，再尽量并行分工 |

全局策略作为基线，项目配置可以覆盖同名策略。角色分配按任务类型提供偏好的类型、模型和思考等级范围；这些字段是建议，不强制每次委派采用。委派指南会注入主代理的提示词，项目级指南可以覆盖或继承全局指南。<sup>[5]</sup>

## 运行状态

| 状态 | 含义 |
|---|---|
| 空闲 | 本轮已结束，记录保留 |
| 运行中 | 正在执行 |
| 已暂停 | 停在等待用户的边界，通常是子代理提问 |
| 随父暂停 | 随父会话暂停而停下，可继续 |
| 已中断 | 被停止或中断 |
| 已关闭 | 已关闭，记录保留 |
| 失败 | 运行失败 |
| 已删除 | 记录、邮箱和自身会话存储已删除 |

每个子代理的运行有墙钟租约，超过两小时会被标记为失败；看门狗每 15 秒检查一次。单个监督器最多同时运行 8 个子代理，进程最多保留 64 个监督器。<sup>[2]</sup>

## 消息

主代理向子代理发送消息使用子代理消息工具，参数为类型、名称和消息正文；该调用不阻塞主代理。子代理向主代理发送消息使用自己的消息工具。两个方向都写入持久邮箱，并按边界投递。<sup>[4][6]</sup>

消息的具体投递模式、去重和恢复规则见[子代理消息](sub-agent-messages.md)。

## 审批与提问

子代理的审批与提问进入父会话的[决策池](decision-pool.md)，卡片带有子代理名称、会话标识和投递者信息。回答按请求标识路由回子代理，而不是默认交给父会话；续跑任务也登记在子代理会话上。<sup>[3][7]</sup>

拒绝子代理的审批会结束该子代理，不终止父回合。父回合结束不自动关闭仍在等待的子代理；只有父会话暂停、恢复或终止时，状态才会按规则传播给成员。<sup>[3]</sup>

## 暂停、终止与删除

| 操作 | 对子代理的影响 |
|---|---|
| 父会话暂停 | 活动成员停下并保留可继续状态 |
| 父会话恢复 | 被暂停的成员继续 |
| 父会话终止 | 活动成员被中断 |
| 关闭子代理 | 停止当前工作，保留记录与历史 |
| 删除子代理 | 删除记录、邮箱和自身会话存储 |

关闭要求类型、名称、模型和思考等级与记录一致。删除拒绝仍在运行或等待的子代理，必须先关闭再删除；删除不会删除父会话的结果记录。<sup>[2]</sup>

## 提示

- 委派前给子代理明确的范围、交付物和证据要求，比笼统分工更容易整合。
- 同一名称复用同一份记录；改变配置时应使用新名称。
- 子代理的审批与提问属于子代理自己的运行，不应在父会话里代为回答后假定已经生效。
- 父会话停止不会自动清理子代理历史；需要释放空间时使用删除。

## 已知问题

1. 工具声明的名称规则只接受小写拉丁字母、数字和下划线；服务端名称校验还接受汉字，两处规则尚未完全一致。
2. 子代理的审批与提问会显示在父会话时间线上，但父会话的时间线并不代表答案归属于父会话；路由必须以卡片上的归属信息为准。
3. 父会话可以在子代理仍在工作时结束；此时子代理的后续消息需要等父会话再次被唤醒或进入下一回合才能消费。
