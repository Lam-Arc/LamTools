# 技能

**技能**（Skill）是可复用的任务指引：它告诉 Sunday 某类任务应该按什么步骤、用什么标准完成。技能可以在插件页管理，也可以从聊天输入框的斜杠建议中调用。

| 信息框 | |
|---|---|
| 类型 | 可复用任务指引 |
| 入口 | 插件 → 技能；聊天输入框斜杠建议 |
| 存放位置 | 桌面技能目录 `.lam/skills/` |
| 文件 | 每个技能一个 `SKILL.md` |
| 调用方式 | `/技能名` 加补充文字 |
| 是否绕过审批 | 否 |

## 概述

技能不是新模型，也不是新工具。它是一段在需要时才加载的工作指引，用来稳定某类任务的做法。<sup>[1]</sup>

例如，一个“代码审查”技能可以规定先看改动范围、再检查错误处理、最后给出按严重程度排序的问题列表。调用技能后，这段指引会进入当前工作的上下文。

## 浏览与启用

1. 打开“插件”页，切换到“技能”分区。
2. 查看当前发现的技能。
3. 按需启用或禁用。

禁用的技能不会作为当前可用能力参与调用。桌面会从 `.lam/skills/` 目录发现技能。

列表为空时，可以点击“新建技能”，或把完整的技能文件放入技能目录后重新加载。

## 创建与编写

新建技能时填写：

| 字段 | 要求 |
|---|---|
| 名称 | 简短标识，使用字母、数字、点、下划线或连字符 |
| 用途说明 | 一句话说明什么时候使用 |
| 指引正文 | 步骤、输入要求、结果格式 |

指引应写清：

- 这类任务的目标。
- 需要先确认哪些信息。
- 按什么顺序执行。
- 结果如何组织与验收。

技能内容加载后会把命令与视图纳入当前工作，因此不要放入 API 密钥、私人数据或只适用于单次工作的指令。

## 在聊天中调用

在输入框键入斜杠，从建议列表选择技能，例如：

> /review 请重点检查错误处理

规则：

- 技能可以与普通文字一起提交。
- 斜杠后的名称必须匹配已启用的技能。
- 名称不匹配时，不会自动执行某个技能。
- 技能前后的普通文本仍会作为上下文传入。

建议列表找不到技能时，检查技能是否启用、名称是否正确，以及 `SKILL.md` 是否位于可扫描的目录。

技能本身不绕过权限确认。它改变的是做法，不是权限。

## 与插件、MCP 的区别

| 能力 | 提供什么 | 是否需要外部服务 |
|---|---|---|
| 技能 | 任务指引 | 否 |
| 插件 | 工具、界面与配置 | 取决于插件 |
| MCP | 外部工具服务连接 | 是 |

技能可以配合插件或 MCP 使用，但它本身只提供说明，不提供新的可执行能力。

## 提示

- 技能名称要能让人一眼看出用途。
- 把步骤写成可核对的动作，而不是笼统建议。
- 长期有效的做法写技能，单次要求写在当前消息里。

## 已知问题

- 技能数量增多后，斜杠建议列表会变长。
- 技能内容占用上下文，过长的指引会增加请求费用。
