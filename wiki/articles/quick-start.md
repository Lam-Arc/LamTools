# 快速开始：完成第一项工作

**快速开始**（Quick start）是第一次使用 Sunday 时的推荐路径：先让模型成功回答，再让它处理一个小任务，最后核对结果。一次只验证一层，比同时打开所有高级功能更容易判断问题出在哪里。

## 概述

Sunday 的运行依赖三样东西：可用的模型服务、明确的工作目录、允许使用的工具。快速开始按这个顺序逐项确认，避免把模型问题误判成文件问题，或把权限问题误判成网络问题。<sup>[1]</sup>

## 准备模型服务

Sunday 需要可用的模型服务。用户需要按服务商的说明申请密钥，也就是允许软件调用模型的一串凭据。使用普通聊天网站的账号或订阅，并不自动代表拥有可调用的接口额度。

在首次启动的引导中：

1. 选择一个服务模板。
2. 填写密钥并保存。
3. 使用自定义服务时，填写服务地址与准确的模型名称。

模板只帮助填写常用信息，不能保证账号有权限调用其中的全部模型。跳过引导后，也可以在设置里补齐。<sup>[1][2]</sup>

## 创建项目与会话

为这次工作选择一个项目目录。初次使用建议选一个只放少量非敏感资料的练习文件夹。

创建会话后，在输入框附近确认已经选中模型，然后发送一句简单的话，例如“请用一句话介绍你能怎样帮助我”，确认能收到回答。

项目目录决定文件工具从哪里开始工作。会话名称相同，不代表它们指向同一个文件夹；打开已有项目时，要确认当前选中的项目正确。<sup>[3]</sup>

## 试做一个小任务

把一份简短说明放进练习目录，然后发送：

> 请读取项目中的说明文件，用三条要点总结。暂时不要修改任何文件；如果找不到文件，请告诉我你查过哪里。

这一步同时验证三件事：模型是否能回答、项目路径是否正确、读取工具是否可用。

确认读取正常后，再试一次写入：

> 把这三条要点保存为总结.md，保留原文件。

出现审批卡时，先核对目标路径与将要执行的动作，再决定是否批准。<sup>[4]</sup>

## 判断结果是否可信

成功标准不是“回答看起来合理”，而是：

- 它确实读取了指定的文件。
- 总结中的主要信息能在原文中找到。
- 回答说明了来源，用户可以自行复核。
- 写入操作只改动了被批准的文件。

如果回答没有引用文件内容，或给出了原文中不存在的信息，应先回到项目路径与工具记录检查，而不是继续追加更复杂的任务。

## 不顺利时怎么处理

| 现象 | 先检查 |
|---|---|
| 普通问答也失败 | [模型配置](models.md)、[网络](network.md) |
| 能回答但不能读文件 | 项目路径、[工具模式](tool-modes.md) |
| 能读但不能写 | [审批](approvals.md)与权限设置 |
| 图片无法识别 | 模型是否支持图片、[子代理](sub-agents.md)配置 |
| 一直停在运行状态 | [运行状态与工具记录](runtime-status.md) |

## 提示

- 练习时使用单独的文件夹，不要直接在工作项目的根目录试写操作。
- 第一次写入让学生保留原文件，确认结果后再考虑覆盖。
- 任务描述里写清“读哪里、做什么、不要做什么”，比反复补充更省时间。

## 已知问题

- 服务模板可能包含账号无权调用的模型；模板可用不代表该模型可用。
- 不同供应商对图片、工具调用和思考模式的支持程度不同，界面可选项也会随之变化。
