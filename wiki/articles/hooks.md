# 钩子

**钩子**（Hook）是 Sunday 在工具执行相关事件发生时自动运行的一段处理逻辑。它可以调用本机命令、HTTP 地址、MCP 工具或提示处理器，并把结果注入当前上下文。

| 信息框 | |
|---|---|
| 类型 | 事件钩子 |
| 入口 | 插件 → 钩子 |
| 处理器类型 | 本机命令、HTTP、MCP、提示 |
| 匹配条件 | 事件 + 工具名或通配规则 |
| 可注入 | 上下文提示、执行前状态文字 |
| 失败行为 | 可选择是否阻断主任务 |

## 概述

钩子用于在工具调用前后插入检查、通知或补充信息。它不替代审批：审批决定“是否允许执行”，钩子决定“执行时顺带做什么”。<sup>[1]</sup>

钩子可以很轻，例如记录一次调用；也可以阻断主任务，例如验证失败时停止。

## 配置事件与匹配条件

在“钩子”页选择：

- 触发事件。
- 处理器类型。
- 匹配的工具名或通配规则。

多个工具名可以用竖线分隔。匹配范围应尽量窄，避免宽泛规则在无关操作上运行。

保存前检查命令路径或服务地址的拼写。

## 处理器类型

| 类型 | 需要填写 | 适用 |
|---|---|---|
| 本机命令 | 可执行命令 | 本地检查、脚本 |
| HTTP | 可访问地址 | 外部通知、审计服务 |
| MCP | 工具名 | 调用已连接的外部工具 |
| 提示 | 提示文本 | 向上下文补充说明 |

本机命令必须在当前桌面环境可执行；HTTP 地址必须可访问；MCP 处理器必须填写存在的工具名。

## 注入与失败行为

钩子可以填写两类文字：

- **注入上下文**：处理任务需要知道的补充信息。
- **执行前状态**：显示给用户的状态说明。

提示文本应短而具体。把大段规则写进钩子，会占用上下文并增加费用。

“失败时阻断”决定钩子出错后主任务是否停止：

| 用途 | 建议 |
|---|---|
| 验证类检查 | 失败时阻断 |
| 通知类动作 | 失败时继续 |

## 原始配置与排错

页面同时提供 `hooks.json` 原始内容编辑器，适合精确调整。结构化表单保存后，核对生成的配置，避免两个入口同时覆盖。

钩子没有触发时，按顺序检查：

1. 事件名称是否正确。
2. 工具匹配表达式是否命中。
3. 对应插件是否启用。
4. 处理器所需的命令、地址或 MCP 服务是否可用。

触发后失败时，检查处理器连通性，并确认“失败时阻断”是否符合预期。

修改网络代理后，已运行的后台进程可能需要重启应用。

## 提示

- 匹配范围越窄，越不容易误触发。
- 验证类钩子优先阻断，通知类钩子允许继续。
- 改动配置后先用低风险工具试触发一次。

## 已知问题

- 钩子失败可能让主任务停在等待或错误状态。
- 原始配置与表单同时编辑容易产生覆盖。
