# 记忆

**记忆**（Memory）是 Sunday 用来跨会话保留稳定背景的资料。它分为项目记忆与全局记忆两档，可以在资料库中浏览和编辑。

| 信息框 | |
|---|---|
| 类型 | 长期背景资料 |
| 入口 | 资料库 → 记忆；对话中的记忆工具 |
| 档位 | 项目记忆、全局记忆 |
| 适合内容 | 项目术语、长期偏好、常见约束 |
| 不适合内容 | 单次任务步骤、临时日期 |
| 写入前提 | 项目记忆需要先进入项目 |

## 概述

会话结束后，对话中的细节不会自动变成长期知识。记忆提供一个明确的位置，用来保存以后仍然有用的背景。<sup>[1]</sup>

记忆不是聊天记录的替代品。它保存的是经过挑选的结论与约定，而不是完整对话。

## 两档记忆

| 档位 | 适用范围 | 典型内容 |
|---|---|---|
| 项目记忆 | 当前项目 | 项目术语、目录约定、常见坑 |
| 全局记忆 | 所有项目 | 个人偏好、通用写作习惯 |

项目记忆先选择项目，再进入具体档位或文件。全局记忆不依赖项目。

先确认当前项目，再阅读内容，避免把某个项目的约定误用到另一个项目。

## 通过对话读写

除了在资料库中浏览，也可以让 Sunday 直接读写记忆。它使用的记忆工具支持：<sup>[3]</sup>

| 动作 | 作用 |
|---|---|
| 列出、读取 | 浏览目录与文件内容 |
| 写入、追加 | 新建或补充内容 |
| 编辑 | 替换指定文字 |
| 删除、重命名、建目录 | 整理记忆结构 |

路径相对于所选档位的根目录。项目记忆只影响当前项目，全局记忆对所有项目生效。

每个档位都会生成一份索引，并随请求进入模型可见内容。索引不能直接改写，它由记忆文件自动生成；文件标题会出现在索引里，因此标题应写清“什么时候该来看这篇”，而不只是写主题。

## 如何使用记忆

适合写入：

- 稳定的项目背景。
- 反复用到的术语与缩写。
- 长期有效的偏好与限制。

不适合写入：

- 一次任务的步骤。
- 临时截止日期。
- 会很快过期的状态。

记忆内容不会替代当前请求中的明确要求。用户当次说的话优先于记忆中的旧偏好。

## 与规则文件的区别

| 内容 | 放置位置 |
|---|---|
| 必须遵守的长期规则 | [上下文文件](context-files.md)，例如 `AGENTS.md` |
| 可参考的背景与事实 | 记忆 |
| 本次任务的要求 | 当前消息 |

规则文件更像“约束”，记忆更像“资料”。两者都会进入模型可见的内容，但用途不同。

## 空列表与刷新

记忆分区没有内容时：

1. 确认当前工作区与记忆档位。
2. 项目记忆需要先选择项目。
3. 检查该范围是否已有记忆文件。

不要因为空列表就在错误目录手工新建同名文件。文件未更新时，可以退出该层再进入，或使用页面提供的刷新操作。

如果当前版本没有提供某项编辑能力，页面会显示说明，而不是假装存在可编辑列表。

## 提示

- 记忆只保存以后还会用到的东西。
- 项目约定写项目记忆，不要污染全局记忆。
- 记忆与规则冲突时，先修订规则，再把事实补进记忆。

## 已知问题

- 记忆不会自动从对话中提取，需要明确写入。
- 切换项目后，项目记忆需要重新选择对应项目。
