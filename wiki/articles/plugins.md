# 插件

**插件**（Plugin）是 Sunday 中按目录安装、按清单声明能力的扩展单元。一个插件可以只声明名称与版本，也可以同时提供工具、技能、钩子、MCP、命令、上下文、配置面板、界面、窗口、模式、Agent 接管或模块覆盖。<sup>[1][2]</sup>

2026 年 10 月的插件系统重构之后，应用内只有一套装配系统：所有清单由它读取，所有启用状态记录在同一份账本里。此前与旧注册表并存的过渡形态已在同月移除。<sup>[1][18]</sup>

| 信息框 | |
|---|---|
| 类型 | 扩展单元 |
| 入口 | 设置 → 插件 |
| 清单文件 | `plugin.json` |
| 必填字段 | 名称、版本 |
| 可选能力 | 工具、技能、钩子、MCP、命令、上下文、配置、界面、窗口、模式、Agent、模块覆盖 |
| 装配时机 | 启动与每次会话装配 |
| 安装来源 | 本机目录、压缩包、链接 |
| 数据保留 | 更新保留；卸载默认保留 |
| 内置插件 | 7 颗，可禁用，不可卸载 |
| 当前状态 | 单一插件系统，前端模块替换已启用 |

## 概述

插件是一个目录，目录根部放一份清单。清单声明插件叫什么、版本是多少，以及它要提供哪些能力。宿主按清单读取声明，不要求插件在启动时执行注册代码。<sup>[1][2]</sup>

只有名称与版本的插件也能安装、启用、禁用和卸载。这类插件没有可声明的能力，插件页仍会为它显示一个只含身份信息的配置面板。能力是逐步叠加的：先声明工具，再加技能或界面，不会因为新增一项能力而要求重写整个插件。<sup>[2][13]</sup>

插件代码在 Sunday 进程内运行。宿主不提供沙箱，安装一个插件等同于信任它。工具调用可以受审批约束，但审批只覆盖需要确认的动作，不限制插件代码本身的读写与联网能力。<sup>[10][18]</sup>

## 插件目录与清单

### 最小清单

一个插件至少包含三件事：目录名、`plugin.json`、以及清单里的名称与版本。早期版本用于区分新旧系统的装配标记已经废除，清单不再需要任何迁移字段。<sup>[1]</sup>

| 字段 | 必填 | 作用 |
|---|---|---|
| 名称 | 是 | 插件唯一标识，同时作为目录名使用 |
| 版本 | 是 | 展示与人工判断用，宿主不做版本比较 |
| 描述 | 否 | 插件页显示的一行说明 |
| 生效范围 | 否 | `global`、`mode`、`session`，用于 Agent 接管 |
| 默认启用 | 否 | 随包插件可以声明首次安装时关闭 |
| 运行环境 | 否 | 声明 Python、应用版本、平台与依赖 |
| 能力字段 | 否 | 工具、技能、钩子、MCP、命令、上下文、配置、界面、Agent、覆盖 |

清单里未声明的字段会被保留但不参与装配；拼错字段名不会报错，只会表现为对应能力没有出现。路径必须以相对路径书写并留在插件目录内，越界路径会在读取时被拒绝。<sup>[1][2]</sup>

### 字段

| 字段 | 内容 |
|---|---|
| 工具 | 一份或多份工具声明文件，逐项列出工具名、处理器、权限、可见性、超时 |
| 技能 | 一个或多个技能目录，每个目录含一份 `SKILL.md` |
| 钩子 | 一个或多个钩子配置文件，按事件分组 |
| MCP | 一个或多个 MCP 配置文件，内含服务器定义 |
| 命令 | 清单内联的斜杠命令数组 |
| 上下文 | 清单内联的片段数组，每项含文件与序号 |
| 配置 | 配置表单的结构文件，或自定义面板脚本 |
| 界面 | 样式、页面脚本、区域、窗口、模式 |
| Agent | 提示词、工具白名单、审批口径、上下文文件 |
| 覆盖 | 模块名到替换文件的映射 |
| 运行环境 | 运行时类型、Python 版本、应用版本、平台、依赖 |

### 目录结构

| 路径 | 是否必需 | 用途 |
|---|---|---|
| `plugin.json` | 是 | 清单 |
| `skills/` | 否 | 技能目录 |
| `tools.jsonc` 与处理器文件 | 否 | 工具声明与实现 |
| `hooks/` | 否 | 钩子配置 |
| `mcp/` | 否 | MCP 配置 |
| `config/` | 否 | 配置结构或自定义面板 |
| `ui/` | 否 | 样式、脚本、页面与窗口入口 |
| `data/` | 否 | 插件自有数据，更新与卸载时保留 |
| `logs/` | 否 | 插件自己的日志，宿主不代管 |

`data/` 是唯一在更新与卸载中默认保留的位置。插件应把需要长期保存的内容放在这里，而不是写在插件代码目录或应用安装目录。<sup>[9]</sup>

## 插件能提供什么

| 能力 | 声明位置 | 装配结果 |
|---|---|---|
| 工具 | 工具声明文件 | 模型工具列表中出现对应工具 |
| 技能 | 技能目录 | 技能索引中出现条目，按需加载 |
| 钩子 | 钩子配置 | 在指定事件前后执行，可观察、修改或拦截 |
| MCP | MCP 配置 | 外部服务器工具并入会话工具列表 |
| 命令 | 清单命令数组 | 输入框输入命令即可触发 |
| 上下文 | 清单上下文数组 | 片段进入系统提示词 |
| 配置 | 配置结构或面板 | 插件页出现可填写的配置面板 |
| 界面 | 界面声明 | 区域内容、样式、页面脚本生效 |
| 窗口 | 窗口声明 | 可打开独立桌面窗口 |
| 模式 | 模式声明 | 主内容区可切换为插件页面 |
| Agent | Agent 声明 | 提示词、工具白名单、审批与上下文被接管 |
| 覆盖 | 覆盖映射 | 指定宿主模块在导入前被替换 |

### 工具与审批

工具声明必须同时给出名称与处理器。权限分三档：自动允许、需要确认、硬阻止。硬阻止的工具不会出现在模型工具列表中，也无法通过审批继续执行。<sup>[2][10]</sup>

工具可以声明为始终可见，或声明为随指定技能加载后才出现。后者适合把一组低频工具与使用说明放在同一个技能里。超时可选，未声明时不设上限。<sup>[2]</sup>

工具的参数结构与返回结构会被展示，但宿主不校验实际输入输出。处理器返回失败状态与说明文字时，模型会看到错误并决定是否重试。<sup>[2][18]</sup>

插件 Agent 还可以声明自己的审批口径：照常询问、自动允许、阻止需要确认的调用。该口径只作用于需要确认的调用，硬阻止与敏感路径拦截不受影响。<sup>[4]</sup>

### 技能、钩子与 MCP

技能与内置技能走同一套索引。技能目录中一份带名称与描述的说明文件即可被发现；声明了作用范围时，只在对应模式中出现。<sup>[2]</sup>

钩子按事件声明，支持工具调用前、工具调用后、工具失败后、会话开始、停止、用户提交输入、权限请求七类事件。处理方式包括执行命令、发起 HTTP 请求、调用 MCP、注入提示词。<sup>[2]</sup>

MCP 配置按服务器声明，会话启动时并入 MCP 客户端。服务器自身不可用时，对应工具会失败，插件不会被连带禁用。<sup>[2]</sup>

### 上下文片段

上下文声明只描述文件与序号，不直接写提示词。片段按序号插入系统提示词；序号相同时按文件名排序，保证作者声明的顺序始终有效。<sup>[2][18]</sup>

上下文变化不会在对话中途改写已经发送的提示词。它要等到下一次上下文压缩或新会话才生效。需要立即生效的内容应放进钩子或命令，而不是上下文片段。<sup>[18]</sup>

### 斜杠命令

命令在清单里声明名称、标题、说明与要执行的操作。输入框输入命令后，命令参数会随请求传给对应操作。命令不另开执行通道，执行结果与普通操作一致。<sup>[2][11]</sup>

命令可以只声明效果而不执行操作，用于触发界面动作，例如打开插件窗口。命令没有独立权限体系，实际权限由它调用的操作决定。

## 装配与生效时机

### 启用状态

安装与启用是两件事。安装只把插件放进插件目录；启用写入单独的启用记录。禁用后插件的能力不再参与装配，文件与数据保留；重新启用不需要重新安装。<sup>[9][10]</sup>

随包插件可以声明首次安装时默认关闭。用户显式开关过后，以用户的记录为准，不再回到默认值。<sup>[1][9]</sup>

随包插件可以禁用，但不能卸载。卸载随包插件会破坏应用自带内容，宿主会拒绝该操作。<sup>[9][10]</sup>

### 冻结与即时

| 内容 | 变化何时被模型看到 |
|---|---|
| 系统提示词 | 新会话或下一次上下文压缩 |
| 工具数组 | 新会话或下一次上下文压缩 |
| 上下文片段 | 新会话或下一次上下文压缩 |
| 钩子 | 下一次工具调用或事件 |
| 斜杠命令 | 下一次打开命令列表 |
| 配置值 | 下一次读取配置的调用 |
| 界面区域与样式 | 刷新插件页或重新进入页面 |

提示词与工具数组按压缩周期冻结，是为了保持模型请求前缀稳定。插件更新后如果只改了提示词，旧会话不会立刻变化；需要新会话或压缩一次。<sup>[18]</sup>

### 冲突处理

宿主不对冲突做静默覆盖。能排序的按声明顺序排列，不能排序的拒绝加载并在插件页显示错误。<sup>[2][3]</sup>

| 冲突 | 处理 |
|---|---|
| 两个插件声明同名工具 | 后一个工具不加入，报冲突 |
| 两个插件声明同名技能 | 后一个技能不加入，报冲突 |
| 两个插件声明同名命令 | 后一个命令不加入，报冲突 |
| 两个插件替换同一区域 | 后一个替换被拒绝，报冲突 |
| 同一插件内重复的窗口标识 | 后一个窗口不加入，报冲突；不同插件各自声明同名窗口不冲突 |
| 两个插件声明全局 Agent | 后一个不生效，报冲突 |
| 两个插件覆盖同一模块 | 后一个覆盖被拒绝，报冲突 |
| 两个目录出现同名插件 | 扫描顺序靠前者生效，另一个报错 |

## Agent 接管

插件可以整套接管当前 Agent 的身份，而不是逐项混搭。接管内容包括提示词、工具白名单、审批口径与上下文文件。<sup>[4][18]</sup>

生效范围分三档，优先级从高到低为会话、模式、全局：

| 范围 | 何时生效 |
|---|---|
| 会话 | 会话由该插件创建或归属该插件时 |
| 模式 | 切到该插件声明的模式时 |
| 全局 | 没有更具体的接管时 |

接管生效时，插件提示词替换原有身份说明，工具白名单限制模型可见的工具，审批口径替换默认口径，上下文文件追加到提示词。切走模式后恢复原有 Agent。学习模式是这种接管的内置样例。<sup>[4][18]</sup>

## 界面

### 区域

插件可以把声明式内容挂到宿主已有的区域，而不是重绘整个界面。区域名单固定；名单之外的界面需求通过页面脚本或独立窗口实现。<sup>[3]</sup>

| 区域 | 原本放置的内容 |
|---|---|
| `appRail` | 最左侧常驻导航条 |
| `left` | 会话与项目列表，顶部有新建、搜索、设置入口 |
| `titlebar` | 会话标题与重命名入口 |
| `main` | 聊天消息列表，或被整版页面替换 |
| `right` | 右竖栏模块 |
| `composer` | 输入框、命令菜单、附件区、发送按钮 |
| `composerSide` | 输入框右侧工具按钮 |
| `message` | 每条消息内部的思考、工具调用与结论 |
| `settings` | 设置页中的插件卡片 |

区域内容以块声明，支持文本、状态、指标、列表、进度五类。追加是默认行为；替换需要显式声明，且同一区域只能有一个替换者。区域动作可以绑定到操作：声明为危险的动作点击后先弹确认；声明了参数结构的动作会先弹出参数表单，填写后才执行。<sup>[3]</sup>

左侧栏与右侧栏提供图标注册接口。向左侧栏声明区域贡献的插件会注册成抽屉底部的图标项，点击在上方展开面板渲染该贡献的块与动作；向右侧栏声明贡献的插件会注册成右缘图标竖栏的图标项，悬停浮出对应卡片。两处的图标行（栏）都有滚动兜底，展开的面板限高滚动，插件数量多时界面不外溢。声明了替换的插件不进图标区，整块接管对应栏体。<sup>[3][26]</sup>

样式是普通 CSS，注入后对整个页面生效，因此可以只写样式就改变现有界面的外观。页面脚本在页面内执行，适合声明式块无法表达的交互，由插件作者自行承担兼容性。<sup>[3][13]</sup>

### 窗口

插件可以声明独立桌面窗口。窗口声明包含标识、标题、入口页面、初始尺寸，可选声明拖放文件与浮动窗口的多档尺寸。<sup>[3][19]</sup>

窗口与主界面属于同一应用，可以访问本机接口；与主页面的通信方式由插件自行实现。桌宠就是以内置窗口插件的形式存在。<sup>[19]</sup>

### 模式

模式会把主内容区切换为插件页面，并在模式切换器中出现。模式声明与旧格式保持同形，界面组件仍随应用编译，后端只发描述。<sup>[3][16]</sup>

模式可以声明自己的工具表与独占工具。声明独占后，属于该插件的工具只在模式激活时可见与可执行；通用工具不受影响。学习与工作流是内置模式样例。<sup>[3][18]</sup>

### 配置面板

每个插件都有配置面板。没有配置声明时，面板显示名称、版本与描述，没有可填字段；声明配置结构后，宿主按字段类型生成表单；声明自定义面板后，面板脚本接管渲染。<sup>[7][14]</sup>

| 配置写法 | 面板行为 |
|---|---|
| 不写配置 | 只显示身份信息 |
| 写配置结构 | 生成文本、数字、开关、下拉、数组与对象控件 |
| 写自定义面板 | 脚本在面板容器内挂载，使用宿主提供的取值与保存接口 |

配置值保存在插件自己的数据目录。保存时按结构检查必填、类型与枚举；没有结构时接受任意对象。自定义面板加载失败或未注册挂载函数时，宿主退回默认表单，不会把用户锁在坏面板里。<sup>[7][14]</sup>

## 模块覆盖

模块覆盖允许插件替换宿主的某个后端模块或前端模块。后端替换发生在宿主导入模块之前，因此调用方拿到的就是插件提供的版本，而不是先导入再补丁；前端替换通过页面加载时的模块映射完成，映射由宿主在返回页面时合并注入。<sup>[5][6][22]</sup>

覆盖键分两族，规则一致但生效路径不同：

| 键族 | 指向 | 生效时机 | 撤销方式 |
|---|---|---|---|
| 宿主后端模块名 | 插件目录内的 Python 文件 | 应用启动时装配，改动后需重启 | 重启后不再装配 |
| 前端模块路径 | 插件目录内的脚本文件 | 页面加载时经模块映射解析，改动后需整页刷新 | 整页刷新后恢复 |

| 规则 | 行为 |
|---|---|
| 可替换目标 | 宿主自身的后端模块名，或界面源码内的前端模块路径 |
| 粒度 | 整个模块，不支持只替换其中一个函数 |
| 同一目标 | 只能有一个插件接管，后声明的被拒绝，两族同表查冲突 |
| 导出校验 | 不做。缺少导出时由导入方或页面报错 |
| 安全模式 | 设置 `LAMTOOLS_SAFE_MODE` 后跳过全部覆盖 |

前端可替换的模块范围以插件页可查询的行为表为准；随包的第三方依赖与桌面壳层不在可替换范围内。覆盖是最强也最危险的扩展方式。插件作者需要自行保证替换后的模块仍然提供调用方需要的名称；缺失时应用可能在启动阶段或页面加载时报错，日志与控制台会记录具体模块与失败原因。宿主不校验输入输出，也不保证覆盖后的功能完整。<sup>[5][6][21][22][23]</sup>

## 安装、更新与卸载

| 操作 | 支持来源 | 说明 |
|---|---|---|
| 安装 | 本机目录、压缩包、链接 | 校验清单与运行环境后复制到插件目录 |
| 更新 | 本机目录、压缩包、链接 | 同名插件整体替换代码，保留数据 |
| 卸载 | 已安装插件 | 默认保留数据目录 |

链接安装支持附带校验值：填写压缩包的完整性校验串后，下载内容与校验值不符时安装被拒绝，插件目录不留残余。<sup>[24]</sup>

安装时会检查清单必填字段与运行环境。声明了宿主不满足的 Python 版本或平台时，安装被拒绝并说明是哪一条不满足。声明了第三方依赖时，安装完成即逐项探测能否导入，并把缺失的包名列在安装结果里；缺包不阻止安装，补装依赖后工具才能执行。能力路径是否越界在装配时校验，宿主不会代为安装第三方包。<sup>[8][9][24]</sup>

更新不做版本比较，也不支持回滚。更新以同名插件为前提，不能借更新改名。更新中途失败时，插件本体与数据目录回到更新前的状态，插件目录不留临时残余。更新完成后需要重新进入会话或压缩一次，提示词与工具数组的变化才会被模型看到。<sup>[9][18][25]</sup>

卸载用户安装的插件后，插件目录与其能力一起消失；数据目录按选择保留。卸载随包插件会被拒绝。<sup>[9][10]</sup>

## 权限与安全边界

- 插件在宿主进程内运行，没有沙箱，也没有独立的系统权限边界。<sup>[18]</sup>
- 工具调用可以要求用户确认；需要确认的动作会进入审批流程，硬阻止的工具无法执行。<sup>[10]</sup>
- 模块覆盖可以改变宿主行为，包括启动路径；作者需要自行验证后果。<sup>[5][6]</sup>
- 插件配置中的密钥由插件自行保存，宿主不额外加密。本机数据目录的访问控制就是全部保护。<sup>[7]</sup>
- 宿主不校验工具输入输出，也不校验覆盖模块的导出完整性。错误由调用方或作者承担。<sup>[2][5]</sup>

## 提示

- 从最小清单开始，确认插件能安装、启用、禁用，再逐项添加能力。
- 插件页会显示清单读取错误与单插件的声明错误，先看错误再改清单。
- 修改提示词、工具或上下文后，开启新会话或执行一次上下文压缩，否则旧会话仍使用冻结内容。
- 需要频繁调用、返回结构严格或需要绕过命令审批的动作，才做成独立工具；其余场景优先用技能加命令实现。
- 覆盖插件先在副本上验证，保留安全模式入口，避免应用无法启动时无从恢复。
- 更新前备份插件的 `data/`，尤其是插件自己管理日记、索引或数据库的场景。

## 已知问题

1. 覆盖是模块级替换，不校验导出。缺少导出时应用可能在启动或页面加载阶段失败，只能删插件或进入安全模式恢复。
2. 前端可替换范围以行为表为准：随包第三方依赖与桌面壳层不可替换；前端覆盖变更后需要整页刷新。
3. 市场与远程索引尚未接入，也没有版本比较、自动更新与降级。
4. 工具输入输出声明不参与校验，错误只能在执行结果中体现。
5. 插件没有沙箱，配置中的密钥以明文保存在本机数据目录。
6. 插件页逐插件展示声明错误与读取错误；跨插件的工具、命令或区域冲突目前在装配结果中返回。

## 历史

- **2026 年 10 月下旬**：插件系统收尾，单一系统成型。
  - 旧注册表、旧账本与旧插件页移除，装配标记废除；启用状态只记一份账本。
  - 声明装配与后端生命周期分层：连续多轮对话不再重复创建插件后端。
  - 安装与更新接入链接来源与完整性校验；安装即报告缺失依赖；更新失败自动回滚且不留残余。
  - 九个界面区域全部挂载；区域动作支持危险确认与参数表单；联网搜索面板的存在随插件启停变化；生图与搜索的配置面板回到插件页。
  - 前端模块替换启用：界面源码内模块可经模块映射替换，行为表可在插件页查询每个行为落在哪个模块。
- **2026 年 10 月**：插件系统重构完成。
  - 新装配系统接管清单、六类声明能力、界面区域、独立窗口、界面模式、Agent 接管、配置面板、操作注册、后端生命周期与命令行挂载。
  - 七颗内置插件完成迁移。Git 插件删除；新增管道校验器插件；桌宠改为窗口插件。
  - 学习与工作流的系统提示词、模式与工具不再由宿主硬编码。
  - 模块覆盖改为启动前按模块替换，冲突拒绝，安全模式可整体跳过。
  - 插件更新保留数据，随包插件禁止卸载。
- **2026 年 9 月**：插件页支持预览新清单与启停；插件能力开始从核心代码迁入声明式清单。
