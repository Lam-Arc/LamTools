# 思考模式

**思考模式**（Thinking mode）是 Sunday 控制模型推理强度的运行选项。可选档位由当前模型声明的能力决定，不由供应商名称统一决定。

| 信息框 | |
|---|---|
| 类型 | 运行设置 |
| 入口 | 聊天输入框的运行控制 →“思考模式” |
| 作用范围 | 后续提交的运行请求 |
| 选项来源 | 当前模型声明的推理能力 |
| 对已完成消息 | 不修改 |

## 概述

思考模式影响模型在回答前投入多少推理。较高的档位适合多步分析、跨文件排查和复杂规划；较低档位适合简单问答与短文本处理。

档位不是越多越好。它只改变后续请求，不会回头修改已经完成的消息。<sup>[1]</sup>

## 选择档位

1. 在聊天输入框附近打开“思考模式”菜单。
2. 选择当前模型支持的档位。
3. 发送下一条消息。

不同模型可能提供不同等级。模型目录中的“支持推理”、推理等级和预算信息会影响菜单内容。没有推理支持的模型不会显示虚构的档位。

## 按任务调整

| 任务 | 建议 |
|---|---|
| 简单问答、短文本改写 | 较低档位 |
| 多步分析、长代码检查 | 较高档位 |
| 跨文件排查 | 先在常规档位定位范围，再提高强度 |

例如，先用常规档位解释一个配置项；遇到需要跨文件追踪的问题时，再提高思考强度。

即使选择了某个档位，如果模型没有声明该档位，应用会映射到实际支持的最近强度，而不是把请求直接失败。

## 选项缺失时

先确认当前选中的模型，而不是只看供应商：

1. 打开模型设置，确认当前模型。
2. 查看模型目录中的推理能力元数据。
3. 重新选择模型，再打开思考模式菜单。

菜单只有少数选项，通常表示该模型只声明了有限能力，不是设置页漏载。

修改模型元数据后要重新选择模型，菜单才会按新能力刷新。请求仍被拒绝时，以服务端支持的字段和模型文档为准。

## 与等待时间、费用的关系

更高的推理强度通常意味着：

- 更长的等待时间。
- 更多的输出 token。
- 可能更高的费用。

具体影响取决于供应商的计费方式。命中缓存只影响输入部分的单价，不会让推理本身免费。

## 提示

- 默认使用常规档位，遇到确实需要多步推理的任务再提高。
- 同一会话中频繁切换档位会改变请求参数，可能使缓存前缀失效。
- 模型不支持某个档位时，不要在提示词里强行要求“深度思考”。

## 已知问题

- 不同模型对“推理等级”的定义并不统一。
- 档位提高不保证答案正确，只增加推理预算。
