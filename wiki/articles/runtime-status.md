# 看懂运行状态与工具记录

**运行状态**（Runtime status）是 Sunday 对当前一轮工作所处阶段的显示。配合工具记录，可以判断它是在处理任务、等待用户操作，还是已经失败。

| 信息框 | |
|---|---|
| 类型 | 状态显示 |
| 位置 | 会话运行记录；右侧运行状态区域 |
| 状态 | 空闲、运行中、等待中、已完成、运行失败 |
| 右侧区域 | 是否显示取决于布局配置 |
| 作用 | 判断进展与等待原因 |

## 概述

运行状态描述“这一轮进行到哪”，不评价最终成果。状态为“已完成”也可能只是回答结束，并没有产生用户期望的文件。<sup>[1][2]</sup>

## 常见状态

| 状态 | 含义 | 建议动作 |
|---|---|---|
| 空闲 | 当前没有活跃工作 | 可以开始新一轮任务 |
| 运行中 | 正在生成回答或执行步骤 | 查看最新记录，必要时补充引导 |
| 等待中 | 等待审批、答案、排队或其他条件 | 找到具体等待事项 |
| 已完成 | 当前运行结束 | 检查交付内容 |
| 运行失败 | 某个环节报错 | 阅读错误，按原因处理 |

等待中最常见的是审批卡和提问卡。找不到等待事项时，再检查后台进程、网络和子任务。

## 工具记录能告诉你什么

展开工具调用，可以核对：

- 读取了哪个文件。
- 运行了哪条命令。
- 搜索了什么关键词。
- 返回了什么结果。

成功返回表示调用完成，但返回的资料可能不完整，也可能不是用户想要的范围。失败记录是定位原因的线索，例如路径不存在、没有权限或外部服务拒绝。

## 子代理的状态

子代理有自己的任务和运行记录。主回答里写“已委派”，不代表子任务已经成功。

要判断子任务是否完成，应查看子代理面板中的任务状态与结果。长时间没有进展的子代理可能停下来等待，见[子代理](sub-agents.md)。

## 看起来不动时

按以下顺序检查：

1. 是否有审批卡或提问卡。
2. 是否有后台进程正在启动或等待健康检查。
3. 是否有子任务在运行。
4. 是否有网络错误或工具失败。
5. 是否正在执行一个耗时步骤。

没有新文字不一定是卡死；界面动画仍在转，也不保证工作有进展。

确实报错时，记录最后成功的动作和第一条错误，再按[故障排查](troubleshooting.md)处理。重复点击发送可能生成额外任务，让情况更难判断。

## 提示

- 先看状态，再看工具记录，最后看错误信息。
- 等待中时优先处理审批或提问，不要继续发送新要求。
- 完成后打开实际文件核对，不要只看状态。

## 已知问题

- 状态只反映当前运行，不反映历史运行是否成功。
- 右侧状态区域可能被布局配置隐藏。
