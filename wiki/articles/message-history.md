# 消息编辑、分支与回退

**消息历史操作**（Message history actions）是 Sunday 对已发送消息提供的复制、编辑、另开会话和删除后续内容的能力。它们解决的是不同问题，不能互相替代。

| 信息框 | |
|---|---|
| 类型 | 历史消息操作 |
| 入口 | 用户消息附近的操作按钮；部分在消息菜单 |
| 操作 | 复制、编辑、从此处另开会话、删除此消息及之后内容 |
| 编辑确认 | Ctrl+Enter |
| 编辑取消 | Esc |
| 撤销范围 | 不撤销已执行的命令、请求或文件写入 |

## 概述

对话走偏时，有四种处理方式：复制原话、修改原话、从某条消息分叉、删除该消息及后续内容。前两种改变当前对话，后两种改变对话的结构。<sup>[1]</sup>

这些操作只作用于对话记录，不保证回退已经发生的文件修改、命令执行或外部请求。

## 复制与编辑

**复制**适合把原话拿去修改，或记录一段有效的提问。复制不会改变会话。

**编辑**会进入文字编辑状态：

| 按键 | 行为 |
|---|---|
| Ctrl+Enter | 确认并发送修改 |
| Esc | 取消编辑 |

编辑旧提问会影响后续对话的处理，不是普通文本笔记的改字。重要对话先导出，或使用“从此处另开会话”比较两种提问。

可编辑范围以该消息的按钮状态为准。

## 从此处另开会话

“从此处另开会话”会以该消息为起点分出一条新会话，用于尝试另一条思路，同时保留原来的讨论。

- 新会话用于继续讨论，不会自动复制项目文件。
- 两条会话如果仍指向同一个项目目录，可能操作同一批文件。
- 会话分叉不等于文件版本备份。

需要真正隔离文件改动时，应配合版本控制或目录副本，见[项目](projects.md)和[查看 Git 状态和改动](git.md)。

## 删除此消息及之后内容

回退会删除指定消息及其后的所有对话内容。

执行前要确认起点，因为后面的讨论也在删除范围内。它不能保证撤销：

- 已经执行的命令。
- 已经发出的外部请求。
- 已经写入的文件。

实际文件需要另行恢复。

## 为什么有些按钮不能用

某些历史边界、上下文压缩相关消息或锁定状态不允许直接操作。按钮隐藏或禁用是保护机制，不是故障。

不要通过清空数据库来“解除限制”。可以新建会话，把需要继续的背景整理过去，并保留原记录用于核对。

## 提示

- 想保留原讨论时，用“从此处另开会话”，不要直接编辑旧消息。
- 回退前先确认后续是否还有需要保留的内容。
- 重要会话在大量编辑前先导出。

## 已知问题

- 回退不会恢复已经被工具改动的文件。
- 压缩相关的历史消息可能不可编辑或删除。
