# 界面样式体系

**界面样式体系**（Interface style system）是 Sunday 桌面端让同一套界面在四套主题、两种明暗模式与各种窗口尺寸下保持一致的一组约定。它由令牌、主题变量、基础件、分层样式与动效预设组成，目标是把外观变化收在少数几个入口，而不是分散到每个页面。

| 信息框 | |
|---|---|
| 类型 | 设计约定 |
| 作用域 | 桌面端界面 |
| 主题数量 | 四套，另有明暗两种模式 |
| 令牌类别 | 颜色、字阶、间距、圆角、阴影、层级、动效、图标、焦点 |
| 按钮角色 | 五种 |
| 动效预设 | 六类 |
| 当前状态 | 已统一控件与动效，内容排版仍按区域维护 |

## 概述

界面样式分成五层：令牌定义可用的数值，主题把令牌换成当前配色，基础件用令牌拼出按钮与开关，外壳与功能面再用基础件拼出整页。任何一层都不应该直接写死颜色或尺寸，否则换主题与窄屏适配就会失效。

这套约定在 2026 年 10 月做过一次集中整理：把原先各写一遍的按钮、开关和动效收成一份，把过大的样式文件按区域拆开，并让图表跟随当前明暗模式。

## 分层

| 层 | 职责 | 变化频率 |
|---|---|---|
| 令牌 | 提供颜色、字阶、间距、圆角、阴影、层级、动效、图标与焦点环 | 很少 |
| 主题 | 把四套配色与明暗模式换算成当前表面的底色与文字色 | 用户切换时 |
| 基础件 | 按钮、开关、分段、滑块、进度条 | 很少 |
| 外壳 | 侧栏、主区、输入栏、抽屉、分屏 | 随功能调整 |
| 功能面 | 设置、资料库、学习、插件管理 | 随功能调整 |

加载顺序固定为令牌、基础、外壳、功能面。外壳样式内部又按玻璃层、外壳骨架、侧栏、主区的顺序展开，功能面按设置、资料库、控件、消息的顺序追加。<sup>[1][2]</sup>

## 令牌

| 令牌类别 | 覆盖范围 | 说明 |
|---|---|---|
| 颜色 | 语义色与四区域底色 | 语义色不随主题变化，区域底色随主题变化 |
| 字阶 | 十号到二十二号共九档 | 取代过去散落的小数字号 |
| 间距 | 四像素为基的六档 | 密集工作台布局 |
| 圆角 | 小、中、大、超大四档 | 卡片与浮层共用 |
| 阴影 | 四档 | 浮层不再自写阴影 |
| 层级 | 背景信息到全屏共九档 | 弹窗与提示固定在高位 |
| 动效 | 五档时长与三条缓动曲线 | 组件不再自写毫秒数 |
| 图标 | 三档尺寸与一档线宽 | 线宽默认一点八 |
| 焦点 | 宽度、偏移、颜色 | 键盘操作时统一显示 |

只允许令牌层出现具体数值。功能面里出现颜色值时，必须是令牌组合出来的派生色，而不是新的固定值。

## 主题与配色

主题把界面分成四个区域：背景板与侧栏、主界面、输入栏、控件。每个区域的底色由填充（纯色、渐变或图片）决定，另有一个独立的玻璃材质偏好，开启后区域表面变成玻璃、填充作为着色；背景板使用侧栏与窗口底色，没有单独的侧栏配色项。

四套主题分别是象牙白与石墨灰、中性灰阶、莓紫到青绿的渐变、雾蓝到奶油白的渐变。明暗模式分为跟随系统、浅色、深色与定时切换。浅色与深色分别保存，切换模式不会互相覆盖。具体操作见[界面外观](appearance.md)。<sup>[3]</sup>

## 基础件

按钮在 2026 年 10 月的整理中收成一份：一个基础几何加五种角色，分别是主要、次要、安静、纯文字与危险。尺寸、禁用态、按压位移和过渡都由基础件负责，功能面只允许覆盖取色，不再重写几何。

开关、分段控件、滑块与进度条同属基础件。带文案的开关复用同一条轨道，文案作为整行标签，因此“已允许”“需确认”这类状态文字不再需要单独的轨道组件。<sup>[4]</sup>

| 基础件 | 形态 | 典型用途 |
|---|---|---|
| 主要按钮 | 实心控件底色 | 提交、确认 |
| 次要按钮 | 实心控件底色，轻量 | 常规操作 |
| 安静按钮 | 透明底，文字跟随面板 | 辅助动作 |
| 纯文字按钮 | 无底无边，小字号 | 行内操作 |
| 危险按钮 | 红色文字 | 删除、撤销 |
| 开关 | 轨道加滑块，可带行内文案 | 设置项 |
| 分段 | 等分选项加滑动指示条 | 密度、模式选择 |
| 进度 | 轨道加填充 | 更新、上传 |

## 动效

动效参数集中在一处，组件只声明用哪一类。<sup>[5]</sup>

| 动效 | 时长与曲线 | 典型场景 |
|---|---|---|
| 从触发点形变 | 零点六二秒，回弹曲线 | 更新卡片从侧栏图标长出 |
| 淡入上移 | 零点二二秒 | 列表项、产出块 |
| 弹出 | 零点三二秒，带回弹 | 菜单与浮层 |
| 展开与折叠 | 展开零点二四秒，收起零点二秒 | 折叠面板 |
| 遮罩淡入淡出 | 淡入零点二六秒，淡出零点三秒 | 模态背景 |
| 减弱动效 | 瞬时切换 | 系统要求减少动效时 |

形变动效的要点是从触发元素的位置与大小开始，先压回触发元素大小，再长到自身尺寸，因此看起来是从按钮里“长出来”。关闭时原路缩回，随后才移除节点。

## 消息渲染

聊天消息由富文本渲染成一段文档结构，因此消息区的样式保持全局作用域，不能使用组件作用域。这是有意为之：消息体内联的代码块、表格、引用与数学公式都在这段文档里，作用域限制会让它们失去样式。

消息区因此是唯一允许出现大段全局样式的区域，但它仍只使用令牌，不引入新的固定颜色。

## 尺寸与窄屏

功能面按自身容器宽度适配，不看窗口宽度。同一个设置页在整窗与分屏里宽度不同，但排版依据始终是它自己的可用宽度。侧栏宽度按窗口分三档，窄屏时收起为抽屉。<sup>[6]</sup>

## 已知问题

1. 空态、卡片与列表行仍按区域各自维护。它们在不同位置的意图不同，有横排、居中与卡片三种，尚未合并成单一基础件。
2. 键盘焦点环已经统一，但输入框按设计不显示焦点框，只保留光标闪动。
3. 用户还不能覆盖单个组件的样式，可视化界面编辑尚未提供。
4. 部分较早的自动化检查仍在断言旧的分层方式，与当前实现存在偏差。

## 历史

- **2026 年 10 月**：集中整理界面样式。合并按钮、开关与动效；补齐字阶、图标与焦点令牌；把设置、消息、插件管理的样式按区域拆分；图表改为跟随当前明暗模式；删除重复的样式规则与失效的组件引用。
