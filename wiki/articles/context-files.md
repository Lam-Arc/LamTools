# 上下文文件与规则

**上下文文件**（Context files）是 Sunday 从磁盘读取、并作为长期背景放进系统提示词的规则与资料。全局规则对所有工作区生效，项目规则只对当前项目生效。

| 信息框 | |
|---|---|
| 类型 | 提示词来源 |
| 全局入口 | 设置 → 上下文 |
| 项目入口 | 项目菜单 → 项目设置 |
| 全局规则文件 | `.lam/core/config/AGENTS.md` |
| 加载清单 | `load_context.jsonc` |
| 叠加方式 | 全局规则与项目规则相加，不互相覆盖 |

## 概述

上下文文件解决“哪些长期要求需要每次都告诉模型”。把稳定的约定写进文件，比在每次对话里重复更省事，也更不容易遗漏。

这些文件会成为系统提示词的一部分，因此位于请求最前部；它们的变化会影响缓存前缀。<sup>[1]</sup>

## 全局规则

“设置 → 上下文”中的全局规则保存在 `.lam/core/config/AGENTS.md`，对所有工作区生效。

适合写入：

- 跨项目的代码风格。
- 提交与命名习惯。
- 沟通偏好与输出格式。

不适合写入：

- 单次任务的步骤。
- 临时截止日期。
- 只对某个项目成立的约定。

修改后点击“保存”才会写入。可以用“刷新”重新读取磁盘内容；保存前不要同时从外部编辑器覆盖同一文件。

## 项目规则

项目自己的 `AGENTS.md` 位于项目目录，通过“项目设置”编辑。

项目规则会叠加在全局规则之上，因此项目特例应写在项目规则中，避免全局说明过长。两类规则同时生效，不是后写覆盖先写。<sup>[2]</sup>

## 加载附加文件

全局加载清单保存在 `.lam/core/config/load_context.jsonc`，用于把额外文件加入上下文。

清单可以配置：

| 项 | 作用 |
|---|---|
| 文件名 | 要加载的文件 |
| 优先级 | 注入顺序，数值越小越靠前 |
| 加载类型 | 文件作为哪类内容注入 |
| 排除列表 | 不参与加载的路径 |

工作区自己的 `load_context.jsonc` 会叠加在全局清单之上。

添加文件时确认名称与路径确实存在，并只加载任务真正需要的资料。无关内容会占用上下文空间，也会增加请求费用。

## 优先级与排除

- 优先级只调整顺序，不保证文件内容一定能读到。
- 排除列表优先级高于加载项：路径匹配后不会被加载。
- 默认项目上下文文件包括 `AGENTS.md`、`CLAUDE.md`、`CONTEXT.md`。

如果两个文件的指令冲突，先修订规则使它们一致。调整顺序不能解决内容矛盾。

## 规则没有生效时

1. 确认修改已经保存。
2. 确认文件位于预期范围：全局还是项目。
3. 检查排除列表是否匹配了该文件。
4. 确认当前会话选中的是预期项目。
5. 检查文件是否被外部程序覆盖或移动。

单次任务的要求直接写进当前消息通常更清楚，不要为了一个临时要求修改长期规则。

## 与冻结机制的关系

系统提示词在压缩周期内保持冻结。修改上下文文件后，Sunday 不会回头改写已经发送的系统提示词，而是在请求末尾追加一条变化通知；下一次上下文压缩成功后，才用最新内容重建。

因此，修改规则不会立刻改变前缀，但会产生一条通知。完整机制见[上下文与缓存命中](context-and-cache.md)和[对话太长时的上下文整理](compaction.md)。

## 提示

- 全局规则只写真正跨项目的约定。
- 项目特例写进项目规则，不要把全局文件变成例外清单。
- 加载清单只放常用资料，长文档按需读取。

## 已知问题

- 规则冲突不会自动裁决，需要人工修订。
- 修改文件后，系统提示词要到下一次压缩才重建。
