# 查找本地数据和制作备份

**数据备份**（Backup）是保存 Sunday 会话、配置和项目资料的做法。了解数据位置有助于迁移或恢复，但不要在程序运行时直接改写数据库或配置文件。

| 信息框 | |
|---|---|
| 类型 | 数据与备份 |
| 数据库 | 数据目录中的 `core.db` |
| 配置 | `.lam/core/config/` |
| 项目记忆 | 工作区 `.lam/memory/` |
| 附件 | 数据目录内 |
| 备份前提 | 先完全退出应用 |

## 概述

Sunday 的会话、项目登记和运行状态保存在本机数据目录；设置、模型和供应商信息使用配置文件。<sup>[1][2]</sup>

安装目录和数据目录不一定是同一个位置。重装应用未必会删除或迁移用户数据，因此排查前先确认实际路径。

## 重要数据位置

| 数据 | 位置 |
|---|---|
| 核心数据库 | 数据目录中的 `core.db` |
| 全局配置 | `.lam/core/config/` |
| 项目记忆 | 工作区 `.lam/memory/` |
| 附件与部分插件数据 | 数据目录内 |
| 项目文件 | 各项目自己的工作目录 |

配置根目录可以通过环境变量更改。桌面安装版的数据根目录由系统和安装方式决定，应通过应用日志或安装说明确认实际位置，不要仅凭开发环境路径查找。

## 备份步骤

1. 完全退出 Sunday。
2. 复制整个数据目录。
3. 复制配置目录。
4. 复制工作区中重要项目文件。
5. 复制各项目的 `.lam/memory/`。
6. 备份用户自建的技能与插件。
7. 记录版本号、模型配置方式和工作区位置。

涉及 API 密钥的配置文件应按密码级别保护，避免上传公开网盘或代码仓库。

迁移后先核对文件数量，并确认数据库可以打开，再启动应用。

## 恢复问题

数据库无法打开时：

1. 保留原始文件，不要覆盖。
2. 使用最后一份完整备份恢复。
3. 确认配置路径与工作区位置一致。
4. 再启动应用。

不要反复覆盖唯一备份。

若配置变更后服务无法连接，可以恢复最近的配置副本并核对路径。密钥不要粘贴到公开日志或求助信息中。

备份政策和加密强度取决于保存副本的位置。

## 提示

- 备份前退出应用，避免复制到写入中的数据库。
- 至少保留一份离线副本。
- 升级或大改动前先备份，不要依赖“以前没出过问题”。

## 已知问题

- 重装应用不保证保留数据，提前确认目录。
- 数据库与配置文件需要一起恢复，否则可能出现配置与记录不匹配。
