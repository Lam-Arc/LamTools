# 网络与连接

**网络设置**（Network）管理 Sunday 使用代理和自定义证书的方式。它决定模型、外部工具和下载请求怎样连接网络。

| 信息框 | |
|---|---|
| 类型 | 网络配置 |
| 入口 | 设置 → 通用 |
| 可配置 | HTTP 代理、不使用代理的地址、自定义根证书 |
| 使用代理的流量 | 模型、MCP、命令工具、网页、插件安装、更新 |
| 页面渲染 | 跟随系统代理 |
| 留空含义 | 直连，不读取系统环境变量 |

## 概述

网络设置只影响 Sunday 自己发起的部分请求。浏览器页面渲染、系统下载等行为可能使用系统代理，两者不是同一套配置。<sup>[1][2]</sup>

## 配置代理

在“通用”分区的“HTTP 代理”填写代理地址，例如：

```text
http://127.0.0.1:7890
```

“不使用代理的地址”填写逗号分隔的主机名或网段，让这些目标直连。

使用该代理的流量包括：

- 模型请求。
- MCP 调用。
- 命令工具的网络访问。
- 网页抓取与搜索。
- 插件安装与更新下载。

规则：

- 留空表示这些请求直连。
- 不会自动读取系统环境变量中的代理。
- 本机回环地址始终直连。
- 页面渲染跟随系统代理，不受此项控制。

## 自定义证书

如果网络环境使用自建证书，可以在“自定义证书”填写 PEM 根证书文件路径。

- 模型请求会把它作为信任根。
- MCP 和命令工具会收到相关证书环境变量。
- 留空时使用系统信任链。

路径应指向有效的 PEM 文件。路径拼错或证书内容错误会导致 TLS 验证失败。

不要把私钥当作根证书填写，也不要通过关闭安全校验绕过证书问题。

## 排查连接问题

| 现象 | 先检查 |
|---|---|
| 全部联网功能失败 | 代理地址、端口、代理进程 |
| 部分地址失败 | “不使用代理的地址”是否冲突 |
| 只有一家供应商失败 | 该供应商的地址与密钥 |
| 下载类功能失败 | 代理能否访问该站点 |
| TLS 验证失败 | 根证书路径与内容 |
| 刚改设置不生效 | 已连接服务是否需要重启应用 |

保存后，新发起的模型、MCP 和命令调用会按新设置连接。已经连接的 MCP 服务与正在运行的后台命令需要重启应用才会采用新环境。

界面错误信息通常能区分连接超时、鉴权失败与证书错误。

## 提示

- 先在本机确认代理端口可用，再填入设置。
- 内网地址加入“不使用代理的地址”，避免被代理拦截。
- 修改代理后重启应用，确保后台服务使用新配置。

## 已知问题

- 设置中的代理不会自动继承系统环境变量。
- 页面渲染与后台请求可能走不同的网络路径。
