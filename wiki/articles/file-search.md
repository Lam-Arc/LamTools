# 查找文件和内容

**文件搜索**（File search）是 Sunday 在当前工作区内按文件名或文件内容定位资料的能力。它用于不知道文件在哪、或想从大量资料中找到某个说法的场景。

| 信息框 | |
|---|---|
| 类型 | 工作区搜索 |
| 搜索方式 | 文件名、文件内容 |
| 范围 | 当前工作区可见文件 |
| 匹配方式 | 内容按字面文本匹配 |
| 不覆盖 | 整台电脑、云盘、邮件 |

## 概述

文件搜索解决“东西在哪”，不负责解释内容。搜索结果只是候选列表，找到文件后仍应读取原文件，确认上下文与完整含义。<sup>[1][2]</sup>

搜索只覆盖当前工作区内可见的文件，不会自动扫描整台电脑、云盘或邮件。

## 两种搜索方式

| 方式 | 适用情况 | 示例 |
|---|---|---|
| 按文件名 | 知道大致名称或扩展名 | “在项目里找所有 *.toml 文件” |
| 按内容 | 记得某句话或某个词 | “查找包含‘接口超时’的文件” |

文件名搜索支持通配模式。内容搜索按字面文本查找，普通标点不需要写成复杂表达式。

两种方式都可以限定目录，减少无关结果。

## 怎么提问更有效

从目标目录和关键词开始：

> 只在 core 下查 context_window，列出相关文件。

如果结果太多：

1. 换成更有辨识度的短语。
2. 限定文件类型。
3. 缩小目录范围。

拿到文件列表后，再让 Sunday 逐个读取并比较。搜索中文时，优先使用文件里原有的词；不知道确切写法时，先搜较短、常见的片段，再逐步缩小。

## 结果为空怎么办

| 可能原因 | 处理 |
|---|---|
| 项目选错 | 确认当前项目 |
| 路径拼错 | 改用更短的相对路径 |
| 文件在排除目录 | 换到目标目录内搜索 |
| 文件尚未保存 | 先保存，再搜索 |
| 大小写、空格或标点不同 | 改用更短的片段 |
| 内容确实不存在 | 换关键词或改用全局搜索 |

内容搜索是字面匹配，不会自动理解同义词或纠正错别字。

## 与全局搜索的区别

| 功能 | 范围 | 用途 |
|---|---|---|
| 文件搜索 | 当前工作区 | 找项目里的文件和词句 |
| 全局搜索 | 跨项目 | 找会话、任务、插件条目和已索引文件 |

全局搜索的入口是 Ctrl+K 或侧栏“搜索”；文件搜索通常在对话里由 Sunday 调用。两者不能互相替代。<sup>[3]</sup>

## 提示

- 搜索命中不等于结论；引用原文时保留前后段落。
- 中文关键词优先使用原文中的写法。
- 结果过多时先加目录限制，再加关键词限制。

## 已知问题

- 内容搜索不区分语义，同义词与拼写差异不会被自动匹配。
- 部分生成目录或二进制文件可能被排除在搜索之外。
