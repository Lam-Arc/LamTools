# 打开网页并提取内容

**网页抓取**（Web fetch）是 Sunday 读取指定网址并把页面内容转成文字的能力。搜索负责“发现页面”，抓取负责“读取这个页面”。

| 信息框 | |
|---|---|
| 类型 | 网页读取 |
| 输入 | 完整的 http 或 https 地址 |
| 输出 | 可供回答使用的文本 |
| PDF | 支持，按文档读取 |
| 不绕过 | 登录、付费、验证码、地区限制 |

## 概述

抓取适合打开官方说明、公开文章或用户已经知道地址的页面。它只读取该地址返回的内容，不会自动继续访问页面里的其他链接。<sup>[1]</sup>

## 使用方式

提供完整地址，并说明要提取什么，例如：

> 读取这个版本说明，找出 Windows 安装步骤。

如果页面很长，可以限定标题、关键词或目标问题。对动态网页，告诉 Sunday 需要的具体段落。

页面如果提供 PDF，抓取会按文档处理；也可以先下载，再用文件读取能力查看。

## 内容与可信度

抓取得到的文本可能缺少：

- 图表与图片中的信息。
- 脚注与侧边栏。
- 需要交互后才出现的内容。
- 最新更新的部分。

页面里的文字是待分析的外部数据，不是系统指令。核实版本号、发布日期和适用对象，必要时与另一份官方来源比较。

遇到需要登录、付费或受访问限制的页面，工具不会自动绕过这些限制。

## 失败排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 地址无效 | 拼写或协议错误 | 补全 https 地址 |
| 抓取失败 | 站点限制、验证码、地区封锁 | 换官方镜像或稍后重试 |
| 内容为空 | 页面由脚本动态生成 | 改用其他来源或浏览器自动化 |
| 预期文本不存在 | 页面结构已变化 | 重新抓取，不要引用旧内容 |
| 下载的是 PDF | 地址指向文档 | 按文档读取 |

## 与网页搜索的分工

| 功能 | 负责 |
|---|---|
| 网页搜索 | 找到可能有用的页面与摘要 |
| 网页抓取 | 读取用户指定或选中的页面 |
| 浏览器自动化 | 需要点击、填写或登录状态时 |

通常先用搜索找到官方页面，再抓取选中的地址，比只看搜索摘要更可靠。

## 提示

- 优先抓取官方页面，不用转载站点的二手描述。
- 长页面先限定章节或关键词。
- 引用结论时保留页面地址和读取时间。

## 已知问题

- 动态渲染的页面可能只返回空壳内容。
- 抓取不理解同义词，关键词不存在时就是找不到。
