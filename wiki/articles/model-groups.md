# 模型组

**模型组**（Model groups）是 Sunday 中按用途整理模型的目录方式。它把不同供应商下的模型集中到一组，便于浏览和管理，但不会创建新的连接。

| 信息框 | |
|---|---|
| 类型 | 目录整理 |
| 入口 | 设置 → 模型与供应商 → 模型组 |
| 成员来源 | 已登记的任意模型 |
| 删除组 | 只删除整理关系，不删除模型 |
| 移出成员 | 只移出组，不删除模型 |
| 对默认模型 | 无影响 |

## 概述

模型组解决“模型太多、按用途找起来麻烦”的问题。它只改变设置页里的组织方式，不改变模型本身的能力、连接或默认选择。<sup>[1]</sup>

一个模型可以属于多个组；组内模型仍属于原来的供应商。

## 建立分组

1. 打开“设置 → 模型与供应商”。
2. 切换到模型组视图。
3. 点击“新建模型组”。
4. 输入名称并保存。

可以按用途命名，例如“日常对话”“代码审查”“长文阅读”。组名应让人一眼看出用途，不要把服务商名称、密钥等信息写进名称。

左侧可以搜索模型组，并选择要查看的一组。

## 添加和新建成员

有两种方式：

| 方式 | 行为 |
|---|---|
| 添加已有模型 | 从已登记模型中勾选成员 |
| 新增模型 | 直接建立模型并加入该组 |

组内模型仍属于其原有供应商。修改连接信息要回到供应商视图处理，不要在组里寻找地址或密钥字段。

成员可以从组中移出而不删除模型本身。确认按钮保存成员列表，取消则退出编辑。

## 重命名与清理

组详情页支持：

- 重命名模型组。
- 删除模型组。
- 移出成员。

删除组用于清理整理关系，不等于删除所有模型。界面会区分“删除”和“移出组”，操作前看清文字。

若一个组显示为空，检查成员编辑是否保存，并确认相关模型记录仍然存在。

## 与运行选择的关系

模型组用于设置页内的组织与浏览：

- 不保证聊天模型菜单按组过滤。
- 不改变默认模型。
- 不改变模型能力或思考档位。

要设置新会话的默认模型，使用模型行上的“设为预设首选”；要改变当前运行，使用聊天输入框的模型菜单。

## 提示

- 按用途建组，不要按供应商建组，供应商视图已经能完成这件事。
- 一个模型可以同时出现在多个用途组中。
- 清理组前先确认成员是否还需要。

## 已知问题

- 模型组不参与运行时的模型选择逻辑。
- 删除组与删除模型是两个不同操作。
