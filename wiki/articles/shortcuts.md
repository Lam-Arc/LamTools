# 快捷键与快速定位

**快捷键**（Keyboard shortcuts）是 Sunday 桌面端提供的键盘操作。不同输入区域使用不同的按键规则，同一个组合键在聊天输入框、历史消息编辑框和队列编辑框中可能对应不同动作。

| 信息框 | |
|---|---|
| 类型 | 键盘操作 |
| 作用域 | 桌面工作台 |
| 全局快捷键 | 4 个 |
| 输入框内 | 优先保留文字编辑行为 |
| 相关区域 | 工作台、聊天输入框、历史消息、队列、文档编辑器 |

## 概述

工作台快捷键在文档层面监听按键，但会避开正在输入文字的控件。唯一的例外是 Ctrl+K：它在输入框内也会打开搜索，因为搜索本身不依赖当前输入内容。<sup>[1]</sup>

## 工作台快捷键

| 按键 | 操作 | 生效条件 |
|---|---|---|
| Ctrl+K | 打开全局搜索 | 任何位置，包括输入框内 |
| Ctrl+N | 创建新会话 | 焦点不在文字输入区 |
| Ctrl+O | 打开项目选择 | 焦点不在文字输入区 |
| Ctrl+B | 切换左侧栏固定状态 | 焦点不在文字输入区 |

在输入框中，Ctrl+N、Ctrl+O、Ctrl+B 会保留给文字编辑或输入法，不触发工作台动作。不要把搜索弹窗里出现的所有提示都当成已经绑定的快捷键；本表按实际处理逻辑整理。

## 发送与引导

聊天输入框的 Enter 键有两种用法：

| 按键 | 行为 |
|---|---|
| Enter | 发送当前输入 |
| Ctrl+Enter | 越过排队，直接引导正在运行的任务 |
| Shift+Enter | 换行，不发送 |

“直接引导”会让这条消息优先进入当前运行，而不是排到后面。任务没有在运行时，它与普通发送没有区别。

## 编辑消息与队列

| 场景 | 按键 | 行为 |
|---|---|---|
| 编辑已发送的消息 | Ctrl+Enter | 确认并发送修改 |
| 编辑已发送的消息 | Esc | 取消编辑 |
| 编辑队列中的待发送文字 | Enter | 保存 |
| 编辑队列中的待发送文字 | Esc | 取消 |
| 编辑队列中的待发送文字 | 失去焦点 | 尝试保存 |

历史消息编辑与队列编辑是两套独立流程，不能用同一个按键规则类推。

文档编辑器另有一套规则：Enter 延续列表，Tab 缩进，Shift+Tab 减少缩进，Ctrl+B 加粗。<sup>[2]</sup>

## 在长对话中定位

对话大纲用于在不同轮次之间跳转。聚焦大纲项目后：

- 方向键在项目之间移动。
- Home 跳到第一项，End 跳到最后一项。
- Enter 或空格进入目标轮次。

按内容寻找旧消息时，使用[全局搜索](search.md)比翻大纲更快。<sup>[3]</sup>

## 按键没有反应怎么办

1. 确认焦点是否在输入框、弹窗或其他程序中。
2. 用界面上的同名按钮验证功能本身是否可用。
3. 检查是否有其他程序占用了同一个组合键。

快捷键冲突不代表功能不存在。不要反复按创建会话的快捷键，以免生成多条空会话。

## 提示

- 输入文字时使用 Ctrl+K 搜索，不会丢失草稿。
- 想在任务运行中插话，用 Ctrl+Enter 直接引导，而不是普通发送。
- 队列编辑可直接用 Enter 保存，不需要找保存按钮。

## 已知问题

- 不同操作系统上，部分组合键可能被系统或输入法占用。
- 手机端键盘不适用本条目。
