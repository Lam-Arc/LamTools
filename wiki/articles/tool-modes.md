# 工具模式

**工具模式**（Tool mode）是 Sunday 中按工作模式组织工具、并决定哪些工具参与工作的设置。它让用户看到某个模式包含哪些能力，而不是面对一份无分类的工具总表。

| 信息框 | |
|---|---|
| 类型 | 工具配置 |
| 入口 | 设置 → 工具模式 |
| 内容 | 工作模式、模式说明、工具清单 |
| 工具类别 | 技能、MCP、子代理、记忆、RAG、插件工具、控制 |
| 影响范围 | 后续请求的工具清单 |
| 与权限的区别 | 模式决定“有哪些工具”，权限决定“能否执行” |

## 概述

工具模式把协同工作的一组能力放在一起。模式内容取决于已安装的插件、技能和外部工具服务，不是固定清单。<sup>[1]</sup>

模式与权限是两个层面：

- **工具模式**回答“这次可以用哪些工具”。
- **权限预设**回答“这些工具执行时需不需要确认”。

关闭一个工具，不会自动开放另一个；放开权限，也不会把不存在的工具变出来。

## 选择工作模式

1. 打开“设置 → 工具模式”。
2. 在左侧模式列表中搜索或选择模式。
3. 阅读模式说明。
4. 检查该模式的工具清单。

模式用于组织能力，不代表所有工具都已连通。某项能力是否真的可用，还要看对应插件、技能或 MCP 服务是否启用。

## 搜索工具与类别

工具列表支持按名称搜索，并按来源分类：

| 类别 | 说明 |
|---|---|
| 技能 | 由技能提供的工具 |
| MCP | 外部服务的查询入口；实际调用通过命令执行 |
| 子代理 | 委派给子代理的能力 |
| 记忆 | 读写记忆的工具 |
| RAG | 检索增强相关工具 |
| 插件工具 | 插件自带的工具 |
| 控制 | 运行控制类工具 |

每个工具的名称与说明用于判断作用。搜索结果为空时，先清空过滤词，再检查插件或技能是否启用。MCP 工具还需要在插件详情中确认连接与配置。

## 调整后的行为

更改工具配置后：

- 同一压缩周期内工具数组冻结；更改工具配置后，要等到压缩、新会话或重启才进入请求。
- 已经开始的调用可能仍按当时的状态完成。
- 期间调用尚未进入数组的工具，会收到“当前工具组未更新”的提示。

工具不可用时，按以下顺序检查：

1. 对应插件、技能或 MCP 服务是否安装。
2. 是否启用。
3. 是否适用于桌面端。
4. 当前模式是否包含该工具。

思索模式使用 1 级操作上限，因此可以执行只读命令，而不会把整个命令工具一概禁用。MCP 工具不再动态加入模型工具数组，其查询与调用方式见[MCP](mcp.md)。

## 与权限预设的区别

| 设置 | 控制内容 | 典型问题 |
|---|---|---|
| 工具模式 | 工具有没有被提供给模型 | “为什么它不用这个工具？” |
| 权限预设 | 工具执行前是否要确认 | “为什么它停下来问我？” |

任务依赖某个工具时，可以在请求中说明目标；应用会根据当前可用能力选择。但不要仅凭类别名称推断工具一定已经连通。

## 提示

- 先读模式说明，再逐项关闭工具，避免误以为任务仍能自动完成。
- 搜索工具时用具体名称，不要用宽泛的类别词。
- 工具变更后，用一轮小任务验证，再处理重要文件。

## 已知问题

- 工具清单随插件安装状态变化，不同设备可能不同。
- 已开始的运行不会因为中途改设置而立刻换用新工具。
