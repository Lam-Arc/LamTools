# 提问

**提问**（Question）是 Sunday 在缺少必要信息、存在多个选择或需要用户确认方向时，通过提问工具发起的交互。提问会暂停当前运行，直到用户选择选项、输入文字或跳过。<sup>[1][2]</sup>

| 信息框 | |
|---|---|
| 类型 | 决策交互 |
| 工具 | 提问工具 |
| 作用域 | 主会话与子代理会话 |
| 入口 | 聊天待处理面板、聊天内提问卡 |
| 记录位置 | [决策池](decision-pool.md) |
| 当前状态 | 启用 |

## 概述

提问不是普通文本回复，而是会改变回合状态的交互。模型发起提问后，运行进入等待；用户回答后，答案作为该工具的结果返回模型，运行继续。提问与[审批](approvals.md)共用决策池、顺序和归属规则，但两者的安全语义不同：提问的回答可以被超时跳过，审批不可以。<sup>[2][3]</sup>

## 工具参数

提问工具接受三类内容：<sup>[1]</sup>

| 内容 | 必填 | 含义 |
|---|---|---|
| 问题文本 | 是 | 展示给用户的问题或确认语句 |
| 可选项 | 否 | 选项列表；每项包含标签和可选的说明 |
| 背景说明 | 否 | 帮助判断回答范围的上下文 |

未提供可选项时，服务端生成两个默认选项：“确认并继续”和“跳过问题”。前者把确认文本作为回答，后者把“用户跳过了这个问题”作为回答。<sup>[2]</sup>

## 回答方式

### 选项

选项在卡片中按顺序展示。选择一项后，该选项的回传文本作为答案；若选项没有单独的回传文本，则使用选项标签。选项标识与标签分离，标签文本不会被当作决定动词。<sup>[2]</sup>

### 自由输入

卡片提供文字输入时，用户可以输入选项之外的说明。文字答案以引导形式回传，模型据此调整问题或按用户给出的约束继续。<sup>[3]</sup>

### 跳过

“跳过问题”表示没有收集到用户答案，而不是选择了某个选项。开启提问自动继续后，五分钟未回答会以同一语义回传，并在答案文本中说明等待时间和未收集到答案。<sup>[4]</sup>

## 生命周期

提问卡遵循决策池的统一阶段：

| 阶段 | 状态 | 行为 |
|---|---|---|
| 出现 | 待回答 | 运行进入等待，卡片可回答 |
| 处理中 | 处理中 | 回答已被持久续跑任务接受，卡片显示“处理中” |
| 结束 | 已回答、已取消、已过期 | 卡片从池中移除，运行继续或结束 |

答案落库后卡片立即结束，不需要等到下一轮模型请求。重复点击已经回答的卡片不会创建第二个续跑任务；过期或失去运行时归属的卡片会被标记为已取代。<sup>[3]</sup>

## 自动继续

设置中的“提问自动继续”控制这一行为。开启后，提问卡在五分钟内无人回答时，界面以“用户跳过”回传并继续当前回合。<sup>[4][5]</sup>

| 条件 | 自动继续 |
|---|---|
| 卡片类型为提问 | 适用 |
| 卡片类型为审批 | 不适用 |
| 回合已暂停、取消或结束 | 不适用 |
| 用户已经手动回答 | 取消计时 |
| 回传失败 | 重新计时，等待下一次窗口 |

计时器只在提问卡出现时读取一次偏好，避免每次界面刷新都请求设置。自动继续的答案文本明确说明这是超时跳过，模型不会把它误认为用户选择。<sup>[4][5]</sup>

## 子代理提问

子代理可以发起提问。此类交互带有代理名称与投递者信息，在父会话时间线上可见，但归属仍属于子代理。回答按请求标识路由回子代理的运行状态，续跑任务也登记在子代理会话上。<sup>[3][6]</sup>

父任务结束不自动关闭子代理仍然等待的提问；子代理提问也不改变父回合的状态。关闭或删除子代理时，其待回答的交互会随运行一起处理。<sup>[6]</sup>

## 提示

- 选项能表达意图时优先选择选项；需要附加限制时使用自由输入说明。
- 提问卡显示“处理中”后不必重复提交；答案已经进入持久任务。
- 自动继续只适用于提问，不应把它理解为对所有等待的通用超时策略。
- 来自子代理的提问应结合卡片上的来源信息判断属于哪个子任务。

## 已知问题

1. 工具在自动批准路径下可能直接返回“未收集到用户答案”的占位结果；正常提问应通过权限闸门暂停运行。
2. 同一会话可以同时存在多张提问卡，但续跑以会话为串行单位，回答顺序会影响后续推进顺序。
3. 旧快照缺少决策池字段时，界面会退回消息树查找提问卡；该兼容路径只能识别消息树中仍然存在的卡片。

## 历史

- **2026 年 10 月**：提问成为决策池中的一等交互，回答通过持久任务续跑。
- **2026 年 10 月 22 日**：提问卡只由单一事件生成；回答落库即出池；重复等待事件不再生成无选项的第二张卡。
