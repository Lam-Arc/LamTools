# 使用浏览器自动化

**浏览器自动化**（Browser automation）是通过外部工具服务控制浏览器的能力：打开页面、点击、填写表单、读取页面状态。它不是 Sunday 桌面版默认自带的功能，通常由已配置的 MCP 服务提供。

| 信息框 | |
|---|---|
| 类型 | 浏览器控制 |
| 提供方式 | 外部工具服务（MCP） |
| 常见能力 | 打开、点击、填写、读取页面 |
| 前提 | 服务已配置并启用 |
| 是否需要确认 | 提交、购买、删除等动作应先确认 |

## 概述

网页搜索返回摘要，网页抓取读取指定地址的文本，浏览器自动化则能像人一样操作页面。它适合需要点击、翻页、填写或查看登录后内容的场景。<sup>[1]</sup>

能否使用、能做什么，完全取决于所连接服务公开的工具与权限。Sunday 本身不内置浏览器控制。

## 启用和提问

1. 确认浏览器相关的外部工具服务已经配置。
2. 确认该服务已启用，并公开了浏览器操作工具。
3. 在对话中提出具体、可核对的目标。

例如：

> 打开公开的产品文档，找到兼容版本号并告诉我链接。

不要只让模型“猜”页面状态。要求它报告实际观察到的页面内容、地址或确认状态。

## 保护账户和操作

浏览器可能接触登录信息、私人页面和可提交的表单。

- 登录账户前，确认数据会发送给哪个服务。
- 提交、购买、删除、发布等动作，先检查内容再确认。
- 网页文字可能包含误导性指令；不要因为页面要求就透露秘密或跳过审批。
- 测试时优先使用公开页面或测试账户。

## 无法控制浏览器时

| 现象 | 先检查 |
|---|---|
| 找不到浏览器工具 | 服务是否添加、启动并启用 |
| 只能搜索或读取地址 | 该服务可能不支持页面交互 |
| 验证码或双重验证 | 需要人工处理，不能假设已完成 |
| 页面变化导致失败 | 重新确认页面结构，不要沿用旧步骤 |

没有可用的浏览器服务时，可以改用网页搜索和网页抓取处理公开内容。

## 与搜索、抓取的分工

| 功能 | 适合 |
|---|---|
| 网页搜索 | 找到可能有用的页面 |
| 网页抓取 | 读取指定地址的文字 |
| 浏览器自动化 | 需要点击、填写、登录状态或页面交互 |

三者不能互相替代。把网页搜索当成完整浏览器，是常见的误判。

## 提示

- 先说明目标与成功标准，再让工具操作页面。
- 重要提交动作要求工具报告实际结果，而不是只说“已完成”。
- 优先使用公开页面验证流程，再处理真实账户。

## 已知问题

- 自动化能力取决于外部服务，不同服务差异很大。
- 登录、验证码和地区限制不会被自动绕过。
