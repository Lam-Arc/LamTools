# 查看或停止后台进程

**后台进程**（Background process）是 Sunday 以脱离当前命令的方式启动的长时间运行程序，例如开发服务器、预览站点或监听任务。Sunday 可以列出当前会话登记过的进程，并停止由本会话启动的进程。

| 信息框 | |
|---|---|
| 类型 | 进程管理 |
| 范围 | 当前会话登记的进程 |
| 操作 | 查看状态、停止进程 |
| 健康检查 | 可选，用地址确认服务可访问 |
| 日志 | 记录工作区内的日志位置 |
| 应用退出 | 长期后台进程随之结束 |

## 概述

普通命令执行完就结束；后台进程会持续运行，因此需要单独的登记与停止机制。Sunday 只管理当前服务登记过的进程，不会按编号结束任意系统进程。<sup>[1][2]</sup>

## 查看进程

在对话中说“列出我启动的后台服务”，Sunday 会显示当前会话登记的进程及状态。

进程记录通常包含：

- 进程编号。
- 启动命令。
- 所属会话。
- 是否仍在运行。
- 日志位置。

应用重启后，旧进程可能只剩展示信息。出于安全原因，仅凭编号无法证明它仍属于原来的命令，因此这类记录不会被直接结束。

## 健康检查与日志

启动后台任务时，可以提供健康检查地址，例如本地网页地址。工具会访问该地址，确认服务是否真的可以访问；只看到进程存在，不代表服务已经准备好。

健康检查可以配合响应文本匹配使用：不仅要求地址可访问，还要求页面包含指定文字。这样可以区分“端口有响应”和“服务真的启动完成”。

启动失败或服务不可达时，可以读取工作区内记录的日志，判断是命令本身失败，还是启动后无法访问。

## 停止进程

先列出进程，再指定列表中返回的进程编号，例如：

> 停止刚才启动的预览服务。

规则：

- 只接受当前服务登记过的编号。
- 不负责结束任意系统进程。
- 停止前确认进程对应的项目和服务，避免误停其他任务。
- 应用退出时，长期后台进程也会结束。

## 端口或启动检查失败

| 提示 | 可能原因 | 处理 |
|---|---|---|
| 端口被占用 | 已有旧服务仍在运行 | 查看已有进程或换空闲端口 |
| 健康检查不可达 | 地址、端口或路径不对 | 确认服务实际监听位置 |
| 响应文本不匹配 | 页面没有指定内容 | 检查服务是否真的启动完成 |
| 不是当前工作区的服务 | 地址指向了旧服务 | 核对端口与项目 |

不要盲目重复启动同一个服务。重复启动往往会制造更多占用端口的进程。

## 提示

- 启动长期服务时同时提供健康检查地址和日志位置。
- 停止前先列出进程，确认编号与命令对应。
- 端口冲突时优先停止旧进程，而不是不断换端口。

## 已知问题

- 应用重启后，旧进程记录可能无法安全停止。
- 健康检查只证明地址可访问，不证明业务逻辑正确。
