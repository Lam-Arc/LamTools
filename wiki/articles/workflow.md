# 创建和运行工作流

**工作流**（Workflow）是 Sunday 内置插件提供的节点图执行方式。它把输入、处理步骤和输出连接起来，适合重复、可检查的任务，并提供运行队列与历史记录。

| 信息框 | |
|---|---|
| 类型 | 节点图工作流 |
| 入口 | Workflow 模式（插件提供） |
| 组成 | 输入节点、处理节点、输出节点 |
| 触发方式 | 手动、单次、间隔、日历、事件 |
| 调度 | 由定时任务承担 |
| 数据位置 | 工作流定义与运行状态保存在本地 |

## 概述

工作流把一次任务的多个步骤固定下来，减少每次重新描述的成本。它适合数据处理、定期检查、批量生成这类步骤明确的工作。<sup>[1]</sup>

工作流不会自动让外部服务可用。模型、命令、连接器和审批都受当前环境限制。

## 从简单流程开始

1. 从 Workflow 模式进入画布。
2. 放入输入节点、处理节点和输出节点。
3. 连接它们。
4. 设置节点所需模型、提示、参数或命令。
5. 填写运行输入并启动。
6. 用一组小而明确的示例数据检查输出。
7. 保存后再次运行，查看状态、耗时和错误。

复杂流程可以用子工作流拆分复用。

## 节点与连接

数据从输入节点流向处理节点，再汇总到输出节点。

- 左侧节点目录列出当前可添加的类型。
- 选中节点后可以配置字段并连接端口。
- 节点的实际参数由类型定义决定。

常见节点包括输入、输出、常量、模板、模型、智能体、命令、Python 脚本、条件、合并、汇聚、等待事件、人工审批和子工作流。详细说明见[Workflow 节点、输入和运行控制](workflow-nodes.md)。

## 触发方式

| 类型 | 需要填写 |
|---|---|
| 手动 | 无 |
| 单次 | 日期时间 |
| 间隔 | 正数秒数，可选开始时间 |
| 日历 | 每天或每月，使用指定时区 |
| 事件 | 事件类型 |

实际调度由定时任务承担。可以设置最大运行次数。停用或修改触发后，检查定时任务中的状态与下一次运行时间。

## 运行限制和排查

- **命令或 Python 节点**：会执行本机动作，运行前检查代码、路径和权限。
- **模型节点**：受模型配置与网络影响。
- **等待事件或人工审批**：会暂停，直到收到信号或完成审批。
- **连接器节点**：受当前主机授权能力限制，不能假设任意账号已接通。

失败时先打开对应节点的运行记录，确认输入和上游结果，再修正并重试。

## 提示

- 先用小数据验证流程，再扩大到真实资料。
- 把会写入的节点放在流程末尾，减少失败时的副作用。
- 需要人判断的步骤用人工审批节点，不要靠模型猜。

## 已知问题

- 工作流持久化不代表外部服务一定可用。
- 策略限制会让运行进入可重试暂停，而不是立刻失败。
