# 查看 Git 状态和改动

**Git 查看**（Git status and diff）是 Sunday 通过运行本机命令读取当前工作区版本控制状态与差异的能力。它用于检查，不会自行提交或推送。

2026 年 10 月的插件系统重构删除了独立的内置 Git 插件。Git 查看改由运行本机命令执行，不再占用一组专用工具。<sup>[1][3]</sup>

| 信息框 | |
|---|---|
| 类型 | 版本控制查看 |
| 提供方式 | 运行本机命令 |
| 常用命令 | `git status`、`git diff` |
| 范围 | 当前工作区 |
| 是否提交 | 否 |
| 是否推送 | 否 |
| 变更 | 2026 年 10 月起不再有独立 Git 工具 |

## 概述

Git 状态说明哪些文件被修改、哪些尚未跟踪；差异说明具体改了什么。两者结合，才能判断一次工作是否只动了预期范围。<sup>[1]</sup>

这些命令只读。需要提交、推送或撤销时，必须明确提出相应操作，并审阅具体改动。命令是否需要确认取决于命令本身的危险等级：查看类命令通常直接执行，包含重置、清理、强制切换等动作的命令会要求确认。<sup>[1][2]</sup>

## 查看状态

可以要求执行：

> 运行 git status --short，列出当前项目的改动。

结果按行显示状态与路径，常见标记包括：

- 新增文件。
- 修改文件。
- 删除文件。
- 未跟踪文件。

结果很多时，可以限定路径，或先让 Sunday 概括改动范围。开始处理任务前检查状态，能区分本次工作和原有改动。

## 查看差异

可以查看整体差异，也可以限定文件：

> 运行 git diff，只看 core/ui/src 下改了什么并解释影响。

注意：

- 未跟踪文件通常不会出现在普通差异中。
- 删除与重命名要结合状态一起理解。
- 差异为空可能是文件未保存、改动未被跟踪，或路径不对。

对代码改动，建议继续要求说明行为变化、潜在影响和未验证之处。

## 排查与限制

| 现象 | 先检查 |
|---|---|
| 提示不是 Git 仓库 | 项目根目录是否正确 |
| 差异为空 | 文件是否保存、是否被跟踪、路径是否正确 |
| 状态很多 | 指定文件或目录 |
| 看不到新文件 | 未跟踪文件需要单独处理 |
| 命令被拦截 | 命令是否包含危险动作、是否需要确认 |

Git 查看不能替代备份，也不能证明代码正确。它只显示版本控制能识别的变化。

## 与回退操作的区别

| 操作 | 作用 |
|---|---|
| 运行状态与差异命令 | 只读检查 |
| 删除消息及之后内容 | 只影响会话记录 |
| Git 撤销 | 需要明确要求并审阅 |

会话回退不会恢复文件，Git 查看也不会撤销任何改动。

## 提示

- 开工前先看状态，收工后再看一次。
- 让 Sunday 解释差异时，要求它区分“行为变化”和“格式变化”。
- 提交前确认没有把密钥或临时文件带进去。
- 需要长期重复的检查，可以写成技能或斜杠命令，减少每次复述。

## 已知问题

- 不再有独立的 Git 状态与差异工具，所有查看都通过运行本机命令完成。
- 未跟踪文件的正文不会出现在普通差异里。
- 非 Git 目录无法提供状态与差异。
- 包含危险动作的 Git 命令会进入确认流程，不能自动放行。
