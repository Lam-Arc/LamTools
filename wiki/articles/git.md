# 查看 Git 状态和改动

**Git 查看**（Git status and diff）是 Sunday 读取当前工作区版本控制状态与差异的能力。它用于检查，不会自行提交或推送。

| 信息框 | |
|---|---|
| 类型 | 版本控制查看 |
| 提供方式 | 内置 Git 插件 |
| 工具 | 状态、差异 |
| 范围 | 当前工作区 |
| 是否提交 | 否 |
| 是否推送 | 否 |

## 概述

Git 状态告诉你哪些文件被修改、哪些尚未跟踪；差异告诉你具体改了什么。两者结合，才能判断这次工作是否只动了预期范围。<sup>[1]</sup>

这两个工具只读。需要提交、推送或撤销时，必须明确提出相应操作，并审阅具体改动。

## 查看状态

可以问：

> 查看当前项目有哪些未提交改动。

状态会显示：

- 新增文件。
- 修改文件。
- 删除文件。
- 未跟踪文件。

结果很多时，可以指定某个路径，或先让 Sunday 说明改动的大致范围。

开始处理任务前检查状态，能区分本次工作和原有改动。

## 查看差异

可以查看整体差异，也可以限定文件：

> 只看 core/ui/src/... 的改动，解释影响。

注意：

- 未跟踪文件通常不会出现在普通差异中。
- 删除与重命名要结合状态一起理解。
- 差异为空可能是文件未保存、改动未被跟踪，或路径不对。

对代码改动，建议继续要求说明行为变化、潜在影响和未验证之处。

## 排查与限制

| 现象 | 先检查 |
|---|---|
| 提示不是 Git 仓库 | 项目根目录是否正确 |
| 差异为空 | 文件是否保存、是否被跟踪、路径是否正确 |
| 状态很多 | 指定文件或目录 |
| 看不到新文件 | 未跟踪文件需要单独处理 |

Git 视图不能替代备份，也不能证明代码正确。它只显示版本控制能识别的变化。

## 与回退操作的区别

| 操作 | 作用 |
|---|---|
| 查看状态与差异 | 只读检查 |
| 删除消息及之后内容 | 只影响会话记录 |
| Git 撤销 | 需要明确要求并审阅 |

会话回退不会恢复文件，Git 查看也不会撤销任何改动。

## 提示

- 开工前先看状态，收工后再看一次。
- 让 Sunday 解释差异时，要求它区分“行为变化”和“格式变化”。
- 提交前确认没有把密钥或临时文件带进去。

## 已知问题

- 未跟踪文件的正文不会出现在普通差异里。
- 非 Git 目录无法提供状态与差异。
