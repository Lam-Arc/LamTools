# Workflow 节点、输入和运行控制

**工作流节点**（Workflow nodes）是工作流中的处理单元。节点把数据从入口传到处理步骤，再汇总成结果。

| 信息框 | |
|---|---|
| 类型 | 节点类型与运行策略 |
| 节点来源 | 画布左侧节点目录 |
| 数据流 | 输入 → 处理 → 输出 |
| 运行输入 | 由工作流定义的输入项生成 |
| 运行策略 | 优先级、并发、速率、节流、防抖 |
| 副作用节点 | 命令、Python 脚本、智能体 |

## 概述

节点由一个类型定义决定它能接收什么、输出什么、需要哪些配置。先读类型说明，再连线。<sup>[1][2]</sup>

画布左侧的节点目录只列出当前可添加的类型；旧版类型可能隐藏，仅用于兼容已有工作流。

## 内置节点速查

| 节点 | 用途 |
|---|---|
| 输入、输出 | 暴露工作流输入；输出节点需要接收一个值 |
| 常量、模板 | 提供固定 JSON 值；按命名输入生成文字 |
| 模型、智能体 | 调用选定模型生成内容；调用可使用工具的独立助手 |
| 命令、Python 脚本 | 执行主机批准的 Shell 命令或 Python 脚本 |
| 条件 | 用表达式把数据送到 true 或 false 输出 |
| 合并、汇聚 | 合并时输出首个有效输入；汇聚时把具名输入收集为一个对象 |
| 等待事件、人工审批 | 持久暂停，等待匹配事件或批准/拒绝结果 |
| 子工作流 | 调用另一个已保存的工作流，并传入输入 |

## 运行输入

运行表单根据工作流定义的输入参数生成字段：

| 类型 | 输入方式 |
|---|---|
| 文字 | 文本框 |
| 数字 | 数字框 |
| 开关 | 开关 |
| 对象、数组 | JSON 编辑器 |

必填字段缺失会阻止提交。JSON 顶层必须是对象或数组，格式错误时表单会拒绝。

## 运行策略

策略面板可以配置：

- 队列优先级。
- 并发上限。
- 速率限制。
- 最小间隔节流。
- 防抖窗口。

防抖可以采用“首个”或“最后一个”执行模式。被策略限制的运行会进入可重试暂停状态，不占用执行槽。

策略不是对节点动作的审批替代。命令与写入仍然受权限控制。

## 配置和排错

连线顺序：

1. 输入节点连到处理节点。
2. 处理结果连到输出节点。
3. 检查字段名、类型和条件分支。

| 现象 | 检查 |
|---|---|
| 空输出 | 上游节点状态、命中分支 |
| 必填缺失 | 运行输入表单 |
| 运行被暂停 | 策略限制、等待事件或审批 |
| 命令失败 | 路径、权限、命令内容 |
| 模型节点失败 | 模型配置与网络 |

命令与 Python 节点会执行本机操作，必须核对内容及权限。

## 提示

- 先用常量或模板节点替代外部输入，验证主流程。
- 条件分支要给两个出口都接上节点或明确结束。
- 把有副作用的节点放在可回退的位置。

## 已知问题

- 隐藏的旧版节点仍可能出现在已有工作流中。
- 策略限制与审批是两套机制，不能互相替代。
