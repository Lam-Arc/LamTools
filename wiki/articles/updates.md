# 检查和安装桌面更新

**桌面更新**（Desktop update）是 Sunday 在应用内检查并安装新版本的能力。检查时先读取项目官网的更新清单；当清单不可用或没有当前平台的安装包时，才转向 GitHub Releases。

| 信息框 | |
|---|---|
| 类型 | 更新机制 |
| 检查顺序 | 官网清单 → GitHub Releases |
| 请求上限 | 每次约 10 秒 |
| 安装前校验 | 文件摘要 |
| 适用平台 | Windows x64、Linux x64 |
| 入口 | 设置 → 关于与更新 |

## 概述

更新分为“检查”和“安装”两个阶段。检查只读取版本信息与下载地址，不修改本机文件；安装由用户确认后才开始，并在调用安装程序前核对下载文件的摘要。<sup>[1][2]</sup>

官网清单是首选来源，因为它与安装包放在一起，通常更容易访问。GitHub 只在官网清单不可用、或清单里没有当前平台的安装包时使用。两个来源都不会把其他平台的安装包当成当前平台的替代品。

## 检查更新

在“设置 → 关于与更新”的更新卡片中查看当前版本与检查结果。

- **显示有新版本**：清单提供了更高的版本号，可能同时给出版本说明与下载入口。
- **显示已是最新**：当前可用清单没有更高版本。
- **检查失败**：可能来自网络、DNS、代理、清单格式，或两个来源都无法访问。

检查请求通常有约 10 秒的等待上限。网络较慢时可能直接失败，而不是一直等待。<sup>[1]</sup>

## 安装更新

1. 阅读版本说明，确认它确实是需要的版本。
2. 确认下载文件与当前平台相符。
3. 选择下载或安装。
4. 下载完成后等待摘要校验通过。
5. 按平台提示退出或重启应用，让安装程序完成替换。

摘要不匹配时不要手动绕过校验。正确做法是重新下载，或联系发布者确认文件。清单如果没有提供摘要，应用会失去这条安装路径，而不是跳过校验继续安装。<sup>[1][2]</sup>

不同平台的资产名称不同：Windows 是安装程序，Linux 是 AppImage 或 Debian 包。不能把其他平台的文件拿来安装。

## 更新失败排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 检查一直失败 | 网络、DNS、代理或两个来源都不可达 | 稍后重试，检查代理 |
| 有更新但无法下载 | 当前平台暂无对应安装包 | 等待该平台资产发布 |
| 下载后校验失败 | 文件损坏或被替换 | 重新下载，不要绕过校验 |
| 安装后版本没变 | 安装程序未完成替换 | 退出应用后重新安装 |

错误信息中通常会包含失败的地址，可据此判断是官网、GitHub 还是本地校验环节的问题。不要通过删除配置目录来修复更新问题；更新失败与用户数据无关。<sup>[2]</sup>

## 提示

- 更新前先备份重要项目与会话。
- 更新后先确认项目、会话和模型配置仍能读取。
- 在公司网络或受限网络中，可以稍后重试，或先确认代理是否允许访问发布地址。

## 已知问题

- macOS 当前没有受支持的桌面分发。
- 官网清单与 GitHub 都可能因网络原因不可达。
- 清单缺少摘要时，应用内安装不可用。
