# 子代理消息

**子代理消息**（Sub-agent message）是主代理与子代理之间不阻塞当前工作的书面通信。两个方向的消息都写入持久邮箱，并按运行边界投递；消息不会因为父回合结束或连接中断而消失。<sup>[1][2]</sup>

| 信息框 | |
|---|---|
| 类型 | 双向消息通道 |
| 作用域 | 父会话与子代理 |
| 方向 | 主代理到子代理、子代理到主代理 |
| 记录位置 | 本机持久邮箱 |
| 入口 | 子代理消息工具、子代理的消息工具、命令行 |
| 当前状态 | 启用 |

## 概述

主代理可以在不等待子代理返回的情况下发送补充要求；子代理也可以在运行中把进展或结果交回主代理。消息先写入邮箱，再由当前运行或下一次运行边界读取，因此发送成功不等于对方已经处理。<sup>[1][2]</sup>

子代理消息与输入框的[消息引导与排队](queued-messages.md)是两条独立通道。前者只在主代理与子代理之间传递，不进入主会话的待发送队列；后者处理用户对主会话的输入。

## 方向与工具

| 方向 | 使用什么 | 参数 | 行为 |
|---|---|---|---|
| 主代理到子代理 | 子代理消息工具 | 类型、名称、消息正文 | 写入子代理邮箱，不阻塞主代理 |
| 子代理到主代理 | 子代理自己的消息工具 | 消息正文 | 写入父会话邮箱，等待父会话读取 |

主代理发送消息时，子代理必须已经存在、类型匹配，并且不处于已关闭、已中断或失败状态。若子代理正由另一个活动进程持有，发送会被拒绝。<sup>[2]</sup>

子代理不能使用子代理消息工具向另一个子代理转发消息；子代理只能通过自己的消息工具把消息交回主代理。<sup>[1][3]</sup>

## 投递模式

主代理发送消息时，邮件的投递方式取决于子代理当前是否已有运行任务：<sup>[2]</sup>

| 子代理状态 | 投递方式 | 含义 |
|---|---|---|
| 没有活动运行 | 新回合 | 消息成为子代理新运行的输入 |
| 已有活动运行 | 下一回合边界 | 消息等待当前运行到达边界后读取 |

子代理到主代理的消息同样写入邮箱，父会话在边界读取。父回合可以在子代理仍在工作时结束，消息仍保留在邮箱中，等父会话再次被唤醒或进入下一回合时消费。<sup>[2][4]</sup>

## 持久化与去重

邮箱为每个方向保存消息正文、创建时间和投递时间。每条消息有一个稳定的消息键；相同消息键的重复写入不会产生第二份消息。<sup>[2]</sup>

| 字段 | 作用 |
|---|---|
| 方向 | 区分主代理到子代理、子代理到主代理 |
| 消息键 | 标识一次发送，用于去重 |
| 创建时间 | 保留消息顺序 |
| 投递时间 | 记录消息何时被读取 |

读取后，邮箱项标记为已投递；未投递的消息在恢复后仍然可读。消息正文与投递状态分开保存，避免读取失败时丢失内容。<sup>[2]</sup>

## 运行边界

消息在以下边界被消费：

1. 子代理没有活动运行时，主代理消息启动一次新运行。
2. 子代理已有活动运行时，主代理消息等待当前运行到达可读取的边界。
3. 子代理把消息交回主代理后，父会话在边界读取；父会话结束时，消息保留到下一次唤醒。

子代理被关闭、中断或失败后，主代理不能再向它发送消息；需要继续工作时先重新启用或创建。删除子代理会同时删除它的邮箱与会话存储。<sup>[2][3]</sup>

## 提示

- 主代理发送消息后，不应假定子代理已经读取；结果仍以子代理的回报为准。
- 子代理的补充要求应与原任务范围一致；改变目标时说明哪些部分仍需保留。
- 父会话结束不等于子代理停止；子代理消息会在父会话再次进入运行时被读取。
- 删除子代理前先关闭，避免仍有运行时被拒绝。

## 已知问题

1. 消息发送成功只表示进入邮箱，不表示对方已经处理；界面应区分“已发送”和“已读取”。
2. 父会话结束后，子代理消息需要等父会话再次被唤醒或进入下一回合才能消费。
3. 子代理不能向另一个子代理发送消息；需要跨成员协调时，由主代理转发。
