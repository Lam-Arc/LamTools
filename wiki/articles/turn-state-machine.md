# 回合状态机

**回合状态机**（Turn state machine）是 Sunday 约束一次任务从创建到结束的状态规则。它把用户意图、单次执行、人工交互、控制请求和子代理分开记录，只允许已定义的变化改变状态。

| 信息框 | |
|---|---|
| 类型 | 状态规则 |
| 作用域 | 会话、回合及其子代理 |
| 对象 | 回合、执行、交互、控制请求、子代理运行 |
| 记录位置 | 本机持久记录 |
| 终态 | 完成、失败、取消 |
| 当前状态 | 启用 |

## 概述

一次任务不是单一状态。<sup>[1][2]</sup>

- 用户发起的是**回合**。
- 回合里可能有一次或多次**执行**。
- 执行停下来等用户时产生**交互**。
- 用户点击暂停、继续、取消或终止时产生**控制请求**。
- 主代理委派工作时产生**子代理运行**。

这些对象各自有状态，但只有回合拥有会话级的所有权。

状态变化由已发生的事实驱动，而不是由调用方直接写目标状态。运行开始、交互打开、用户暂停、取消请求、运行完成或失败，都会经过同一套规则。规则里没有的变化不会发生。

## 回合与执行

| 对象 | 负责什么 |
|---|---|
| 回合 | 用户的一次完整意图 |
| 执行 | 回合的一次实际运行 |
| 交互 | 一次审批或提问 |
| 控制请求 | 一次暂停、继续、取消或重置 |
| 子代理运行 | 一次委派任务的运行记录 |

回合可以重新执行，因此一个回合可以对应多次执行。旧执行的收尾结果不能覆盖新执行或新的控制决定。

## 回合状态

| 状态 | 含义 | 是否终态 |
|---|---|---|
| 排队中 | 已创建，尚未开始执行 | 否 |
| 运行中 | 正在执行模型或工具 | 否 |
| 等待中 | 停下来等待审批、提问或其他交互 | 否 |
| 已暂停 | 用户暂停，保留继续能力 | 否 |
| 停止中 | 已请求取消，正在收尾 | 否 |
| 已完成 | 正常结束 | 是 |
| 失败 | 执行失败 | 是 |
| 已取消 | 被取消或终止 | 是 |

已暂停的回合仍拥有会话：在继续或终止之前，新的无关回合不能开始。

停止中是取消的中间状态，给正在运行的工具或模型留出结束时间，之后才进入已取消。

## 状态如何变化

| 当前状态 | 发生的事 | 目标状态 |
|---|---|---|
| 排队中 | 执行开始 | 运行中 |
| 排队中 | 取消生效 | 已取消 |
| 运行中 | 打开审批或提问 | 等待中 |
| 运行中 | 用户暂停 | 已暂停 |
| 运行中 | 取消生效 | 停止中 |
| 运行中 | 执行完成 | 已完成 |
| 运行中 | 执行失败 | 失败 |
| 等待中 | 交互得到回答 | 运行中 |
| 等待中 | 用户继续 | 运行中 |
| 等待中 | 用户暂停 | 已暂停 |
| 等待中 | 取消生效 | 停止中 |
| 已暂停 | 用户继续 | 运行中 |
| 已暂停 | 用户继续，且有可复用交互 | 等待中 |
| 已暂停 | 取消生效 | 已取消 |
| 停止中 | 执行结束 | 已取消 |
| 停止中 | 取消收尾完成 | 已取消 |

终态没有出边。

取消与终止使用同一套规则：取消从运行中进入停止中，从等待中或已暂停直接进入已取消。终止在取消的基础上，还要求中断子代理。

强制重置会绕过等待中的普通取消，直接把活动回合写成已取消，并取消未结束的交互。

## 交互：审批与提问

交互是审批与提问的统称。它不属于回合状态，但会推动回合进入或离开等待中。<sup>[1][3]</sup>

| 状态 | 含义 |
|---|---|
| 待回答 | 可以作答 |
| 暂缓 | 因回合停放而暂缓，仍属于该回合 |
| 处理中 | 回答已被接受，正在写入或续跑 |
| 已回答 | 回答已保存 |
| 已取消 | 被取消、终止或取代 |
| 已过期 | 已过期 |

| 当前状态 | 发生的事 | 目标状态 |
|---|---|---|
| 待回答 | 回答被接受 | 处理中 |
| 待回答 | 暂停、终止或取代 | 已取消 |
| 暂缓 | 恢复 | 待回答 |
| 暂缓 | 终止或取代 | 已取消 |
| 处理中 | 回答写入完成 | 已回答 |
| 处理中 | 处理失败或被拒绝 | 已取消 |

交互的终态不可逆。回答写入后，卡片立即结束并从[决策池](decision-pool.md)移除；之后到达的重复事件不能把它重新打开。

暂停时，已打开的交互可能被暂缓，也可能被取消后重新发起。界面只看到最终结果；两者的差异记录在“已知问题”中。

## 子代理状态

子代理有独立于父回合的运行状态，但父会话的暂停、恢复和终止会传播到成员。<sup>[6]</sup>

| 状态 | 含义 |
|---|---|
| 空闲 | 本轮结束，记录保留 |
| 运行中 | 正在执行 |
| 已暂停 | 停在等待用户的边界 |
| 随父暂停 | 随父会话暂停而停下 |
| 已中断 | 被停止或中断 |
| 租约过期 | 超过运行租约 |
| 已关闭 | 已关闭，记录保留 |
| 失败 | 运行失败 |
| 已完成 | 本轮完成 |
| 已删除 | 记录、邮箱与自身会话存储已删除 |

活动成员可以进入已暂停、随父暂停、失败或已中断。已暂停和随父暂停可以回到运行中。已关闭、已中断和失败可以用完全一致的配置重新打开。已删除是终态。

## 控制请求

暂停、继续、取消、终止和强制重置都先记录一条控制请求，再由协调器在回合锁内应用。<sup>[2]</sup>

处理顺序：

1. 用户发出请求。
2. 请求被记录为待处理。
3. 协调器在锁内检查回合当前状态。
4. 请求被应用、拒绝或标记为已被取代。

暂停、继续、取消和强制重置会推进回合版本。旧执行收尾时，如果它属于更早的版本，或者回合已经暂停、正在收尾或进入终态，它的完成或失败结果不会覆盖当前状态。

这样，暂停之后迟到的“运行完成”不会把回合改回已完成。

## 跨对象传播

| 控制 | 回合 | 交互 | 子代理 |
|---|---|---|---|
| 暂停 | 运行中或等待中 → 已暂停 | 旧卡取消或暂缓 | 活动成员停下并保留继续能力 |
| 继续 | 已暂停 → 运行中；有可复用交互 → 等待中 | 旧卡结束；重新发起需要的人工决定 | 被暂停的成员继续 |
| 取消 | 运行中 → 停止中 → 已取消；其他活动状态 → 已取消 | 取消未结束的卡 | 活动成员停止 |
| 终止 | → 已取消 | 取消未结束的卡 | 中断活动成员，包括停在提问上的成员 |
| 回答审批或提问 | 等待中 → 运行中 | 处理中 → 已回答 | 子代理的卡按归属回到子代理运行 |
| 强制重置 | 任何活动状态 → 已取消 | 取消全部未结束的卡 | 由调用方决定是否中断成员 |

## 不变量

1. 终态没有出边：已完成、失败、已取消不能被迟到事件改回活动状态。
2. 只有规则列出的变化可以改变回合状态。
3. 每个回合只有一个写入者；控制请求在回合锁内应用。
4. 回答写入即结束交互；卡片结束不从下一轮模型请求开始计算。
5. 决策池只显示池中的卡片；回答后移除，下一张按顺序补位。
6. 暂停的回合拥有会话，新的无关回合不能绕过继续或终止。
7. 停止中必须先完成收尾，才进入已取消。
8. 子代理的卡片显示在父会话时间线上，但归属和续跑仍在子代理自己的会话。

## 提示

- 看到“已暂停”时，先判断是用户暂停还是等待人工决定；两者后续动作不同。
- 看到“停止中”时，说明取消已经生效但工具或模型仍在收尾，不是卡死。
- 卡片结束表示决定已经保存，不表示整个回合已经完成。
- 恢复后出现新的卡片是正常结果；旧卡已经结束。

## 已知问题

1. 暂停恢复时，交互可能被暂缓复用，也可能被取消后重新发起；两条路径在卡片是否复用上尚未统一。
2. 同一会话的续跑以串行方式推进；同时显示多张卡片不代表多个等待步骤会并行续跑。
3. 旧记录中可能出现已废弃的状态名，读取时会映射到当前状态。
4. 提问自动继续目前按“跳过”处理，尚未产生“已过期”的记录。

## 历史

- **2026 年 10 月**：回合、执行、交互和控制请求成为独立对象；暂停、继续、取消和强制重置统一到一套规则。
- **2026 年 10 月 22 日**：交互终态改为不可逆；回答写入即结束卡片；卡片出现收口为单一来源。
