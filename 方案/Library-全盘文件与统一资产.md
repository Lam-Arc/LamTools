# Library × Everything：全盘文件搜索与统一资产管理

> 状态：执行中（P0/V0 + V1 主体已落地；验收记录见 `agent_docs/library-everything-acceptance.md`）
> 摘要：Library 接入本机 Everything 索引，获得全盘即时搜索；搜索到的文件可直接浏览、预览、打开、定位，并被收藏、打标签、评分、归入集合，原文件不搬家、不复制、不重建索引。
> 依据：用户提供的《Sunday Library × Everything · 全盘文件搜索与统一资产管理 PRD · V1》（全文见文末附录，未改动）。

## 一、需求与边界

### 1.1 一句话

打开 Library 就能找到整台电脑上的文件，并且能像资源管理器一样看、像资料库一样管，不必在 Everything、资源管理器和资产管理软件之间来回切换。

### 1.2 做成后用户能看到什么

- 在 Library 输入文件名，几百毫秒内出现整机结果；输入过程中结果实时更新。
- 结果可以直接预览（图片大图、视频/音频播放、PDF/文本查看），可以直接用系统程序打开，可以在资源管理器中定位。
- 可以收藏、打标签、评分、写备注、改名（只改 Library 里的显示名）、放进一个或多个集合；原文件仍在原目录。
- 可以像资源管理器一样浏览磁盘与目录，做复制、移动、重命名、删除到回收站等常用操作；这些操作直接作用于原文件。
- 文件被移动或重命名后，只要还能确认是同一份文件，标签、评分、收藏仍然跟着它。
- Everything 不可用时，Library 明确说“搜索不可用”，但目录浏览和已保存的资产信息照常可用。

### 1.3 这次不做（明确边界）

- 不复制、不移动、不重新组织用户的文件，不要求导入。
- 不建立第二套全盘文件索引；文件名/路径检索复用 Everything 现有索引。
- 不做 Anything 式自有索引重写，不把重写 Everything 当首版目标。
- 不默认对全盘做内容级全文索引，不默认给所有文件生成预览缓存。
- 不默认用 AI 分析文件内容。
- 不自动清理、合并、删除任何文件。
- 不把远端设备文件混进本地结果（多设备来源留到 V3）。
- 不重做一套窗口/分屏系统，预览与结果复用现有工作区能力。

### 1.4 三条不可混淆的界线

1. **搜索到 ≠ 已收藏**：全盘结果只是“能看见”，只有用户做过收藏/标签/评分等动作，才产生资产管理记录。
2. **删资产记录 ≠ 删文件**：从 Library 移除资产信息只删记录；删除磁盘文件必须走另一条明确的操作，并有回收站/永久删除的区分。
3. **资产记录跟着文件身份走，不跟着字符串路径走**：路径只是当前位置；能确认是同一文件时，元数据跟随移动与重命名。

## 三、取舍

### 3.1 选 Everything CLI（ES）作为首选接入方式

- **选它**：官方、单文件、无安装、直接连正在运行的 Everything；实测字段与速度满足 P0。
- **不选 SDK DLL**：需要额外分发 DLL，且同样依赖本机 Everything，收益只是省一次进程启动。
- **不选 HTTP/ETP**：默认未开启，要求用户改 Everything 设置，违背“用户不应看到技术概念”。
- **不选自研 IPC**：协议细节多、版本差异大、出错时无法给出清楚的原因，维护成本高于收益。
- **保留可替换**：搜索提供方是一层接口，将来可加 SDK、HTTP、自有索引，不改上层。

### 3.2 不把全盘结果塞进现有 `core_artifacts`

现有 `core_artifacts` 是“项目里的成果”，有项目归属、上传与来源语义。全盘文件是跨项目、只读发现，二者混在一张表会让统计、删除、同步全部变味。**新开资产表**，只记录用户真正管理过的文件；搜索结果命中时按路径合并展示，不预先写库。

### 3.3 资产身份用“卷序列号 + 文件 ID”，路径只作当前位置

Windows NTFS 上通过文件句柄取 `VolumeSerialNumber + FileIndex`，移动/重命名后不变；取不到时退回“路径 + 大小 + 修改时间”的弱身份，并明确标出不可确认的情况。不靠文件名猜，避免把标签错挂到同名文件上。

### 3.4 界面挂在现有 Library，不新开应用

新增 `本机文件` 分区，与 `资料`、`项目文件`、`记忆`、`方案`、`Wiki` 并列。预览复用现有分屏/预览能力的方向，结果列表与资产编辑在 Library 内完成。

### 3.5 搜索与浏览是两条腿

Everything 负责“找得到”，文件系统负责“走得进”。Everything 故障时浏览、预览、资产信息仍可用；首次索引或非 NTFS/网络盘的速度不套用 Everything 的目标值。

## 四、技术附录（供实施）

### 4.1 搜索提供方

`core/src/lamtools_core/library/everything.py`

- 定位 ES：配置/环境变量 → 应用数据目录 `tools/es.exe` → 仓库 `.tools/everything/es.exe`（开发）→ `%ProgramFiles%\Everything\es.exe` → `PATH`。
- 可用性：`es -get-everything-version` + 进程/版本探测；返回 `installed/running/version/es_path/message`。
- 查询：用户表达式 + 结构化筛选编译为 Everything 语法；`name/path/size/date-modified/date-created/extension/attributes` 七列导出 CSV（UTF-8 BOM），`-o`/`-n` 分页，`-sort` 排序。
- 结果数：`-get-result-count`（带短 TTL 缓存），与列表查询分开，避免为了计数拉全量。
- 失败：区分“未安装 / 未运行 / 版本不兼容 / 查询失败”，绝不把错误伪装成空结果。

### 4.2 数据表（Core 库新增，独立于 artifacts）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `core_file_assets` | asset_id、path、volume_serial、file_id、size、mtime_ns、name、display_name、favorite、rating、tags(JSON)、note、missing、missing_since、created_at、updated_at、last_seen_at | 用户管理过的文件；唯一键 `(volume_serial, file_id)`，弱身份时用路径兜底 |
| `core_file_collections` | collection_id、name、kind(manual/smart)、query(JSON)、created_at、updated_at | 普通集合与智能集合共用 |
| `core_file_collection_items` | collection_id、asset_id、added_at | 普通集合的成员 |

### 4.3 RPC（live，前端 `requestRpc` 直接用）

- `libraryfs.status`：引擎状态、索引范围、异常说明。
- `libraryfs.search`：关键词/表达式 + 类型、范围、大小、时间、排序、分页；结果合并资产信息。
- `libraryfs.browse` / `libraryfs.roots`：目录浏览与磁盘入口。
- `libraryfs.asset.get` / `libraryfs.asset.update` / `libraryfs.asset.list`：收藏、评分、标签、显示名、备注。
- `libraryfs.collection.*`：集合增删改、成员增删、智能集合求值。
- `libraryfs.file.operate`：新建、重命名、复制、移动、删除到回收站/永久删除；返回逐项结果与冲突信息。
- `libraryfs.open` / `libraryfs.reveal`：系统打开、资源管理器定位。
- `libraryfs.raw`（HTTP GET）：图片/视频/音频/PDF 预览取流，带 Range。

### 4.4 Agent 工具

新增 `library_files` 工具（与现有 `library` 资料库工具并列，不混用）：

- `search`：按关键词/类型/时间/大小/路径/标签/评分搜索。
- `stat`：文件属性与资产信息。
- `list_assets`：按标签、评分、收藏、集合筛选。
- `collect`：加入集合、打标签、评分、收藏。
- `locate`：定位文件所在目录。
- `open`：用系统程序打开（高风险操作仍走既有授权）。
- 文件写操作（移动/删除）继续受 Sunday 原有授权机制约束，工具默认只读。

### 4.5 前端

`core/ui/src/components/LocalFilesView.vue`，挂到 `LibraryHomeView` 的 `本机文件` 分区：

- 搜索栏：输入即搜（防抖 250ms），范围（全电脑/当前目录）、类型药丸、排序、视图切换。
- 视图：紧凑列表（默认）、详细信息表格、网格、瀑布流；切换保留筛选、选中与滚动位置。
- 结果：缩略图/图标、名称、目录、大小、时间、资产标记；滚动到边界继续加载，不一次性渲染一万条。
- 预览：右侧预览区（图片缩放、视频/音频播放、PDF、文本），下方资产编辑（收藏、星级、标签、备注）。
- 浏览：磁盘入口、面包屑、路径直达、前进/后退/上级、双击进入/打开。
- 状态：引擎异常条（可重试）、空结果、离线磁盘、操作进度与失败逐项说明。

## 五、实施步骤与验收方式

### 第 1 步：搜索提供方与验证

- 新增 Everything 客户端：定位、探测、查询编译、CSV 解析、计数、错误分类、超时。
- 验收：单测覆盖查询编译与解析；本机真实查询 `Everything.exe`、`*.png`、`size:>1gb`、`dm:7days` 都能返回结果与计数；杀不掉 Everything 时也能给出明确错误码。

### 第 2 步：资产表与身份

- 新增三张表与 `FileAssetStore`：身份计算（Win32 卷序列号 + 文件 ID）、按身份 upsert、路径更新、缺失标记、标签规范化、评分范围。
- 验收：同一文件移动到新路径后，用新路径查到的资产仍是同一条，标签/评分/收藏不变；复制出的第二份文件不会被误认成同一资产。

### 第 3 步：RPC 与文件操作

- 注册 `libraryfs.*`，接入 live RPC；文件操作用临时目录做单测（重命名冲突、跨盘移动、删除到回收站、失败逐项返回）。
- 验收：前端可只靠 RPC 完成“搜索 → 资产更新 → 打开/定位”；文件操作失败时有明确原因，不静默吞掉。

### 第 4 步：Library 本机文件界面

- 新分区、搜索、四类视图、预览、资产编辑、浏览与操作、状态提示。
- 验收：在真实应用里输入 `miku` 能出结果、点图能预览、能加标签与五星、能在资源管理器中定位；Everything 停掉后显示明确故障条，浏览仍可用。

### 第 5 步：Agent 工具与集合

- `library_files` 工具与智能集合求值（文件系统条件 + 标签/评分条件）。
- 验收：助手能“找出上周生成的初音图片并按大小排序”，能把结果加入集合而不复制文件。

### 第 6 步：变化追踪与重复文件（V2，按优先级推进）

- 搜索/资产列表定期核对路径与身份；离线磁盘标“离线”不删记录；同名/同大小/内容校验分组。
- 验收：外部程序新建图片后无需导入即可搜到；拔掉移动硬盘后资产显示离线且元数据不丢；只有内容一致的才标“完全相同”。

> 本轮的完成线：第 1–5 步可用并验收；第 6 步保留接口与数据结构，不阻塞 Library 成为日常文件入口。

## 六、目标与完成判据

1. 从 Library 能搜整台电脑，交互速度接近 Everything（本机目标：输入到首批结果 P95 ≤ 400ms）。
2. 搜索结果可直接预览、打开、定位，不需要跳资源管理器。
3. 全盘文件与收藏资产共用一套界面和文件身份关系；搜索命中不预写资产库。
4. 收藏、标签、评分、备注、集合在重启后仍在；移动/重命名后能跟住。
5. 不需要重复导入、重复扫描或迁移原文件。
6. Agent 与用户使用同一套搜索与资产能力。
7. Everything 只是底层依赖：故障时明确报告，不伪装成“没有结果”，不影响浏览与已保存资产。
8. 删除资产记录与删除磁盘文件严格分开；高风险操作有明确确认。

## 七、性能目标（Windows 11 / 本地 NTFS SSD / 已完成索引）

| 指标 | 目标 | 本轮验证方式 |
|---|---|---|
| 文件名查询响应 | P95 ≤ 200ms | 本机 ES 实测基线 20–67ms（计数），加列表导出与解析后复测 |
| 输入到首批结果可见 | P95 ≤ 400ms | 前端防抖 + 首批 60 条，实测记录 |
| 1 万条结果 | 可持续滚动 | 分页 100/批，按需渲染 |
| 切换视图 | 不重新全盘扫描 | 复用当前结果集，仅换渲染 |
| 资产操作 | 即时反馈、本地持久化 | SQLite 同步写入 + 乐观更新 |
| 引擎故障 | 明确报错、浏览仍可用 | 停 Everything 实测故障条 |

非 NTFS、网络磁盘、内容搜索、首次索引不套用上述数值。

## 八、风险与应对

| 风险 | 可能性 | 应对 |
|---|---|---|
| 用户机器没有 Everything 或没有 ES | 高 | 状态里给“安装/放置 CLI”的明确入口；浏览与资产功能不依赖它；后续做引导安装，不静默装服务 |
| ES 与企业安全软件冲突/被拦 | 中 | 超时与错误分类；提供 SDK/HTTP 备选接口位；不因失败卡住 UI |
| 全盘结果里隐私路径被看到 | 中 | 排除路径/磁盘设置；默认本机处理；不默认上传；Agent 读内容仍走权限 |
| 资产身份在非 NTFS/网络盘不稳定 | 中 | 弱身份并标记“无法确认”；移动后提示重新关联，不静默丢/错挂 |
| 删除误伤 | 低但后果重 | 默认回收站；永久删除独立确认；资产移除与文件删除两条路径 |
| 大目录一次性渲染卡顿 | 中 | 分页 + 虚拟滚动/懒加载缩略图 |
| Everything 索引范围与用户预期不一致 | 中 | 状态里显示索引范围；结果里标注“来自 Everything 索引” |

## 九、未答问题

1. Everything 的 ES CLI 是否随 Sunday 安装包分发，还是首次使用时下载？——影响安装体积与离线可用性；本轮先支持“探测 + 本地放置”，不阻塞功能。
2. 资产层是全局还是按项目隔离？——PRD 说“整台电脑”，本轮按本机全局资产实现；若希望项目内独立，需要再加 `project_id` 维度。
3. 预览是否必须复用分屏，而不是 Library 内右侧预览？——本轮先做 Library 内预览，分屏复用留作后续增强，避免改分屏系统。

## 十、实施结果（本轮）

### 10.1 已完成

- **搜索**：Everything 探测/查询/计数/分页/排序/错误分类；`*.png`、`size:>1gb`、`dm:7days`、`regex:` 与结构化筛选协同；空搜索展示最近变更；缺少 ES 时可一键下载官方命令行工具。
- **搜索服务**：搜索命中按路径合并资产信息；空关键词+筛选、已管理资产、集合三种入口共用一套返回结构。
- **资产层**：`core_file_assets` / `core_file_collections` / `core_file_collection_items` 三张表；收藏、评分、标签、显示名、备注、离线标记；按卷序列号+文件 ID 跟随移动与重命名；移除资产记录不删文件。
- **浏览与操作**：磁盘/目录/面包屑/路径直达/前进后退上级；新建、重命名、复制、移动、回收站、永久删除（需确认）、同名冲突策略、逐项失败说明。
- **预览**：图片（缩放/全屏/同目录左右翻）、视频/音频、PDF、文本/代码、docx/xlsx/pptx 文本、文件夹信息；缩略图批量生成并缓存。
- **集合**：普通集合增删成员；智能集合按文件系统条件 + 标签/评分/收藏求值；「保存为集合」把当前搜索条件存成智能集合。
- **RPC 与取流**：22 个 `libraryfs.*` live 操作；`/api/core/library/raw` 内联取流并支持 Range。
- **Agent**：`library_files` 工具（search/stat/list_assets/collect/collections/locate/open），不暴露文件写操作。
- **界面**：Library 新增「本机文件」分区；搜索、类型/范围/排序、列表/网格/瀑布、预览、资产编辑、批量操作、集合、窄窗抽屉、引擎故障条。

### 10.2 验收证据

- 本机 Everything 1.4.1.1032 + ES 1.1.0.26：状态 ready，索引约 783 万项；计数与列表并发后 `Everything.exe` 热查询 61–101ms，图片范围 60 条热查询 116–117ms（首次冷启动约 924ms）。
- 隔离后端真实启动，三张新表自动建出；`/api/core/library/raw` 返回 200 + `inline` + `accept-ranges`，缺失文件 404。
- 真实 WebSocket live RPC 跑通：status → search → asset.update → preview → thumbs → collection → copy → delete 拒绝 → forget。

# Sunday Library × Everything
## 全盘文件搜索与统一资产管理 PRD · V1

**状态：产品需求草案**

**目标平台：Windows 11 / Tauri 2**

**优先级：P0（Library 核心能力升级）**

---

## 1. 产品目标

让 Library 同时拥有：

- **Everything 的速度：** 全盘文件快速索引、实时搜索、文件变化追踪。
- **资源管理器的能力：** 浏览目录、打开文件、复制、移动、重命名、删除。
- **Library 的能力：** 预览、标签、评分、收藏、分组、智能集合、瀑布流展示。
- **Sunday 的能力：** Agent 搜索、理解、定位、筛选和操作本地文件。

最终效果：

用户只需要打开 Library，就能找到、查看、组织和操作电脑上的文件，而不需要在 Everything、资源管理器和其他资产管理软件之间反复切换。

### 1.1 核心原则

1. 全盘文件自动可搜索，不需要手动导入。
2. 搜索到的文件不代表已被 Library 收藏或管理。
3. Library 不强制移动、复制或重新组织用户文件。
4. 不创建第二套重复的全盘文件索引。
5. Everything 作为底层能力提供方，不作为独立用户入口。
6. 保留原生目录结构，同时支持 Library 自己的虚拟分类。
7. 功能必须可以脱离 AI 独立使用。

## 2. 产品信息架构

Library 统一管理三种信息：

| 层级 | 内容 | 用户获得的能力 |
|---|---|---|
| 全盘索引层 | 电脑上的文件和目录 | 即时查找、定位 |
| 文件操作层 | 实际文件系统 | 浏览、预览、操作 |
| 资产增强层 | Library 附加的资产信息 | 收藏、分类、标签、评分、集合 |

### 2.1 文件与资产的关系

任何被索引的文件，都可以在 Library 中搜索和浏览。

用户对某个文件执行收藏、评分、添加标签等操作后，Library 为其建立管理记录。

**不需要复制原文件，也不需要改变原文件的位置。**

例如：

`D:\Downloads\miku.png`

- 自动出现在全盘搜索结果中。
- 可以直接预览和打开。
- 可以收藏到「初音未来」集合。
- 可以添加「商业海报」「插画」标签。
- 文件仍然存放在原来的 Downloads 目录。

同一个文件可以属于多个虚拟集合，且不额外占用一份文件空间。

## 3. 核心功能需求

### P0-01｜Everything 搜索引擎接入

**目标：用户在 Library 内完成 Everything 式搜索。**

功能要求：

1. 自动检测本机 Everything 可用状态。
2. 对已安装且运行的兼容版本直接连接。
3. 使用 Everything 现有索引，不重新扫描整个硬盘。
4. 支持文件及文件夹搜索。
5. 支持文件名、路径、扩展名、大小、时间等条件。
6. 支持模糊匹配、通配符、正则表达式。
7. 支持结果数量统计、排序和分页加载。
8. 用户输入时动态更新结果，不要求按回车。
9. 文件变更后，搜索结果自动保持同步。
10. 提供搜索引擎状态、索引范围和异常提示。

用户不应看到 SDK、IPC 等技术概念。

**异常要求：**

- Everything 未安装：提供引导安装或启用兼容引擎的入口。
- 后台未启动：支持提示和授权后启动。
- 版本不兼容：明确报告问题。
- 查询失败：允许重试，不把连接失败伪装成“无搜索结果”。
- 引擎暂时不可用：已有普通文件浏览能力继续工作。

**验收：** 输入一个已知文件名，可以直接获得与 Everything 对应搜索范围一致的文件结果，并在 Library 内完成后续操作。

### P0-02｜统一搜索

Library 只提供一个主要搜索入口。

**基础模式：**

- 直接输入关键词。
- 按文件类型快速筛选。
- 选择搜索范围：全电脑、当前目录、已收藏资产、指定磁盘。
- 排序：相关性、名称、修改时间、创建时间、大小。
- 允许组合多个筛选条件。

**高级模式：**

兼容常见 Everything 搜索表达式，例如：

- `*.png`：图片文件。
- `size:>1gb`：大文件。
- `dm:7days`：最近七天修改。
- `D:\Projects\`：指定路径。
- `regex:`：正则搜索。

用户不需要学习这些语法才能使用搜索。

高级表达式与普通筛选控件应能协同工作，且不会意外改变搜索含义。

**验收：** 用户既能通过简单关键词完成搜索，也能直接使用 Everything 高级查询习惯。

### P0-03｜完整文件浏览

Library 不局限于搜索结果列表，还必须提供普通文件浏览能力。

支持：

1. 浏览磁盘、目录和子目录。
2. 路径面包屑导航及直接输入路径。
3. 文件夹双击进入，文件双击打开。
4. 后退、前进、返回上级。
5. 文件复制、剪切、粘贴、移动、重命名。
6. 新建文件、文件夹。
7. 删除至回收站与显式永久删除。
8. 多选与批量操作。
9. 操作进度、取消、失败重试。
10. 与 Windows 资源管理器互相定位。

**关键约束：**

普通文件操作直接作用于原始文件。

删除资产管理记录与删除磁盘原文件必须是两种不同操作，不能混淆。

跨磁盘移动、同名冲突、文件占用、权限不足等情况必须有明确处理流程。

**验收：** 在搜索中找到文件后，可以直接使用 Library 完成这些操作。

### P0-04｜多视图文件展示

同一批文件可以自由切换展示方式。

| 视图 | 主要用途 |
|---|---|
| 紧凑列表 | Everything 式快速搜索、密集结果 |
| 详细信息表格 | 文件属性对比、批量操作 |
| 网格视图 | 普通文件浏览 |
| 瀑布流 | 图片、设计素材、视觉资产 |
| Bento Card Grid | 收藏、集合、精选内容 |
| Dashboard | 文件分布、最近活动、常用集合 |

要求：

- 搜索默认优先展示紧凑结果。
- 图片集合默认适合使用瀑布流。
- 文件夹可记住用户选择的视图。
- 视图切换不清除筛选、选中项和当前位置。
- 大量文件必须采用按需渲染，不一次性生成全部卡片。

### P0-05｜文件预览

用户可以不离开 Library 查看文件内容。

首批支持：

- 图片：缩略图、缩放、全屏。
- 视频：封面、播放、基本信息。
- 音频：播放、进度、时长。
- PDF：页面预览。
- 文本与代码：文本浏览。
- 常用文档：可用时提供预览。
- 文件夹：包含文件数量、目录信息。

无法预览的格式仍然可以正常搜索、定位和使用系统关联程序打开。

搜索结果、目录浏览和收藏集合调用同一套预览能力。

**验收：** 在搜索结果中找到一张图片后，可以直接查看大图，而不是必须先打开 Windows 资源管理器。

### P0-06｜资产增强

Library 为现有文件附加管理能力：

1. 收藏与取消收藏。
2. 自定义标签。
3. 评分。
4. 自定义分类。
5. 自定义显示名称。
6. 备注。
7. 多集合归属。
8. 筛选与排序。
9. 批量编辑资产信息。

原始文件名与 Library 显示名称可以不同。

用户移动或重命名文件后，应尽可能自动保持原有资产信息关联；对于无法确认身份的文件，应提示重新关联，而不是直接丢失元数据或错误关联到其他文件。

**验收：** 文件从 `D:\A` 移动到 `D:\B` 后，只要能够确认是同一文件，原标签、评分和收藏仍然保留。

### P1-01｜智能集合

支持把动态搜索结果保存为集合。

示例：

- 最近七天新增的图片。
- 大于 2GB 的视频。
- Downloads 内尚未整理的压缩包。
- 所有评分至少四星的素材。
- ComfyUI 输出目录下的新图像。

集合可以由文件系统条件与 Library 标签条件联合生成。

新增符合条件的文件后，自动出现在集合中。

用户无需手动将文件拖入集合。

### P1-02｜文件变化追踪

支持感知：

- 新文件创建。
- 文件重命名。
- 文件移动。
- 文件删除。
- 文件修改。
- 存储设备离线或重新连接。

搜索结果与已收藏资产状态应保持一致。

外置硬盘断开时，关联资产可显示为“离线”，不立即删除对应管理记录。

对于不同文件系统、网络磁盘的更新延迟，需要准确呈现，不能统一声称实时。

### P1-03｜重复文件管理

支持：

- 相同名称文件查找。
- 相同大小文件查找。
- 疑似重复文件分组。
- 基于实际内容校验的完全重复识别。
- 重复文件对比预览。
- 批量处理。

只有经过内容校验的文件，才能标记为“完全相同”。

默认不自动删除重复文件。

### P1-04｜Agent 统一文件工具

Sunday Agent 应能够直接使用 Library 的统一文件能力。

包括：

- 搜索指定文件。
- 查询文件属性。
- 根据标签或评分筛选。
- 定位文件及其所在目录。
- 查看支持的文件内容。
- 向用户展示搜索结果。
- 在获得适当授权后执行文件操作。

**示例：**

用户说：“找到我上周生成的所有初音图片，按大小排序。”

Agent 直接使用 Library 搜索和筛选，并在当前工作区展示结果。

用户再说：“把其中最大的五张加到海报集合。”

Agent 可以完成资产管理操作，不需要复制这些图片。

**高风险文件操作继续受 Sunday 的原有授权机制约束。**

### P2｜其他设备与扩展来源

未来支持将其他设备的文件作为 Library 的独立数据来源。

例如通过 Sunday Relay 查询已授权电脑上的文件。

要求：

- 明确标注文件所在设备。
- 不把远端文件误认为本地文件。
- 远端操作需要单独授权。
- 断线时保留必要状态信息。
- 默认不向其他设备暴露全盘文件列表。

此能力不阻塞首版。

- 搜索结果可以在主内容区域展示。

- 用户可以同时查看搜索结果和预览。
- Agent 可引用或展示 Library 中的文件。
- 视图与筛选状态在工作区布局变化后继续保留。

不单独重新设计一套窗口与分屏系统。

## 5. 技术能力边界

### 5.1 搜索能力分层

| 能力 | 主要提供者 |
|---|---|
| 文件名与路径极速检索 | Everything |
| 文件大小、时间、扩展名过滤 | Everything / 文件系统 |
| 文件创建及变更发现 | Everything / 文件系统 |
| 文件内容搜索 | 独立内容检索能力 |
| 文件预览与缩略图 | Library |
| 标签、评分、收藏、集合 | Library |
| 文件复制、移动、删除 | 文件操作层 |
| 自然语言理解和任务执行 | Sunday Agent |

文件内容搜索不能默认获得 Everything 文件名搜索同等速度。

如未来提供全文索引，应作为独立的可选增强能力，明确其磁盘占用和资源消耗。

### 5.2 Everything 依赖策略

**第一阶段：复用 Everything。**

- 优先连接本机已有的 Everything。
- 不建立第二套重复索引。
- 提供兼容性检测和故障提示。

**第二阶段：降低安装负担。**

- 支持经过验证的安装引导或合法打包分发。
- 用户无需手工研究 Everything 配置。
- 不静默安装第三方服务。

**第三阶段：产品独立性。**

- 保持搜索能力可替换。
- 在有充分收益时评估独立索引实现。
- 不把重写 Everything 作为首版目标。

最终用户体验应尽量做到：安装 Sunday，即可在 Library 中完成全盘搜索，无须理解底层引擎的存在。

### 5.3 数据安全

1. 默认本地处理文件名、路径与资产元数据。
2. 不因加入 Library 而自动上传文件到云端。
3. Agent 获取文件内容遵循现有权限。
4. 支持排除敏感路径和磁盘。
5. 不绕过 Windows 文件访问权限。
6. 任何永久删除或批量高风险操作均需明确用户授权。
7. 从 Library 移除资产信息不删除原始文件。
8. 索引来源、覆盖范围、异常状态可查看。

## 6. 性能与体验验收

以下是产品目标值，不代表 Everything 或 Sunday 当前已达到的实测性能。

以 Windows 11、本地 NTFS SSD、已完成索引、约 100 万文件条目的测试环境为基准。

| 指标 | 目标 |
|---|---|
| 文件名查询响应 | P95 ≤ 200ms |
| 输入到首批结果可见 | P95 ≤ 400ms |
| 搜索输入 | 不阻塞 UI |
| 1 万条结果 | 可以持续滚动 |
| 索引更新 | 常规 NTFS 文件变化在 5 秒内反映 |
| 切换视图 | 不重新执行全盘扫描 |
| 资产收藏/标签 | 操作即时反馈，本地持久化 |
| 文件操作 | 进度可见，错误可恢复 |
| 离线磁盘 | 无假结果、无资产信息丢失 |

非 NTFS、网络磁盘、内容搜索及首次索引另设专项性能标准，不套用上述速度目标。

## 7. 用户场景验收

**场景 A：代替 Everything**

搜索一个散落在 E 盘的文件，直接找到、预览、打开或定位。

**场景 B：代替资源管理器的常用操作**

进入一个文件夹，选择五个文件移动到其他目录；处理名称冲突并获得明确结果。

**场景 C：管理素材**

搜索全部 PNG 图片，切换瀑布流，将其中若干图片加入自定义集合，不复制文件。

**场景 D：文件变化同步**

外部程序生成一张新图片，Library 能发现并展示，而不要求用户重新导入。

**场景 E：资产信息持久化**

重命名或移动已收藏文件后，在可确认文件身份的情况下，原分类、标签和评分仍有效。

**场景 F：引擎故障**

Everything 不可连接时，Library 明确报告搜索不可用，同时普通文件浏览与已保存资产信息仍可访问。

**场景 G：Agent 协作**

Agent 查找并展示文件，用户确认后执行批量收藏或移动操作，不重复开发一套独立的文件搜索系统。

## 8. 版本优先级

| 版本 | 交付范围 | 必须达到的结果 |
|---|---|---|
| V0 / FMVP | Everything 搜索 + Library 结果展示 + 打开/定位 | 搜索不再需要跳转到 Everything |
| V1 | 目录浏览、文件操作、多视图、基础预览 | Library 成为可用的日常文件入口 |
| V1.5 | 收藏、标签、评分、集合、元数据维护 | 普通文件可无损升级为可管理资产 |
| V2 | 智能集合、重复文件、变化追踪、Agent 深度集成 | Library 成为统一文件与资产工作区 |
| V3 | 多设备来源、增强内容检索、自有索引可选方案 | 降低底层依赖，扩大文件覆盖范围 |

## 9. 明确不做

- 不开发另一套功能重复的 Everything UI。
- 不要求用户重新导入全盘文件。
- 不把所有磁盘文件复制进 Library。
- 不强制用户重组现有目录。
- 不默认对所有文件执行 AI 分析。
- 不默认生成全盘所有文件的预览缓存。
- 不默认运行高成本全文索引。
- 不自动清理、合并或删除文件。
- 不以重写 Everything 为启动条件。

## 10. 最终验收定义

Library 达到以下状态，即视为完成 Everything 能力吸收：
