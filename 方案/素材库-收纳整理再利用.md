# 素材库：收纳、整理、再利用

> 本文替换 `方案/Library增强-样式展示与标签评分.md`。旧文档只覆盖了「收纳」的一半，把「挑按钮」当成了终点。这一版把三件事写全。

## 一、需求

用户原话：

> 让现有库通过添加一部分能力，能够实现对素材的收纳、整理与再利用。

> 再利用是 agent 来再利用，人只做观测和选用，比如说，我现在告诉你，去给我做一个什么什么什么东西，用低透玻璃材质和 ping 环的环形交互样式，质量按照星级就行。

> 本项目的所有 UI 是对这个功能的一个测试。

三条落点：

1. 收纳：项目里所有能复用的东西进库，不只样式，也包括材质、控件、布局、动效、页面。
2. 整理：进库的东西能被「人话」检索，而不是靠翻文件名。
3. 再利用：Agent 按人的一句话去库里取，取到能直接用的东西，用完之后这次使用被记下来。

分工是固定的：**人观测和选用，Agent 取用和落地。**

质量只用星级，0 到 5，0 表示没评。不引入第二套质量状态。

## 二、一次真实的再利用长什么样

这就是验收脚本，不需要别的场景。

人说的话：

> 给我做一个悬浮操作面板，用低透玻璃材质和 ping 环的环形交互样式，质量按星级。

Agent 要做完的五步：

1. 把这句话拆成两个取用意图：材质 `低透玻璃`，交互 `环形`。
2. 在库里按标签找，每个意图给出候选，按星级从高到低排。
3. 候选必须自带「怎么用」：从哪个类名或组件进、依赖哪些设计令牌、需要什么父级、有没有最小示例。
4. 把两个素材组合落地到新代码里。
5. 把这次使用回写到这两个素材上：用在哪、什么时候、和谁一起用的。

人这一侧只做两件事：在库里看这两个素材长什么样、多少分、被用过几次；以及需要人工定夺时并排对比候选。

## 三、现在的差距

有证据，不是猜测。

### 3.1 标签是从文件名反推的碎片，不是使用时的说法

库里 32 份样式表，实际标签长这样：

```
css,head,row,icon,label,actions,card
css,thread,head,row,icon,label,dot
css,settings,base,row,label,actions,card
```

`head`、`row`、`label`、`actions` 这些词来自样式表里出现频率最高的类名，对人没有检索价值，对 Agent 也没有。真正的取用词 `glass`、`ring`、`button` 覆盖极差。

实测：按 `tag=glass` 能查到 3 条，按 `tag=ring` 返回空。也就是说，用户举的那个例子，今天连候选都拿不到。

### 3.2 只有位置，没有用法

`list` 的输出是 `名称 + 层 + 标签 + 评分 + 文件路径`。Agent 拿到 `.css` 路径之后仍然要自己读文件猜类名、猜依赖、猜适用场景。这不是「取用」，这是「给它一个线索让它重新研究一遍」。

### 3.3 没有排序，没有多意图

`list` 只接受一个 `tag` 参数，不支持多个标签同时命中，也不按星级排序。用户说「质量按星级就行」，这句话现在没有地方生效。

### 3.4 用完没有痕迹

没有使用记录。人看不出哪个素材真的被用过、用在哪，也就没法判断该给谁加分、该淘汰谁。

### 3.5 人看不见「长什么样」以外的东西

卡片有星级和标签，但没有用法、没有使用记录、没有并排对比。观测这条腿只有一半。

## 四、设计

### 4.1 标签只留一个自由数组，但改打标签的方式

不引入类型枚举，不写死分类。分类和同类一律靠标签匹配，这是已经定下的原则。

变的是打标签时问什么。每份素材按三个问法各给一到三个标签：

| 问法 | 举例 |
|---|---|
| 它是什么 | `material` `control` `layout` `motion` `surface` |
| 它看起来怎样 | `glass` `low-trans` `ring` `rounded` `glow` `outline` |
| 它用在哪 | `button` `dialog` `ping-ring` `card` `composer` |

存储上仍然是 `tags: string[]`，三个问法只是打标签时的提示，不是数据结构。这样既满足「按 tag 匹配」，又不会退回写死分类。

判断标准一条：**人用嘴说得出这个标签，Agent 才查得到。** `head`、`row` 这种从类名里切出来的词一律不算。

### 4.2 素材必须自带用法

新增一列 `usage`，JSON，三件事：

| 字段 | 说明 | 例子 |
|---|---|---|
| `entry` | 从哪进 | `.optical-glass--low-trans` / `import PingRing from '@/pet/ui/PingRing.vue'` |
| `requires` | 依赖 | `--glass-tint`、父级需要有定位、需要 `variables.css` |
| `example` | 最小可用片段 | 五行以内的 HTML 或模板 |

`entry` 是 Agent 落地的直接抓手。没有 `entry` 的素材，取用会退化成重新阅读源码，也就是这次要消灭的东西。

### 4.3 一次取用可以是一组

用户的例子是两个素材组合：材质负责观感，环形组件负责交互。所以回写不是单条，是「一组里的每一条都记上这次使用」。

### 4.4 使用记录

三个字段，够用：

| 字段 | 说明 |
|---|---|
| `usage_count` | 被取用次数 |
| `last_used_at` | 最后一次时间 |
| `used_in` | 最近若干次的使用位置，形如 `会话/任务 + 文件路径` |

记录由 Agent 在代码落地之后写，不是点一下就写。写成独立动作 `use`。

### 4.5 工具

`library` 现在八个动作，两个要改，一个要加：

- `list` 增强：
  - `tag` 支持数组，语义取「全部命中」，因为组合取用通常要求同时满足材质和形态。
  - 增加 `sort`，默认按星级从高到低，同分按最近使用。
  - 输出补 `entry` 一行和 `used=N`，让 Agent 一眼看到怎么用、用得多不多。
- `register` 增强：接受 `usage` 对象。
- 新增 `use`：参数 `artifact_ids`、`used_in`，累加计数与时间。

### 4.6 人这一侧

只做观测和选用，不做第二套浏览器。

- 卡片：样子、名字、星级、`used=N`。标签胶囊显示全部，按三问法顺序排，便于扫。
- 详情：用法三行原文，加使用记录列表。人要看的是「这东西怎么用、谁用过」，不是再抄一遍 CSS。
- 对比：勾选两到多个条目，并排显示它们的实际渲染与星级。这是人做最终选择时唯一需要的新交互。
- 不再新开分区。仍然只有资料、记忆、方案、Wiki 四个入口。

## 五、实施顺序

按「同样工作量，谁先让验收脚本能跑通」排序，不按代码层次排序。

1. **重打标签**。把已入库的 35 条按三问法重打，同时把 ping 环、玻璃两种、按钮八种这些真会用到的素材补进库。做完这一步，`tag=ring` 和 `tag=glass` 同时命中就成立了。这一步不写代码，收益最大。
2. **补用法**。给已入库素材填 `usage`，先填会用到的十几条，不求全。
3. **排序与多标签**。`list` 加 `sort` 与数组 `tag`，让星级真正生效。
4. **`use` 动作**。跑通回写，先用工具验证，不动界面。
5. **人端展示**。卡片加 `used=N`，详情加用法与记录。
6. **并排对比**。勾选、并排、退出。
7. **预览真实化**。卡片里的预览目前是从选择器反推的骨架，文字是占位词。改成真实渲染，用带测试的模板扫描实现，不达标不接入。
8. **按钮八种迁移**。24 个存量按钮类按材质乘形状收敛到八种，涉及 43 个 `.vue` 文件，放最后。

第 1 到 4 步做完，「用低透玻璃和 ping 环做一个面板」这条链路就能端到端跑通，界面还是原来的样子。第 5 到 6 步补人的观测面。

## 六、验收

一条主链，四条支链。

主链：`用低透玻璃材质和 ping 环的环形交互样式做一个悬浮面板，质量按星级`，Agent 能从库里取到两个素材、按星级排序、拿到类名与组件路径、落到代码、并回写使用记录。

支链：

1. `tag=ring`、`tag=glass` 都能命中，且候选按星级从高到低。
2. 任一素材的 `entry` 直接可粘进代码，不需要再读源文件确认类名。
3. 用完打开库，该素材显示 `used=1` 与使用位置。
4. 勾选玻璃两种，并排渲染，能看出着色差别。

## 七、已知问题与风险

- 玻璃对照页在无 GPU 环境下 `backdrop-filter` 不生效，只剩着色差。并排对比要换不依赖 GPU 的底座，否则人看不出「低透」和「普通」的区别，对比功能等于废。
- 预览占位词未解决，第 7 步之前卡片显示的不是真样子，人的观测面不完整。
- 标签仍是自由字符串，会有 `ring` 和 `annular` 两套写法。靠打标签时统一用词，不做同义合并，积累后再定。
- `usage` 需要人工或 Agent 填，填不全就会退化成空字段。取舍是先填真会用的十几条，不追求 35 条全填。
- 24 个按钮类的迁移面很大，属于独立工程，不在本次链路内，但八种按钮的素材必须先入库才有迁移目标。
