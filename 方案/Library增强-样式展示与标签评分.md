# Library 增强：样式展示与标签评分

## 一、结论

这次提升的落点在库本身，不在库外面再建一套。

库已经有的能力：条目目录、所属层、收藏、搜索、软删除与恢复，以及一套给助手用的 `library` 工具。缺的两件事：

1. 条目能展示它自己的样子。样式表、页面、组件不该只显示扩展名。
2. 条目能打标签、能评分。标签让「我要挑几个按钮」变成一次查询，评分让好的沉淀下来。

这两件事做完，剩下的靠提示词和工具组合就能自然发生，不需要再为「挑按钮」单独做一个界面。

## 二、需要撤掉的东西

上一版我另建的分区要全部撤掉，因为它和库是两套模型：

- 资料库里的「样式」分区，以及它的标签栏、舞台网格、索引表。
- 自己算出来的一套分类词表，它和库的层、收藏、搜索结果不共享任何状态。
- 独立的收藏与评分存储，它和库的 `favorite` 各存一份。

## 三、需要保留的东西

一样东西值得留下来：把一份 CSS 渲染成真实界面的能力。它从样式表里抽出选择器、还原成标签、清掉祖先的视觉，让条目在库里直接看见自己长什么样。这套能力以后是「条目的预览方式之一」，不是一套独立的目录。

保留形式：一个渲染组件，输入是一份 CSS 文本，输出是可渲染片段。它不认识「原子」「组合」这些我编的概念，只服务预览。

## 四、数据模型

在 artifact 记录上补三个字段，其余不动。

| 字段 | 类型 | 说明 |
|---|---|---|
| `tags` | string 数组 | 自由标签，规范成全小写、去空格、去重，单个不超过 32 字，单条不超过 12 个 |
| `rating` | 整数 0 到 5 | 0 表示未评分 |
| `preview_kind` | 字符串 | 由 mime 与扩展名推导，不由用户填：`css` `html` `image` `video` `code` `doc` `none` |

标签不进独立表，直接存 JSON 列，够用且迁移简单。评分是单值，不做多维。

## 五、工具

`library` 工具从六个动作扩到八个，`list` 增加过滤，输出增加字段。

新增动作：

- `tag`：给若干条目加标签或去标签。参数 `artifact_ids`、`tags`、`mode` 取 `add` 或 `remove`。
- `rate`：给若干条目打分。参数 `artifact_ids`、`rating`。

`list` 增强：

- 入参增加 `tag`，只列带这个标签的条目。
- 每行输出末尾追加 `tags=a,b` 与 `rating=3`，助手据此判断能不能复用。

描述里要写清楚：标签是复用的检索键，不是归档手段；层负责归档，标签负责检索。

## 六、界面

沿用资料区，不新开分区。

- 卡片：缩略图位置改为按 `preview_kind` 渲染。`css` 用保留的渲染器画一小块；`html` 用隔离框架；图片视频照旧；代码与文档保持原来的封面。
- 卡片：名称下面一行标签胶囊，最多显示三个，多余的收成 `+N`；评分用五颗星，未评分的在悬停时才出现。
- 筛选：现有的药丸页签接标签，点标签就筛这一标签下的条目；搜索同时匹配名称、标签与文件名。
- 详情：点开条目，右侧栏出现标签编辑与评分，写入即存。

这样「挑按钮」的路径是：打开资料库，点 `button` 标签，看到所有按钮条目并排，每张卡显示它真实的样子，按评分排序。不需要第二套导航。

## 七、实施顺序

第一步，数据与工具。加字段、加迁移、加两个动作、`list` 加过滤与输出。这一步没有界面，可以先用工具跑通「给五个文件打 button 标签，再列出来」。

第二步，卡片上的标签与评分。资料区卡片显示胶囊与星，详情能编辑。

第三步，预览。把保留的渲染器接进 `preview_kind = css` 的条目，先只做资料区的样式表，页面与组件留到后面。

每步都能单独验收，不必等整套做完。

## 八、验收

- 助手能一次列出某个标签下的全部条目，输出里带标签与评分。
- 用户在资料库点一个标签，页面上只剩这些条目，卡片显示真实样子。
- 评分与标签在重启后还在，和收藏各自独立。
- 撤掉自建分区后，资料库仍然只有资料、记忆、方案、Wiki 四个入口。

## 九、风险

迁移要给旧数据补默认值，`tags` 默认空数组，`rating` 默认 0，不能留 NULL。

标签是自由字符串，会出现 `button` 与 `btn` 两套写法。先不做同义合并，靠提示词约定用全称，积累一段时间再决定要不要收敛。

样式渲染要吃进全部样式表，资料区第一次打开会变重。做法是按需加载：只有当前视口里的 `css` 条目才实例化渲染器。

## 十、和按钮简化的关系

按钮的材质与形状是样式自身的问题，跟库无关。等库能打标签之后，八个按钮就是八个带 `button` 标签的条目，评分高的排在前面。两件事分开做，互不阻塞。
