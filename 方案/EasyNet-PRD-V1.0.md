## 1. 产品目标

将 Easy Net 打造为 Sunday 内统一的网络工具中心，让普通用户完成：

1. 管理文件下载与传输。
2. 查看网络状态、速度和连接质量。
3. 诊断网络、DNS、代理及服务连接故障。
4. 管理手机、电脑及其他设备的互联。
5. 按需创建虚拟局域网，实现远程局域网应用互访。

**核心原则：优先增强现有 EasyNet，不重新开发已经实现且可靠的功能。**

不依赖 Sunday 自营服务器、代理节点、云存储、加速服务或公共中继。

## 2. 现有 EasyNet 审查要求

首先检查当前源码、运行逻辑、界面、服务调用、配置、安装包和测试，建立功能现状表。

| 审查对象       | 检查重点                       | 优化目标        |
| ---------- | -------------------------- | ----------- |
| 功能完整度      | 已有按钮是否有实际后端能力，是否存在假功能、重复功能 | 删除空壳，复用可靠能力 |
| 下载模块       | 断点续传、重试、并行任务、文件校验、异常恢复     | 稳定的大文件下载    |
| 网络状态       | 网卡、带宽、延迟、网络切换的真实数据来源       | 准确而非装饰性仪表盘  |
| 网络诊断       | DNS、TCP、TLS、HTTP、代理诊断覆盖情况  | 能解释失败发生在哪一层 |
| 代理管理       | 系统代理读取、检测、冲突识别、配置恢复        | 不需要用户手动排查   |
| P2P / 设备连接 | 与 Sunday Relay 的复用程度       | 不重复造连接模块    |
| 权限与安全      | 网络扫描、系统配置变更、日志敏感信息         | 可控、可撤销、最小权限 |
| 性能与资源      | 常驻内存、后台轮询、下载资源占用           | 不使用时低开销     |
| 用户体验       | 入口重复、术语过多、异常反馈不清楚          | 普通用户容易理解    |

审查结果统一分为：

- **保留**：功能已经可用，没有显著收益的改造不执行。
- **优化**：功能存在，但可靠性、性能或体验不足。
- **补齐**：实际场景需要，当前实现缺失。
- **合并**：与 Browser、Easy File 或 Relay 功能重复。
- **删除**：没有实际价值、属于演示空壳或长期无维护价值。

每个问题记录严重程度、代码证据、用户影响、预期结果和验收方式。禁止把历史缺陷直接认定为当前缺陷。

## 3. 功能要求

### 3.1 网络概览（P0）

默认打开 Easy Net 时展示：

- 当前网络类型和实际连接状态。
- 当前上传与下载速率、累计流量。
- 网络可达性与最近连接异常。
- 正在下载的任务与进度。
- 已连接的 Sunday 设备。
- 网络诊断与快速修复入口。

默认不展示 IP 协议、NAT 类型、网络路由表等技术数据，放入详细信息。

实时速率和累计流量必须区分；网络可达不等于目标服务可达。

### 3.2 下载中心（P0）

整合已有下载功能，支持：

- HTTP/HTTPS 下载、多个任务、暂停和恢复。
- 服务端支持时使用断点续传；不支持时明确提示。
- 并发数量、限速、重试策略可设置。
- 失败任务显示具体原因及恢复操作。
- 支持下载完成通知、校验、快速打开文件。
- 从 Browser 下载、Easy File 和 Agent 工具调用进入同一个任务列表。
- 重启 Sunday 后保留任务、下载进度及必要的临时文件。

BT/Magnet 作为可选增强，须经过单独的引擎复用、资源消耗与许可评估，不进入第一阶段的必交范围。

### 3.3 网络诊断（P0）

提供一个普通用户可以理解的「检查网络」按钮。

检查过程覆盖：

1. 本机网络接口、网关与局域网。
2. DNS 解析是否正常。
3. 外网及指定目标的连接情况。
4. TCP/TLS/HTTP 请求失败原因。
5. 系统代理和应用代理是否发生冲突。

输出示例：

- 网络正常，但目标网站无响应。
- DNS 解析失败，可尝试切换 DNS。
- 当前代理不可用。
- 设备已连接 Wi-Fi，但无法访问互联网。

诊断不依赖单一网站或单一服务端。修复操作涉及改变系统设置时必须告知用户，并提供恢复原设置的能力。

### 3.4 代理与连接设置（P1）

- 查看 Windows 系统代理与 Sunday 内部代理状态。
- 支持 HTTP、HTTPS、SOCKS5 等现有引擎可用的配置方式。
- 支持导入常用代理配置、连接测试和快速启停。
- 可以明确区分「仅 Sunday 使用」与「修改系统代理」。
- 识别代理循环、端口不可达、认证失败等常见错误。
- 用户明确修改后保存并可恢复配置。

不建设自营代理节点，不将 Easy Net 演变成公共代理订阅服务。

### 3.5 设备互联（P1）

提供一个统一入口：**我的设备**。

显示设备名称、系统、连接状态、可用功能和最近使用情况。

支持：

- 添加设备、扫码配对、解除绑定。
- 向设备发送文件。
- 从手机访问已授权的电脑文件。
- 启动设备支持的 Sunday 远程操作。
- 查看连接详情与问题诊断。

内部直接使用第二份 PRD 定义的 Sunday 远程连接底座。

不再开发 EasyNet 专属配对系统或独立消息队列。

### 3.6 虚拟局域网（P2，新增能力）

目标是让不同地点的设备在必要时像处于同一个局域网中一样访问对方的服务。

用户场景包括：

- 跨网络访问共享文件夹、NAS、开发服务。
- 使用远程电脑提供的局域网应用。
- 连接游戏或其他依赖虚拟局域网的程序。
- 查看联网设备的虚拟地址与连接状态。

产品功能：

- 一键创建或加入私人网络。
- 已授权设备可快速加入网络。
- 自动分配和管理虚拟地址。
- 尝试直连，必要时自动使用可用中继。
- 支持设备退出、撤权和访问限制。
- 提供 Ping、延迟和实际连接方式。
- 高级模式支持子网访问，默认关闭。

优先评估 EasyTier 内核复用，不自行开发完整虚拟网络协议。

此模式是**可选网络功能**，不应成为 Sunday 手机与桌面端正常通信的前置条件。

## 4. 界面规划

默认采用 新增标签页形式，支持现有布局系统

| 视图 | 核心内容              |
| -- | ----------------- |
| 概览 | 网络质量、速率、下载进度、设备连接 |
| 下载 | 任务、历史、进度与文件操作     |
| 互联 | 我的设备、文件传输、私人网络    |
| 诊断 | 检查结果、问题定位与修复操作    |

代理和高级网络设置置于设置页，不新增大量平级入口。

尽量复用 Sunday 已有工作区、Bento 卡片、图表和通知系统。

## 5. 非功能要求

- 默认不要求管理员权限，只有必要的系统操作才申请提升权限。
- 无活动任务时避免持续高频轮询。
- 网络断开时下载及传输任务安全暂停、恢复或报告失败。
- 不因一个下载或网络诊断任务故障导致 Sunday Core 崩溃。
- 下载数据、代理凭证、设备密钥分别按照各自的安全要求存储。
- 不在错误日志中泄露代理密码、设备密钥和敏感 URL 参数。
- 对其他 VPN、代理和防火墙软件保持兼容，不能擅自关闭安全防护。

## 6. 验收标准

| 项目    | 验收目标                                   |
| ----- | -------------------------------------- |
| 功能真实性 | 已公开的功能均对应实际可用行为，无无效按钮                  |
| 下载可靠性 | 支持续传的服务端，断线恢复后内容校验一致                   |
| 重启恢复  | 未完成任务恢复或明确失败，不静默丢失                     |
| 诊断有效性 | DNS、代理、网络不可达等典型故障能正确区分                 |
| 数据准确性 | 网络速率和流量有明确来源，不显示模拟值                    |
| 权限安全  | 系统设置修改需授权，支持恢复                         |
| 资源管理  | 无任务时无明显持续 CPU 占用及资源泄漏                  |
| 模块复用  | 与 Relay、Easy File、Browser 不重复维护连接和下载状态 |

## 7. 执行顺序

**阶段 A：现有 EasyNet 审查**
建立代码证据与功能状态清单，删除或合并重复功能。

**阶段 B：核心功能优化**
完成下载中心、网络状态、诊断和代理的可靠性与体验修复。

**阶段 C：整合设备互联**
复用第二份 PRD 的连接底座，完成文件传输与设备管理入口。

**阶段 D：虚拟局域网增强**
评估复用 EasyTier，完成可选私人网络功能和跨平台兼容测试。

完成每个阶段后，应能交付独立可用的产品增量，不等待全部阶段完成。
