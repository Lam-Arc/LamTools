# Sunday Android｜环境、项目、会话层级与跨端交互补充 PRD

**版本：** V1.0  
**类型：** 增量需求补充  
**关联文档：**《Sunday Android — 会话层级与交互入口 PRD》  
**适用范围：** Android UI、项目管理、会话系统、远程连接、未来 AI 通讯

## 一、核心定义

Sunday 采用严格的三级工作层级：

**运行环境（Environment）→ 项目（Project）→ 会话（Conversation）**

其中：

1. **环境是基础组**：代表实际运行 Sunday Agent 的设备环境，例如 Android 本机、Windows 电脑或其他远程设备。
2. **项目是基础单元**：承载工作内容、文件、配置与会话。每个项目必须且只能属于一个运行环境。
3. **会话是基础原子**：独立的 Agent 交互与任务上下文。每个会话必须且只能属于一个项目。

消息、工具调用和任务进一步关联到具体会话。

### 层级示例

```text
Sunday
│
├── 本机 Android                  [运行环境]
│   ├── 默认项目                  [项目]
│   │   ├── 日常聊天              [会话]
│   │   └── 临时任务              [会话]
│   └── 学习项目
│       ├── 高频电子线路
│       └── 信息论
│
└── 我的 Windows 电脑             [运行环境]
    ├── Sunday 开发
    │   ├── Relay 优化
    │   └── Android UI
    └── 默认项目
        └── 日常聊天
```

**环境不是单纯的设备分组标签，而是 Agent 的实际运行边界。**

## 二、数据归属规则

| 对象 | 归属规则 | 执行关系 |
|---|---|---|
| 环境 | 对应独立运行环境 | 拥有自身 Agent、资源与任务 |
| 项目 | 唯一所属环境 | 使用所属环境的资源 |
| 会话 | 唯一所属项目 | Agent 在所属环境执行 |
| 消息 | 唯一所属会话 | 属于该会话的交互记录 |
| 任务 | 关联具体会话 | 由会话所属环境执行 |

核心约束：

- 不允许没有所属环境的项目。
- 不允许没有所属项目的会话。
- 不允许切换设备时隐式迁移项目或会话。
- 不允许将远程项目伪装为本机项目。
- 各环境独立维护自己的 Agent、项目、会话及任务状态。
- 所有环境、项目、会话均使用稳定的唯一标识，不依赖名称区分。

## 三、Android 会话 UI 层级

延续 WeChat / LINE 式聊天界面，但增加环境与项目的上下文管理。

### 3.1 逻辑层级

```text
L1 运行环境
  └── L2 项目
       └── L3 会话列表
            └── L4 聊天详情
```

这是数据与导航逻辑，不要求用户实际逐级打开四个页面。

### 3.2 默认会话列表

进入 Android「聊天」入口时：

- 恢复上次使用的环境和项目。
- 直接展示对应项目的会话列表。
- 顶部显示当前环境与项目。
- 保留搜索、新建会话、会话管理入口。
- 不要求用户每次重新选择环境或项目。

建议顶部结构：

`本机 Android / 默认项目 ▾`

点击后打开环境与项目选择面板。

### 3.3 环境与项目选择

采用分层选择面板：

1. 展示本机及已配对的远程环境。
2. 选择环境后，展示该环境下的项目。
3. 选择项目后，切换会话列表。
4. 进入会话后，使用原有聊天交互页面。

支持记忆每个环境最近使用的项目和会话。

远程环境离线时，可以显示已缓存的目录，但必须明确标记缓存状态，不得伪装为实时数据。

### 3.4 会话列表

使用微信式会话列表：

- 左侧头像或 Agent 标识。
- 会话名称。
- 最新消息或任务状态摘要。
- 最近活动时间。
- 未读消息、待审批、运行状态。
- 点击进入会话。
- 长按置顶、重命名、归档、删除等操作。

列表内容必须属于当前选定项目。

### 3.5 聊天详情

保持原 PRD 的聊天页面设计：

- 顶部显示会话名称及必要状态。
- 中间为消息流、Agent 执行状态及工具结果。
- 底部为输入框、语音、附件和发送操作。
- 更多菜单提供会话信息、历史搜索、文件、任务及配置入口。

不在聊天页面重复设置大型环境树或项目管理面板。

## 四、项目与会话创建

### 4.1 默认项目

每个运行环境至少提供一个默认项目，用于承载未主动分类的日常会话。

默认项目属于该环境，不在多个环境之间共享同一个项目实体。

### 4.2 新建项目

在当前环境下创建项目。

创建后自动绑定该环境，不提供无归属项目。

### 4.3 新建会话

在当前项目下创建会话。

从全局「新聊天」入口进入时，默认选择当前环境最近使用的项目；没有历史记录时使用默认项目。

用户可在创建前更换目标环境或项目。

### 4.4 会话迁移

允许将会话整理到其他项目，但必须保持归属规则。

- **同环境移动：** 可以调整所属项目，保留原有消息和任务历史。
- **跨环境移动：** 不等同于普通移动。需要明确的数据导出、导入或迁移流程，并检查文件、工具及执行上下文兼容性。
- **运行中任务：** 不因整理会话而静默改变执行环境。

第一阶段可以只实现同环境的项目间移动。

### 4.5 删除与解绑

- 删除会话只处理目标会话及约定的关联数据。
- 删除项目必须明确提示所包含会话及运行任务。
- 解绑远程设备只解除连接及信任关系，不自动删除远程数据。
- 删除缓存不等于删除远程原始数据。

## 五、跨设备操作：仅保留两种渠道

当用户使用 Android 想控制 Windows 电脑时，只有以下两种方式。

### 方式 A：切换运行环境

**使用现有 Sunday Connect / Iroh 远程连接。**

```text
Android Sunday
    │
    ├── 当前环境切换为 Windows
    │
    ▼
Windows 运行环境
    └── Windows 项目
         └── Windows 会话
              └── Windows Agent 执行
```

具体行为：

1. Android 选择 Windows 运行环境。
2. 显示 Windows 实际拥有的项目和会话。
3. 用户选择或创建 Windows 会话。
4. 消息通过现有远程连接发送至 Windows。
5. Windows Agent 在电脑上实际执行任务。
6. Android 接收执行状态、消息及结果。

Android 在此模式下是远程交互终端，不负责执行 Windows Agent 的任务。

Windows 离线时，不自动切换成 Android 本机执行。

**用户体验：在手机上直接使用电脑里的 Sunday。**

### 方式 B：Agent 信息通信

**未来功能，尚未实现。**

```text
Android 运行环境
└── Android 项目
    └── Android 会话
         └── Android Agent
              │
              │ AI 通讯 / 任务委派
              ▼
         Windows Agent
              │
              ▼
         Windows 环境内执行
              │
              ▼
         返回消息与结果
```

具体行为：

1. 用户继续使用 Android 本机环境。
2. 用户向 Android Agent 提出任务。
3. Android Agent 判断需要与 Windows Agent 通讯。
4. 通过未来 AI 通讯功能联系 Windows Agent。
5. Windows Agent 在自己的环境与任务上下文中执行。
6. Windows Agent 返回结果。
7. Android Agent 在原会话中继续回应用户。

要求：

- 两端 Agent 保持独立身份和执行上下文。
- 不自动迁移项目或会话。
- 消息与任务委派需要权限、回执、状态和去重机制。
- 接收方需要明确知道请求来自哪个 Agent 和设备。
- 远程任务必须在目标环境内建立或关联执行上下文。
- 原 Android 会话保留通讯记录与结果引用。

**用户体验：让手机里的 Agent 联系电脑里的 Agent 帮忙。**

AI 通讯尚未实现前，只预留数据结构和扩展接口，不展示虚假的可用按钮。

## 六、两种跨端方式的区别

| 维度 | 切换环境 | AI 信息通信 |
|---|---|---|
| 当前工作环境 | Windows | Android |
| 用户对话对象 | Windows Agent | Android Agent |
| 任务执行主体 | Windows Agent | 接受委派的 Windows Agent |
| 项目归属 | Windows 项目 | 两端各自项目 |
| 会话归属 | Windows 会话 | 两端各自会话 |
| 操作方式 | 远程控制现有会话 | Agent 间消息、请求与委派 |
| 底层连接 | Sunday Connect / Iroh | 复用通讯底座 |
| 当前状态 | 复用既有远程能力 | 尚未实现 |

**禁止引入第三种隐式方式：Android 本机会话直接绕过 Agent 通讯机制，调用 Windows 的执行能力。**

## 七、搜索与管理

### 7.1 全局会话搜索

支持跨环境、跨项目搜索会话与消息。

结果必须包含归属信息，例如：

`Relay 优化 · Windows / Sunday 开发`

点击搜索结果后自动定位到正确的环境、项目和会话。

### 7.2 项目管理

每个环境下支持：

- 新建和重命名项目。
- 查看项目会话。
- 项目排序与置顶。
- 项目归档及删除。
- 项目内会话管理。

远程项目的修改应交由远程 Sunday 环境执行，不应仅修改 Android 本地缓存。

### 7.3 设备状态

环境选择器展示实际连接状态：

- 本机可用。
- 远程已连接。
- 正在连接。
- 正在恢复。
- 离线或不可用。

进入远程环境时，不得仅因为传输层连接成功就认定 Agent 已可用。

## 八、与未来 AI 通讯的兼容性

本次只预留必要扩展边界。

未来联系人、Agent 联系人、群组及多 Agent 会话依旧遵守项目归属规则。

- 会话只属于一个项目。
- 项目只属于一个环境。
- 会话可拥有一个或多个参与者。
- 参与者可以来自不同环境。
- 参与者所属环境不改变会话归属。
- 跨环境通讯通过消息协议完成，而不是通过修改归属关系完成。

后续增加 AI 通讯时，直接扩展会话参与者、消息类型与任务委派能力，不需要重新设计整个聊天界面。

## 九、验收标准

1. 项目必须且只能归属一个运行环境。
2. 会话必须且只能归属一个项目。
3. 每个环境拥有独立的项目、会话和执行状态。
4. Android 切换到 Windows 后，展示 Windows 真实项目与会话。
5. Windows 环境的任务由 Windows Agent 执行。
6. 切回 Android 后，原 Android 项目、会话及草稿保持不变。
7. 新建项目和会话自动绑定正确的上级对象。
8. 同名项目与会话不会发生跨设备混淆。
9. 远程离线时正确显示不可用，不自动改用本机执行。
10. 解绑设备不会删除远程原始数据。
11. 会话搜索能够正确定位环境、项目和消息。
12. 未来 Agent 间通讯不会改变任意一方的环境与项目归属。
13. 不出现第三种未经定义的跨设备执行路径。
14. 原有聊天、工具调用、审批和任务功能保持正常。

## 十、实施边界

**当前阶段：**

- 建立环境、项目、会话的明确归属关系。
- 优化 Android 环境及项目选择交互。
- 完善远程环境的项目和会话访问。
- 统一会话创建、搜索、管理及状态展示。
- 复用现有 Sunday Connect 远程连接。

**后续阶段：**

- Agent 联系人及 AI 通讯。
- Agent 间任务委派。
- 跨设备消息与结果同步。
- 多参与者会话与协作。

不因未来功能尚未实现而阻塞当前环境切换和普通聊天功能。

---

## 十一、最终产品原则

**数据层：环境 → 项目 → 会话 → 消息。**

**执行层：会话由所属环境的 Agent 执行。**

**交互层：保留 WeChat / LINE 式聊天体验，通过环境和项目选择器管理工作上下文。**

**跨端层：只有「切换运行环境」与「Agent 信息通信」两种路径。**

让用户在手机上既可以直接操作远程 Sunday，也可以在未来通过本机 Agent 与其他设备上的 Agent 协作，同时保持清晰、独立且稳定的工作边界。
