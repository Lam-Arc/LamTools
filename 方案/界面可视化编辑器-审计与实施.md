## 一、审计口径

逐节对照 §3 到 §11，看三件事：代码里有没有、有没有测试、能不能从界面走到。
「已建成」= 有实现且有测试；「半成品」= 有实现缺一块；「没动」= 全仓无对应代码。

## 三、这一批的五个模块

只挑「完全没动」或「只差一整块」且能独立验收的：

1. **选择与组织**：框选多选、复制/粘贴样式、独显。
2. **三级间距标注**：大括号 / `>` / 单段折线三档，标签在外侧避让，热区有屏幕级最小尺寸。
3. **版本历史与安全恢复**：发布保留上一版、可回滚；坏主题有与主题无关的恢复入口。
4. **主题包导入导出**：`.sunday-theme` ZIP（manifest + document + assets + 哈希），导入先隔离校验再预览。
5. **发布前响应式检查**：连续宽度扫描，溢出与关键入口不可达阻断发布，触控过小只警告。

## 四、明确不选与理由

- **组合/解组**：注册表里的父子关系由组件自己声明，用户不能凭空造结构；真做要改注册表模型，属于另一期。多选加复制粘贴覆盖了「批量把同一套外观搬到别处」的实际用途。
- **容器类型（§4.2）**：改的是真实布局行为，43 个组件的排列都要重新验证，风险和收益不成比例。
- **decoration-portal（§8.4）**：需要跨容器的独立装饰宿主，和正在改的交互层会撞车。
- **插件注册接口（§11.3）**：需要宿主侧插件 UI 契约，单独排期。
- **示例数据（§6.4）**：要给真实业务组件喂 mock，牵动会话与文件数据，先不做。

## 五、验收方式

每个模块都有纯函数测试；编辑器交互项用 `@vue/test-utils` 挂载验证；最后跑 `vitest run` 与 `vue-tsc --noEmit`。

## 六、实现结果（2026-11-09）

五块全部落地，纯逻辑单独成模块，编辑器只负责接线。

| 模块 | 代码 | 行为 |
|---|---|---|
| 选择与组织 | `ThemeStudio.vue` | 空白处拖出矩形框选；Ctrl 追加；Ctrl+C / Ctrl+V 复制粘贴样式（模板样式只能贴到同类模板）；图层行新增独显键，只留当前层与祖先/后代，退出即恢复 |
| 三级间距标注 | `themeStudio/annotation.ts` | 可见间距 ≥12px 画括号、≥4px 画折角、更小只留线段；标签在间距带外侧；热区与标签按缩放换算，保持 24×18 屏幕像素；滚轮与双击输入照旧 |
| 版本历史与安全恢复 | `themeStudio/history.ts`、`bootstrap.ts`、`store.ts` | 发布时把被替换的那一版记进历史（最多 5 版，空主题不占位）；历史面板可回到某一版；`?safe-theme=1` 或本地标记跳过自定义主题；安全恢复清掉已发布与草稿、保留历史；重新发布自动退出安全模式 |
| 主题包导入导出 | `themeStudio/package.ts` | `.sunday-theme` ZIP = manifest + document + assets；导出按内容嗅探决定扩展名；导入校验格式、版本、路径穿越、单张与整包体积、素材哈希；先落待确认面板，确认后只进草稿 |
| 发布前响应式检查 | `themeStudio/preflight.ts`、`ThemeStudio.vue` | 同步压外壳到 1440/1024/768/375/320 取样（不画中间态，异常也恢复原宽度）；溢出与关键入口不可达阻断发布，触控过小只提醒；模板内容、滚动容器里的元素、`display:none` 与整块在壳外的元素跳过，避免误报 |

### 误报边界

检查只对「布局级」问题负责：滚动内容、刻意隐藏的界面状态、整块收起的抽屉都不算溢出；只报有一部分露在外壳外面的元素。

### 验证

- 新增测试 34 条：`theme-studio-history` 10、`theme-studio-package` 6、`theme-studio-preflight` 7、`theme-studio-annotation` 8、`theme-studio-selection` 7（含发布前误报边界）。
- 既有 15 个主题测试文件共 184 条全部通过；`vue-tsc --noEmit` 对本次涉及文件无报错。
