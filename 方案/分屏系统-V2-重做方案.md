## 1. 现状为什么必须重做（不是修补）

| # | 结构性缺陷 | 证据 |
|---|---|---|
| S1 | **布局与内容混在一个可变对象里**：`SplitTab` 既是内容也是位置，`surface:'float'` 只是标签上的一个字段，于是出现「声明是浮层、位置还在分屏」的半状态，需要 normalize 兜底 | `core/ui/src/split/surfaces.ts` 833 行；`layout.ts` 585 行 |
| S2 | **比率树 + 最小尺寸互相打架**：放不下时只有两种结局——压破最小尺寸，或整块藏屏（`cramped`）。前者内容不可用，后者「点了没反应」 | `layout.ts` 的 `splitFits/minimumSize/resizeSplit`；实测 731px 需求 742px |
| S3 | **矩形有两个来源**：布局算一份，组件再用 `getBoundingClientRect()` 量一份，原生 webview 按后者落位 → 缩放不等比时「网页跑到别处」（U5） | `CoreSplitBrowser.vue` 的 `hostRect`；`native.ts::boundsArgs` |
| S4 | **让位靠逐处登记**：原生 webview 永远在 DOM 之上，只能靠 `overlayActive()` 一个个登记，漏一处就被盖（U6） | `browserOverlays.ts`、`browserOverlay.ts` |
| S5 | **形态三态（分屏/聚焦/悬浮）是散装的**：每个形态各自算矩形、各自处理让位，切换要迁移标签，容易残留（U7） | `surfaceModes.ts` 220 行 + `CoreSplitWorkspace.vue` 961 行 |
| S6 | **滚动/缩放/融合这套装饰在写样式**：布局系统没有自己的验收口径，问题靠截图一轮轮修（U8） | 本会话多轮 UI 返工 |

结论：**引擎重写，内容组件保留**。浏览器面板、预览器、编辑器、文件树这些内容本身没有结构问题，问题全在「它们被摆在哪、谁决定矩形、矩形怎么同步」。V2 只替换布局引擎与其外壳。

## 2. V2 架构

### 2.1 三个概念（严格分层，单向依赖）

```
Surface（内容实例）  ── 不知道自己被摆在哪
    id, kind ('agent'|'browser'|'file'|'plugin'|'conversation'), 内容状态
Placement（位置）    ── 唯一的位置表达
    { kind:'area', areaId } | { kind:'float', rect } | { kind:'focus' }
Layout（布局）       ── 只描述区域，不描述内容
    tree（二叉分割）, floats（rect + z + yield）, focusAreaId, collapsed
```

- **一个 Surface 同一时刻只有一个 Placement**。没有第四种状态；任何变更后跑一次 `normalize()`（去重、收拢空区、夹浮层进视口）。
- 切布局 = 改 Placement；**内容实例不重建**（渲染以 surface.id 为 key，宿主节点只换父容器）。

### 2.2 几何：一次纯函数，像素优先，比率存储

```ts
computeWorkspace(model, viewport, prefs) => {
  areas: Map<AreaId, Rect>     // 铺满、无重叠、每个都 ≥ 下限
  floats: Map<SurfaceId, Rect>
  issues: Issue[]              // 'insufficient' | 'collapsed' | 'clamped'
  chrome: Map<AreaId, { tabbar: 'full'|'compact'|'hidden' }>
}
```

规则（全部可单测）：

1. **树只存 ratio**；像素在 compute 里算。拖动只改 ratio。
2. **最小尺寸永不靠"藏屏"满足**：空间不足时按固定顺序降级：① 标签条 compact；② 用 `compact` 下限；③ 仍不足 → 返回 `insufficient`，**拒绝创建**并给出「需要 Npx / 当前 Mpx」。
3. **收敛保证**：两区时必须是完整左右或上下（不存在「主区 + 右下角小面板」）；≥3 区允许 T 形与非贯穿分隔线（二叉树天然满足）。
4. **折叠是显式状态**（`collapsed: { areaId: 'start'|'end' }`），不会被误判成"没画出来"。
5. **浮层坐标同域**：浮层 rect 用同一套 CSS px；`clamp` 只做视口内收，不改变尺寸语义。

### 2.3 三种呈现（U2 的四态收敛为三态 + 灯箱）

| 形态 | 定义 | 与内容的关系 |
|---|---|---|
| 分屏（area） | 参与 tile | 默认形态 |
| 聚焦（focus） | 该 Surface 独占内容区，Agent 退为可输入的窄条（输入栏始终可用） | 布局态，不重建内容 |
| 悬浮（float） | 浮层，独立矩形 + z 序，可拖可缩可置顶/置底 | 不参与 tile；**网页跟手**：rect 每次变更即下发，每帧最多一次 |
| 灯箱 | 只读预览（预览器既有能力） | 不进工作区模型 |

四种之间可互相转换，内容状态连续（U3「内容及运行状态保持连续」）。

### 2.4 融合式标签（U4）

- 每个 Area 有 `axis: 'vertical' | 'horizontal'`，由该 Area 的主内容类型决定：Agent → 纵向（贴在左侧栏），Browser → 横向（顶部，Browser 根入口在左端），File → 纵向。
- 选中标签与内容面用**单层 mask 内凹圆角**连通（不再叠三层装饰）；未选中标签只在 hover 提亮，不画独立胶囊。
- 标签可拖：同 Area 排序、跨 Area 移动、拖到 Area 边缘=切分、拖到空白=浮层（可选入口）。

### 2.5 原生 webview 协同（一次性消除 S3/S4）

- **矩形唯一来源**：`computeWorkspace()` 的 area rect 减去该 Area 的 chrome（页眉 36 / 标签条 36）→ 就是 webview rect。组件**不再测量 DOM**。
- 可见性是一个纯函数：`visible = areaVisible && rect.width>0 && rect.height>0 && !overlayOpen && !interactionHides`。
- 让位改为**单一登记口**：任何浮层（菜单/模态/右栏/浮窗/灯箱）打开时必须 `openOverlay()`，由工作区统一计数；未登记不算数。
- 交互相位只影响会重排布局的手势（拖标签/拉分隔条/区域重停靠）；**浮层拖动/缩放不隐藏网页**（U7）。

### 2.6 持久化

`version: 4`：`{ tree, floats, placements, focusAreaId, collapsed, prefs }`。
只存模型，不存 rect；迁移 v1–v3（旧存档里的 float 标签搬进 floats、v2 的 compact 进 prefs），坏档按「主档 → 备份 → 默认」回退。

### 2.7 交互清单（全部落到纯函数 + 单测）

| 动作 | 规则 |
|---|---|
| 拖分隔条 | 12px 命中、吸附 25/50/75（Alt 关闭）、双击复位、`<8%` 折叠、低于下限则锁定并说明 |
| 建分屏 | 拖标签到 Area 边缘（角柄 > 交叉点 > 边缘 > 标签栏 > 内容区）、右键「向右/向下分屏」、快捷键 `Ctrl+\` / `Ctrl+Shift+\` |
| 固定（pin） | 浮层按中心落位选目标 Area，克隆布局算出结果，**预览条 = 落地结果**；落地后原 Area 自动填满；失败给出原因 |
| 解除固定（unpin） | 恢复该内容上一次浮层尺寸，位置贴近原 Area，置顶并聚焦 |
| 主辅互换 | 交换两个 Area 的标签集合，surface 实例不变 |
| 区域重停靠 | 拖 Area 角柄到另一 Area 边缘：先撤源再切目标，净变化为零 |
| 浮层 | 拖动/缩放跟手、点击置顶、`Alt+\`` 循环焦点、`Esc` 回主区、关闭=收起（不销毁内容） |
| 键盘 | `Ctrl+\`、`Ctrl+Shift+\`、`Ctrl+W`（仅辅助屏）、`Alt+1..9` 切屏、`Ctrl+Tab` 切标签、`Ctrl+Shift+Enter` 聚焦、`Esc` 退出 |

### 2.8 视觉

只使用既有令牌（`--theme-*`、`--radius-*`、`--dur-fast`、`--ease-out`、`--space-*`）；不新增硬编码颜色/像素。层级：内容 > 选中标签 > 操作控件 > 未选中标签 > 装饰（U9）。

## 3. 代码结构（新）

```
core/ui/src/workspace/
  model.ts       类型 + 构造 + normalize（去重/收拢/夹取）
  compute.ts     computeWorkspace 纯几何（铺满、无重叠、降级、chrome）
  ops.ts         所有变更：split/close/resize/collapse/moveArea/pin/unpin/swap/focus/float
  tabs.ts        标签集合：add/close/reorder/move/select
  persist.ts     v4 序列化 + v1–v3 迁移 + 回退
  hit.ts         命中区（角柄/交叉点/边缘/标签栏/内容）+ 拖拽落点
  visibility.ts  网页可见性纯函数（rect + 相位 + 浮层计数）
core/ui/src/components/
  CoreWorkspace.vue        工作区外壳（区域、浮层、预览、折叠）
  CoreWorkspaceArea.vue    单个区域（标签轴 + 内容槽）
  CoreWorkspaceTabs.vue    融合式标签（纵向/横向两种密度）
  CoreWorkspaceFloat.vue   浮层外壳（拖动/缩放/置顶/固定/收起）
```

保留（内容层，不动）：`CoreSplitBrowser.vue`、`CoreSplitPreview.vue`、`CoreSplitTextEditor.vue`、`CoreSplitFileTree.vue`、`CoreSplitContent.vue`（改为只负责按 surface 渲染，不参与几何），`split/native.ts`（IPC 契约）、`split/browserLayout.ts`（改为接收 compute 结果）。

## 5. 验收（直接把用户的口径搬过来）

### 5.1 U3 的 A1–D2 逐条

A1 无辅助区时主内容铺满 · A2 浮层外可正常交互 · A3 拖动缩放无错位 · A4 让位关闭不重排 · A5 让位开启有效且能回退 · B1 固定后形成合理矩形 · B2 无空洞/重叠/错误裁剪 · B3 支持 T 形与非贯穿 · B4 拖边界尺寸正确 · B5 解除固定自动填充且状态保持 · C1 主辅互换不丢状态 · C2 多浮层/多固定共存 · C3 切换与恢复不重载 · C4 隐藏不终止任务 · D1 窗口缩放不出现不可操作区域 · D2 布局异常不丢内容状态。

### 5.2 U4 的 A–E

根入口名称随主内容变化且锚点不变 · Agent 纵向标签与内容融合 · Browser 横向标签在左端、激活标签与网页无缝 · File 结构不与 Agent 混淆 · 连接处无直角硬拼接、层级清楚。

### 5.3 已发生 bug 的回归（必须全绿）

1. 网页必须落在自己的 Area 内（1.25/1.5/1.85 三档缩放各测一次，纯函数断言）。
2. 有分屏时菜单/右栏/浮窗不被网页盖住；分屏里有浏览器时窗口最大化/最小化/关闭可用（U6）。
3. 浮层拖动跟手（每帧一次下发、矩形不变不发）；pin 之后原分屏里不残留同一标签（U7）。
4. 标签高亮不越界、不短一截；输入栏永远在主内容列内（U8）。
5. 网页不可见期间不留残影，`insufficient` 时给出实数字据而不是空白（U8 的「点了没反应」）。

### 5.4 自动化门槛

- 引擎：`vitest` 纯函数单测（含属性测试：任意随机树 × 任意视口 → 铺满 / 无重叠 / 每区 ≥ 下限 或 `insufficient`）。
- 外壳：`@vue/test-utils` 交互测试（拖标签、拖分隔条、pin/unpin、形态切换、键盘）。
- 类型：改动文件 `vue-tsc` 零错误。
- 真机：由用户在 dev 上看一次（不看截图，靠 UIA 与日志）。

## 6. 明确不做

- 画布式自由摆放（用户否决过；V2 仍是矩形分区）。
- 移动端布局（项目排除）。
- 自由让位的「任意形状裁剪」：只做内容内部排版让位，Browser 等矩形视口不裁剪、不变形。
- 布局变形动画曲线与手势魔法（U3 第九章已排除）。
- 新的视觉皮肤：只沿用既有令牌与设计语言。
