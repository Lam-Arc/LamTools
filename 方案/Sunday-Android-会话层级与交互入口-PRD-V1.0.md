# Sunday Android — 会话层级与交互入口 PRD

> 来源：用户 2026-11-22 提供的 PRD 原文（按约定原样存档，不改写、不摘要）。
> 状态：实现中（阶段 B：聊天基础交互）。

版本：V1.0  
适用：Android 客户端  
状态：方案设计，待现有 UI 审查与实现对照

## 1. 设计原则

1. **聊天优先：** 用户首先看到会话，而非模型、项目或工具控制台。
2. **低层级：** 常用操作直接可达，复杂配置收纳进详情。
3. **内容优先：** 让 Agent 的回答成为主角，不让大量工具信息占据屏幕。
4. **状态真实：** 明确区分聊天消息、后台任务、传输状态和执行结果。
5. **跨端一致：** 设备、会话和任务使用 Sunday 现有统一标识。
6. **渐进增强：** 当前主要服务 Agent 聊天，未来可以自然扩展到人与人、Agent 与 Agent 通讯。

## 2. L1｜会话列表

### 2.1 页面结构

从上至下：

| 区域 | 内容 | 交互 |
|---|---|---|
| 顶部导航 | 标题「聊天」、搜索、新建 `+` | 全局会话操作 |
| 搜索区域 | 搜索会话、联系人、消息内容 | 点击进入搜索 |
| 置顶会话 | 用户主动置顶的聊天 | 点击打开 |
| 普通会话 | 按最近活动时间排列 | 点击打开 |
| 底部导航 | Sunday 一级导航 | 切换主要功能区 |

顶部保持克制，不放模型切换器、设备列表或复杂过滤控件。

### 2.2 会话列表卡片

采用微信式布局。

- 左：头像，区分 Agent、用户和系统会话。
- 中上：会话名称。
- 中下：最后一条消息摘要，或任务执行状态。
- 右上：最近消息时间。
- 右下：未读数量、待审批提示或静音标志。

特殊状态：

- **运行中：** 显示简短进度，例如「正在搜索资料」。
- **待审批：** 显示「等待你确认」，优先于普通消息摘要。
- **远程离线：** 显示「电脑离线」，避免误认为 Agent 卡住。
- **消息发送失败：** 有明确失败标记。

系统运行状态不伪装成另一条用户消息。

### 2.3 会话管理

| 操作 | 入口 |
|---|---|
| 打开会话 | 点击会话卡片 |
| 置顶 / 取消置顶 | 长按菜单 |
| 标记已读 / 未读 | 长按菜单 |
| 重命名 | 长按菜单或会话详情 |
| 静音 | 长按菜单或会话详情 |
| 归档 | 长按菜单 |
| 删除 | 长按菜单，二次确认 |
| 搜索 | 顶部搜索 |
| 新建 | 顶部 `+` |

可补充侧滑快捷操作，但所有侧滑操作必须在长按菜单中存在等效入口。

不使用容易与 Android 系统返回手势冲突的复杂手势。

### 2.4 新建会话

点击右上角 `+`，打开底部选择面板。

主要入口：

- 新建 Agent 会话。
- 选择已有 Agent。
- 选择联系人（后续 AI 通讯阶段启用）。

用户选择 Agent 后，直接进入新会话，不要求先选择项目、模型、工作目录等高级配置。

有多个执行设备时，默认沿用用户当前工作环境；切换到远程设备需要明确展示。

允许同一 Agent 拥有多个互相独立的会话。

### 2.5 搜索

搜索应覆盖：

- 会话名称。
- Agent 或联系人名称。
- 消息正文。
- 对话内文件与资源名称。

结果分为「会话」与「消息」，点击消息结果直接跳转到目标消息。

未来可扩展到任务和 Library 的全局搜索，但不让会话页承担整个 Sunday 的搜索界面。

## 3. L2｜会话详情

### 3.1 基本布局

**顶部栏 + 消息区 + 底部输入区。**

#### 顶部栏

| 位置 | 内容 |
|---|---|
| 左侧 | 返回会话列表 |
| 中间 | 会话名称，次级文字显示 Agent / 设备状态 |
| 右侧 | `···` 更多菜单 |

不常驻模型、项目、Agent 参数、多个工具按钮。

当前执行设备必须能够识别，例如「本机」或「Windows · 已连接」。

若设备正在离线恢复，显示真实状态。

#### 消息区域

采用聊天气泡布局：

- 用户发送的消息位于右侧。
- Agent / 联系人回复位于左侧。
- 相邻同一发送者的消息可以适度合并头像与时间展示。
- 短消息使用气泡。
- 长篇 AI 回复使用更宽的正文容器，避免窄气泡导致阅读困难。
- 代码、表格、图像、图表及文件使用专门的内容卡片。

不强制每个 AI 输出都使用小气泡。

#### 输入区

基本结构：

`[ + ] [ 输入消息…… ] [语音] [发送]`

- `+`：附件与扩展操作。
- 输入框：文本和多行输入。
- 语音：调用 Sunday 已有语音输入。
- 发送：发送消息。
- Agent 运行时按既有执行能力显示引导、停止等操作，不能因切换状态丢失输入内容。

输入框高度自适应，但有最大高度，超过后内部滚动。

软键盘打开时，底部输入区始终可见。

### 3.2 更多操作 `···`

点击右上角打开会话菜单：

| 入口 | 行为 |
|---|---|
| 会话信息 | 打开会话设置 |
| 搜索聊天记录 | 在当前会话内搜索 |
| 任务记录 | 查看该会话关联的任务 |
| 文件与资源 | 查看会话中的附件和产物 |
| 多选消息 | 批量选择消息 |
| 导出会话 | 使用现有导出能力 |
| 清理 / 删除 | 经过确认的管理操作 |

低频功能不单独占用顶部栏位置。

## 4. 消息交互

### 4.1 普通消息

点击消息中的链接、附件或可交互内容时，执行对应操作。

长按消息弹出菜单。

基础操作：

- 复制。
- 引用。
- 转发或分享。
- 收藏到 Library。
- 多选。
- 删除（按消息类型和权限支持）。

如果是 AI 输出，可以增加：

- 重新生成。
- 从这条消息继续或创建分支。
- 将内容交给其他 Agent。

这些属于上下文扩展操作，不全部进入默认长按菜单。

### 4.2 引用回复

选择「引用」后，输入栏上方出现被引用消息摘要。

发送后，消息中包含可以点击定位原消息的引用区域。

引用支持文本和文件消息，但不自动复制完整文件内容。

### 4.3 AI 输出操作

AI 回复结束后，按适用情况提供轻量操作：

- 复制。
- 重试。
- 继续。
- 收藏。
- 更多。

工具输出和大型结果不得自动展开成冗长技术日志。

### 4.4 消息生命周期

发送状态应准确区分：

1. 本机等待发送。
2. 发送中。
3. 对端已接收。
4. 执行中或已处理。
5. 失败或状态待确认。

AI 已处理请求，不等于人类「已读」。

断线重连时不自动重复执行有副作用的任务。

## 5. Agent 任务如何嵌入聊天

### 5.1 执行状态卡

当 Agent 执行复杂任务时，在消息流中显示紧凑的执行状态卡片。

例如：

**正在处理：整理文件**

已完成 4 / 6 个步骤

点击可展开本任务的工具调用和过程摘要。

执行状态应由真实后端事件驱动，不显示没有依据的模拟进度。

### 5.2 工具调用

默认折叠展示。

普通用户默认看到工具行为摘要：

- 正在浏览网页。
- 正在编辑文件。
- 正在运行程序。
- 正在等待授权。

点击后查看详细参数、执行记录和结果。

不将每一次工具调用都作为单独的聊天对象挤满列表。

### 5.3 审批消息

审批必须显示在对应任务上下文中。

卡片包含：

- 操作内容。
- 目标设备 / 文件。
- 影响范围。
- 允许、拒绝操作。

用户返回聊天后，未处理的审批仍可找到。

审批失效后按钮立即失效，不能重复触发。

### 5.4 任务完成

任务完成后显示结果消息。

结果中可包含：

- 简短摘要。
- 文件与产物卡片。
- 可继续执行的操作。
- 进入完整任务记录的入口。

任务本身继续归 Sunday 的任务中心管理。

## 6. 输入框扩展面板

点击 `+` 后从底部打开面板，借鉴 WeChat 的附件选择方式。

### 第一层：高频操作

| 入口 | 功能 |
|---|---|
| 图片 | 相册或图片选择器 |
| 文件 | 本地文件与系统文件选择器 |
| 拍摄 | 调用相机 |
| Library | 选择已有资产 |
| 设备 | 选择远程设备或发送目标 |
| 更多工具 | 展开已安装的其他 Sunday 能力 |

所有入口根据当前设备、会话权限和已安装功能展示。

没有必要把 Browser、Terminal、Workflow、Agent Hub 等全部摆在第一层。

### 第二层：工具选择

需要调用较少使用的功能时，进入工具列表或搜索。

支持：

- 按功能名称查找。
- 常用工具前置。
- 用户自定义快捷工具。
- 未授权工具发起正常授权流程。

**区分「发送附件」与「切换执行环境」：选择文件不等于改变 Agent 的工作设备。**

## 7. L3｜会话设置

顶部 `··· → 会话信息`。

### 7.1 基础信息

显示：

- 会话名称。
- 参与者 / Agent。
- 关联项目或工作区。
- 当前执行设备。
- 创建时间等必要信息。

支持重命名、置顶、静音、归档。

### 7.2 Agent 设置

按当前 Agent 支持能力提供：

- 使用的模型。
- Agent 配置或角色。
- 可调用的工具能力。
- 必要的执行参数。

高级参数放入折叠区域，不打断普通聊天体验。

修改模型或执行环境时明确说明对当前任务、下一条消息或新会话的生效范围。

### 7.3 执行设备

允许查看和切换可用设备。

切换前需明确：

- 新请求将在哪台设备执行。
- 相关文件是否存在于目标设备。
- 是否需要额外授权。

不因为选择了另一台设备，就悄悄迁移已有任务或修改其工作目录。

### 7.4 消息与存储

- 查看会话文件。
- 查看关联任务。
- 搜索历史。
- 清理本地缓存。
- 导出会话。
- 删除会话。

删除会话、删除远程数据、终止运行任务必须是不同的操作，不能混为一谈。

## 8. 跨端与未来 AI 通讯

本次设计预留聊天对象类型，但不提前开发社交系统。

### 8.1 对话类型

| 类型 | 表现 | 当前定位 |
|---|---|---|
| Agent | Agent 头像与身份 | 核心 |
| 远程 Agent | Agent 身份 + 设备来源 | 核心 |
| 联系人 | 用户身份 | 后续 |
| 多参与者会话 | 参与者信息与消息归属 | 后续 |
| Agent 协作 | 多 Agent 消息与任务状态 | 后续 |

会话列表可以容纳不同类型，不为每种类型建立不同的聊天主界面。

### 8.2 统一消息结构

底层为消息保留：

- 会话 ID。
- 消息 ID。
- 发送者身份和类型。
- 所属设备。
- 消息类型。
- 时间和顺序信息。
- 发送 / 接收状态。
- 关联任务或资源引用。

会话 UI 根据消息类型决定呈现方式，不通过解析普通文本猜测消息功能。

### 8.3 未来扩展

后续 AI 通讯可逐步增加：

- 联系人。
- Agent 联系人。
- 会话邀请。
- 多人或多 Agent 会话。
- 跨设备消息同步。
- 离线消息。
- 已读状态（仅适用支持该语义的参与者）。

这些能力不应要求重新设计 L1 会话列表和 L2 聊天界面的基本结构。

## 9. Android 交互规范

- 返回手势先关闭键盘或临时面板，再返回上一层，具体遵循 Android 当前系统行为。
- 聊天页面返回列表时保留当前滚动位置与输入草稿。
- 不因页面切换自动停止任务。
- 底部扩展面板与键盘不同时争夺空间。
- 长按菜单不遮挡被选消息的必要上下文。
- 点击外部区域可关闭普通临时面板。
- 图片和文件预览使用适合手机的全屏或底部面板。
- 常用触控目标至少 48dp。
- 横屏、平板、分屏情况下保持一致的会话逻辑。

## 10. 验收标准

| 项目 | 验收要求 |
|---|---|
| 新建聊天 | 选择 Agent 后直接进入可输入的会话 |
| 查找聊天 | 可按名称及消息内容搜索 |
| 多会话 | 同一 Agent 的不同会话不会混淆 |
| 列表管理 | 置顶、静音、归档等功能行为真实 |
| 阅读 | 长文本、Markdown、表格可正常查看 |
| 输入 | 键盘不遮挡输入区，草稿不意外丢失 |
| 工具调用 | 普通视图紧凑，详细信息按需展开 |
| 审批 | 在聊天中可定位、操作并确认结果 |
| 文件 | 附件选择、发送、预览和引用可正常完成 |
| 远程设备 | 能明确判断当前操作设备及连接状态 |
| 消息可靠性 | 发送、接收、执行状态不混淆 |
| 返回操作 | Android 返回手势符合预期，无误退出 |
| 历史记录 | 大量消息可正常滚动、定位与搜索 |
| UI 一致性 | 所有会话类型复用一致的基础交互组件 |

## 11. 实施顺序

**阶段 A：现有页面审查**

检查导航、会话列表、消息组件、输入区、Agent 任务信息和工具面板。

**阶段 B：聊天基础交互**

完成列表、新建会话、搜索、长按菜单、消息布局和输入区优化。

**阶段 C：Agent 专属内容**

统一任务卡、工具调用、审批、文件与结果的交互形式。

**阶段 D：远程与扩展**

接入已有设备状态与跨端会话能力，预留未来 AI 通讯的参与者和消息类型。

**阶段 E：真机体验验收**

重点测试长对话、键盘、返回手势、前后台切换、连接恢复和任务持续执行。

---

## 12. 本次明确不做

- 不复制微信的朋友圈、支付或社交生态。
- 不强制实现联系人、群聊和已读回执。
- 不为聊天 UI 重写 Sunday Agent Loop。
- 不把所有工具都塞入输入栏。
- 不重新开发独立的消息传输或任务系统。
- 不强行把手机变成桌面端的多窗口缩小版。

**最终标准：普通用户像使用微信一样找到会话、发送消息、打开附件；需要 Agent 能力时，再逐步展开 Sunday 的任务、工具和工作区。**
