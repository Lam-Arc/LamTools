## 4. 实验流程

- 流式响应解析器。
- 思考、正文和工具块的事件转换机制。

- Usage 统计机制。
- 消息持久化及会话恢复机制。
- 请求生命周期和结束状态管理。

同时调查星盘实际支持的 Gemini 原生协议与 OpenAI 兼容协议。

优先复用 Sunday 现有能力，不预设必须使用某一种协议，不预设必须修改架构。

脱离 Sunday 的 Agent 流程，使用上述 API Key 直接向中转站发起真实请求，建立上游协议基线。

- 流式结束信号。
- 多轮工具调用所需的上下文结构。

不得将协议文档或第三方检测结果直接当作本次实验的通过证据。

## 5. 重点技术要求

### 5.1 思考块

正确处理上游实际返回的思考内容或摘要，例如 Gemini 原生 thought part、兼容协议中的 reasoning_content 等。

要求：

- 与正文独立存储、独立渲染。
- 不丢失流式分片。
- 不重复拼接。
- 正确处理正文与工具调用之间的思考事件。
- 保留协议要求的 thoughtSignature 等必要字段，并在后续调用中正确回传（如适用）。

如果上游没有返回可展示的思考内容，不得通过正文推测或伪造思考块。

### 5.2 正文块

保证正文实时输出，不截断、不重复、不乱序。

不得将思考内容、工具参数或协议元数据错误地拼入正文。

### 5.3 工具块

验证完整链路：

模型发出工具调用 → Sunday 解析 → 执行工具 → 回传结果 → 模型继续生成 → 任务结束。

正确处理分片参数、调用 ID、多工具调用及工具异常。

### 5.4 Usage

尽可能完整捕获上游提供的：

- 输入 Token。
- 输出 Token。
- 思考 Token。
- 缓存读取 Token。
- 缓存写入 Token（如支持）。
- 总 Token。
- 单次 API 请求用量。
- 整次 Agent 任务累计用量。

特别注意：

- Usage 可能出现在流式响应末尾。
- 思考 Token 与输出 Token 可能存在包含关系。
- 累计统计与增量统计不得混淆。
- 缺失字段不得默认为真实的零用量。
- 不得重复累计同一次请求的 Usage。
- 0.4× 为计费倍率，不得用于修改原始 Token 数量。

将 Sunday 中记录的 Usage 与原始 API 响应逐项对照，确保统计口径一致。

### 5.5 请求结束

正确区分：

- 单次模型请求正常结束。
- 模型请求结束并等待工具执行。
- 整次 Agent 任务正常结束。
- 用户主动取消。
- 网络中断。
- 上游返回错误。

尤其不能将工具调用轮次的结束误判为整个 Agent 任务结束，也不能因等待不存在的后续事件而永久卡在生成状态。

## 6. 实施原则

遵循第一性原则，避免过度工程化。

- 优先使用现有 Provider 和协议适配机制。
- 优先修复通用兼容性问题。
- 不为单个中转站创建不必要的独立架构。
- 不进行与实验目标无关的重构。
- 不破坏其他已正常工作的模型。
- 不使用 Mock 响应替代真实 API 验收。
- 不将临时 Key 硬编码进产品源码或 Git 提交记录。
- 使用必要且适量的真实请求，避免无意义地消耗额度。
- 不限制具体技术实现路径，以最终实际运行效果为准。
