## 1. 产品定位

Sunday Android 不是桌面端的缩小版，也不是电脑的遥控器。

它应当是一个具备独立 Agent 能力、又能无缝连接桌面端的移动工作环境。

### 核心目标

1. **简单：** 让用户用尽可能少的操作完成常见任务。
2. **原生：** 符合 Android 的触控、返回、键盘、通知及系统行为。
3. **统一：** 与 Sunday 桌面端共享设计语言、数据与组件。
4. **独立：** 手机可以独立运行支持的 Agent 任务，不强制依赖电脑。
5. **连续：** 在本机与远程设备之间自然切换，保持任务上下文。
6. **高效：** 小屏幕不堆砌桌面功能，重要内容优先显示。

**原则：复用已有 Vue、Tauri 2、Rust Core 和 UI 组件，不另造一套移动端架构。**

## 2. 现有 Android UI 审查

开发前必须先检查当前 APK、最新源码及真实 Android 设备上的界面。

| 审查对象 | 检查重点 |
|---|---|
| 导航系统 | 入口是否重复，层级是否过深 |
| Agent 对话 | 消息、工具调用、审批、输入栏是否适合手机 |
| 工作区 | 项目、会话、文件及 Browser 是否容易切换 |
| 任务管理 | 运行、暂停、恢复、失败状态是否准确 |
| 远程连接 | 本机与桌面端是否容易区分和操作 |
| Easy Tools | 功能入口是否符合普通用户的语义理解 |
| 视觉设计 | 字体、间距、图标、颜色是否统一 |
| Android 适配 | 状态栏、手势、键盘、返回行为是否正确 |
| 性能体验 | 启动、滚动、切页是否流畅 |
| 异常体验 | 断网、无权限、系统终止任务时的反馈 |

审查必须同时检查**视觉效果和实际交互行为**。

每个问题记录实际截图或操作路径、影响程度、代码位置、优化措施和复测结果。

审查结果分为：保留、优化、合并、补齐、删除。

已经完善的模块不重复开发。

## 3. 信息架构优化（P0）

### 3.1 主导航

保留四个一级入口，建议统一为：

| 入口 | 功能 |
|---|---|
| 对话 | Agent 交流、输入、工具结果与审批 |
| 工作区 | 项目、会话、Library、Browser 和文件 |
| 任务 | 运行中、待审批、已完成的任务 |
| 功能 | Easy Tools、设备管理与设置 |

历史方案曾使用「对话 / 项目 / 运行 / 设置」及其他名称。

最终以现有功能语义和真实导航关系审查后统一，避免出现多个入口名称对应相同内容的情况。

### 3.2 导航要求

- 手机采用底部导航栏。
- 一级入口始终清晰，不随页面变化混乱移动。
- 二级页面通过顶部标题、返回及上下文菜单管理。
- 频繁使用的操作在一至两次点击内可达。
- Android 系统返回键和返回手势行为一致。
- 返回上一页不应意外取消正在执行的 Agent 任务。
- 切换一级入口时尽量保留滚动位置、输入草稿与页面状态。
- 不为了对齐桌面端而引入复杂多窗导航。

### 3.3 当前工作环境

顶部提供简洁的工作环境切换器：

- 本机 Android
- 已配对的 Windows 电脑
- 其他已授权设备

始终明确当前操作由哪台设备执行。

切换工作环境不自动迁移正在运行的任务，也不改变原任务所属设备。

## 4. Agent 对话界面（P0）

这是移动端最重要的页面。

### 4.1 消息布局

- 单列对话，最大化正文可读空间。
- 减少不必要的卡片外边距与装饰。
- Markdown、代码、表格和数学公式正确显示。
- 宽表格及代码区域可独立横向滚动。
- 图片、文件、图表可以点击展开。
- 长消息滚动保持流畅。
- 新消息不强制打断用户阅读历史内容。

### 4.2 Agent 执行过程

默认展示简洁状态，例如：

- 正在执行
- 等待审批
- 已完成
- 执行失败

工具调用与过程记录默认折叠，用户需要时再展开详情。

保留现有 Stop、恢复、工具审批等能力，优先优化信息呈现。

### 4.3 输入区域

底部输入栏支持：

- 多行文本输入。
- 发送与停止操作。
- 附件及文件选择。
- 已支持的语音输入。
- 文本选取、复制、粘贴。
- 草稿保留。
- 长文本输入时适度展开。

键盘弹出后，输入栏始终可见，聊天内容不会被键盘遮挡。

发送按钮、附件按钮和停止按钮必须有明确的状态区分。

### 4.4 审批体验

审批直接嵌入相关消息位置。

用户应当能够看到：

- Agent 准备做什么。
- 影响哪个设备或文件。
- 为什么需要权限。
- 允许与拒绝的实际含义。

高风险操作必须明确展示影响范围。

审批超时、撤销或任务已结束时，旧按钮不得继续产生操作。

## 5. 移动工作区（P0）

### 5.1 设计方向

手机不直接复制桌面端的矩形分屏系统。

采用**单主内容视图 + 快速内容切换**。

同一时间重点展示一个任务或内容对象，其他内容保留访问入口和状态。

### 5.2 工作区内容

整合现有：

- 项目及会话。
- Library 资产。
- Browser 页面。
- Easy File 文件。
- Agent 生成结果。

这些是同一工作环境中的不同内容类型，不应要求用户反复进入完全独立的界面才能相互操作。

### 5.3 文件与内容预览

- 图片、PDF、文本、代码及已支持格式使用统一预览入口。
- 手机优先全屏预览。
- 支持内容缩放、搜索、分享和返回。
- 已支持编辑的文件保留编辑能力。
- 从预览返回时保留原有工作区状态。
- 文件可以交给 Agent 继续处理。
- 不支持的格式明确提示并调用系统可用应用。

### 5.4 Library

移动端直接复用已有 Library 的索引、标签、筛选、搜索及资产管理能力。

重点优化：

- 单列或双列卡片自适应。
- 适合触摸的筛选控件。
- 长按多选及批量操作。
- 图片与视频缩略图加载。
- 大型资源库的滚动性能。
- 本地与远程资产来源区分。

远程 Library 默认按需读取元数据和内容，不自动下载其他设备的完整文件库。

## 6. 任务中心（P0）

任务页集中显示本机及远程设备的 Agent 工作状态。

### 基本功能

- 运行中任务。
- 等待审批任务。
- 已完成任务。
- 失败或中断任务。
- 历史任务及结果。

任务卡片至少显示任务名称、所属设备、状态和必要操作。

### 交互要求

- 点击任务进入对应会话或执行详情。
- 可继续、停止或重试的任务显示真实可用操作。
- 后台任务不因切换页面而意外取消。
- 远程设备离线后明确展示状态未知或暂不可操作。
- 同一任务不得因重复点击产生意外的重复执行。
- 任务完成后可以从通知直接回到相关结果。

不额外创建第二套任务管理系统。

## 7. 设备连接与远程交互（P0）

此部分与 Sunday Connect PRD 共用底层能力，本 PRD 只负责 Android 界面和使用体验。

### 7.1 设备切换

用户可以快速：

1. 查看当前工作设备。
2. 切换到已授权电脑。
3. 查看远程任务。
4. 发起远程 Agent 操作。
5. 返回手机本机环境。

远程状态需要区分：

- 在线且可用。
- 正在连接。
- 正在恢复。
- 离线。
- 权限受限。

不允许仅凭网络连接成功就显示完整业务可用。

### 7.2 首次配对

- 使用二维码完成设备配对。
- 明确展示正在确认的设备。
- 配对完成后自动进入设备列表。
- 拒绝或失败时给出原因。
- 已配对设备不要求每次重新配对。

### 7.3 远程内容

- 支持远程会话和文件按需加载。
- 明确提示内容所属设备。
- 显示文件传输进度。
- 不将远程内容默认为手机本地文件。
- 离线时可显示已有缓存，但不可伪装成实时内容。
- 远程写入、删除及执行操作沿用既有授权规则。

## 8. Easy Tools 移动适配（P1）

移动端应呈现已经适合 Android 使用的功能，而不是照搬桌面全部工具。

| 模块 | Android UI 重点 |
|---|---|
| Easy Net | 当前网络、下载、已连接设备、诊断 |
| Easy File | 文件浏览、搜索、操作及系统文件选择器 |
| Easy Convert | 格式选择、文件转换、进度和结果 |
| Library | 资产查看、检索、整理和发送给 Agent |
| Browser | 浏览、页面切换及与 Agent 互动 |

功能页面优先采取轻量卡片与任务式操作。

已有工具统一复用，避免为 Android 重新开发同名但能力不同的工具。

系统不支持的桌面功能应标明不可用或提供合适替代，不显示无效操作按钮。

## 9. 视觉设计系统（P1）

### 9.1 跨端统一

沿用 Sunday 设计系统：

- 黑、白、灰为基础。
- 太阳色系作为强调色。
- 红色用于确实需要强调的状态。
- 共享图标、字体层级、组件状态和设计 Token。
- 保留必要的品牌辨识度。

Android 与桌面端保持视觉关系，但不要求组件尺寸和布局完全一致。

### 9.2 移动端组件

重点规范：

- 顶部导航栏。
- 底部导航栏。
- 对话消息与输入栏。
- 任务卡片。
- 文件卡片。
- 底部弹出面板。
- 选择器及操作菜单。
- 进度、加载、空状态和错误提示。
- Toast、Snackbar、系统通知。

减少无意义的玻璃特效、模糊、动画和大面积装饰。

优先保证文字清晰、层次明确和设备运行性能。

### 9.3 触控体验

- 常规触控目标至少 48dp。
- 常用操作尽量置于单手容易触及的位置。
- 长按、滑动和拖拽操作必须有可发现的替代入口。
- 危险操作必须避免误触。
- 点击有及时的视觉反馈。
- 动画可以根据系统减少动态效果的偏好进行简化。

## 10. Android 系统适配（P0）

重点处理 WebView/Tauri 与 Android 系统交互之间的问题。

### 必须验收

1. 状态栏和导航栏安全区域。
2. Edge-to-edge 布局和异形屏。
3. 系统返回手势及预测性返回兼容性。
4. 软键盘弹出、收起和页面尺寸变化。
5. 前后台切换后的 UI 状态恢复。
6. 深色、浅色模式。
7. 横屏、分屏、平板及折叠屏窗口尺寸变化。
8. 文件选择、分享、通知及权限请求。
9. 系统字体大小与显示缩放。
10. TalkBack、语义标签、焦点顺序及文字对比度。

手机采用单栏，平板或较宽窗口采用自适应双栏。

双栏优先用于列表与详情关系，不强行移植桌面浮层分屏系统。

## 11. 性能与体验（P0）

### 优化要求

- 消除页面切换时明显的白屏和闪烁。
- 大量消息与文件使用按需渲染。
- 缩略图按需加载。
- 避免不必要的全局状态刷新。
- 输入过程中不发生持续卡顿。
- 后台任务更新不触发整页重新渲染。
- 设备切换不导致无关页面状态丢失。
- 降低空闲状态下的 UI 更新和电量消耗。

### 验收指标

| 项目 | 目标 |
|---|---|
| 导航 | 连续切换无明显白屏、状态错乱 |
| 滚动 | 目标设备正常场景下保持接近显示刷新率 |
| 触控响应 | 常规操作及时反馈，原则上 100ms 内可感知 |
| 页面恢复 | 返回后保留合理的滚动、输入和选择状态 |
| 输入 | 键盘开合不遮挡输入栏或重要操作 |
| 长对话 | 1000 条消息场景可正常浏览，无持续性明显卡顿 |
| 内存 | 长时间使用无持续增长的资源泄漏 |
| 异常恢复 | 被系统回收后可恢复持久化数据，临时状态有明确处理 |

具体启动耗时、内存和帧率门槛，应在代表性真机上测量现有基线后设定。

## 12. 核心用户验收场景

**场景 A：手机独立工作**

打开 Sunday，进入对话，输入任务，查看 Agent 执行过程及结果。无需桌面电脑在线。

**场景 B：远程电脑工作**

手机选择电脑，进入该设备的会话，提交经授权的任务，查看状态和结果。

**场景 C：文件交互**

从 Library 或系统文件选择器选取文件，发送给 Agent，查看处理结果，再保存或分享。

**场景 D：后台恢复**

Agent 正在运行时切换到其他 App，重新打开 Sunday 后显示正确的任务状态，不重复执行操作。

**场景 E：断网与重连**

查看远程任务时断网，界面明确显示离线，恢复后重新获取真实状态。

**场景 F：小屏与键盘**

在小屏设备上输入长消息、展开工具结果、审批操作和预览文件，内容不重叠、不丢失。

**场景 G：平板及折叠设备**

改变窗口大小或设备姿态，布局自动适配，已有输入及任务信息不丢失。

## 13. 明确不做的内容

本轮不包括：

- 重新开发 Android Agent 或共享 Rust Runtime。
- 重新设计 Sunday Relay 通讯协议。
- 将 Android 改造成纯远程桌面控制器。
- 完整复制 Windows 多窗口系统。
- 移植桌宠和完整桌面 Overlay。
- 重做 Library、Browser 或 Easy Tools 的底层能力。
- 引入第二套主题系统或独立 UI 框架。
- 为视觉演示增加没有真实行为的功能。
- 把 Android 系统权限限制伪装为功能成功。

## 15. 最终验收原则

本次 PRD 不以新增页面或视觉改版数量判断完成度。

**最终要求：**

- 现有功能没有因为 UI 优化出现回归。
- 主要操作流程明显简化。
- 用户始终能判断当前设备和任务状态。
- 复杂 Agent 能力在小屏幕上仍然清晰可用。
- Android 系统行为正确，操作稳定。
- UI 与桌面端共享一致的产品语言。
- 手机真正可以独立完成 Sunday 支持的工作。

**完成标准：从用户打开 App 到完成一项实际任务，整个流程不需要理解 Sunday 内部技术架构。**
