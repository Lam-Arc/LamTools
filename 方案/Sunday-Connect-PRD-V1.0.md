# Sunday Connect — 跨设备连接与通讯底座优化 PRD

**版本：** V1.0 · 2026-11-22  
**类型：** 既有 Relay 审查 + Windows/Android 跨端优化  
**优先级：** P0  
**依赖：** Sunday Relay / Iroh、Sunday Core、Android Lite Agent  
**状态：** 需求草案，当前代码状态待验证

## 1. 产品目标

让用户的 Windows 电脑与 Android 手机无需网络知识，即可快速、安全、稳定地连接。

在此基础上建立可复用的设备通讯能力，为后续以下功能提供底座：

- 手机和电脑之间的消息、文件与内容同步。
- 手机远程调用电脑的 Sunday Agent。
- 电脑向手机推送通知、审批和任务结果。
- 多个 Sunday 设备之间的任务移交。
- 后续人与 Agent、Agent 与 Agent 的 AI 通讯。

**目标不是重新制造一个独立的聊天系统或 VPN，而是让 Sunday 的所有跨端功能共享一套可信连接。**

Android 保持独立工作环境，运行自己的轻量 Agent；Windows 端保留完整 Agent。连接只负责打通设备与能力，不强制把全部工作交给电脑执行。

## 2. 已有系统的审查要求

针对最新实际运行分支审查：

| 对象 | 审查内容 | 预期结果 |
|---|---|---|
| Iroh 集成 | 真实初始化、地址发现、直连及中继路径 | 不存在仅部分接入 |
| 配对机制 | 二维码、设备身份、一次性授权 | 陌生设备不能自动获得信任 |
| 打包发布 | Sidecar、运行依赖、启动和退出管理 | 安装包在干净系统上可运行 |
| Android 客户端 | 前后台切换、休眠、网络切换 | 自动恢复，不无限转圈 |
| Core 生命周期 | Core 重启、进程异常、服务初始化 | 链路状态与业务状态一致 |
| 设备撤权 | 密钥、信任关系及现有连接 | 解绑后不再允许操作 |
| 消息协议 | ID、ACK、去重、重试、顺序恢复 | 消息可靠且不会重复执行任务 |
| 文件传输 | 传输中断、流控、校验和续传 | 数据完整 |
| 性能 | 建连耗时、重连耗时、资源占用 | 可量化且可诊断 |
| 安全 | 远程指令、文件访问、屏幕能力 | 按能力授权，避免越权 |

复核历史已发现的问题，但以最新代码和测试为最终依据。已经修复的功能标记为通过，不重复开发。

## 3. 用户交互

### 3.1 首次配对（P0）

电脑打开「我的设备」并选择添加手机。

1. 电脑生成短时有效的配对二维码。
2. 手机使用 Sunday 扫码。
3. 两端建立设备身份验证，电脑显示待确认设备。
4. 用户确认配对。
5. 自动选择可用网络路径。
6. 双方完成 Sunday 服务握手，进入可用状态。

要求：

- 用户无需配置 IP、端口、NAT 或中继地址。
- 配对凭证一次性使用，有时效限制。
- 拒绝、超时、重复扫码均有清晰反馈。
- 配对成功后建立持久设备信任，下次自动连接。
- 配对授权不等于授予全部远程控制权限。

### 3.2 日常自动连接（P0）

用户完成第一次配对后：

- 打开 Sunday 时自动连接可信设备。
- Wi-Fi 与移动网络切换后自动恢复。
- 电脑休眠唤醒、Sunday Core 重启后能够恢复会话。
- 短暂断线不打断正在查看的内容，不频繁弹窗。
- 无法恢复时明确显示设备离线或服务不可用。
- 远程访问总开关可关闭，用户关闭后不擅自恢复。

连接状态必须基于真实业务可用性，而非仅依据网络通道存活。

### 3.3 连接状态（P0）

用户可见状态：

| 状态 | 说明 |
|---|---|
| 等待授权 | 设备尚未完成确认 |
| 正在连接 | 正在建立安全连接及准备服务 |
| 已连接 | 已验证身份并完成必要的 Sunday 服务握手 |
| 正在恢复 | 连接暂时不可用，系统正在自动处理 |
| 离线 | 设备不可达或远程服务已关闭 |
| 权限受限 | 已连接，但当前操作未获授权 |

网络传输层连接、设备认证、Core 初始化、会话恢复必须分别检查。

只有完成业务层握手并通过基本消息收发检查，才能显示已连接。

## 4. 核心能力

### 4.1 智能连接与自动选路（P0）

优先使用当前 Sunday 已集成的 Iroh。

连接目标：

- 局域网内尽可能直接连接。
- 不同网络优先尝试 P2P。
- 无法直连时自动使用已配置、可用的第三方中继。
- 在已建立可用连接的前提下，后台尝试优化传输路径。
- 网络变化时自动恢复或迁移可用路径。
- 中继不可用时报告实际故障，不假装已连通。

连接详情展示直连或中继、往返延迟、传输速率和错误原因。

普通用户只需看到能否正常使用。

不要求用户自己部署公共服务器，不承诺所有 NAT 条件都能纯 P2P。

### 4.2 可信设备与权限（P0）

每台设备应拥有独立且稳定的设备身份。

功能包括：

- 设备命名、识别、配对、解绑。
- 密钥安全保存和必要时轮换。
- 用户可以立即撤销设备授权。
- 撤销后既有连接与后续请求都必须失效。
- 设备认证与具体操作权限相互独立。
- 审计远程访问、授权和拒绝操作。

权限按能力分类，例如：

| 能力 | 默认行为 |
|---|---|
| 查看设备状态 | 已配对设备可按策略访问 |
| 发送消息 | 已配对设备可用 |
| 文件读取 | 按目录或文件授权 |
| 执行 Agent 任务 | 按任务授权或受控的持久授权 |
| 屏幕查看 | 单独授权 |
| 控制键鼠 | 单独授权，默认关闭 |
| 执行系统命令 | 高风险权限，必须明确授权 |

不得因为进入同一个虚拟局域网，就自动获得这些应用级权限。

### 4.3 可靠消息（P0）

统一复用现有 Sunday 消息、事件与任务协议，补齐必要能力，而不是另造消息总线。

要求：

- 每条消息具备唯一 ID。
- 区分已入队、已发送、对端已接收、业务已处理、失败或状态未知。
- 超时不自动等同于发送失败。
- 断线后恢复未确认的消息与任务状态。
- 同一会话内有明确顺序规则。
- 支持 TTL、取消、去重及必要的重试。
- 对于可能产生副作用的操作，不能因重传重复执行。
- 已过期或已撤销权限的指令不能在恢复连接后重新生效。

传输消息与执行任务采用不同回执，确保用户知道「对方收到了」和「任务完成了」是两件事。

### 4.4 文件与数据传输（P1）

支持手机和电脑互传文件、截图、Agent 结果和资产引用。

要求：

- 小文件可以直接发送。
- 大文件支持分块、暂停、恢复和完整性校验。
- 支持传输进度、剩余大小、失败原因。
- 可限制移动网络流量及带宽。
- 传输完成后可选择在 Easy File 或 Library 中打开。
- 不强制将所有文件上传至中转服务器。
- 未授权的远程文件路径不可直接读取。

### 4.5 任务与会话接力（P1）

用户可以：

- 在手机上继续查看电脑的 Agent 任务。
- 在手机发起需要桌面能力的任务。
- 从电脑发送审批请求至手机。
- 在手机收到任务完成通知并查看结果。
- 将内容或文件引用在两个工作环境之间移交。

跨设备接力必须保留任务身份、授权状态、进度、结果引用与必要的上下文。

同一任务不能因跨设备重复提交而意外执行多次。

### 4.6 Android 后台连接（P1）

针对 Android 系统约束专项优化：

- App 进入后台后保留系统允许的必要连接能力。
- 系统限制后台执行时，支持在重新打开 App 后恢复状态。
- 用户可明确选择是否开启需要持续运行的连接服务。
- 避免无意义的高频心跳和持续唤醒。
- 电量优化、系统限制或通知权限影响功能时说明原因。
- 网络变化、VPN 冲突和后台限制进入诊断结果。

不得以「永久在线」为目标绕过系统行为，也不得把应用被系统暂停解释为账号或设备异常。

## 5. 可选虚拟局域网扩展（P2）

在 Sunday 自身的连接可靠后，可扩展成更广泛的网络互联能力。

此功能由 Easy Net 对用户呈现，但由独立网络适配层提供。

### 目标

将远程设备加入同一个私人网络，使现有局域网应用可以通过虚拟 IP 通信。

包括：

- 网络创建与加入。
- 虚拟地址分配。
- 网络成员管理。
- 自动连接与恢复。
- 网络访问限制。
- 基本连通性诊断。
- 可选的局域网服务发现和子网访问。

### 技术复用要求

优先评估 EasyTier 等现有解决方案，重点审查：

- Windows 与 Android 可用性。
- 内核复用、第三方进程运行和安装管理。
- 虚拟网卡/系统 VPN 权限。
- 与 Sunday Iroh 连接是否冲突。
- 与现有 VPN、代理及网络路由是否兼容。
- 第三方依赖许可与长期维护风险。
- 使用社区节点时的可用性、隐私与可靠性。
- 不使用自营服务器能否完成普通用户的基础场景。

若最终使用 EasyTier，应视为可选的虚拟网络引擎，而不是替换 Sunday Relay。

Sunday 本身的消息、Agent 任务、文件访问不依赖虚拟局域网开启。

## 6. 面向 AI 通讯的预留能力

本 PRD 不直接开发完整 AI 聊天产品，但必须为其保留共同底座。

### 6.1 统一通讯对象

未来通讯可在以下对象之间发生：

- 人与自己的 Sunday 设备。
- 人与 Agent。
- Agent 与 Agent。
- 不同设备上的 Agent。
- 经明确授权的不同用户及其设备。

自有设备与外部用户应使用不同的信任和权限边界。

### 6.2 标准消息能力

至少覆盖：

- 文本消息。
- 文件与资产引用。
- Agent 任务请求。
- 审批请求和结果。
- 状态通知。
- 错误和撤销消息。

消息需要可辨认发送者、接收者、会话、任务、消息 ID、权限和生命周期。

### 6.3 离线与同步

后续支持离线消息和历史同步时，复用同一通讯协议。

第一阶段无需建设公共云消息服务器。离线消息可先采用设备端持久队列，在双方恢复在线后同步。

明确区分本机已保存、远端收到和远端已读；双方长期同时离线时，不承诺实时送达。

### 6.4 扩展边界

通讯协议与界面分离。

未来增加联系人、聊天窗口、群组、Agent 协作或通知渠道时，不重新设计设备身份、底层传输、回执和权限系统。

## 7. 量化验收

以下为建议目标，必须通过 Sunday 实机测试取得结果，不能直接使用 Iroh 或其他产品的宣传指标。

| 指标 | 目标 |
|---|---|
| 首次配对 | 正常网络下流程清晰，无需手工配置网络；统计 P50/P95 耗时 |
| 连接成功率 | 分别统计直连成功率和包含中继的最终连通率 |
| 短断线恢复 | 100 次测试中至少 95 次自动恢复业务会话 |
| 业务状态 | 禁止出现长期显示已连接但实际无法通信的假在线 |
| 消息可靠性 | 网络中断、重传后不丢失已确认消息、不重复执行副作用操作 |
| 文件完整性 | 10 MB 文件中途断开 20 次，最终校验全部正确 |
| 权限撤销 | 撤权后既有会话不能继续执行受保护操作 |
| 设备恢复 | 电脑休眠唤醒、Core 重启、手机切换网络后可恢复 |
| 长时间运行 | 24 小时无持续增长的连接、任务队列或明显资源泄漏 |

测试至少覆盖家庭 Wi-Fi、手机热点、不同外网、受限 NAT、第三方 VPN 干扰等环境。

耗时目标根据真实基线确定，不人为编造具体建连时间。

## 8. 产品验收场景

**场景 A：首次连接**

在电脑和手机分别安装 Sunday，扫码、确认，即可远程查看设备状态并发送消息。

**场景 B：电脑不在身边**

使用移动网络打开手机 Sunday，查看电脑中的任务并发起经授权的远程操作。

**场景 C：中途断网**

电脑 Agent 执行任务时手机断网，恢复后任务状态准确，已经执行的操作不重复发生。

**场景 D：传输大文件**

向另一端发送文件，中途断线后恢复，文件内容一致。

**场景 E：设备丢失**

在另一台可信设备上解除丢失设备的授权，丢失设备不再能够执行远程操作。

**场景 F：虚拟局域网**

在不同网络中的电脑之间建立私人网络，访问经过授权的共享服务，不需要手工配置公网 IP 和端口转发。

## 9. 实施阶段

**C0 — 现有实现复核**  
确认打包、设备信任、撤权、连接状态和重连机制的实际完成情况。

**C1 — 连接可靠性**  
完成配对安全、状态准确、无感恢复、消息可靠性。

**C2 — 跨设备能力**  
完成文件传输、权限管理、任务与会话接力。

**C3 — 虚拟局域网**  
评估并接入可复用网络内核，提供可选私人网络能力。

**C4 — AI 通讯准备**  
统一设备、用户、Agent 的寻址和消息能力，确保后续通讯产品可直接复用。

每个阶段应独立验收。C3 不是 C1/C2 的必要前置条件。
