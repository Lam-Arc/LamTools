#### `read_file`

- 权限：`auto_allow`　分类：`file_read`
- 描述：Read file content within the workspace. DOCX, PDF, and XLSX documents are automatically normalized to Markdown and labeled as untrusted content. Image files (PNG/JPG/JPEG/GIF/WebP/AVIF/BMP) are returned as an image the model can view directly. An image is shown at full resolution only in the request that immediately follows this call; later requests carry a low-resolution copy for recognition. Read the file again when you need fine detail, small text, or a picture-quality judgement. The content is exactly the file text; the line count and byte size are reported as structured metadata, never as a line inside the content.

```json
{
  "name": "read_file",
  "parameters": {
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "path": {
        "type": "string",
        "description": "File path relative to the workspace"
      }
    },
    "required": [
      "path"
    ]
  }
}
```

#### `memory`

Title every memory — its first line, which is what the index shows — with the condition under which it should be consulted: the trigger, written the way a skill's description reads ('when X, read this'), not just the topic. A memory titled only with a topic is not retrieved at the moment it matters. When a task matches the condition in a title, read that file before acting. Two tiers: 'project' (<workspace>/.lam/memory/) for this project only, 'global' (user config memory/) shared across all projects. Paths are relative to the tier root. #### `library`

- 权限：`auto_allow`　分类：`library`
- 描述：Curate the project library (资料库): the catalog of files that matter for this project — user uploads and the deliverables you deliberately file into it. Nothing you produce enters the catalog automatically: registering is your call. The catalog is bookkeeping only — entries point at files and no action here reads, moves or deletes those files. Folders are catalog layers (the library's archive tabs), not disk directories; layer names are free-form and may nest with '/', empty string = unarchived. Every entry lists the file it points at (file=…): workspace uploads live under the project's 资料/ folder, chat uploads live in the app's attachment store, and either way the listed path is a real file you can read_file. Actions: list (entry ids, names, roles, layers, favorites, file locations), register (file a workspace file into the catalog; optionally assign its layer in the same call), favorite (set favorite true/false), folder (re-layer one or more entries), remove (soft-remove; restorable, file untouched), restore. File deliberately: after a turn produces a deliverable worth keeping, 'register' it and give it a fitting layer in the same call — follow the layers this project already uses (check with 'list' first), otherwise pick a short fitting layer name. Leave scratch files, intermediate debris and things the user never asked to keep out of the library. Favorite only when the user marks something as important; remove or restore only when the user explicitly asks. Resolve entries by id from 'list'.

#### `edit_file`

- 权限：`ask_user`　分类：`file_write`
- 描述：Replace one exact UTF-8 text segment in an existing file. Matching is case-sensitive and preserves all whitespace and line endings. The edit must be unique unless occurrence (1-based) or exact before_context/after_context makes it unique; never guess among multiple matches. When no context constraint is needed, omit those fields or pass JSON null without quotes; the placeholder string "null" is also read as no constraint.

```json

  "name": "edit_file",
  "parameters": {
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "path": {
        "type": "string",
        "description": "File path relative to the workspace"
      },
      "old_string": {
        "type": "string",
        "description": "Exact text to replace"
      },
      "new_string": {
        "type": "string",
        "description": "Replacement text"
      },
      "expected_file_hash": {
        "type": [
          "string",
          "null"
        ],
        "description": "Expected full-file sha256:... hash, or null for no full-file check"
      },
      "occurrence": {
        "type": [
          "integer",
          "null"
        ],
        "description": "Optional 1-based occurrence after context filtering"
      },
      "before_context": {
        "type": [
          "string",
          "null"
        ],
        "description": "Exact text immediately before old_string, or JSON null (without quotes) when unused; the placeholder string \"null\" is also read as absent"
      },
      "after_context": {
        "type": [
          "string",
          "null"
        ],
        "description": "Exact text immediately after old_string, or JSON null (without quotes) when unused; the placeholder string \"null\" is also read as absent"
      },
      "expected_content_hash": {
        "type": [
          "string",
          "null"
        ],
        "description": "Expected sha256:... hash of the selected old_string plus any supplied contexts, or null"

    },
    "required": [
      "path",
      "old_string",
      "new_string",
```

## 同一台机器上的另一套工具实现

`core/runtime-rs` 自带一份独立的工具定义与执行：

- 文件：`read_file` `write_file` `list_dir` `search_files` `search_content` `edit_file`（`project_tools.rs`）
- 控制：`write_checklist` `update_checklist` `question`（`plan_tools.rs`）
- 其它：`web_fetch` `generate_image` `load_skill` `read_skill_reference`（`fetch_tools.rs` / `image_gen.rs` / `skills.rs`）

同名工具的 schema 与 Python 侧不一致，例如 Rust 的 `read_file` 只有 `path`，描述是 `Read a UTF-8 project file`；`edit_file` 没有 `expected_content_hash`。桌面端走的是 Python 这一套。

## 影响工具可见性的配置面

| 文件 | 作用 | 现状 |
| --- | --- | --- |

| `.lam/core/config/loadtools.jsonc` | 每个模式的工具白名单 | `consider` 11 个只读工具，`execute` 空（全部） |

## 事实性观察

- 两套工具定义同时在仓库里：Python `default_toolbox.py` 是桌面在用的，Rust `runtime-rs` 是另一份并行实现，同名不同 schema。
- 两套插件系统同时在跑：`plugins/`（v1，legacy）与 `plugin_system/`（v2）。`PluginRegistry.discover()` 主动跳过 `assembly: v2`，bundled 目录里 7 个插件全部是 v2，v1 注册表在本机一个都发现不到。
- 工具数组按会话加压缩周期冻结在进程内存里，冻结期内新增的工具调不到，只在压缩或新会话时更新。
- `DEFAULT_TOOL_ORDER` 里 4 个名字被 `_BUNDLED_PLUGIN_TOOL_NAMES` 排除后，其中 2 个已经没有来源，属于残留常量。
- 同名冲突处理：插件工具与核心、MCP、durable 中任一重名，则该插件工具不注入并记一条冲突；插件之间同名先声明者保留。核心这一侧没有重名。

## 按四项基础工具看可替换性

口径：基础工具只有 read、write、edit、command 四项，其余 33 个逐个判断能不能被它们顶掉。结论分三档，依据都写在表里。

### 一档：能被顶掉，功能不丢

| 工具 | 顶它的基础工具 | 现状 |
| --- | --- | --- |
| `list_dir` | command | 列目录、带大小和时间、有条目上限。命令能做同样的事。 |
| `search_files` | command | glob 找文件，有结果上限。命令能做同样的事。 |
| `search_content` | command | 字面量搜内容，有结果上限。命令能做同样的事。 |
| `check_exports` | command | 纯静态分析，一段 Python 脚本就能算。 |

### 二档：能被顶掉，但会丢掉具体保障

| 工具 | 顶它的基础工具 | 会丢什么 |
| --- | --- | --- |
| `kill_process` | command | 会话归属校验与注册表清理。直接 taskkill 能杀，但杀的是整台机器的 pid。 |
| `list_processes` | command | 会话登记簿、持久标记、日志路径。系统级进程列表看不出哪个是本会话起的。 |
| `web_fetch` | command | 内网地址拦截、代理分流、25MB 上限、PDF 转文本、重定向处理、图片候选提取。 |
| `memory` | write/edit | `INDEX.md` 不再刷新。索引是每轮注入的，绕过工具写文件，下一轮的索引还是旧的。 |
| `load_skill` | read | 提示词里的技能索引只有名字和描述，没有目录。还丢掉禁用技能与模式过滤。 |
| `notes` | write/edit | 修订号、内容哈希比对、用户锁定区间校验。Markdown 能写，但库里的引用关系不动。 |
| `workflow_graph` | read | 工作流是文件夹加 `workflow.json`，能读。丢掉的是名字到目录的解析和旧格式迁移。 |
| `workflow_add_node` `workflow_connect` `workflow_delete_node` `workflow_update_node` | edit | 直接改 JSON 会绕过结构校验、修订号、节点版本与缓存失效。 |
| `plugin_list` | command | 启停状态在 `plugin-system.jsonc`，依赖状态要另查 pip。 |
| `plugin_deps` | command | 依赖清单来自插件清单，不是 pip 全局列表。 |

### 三档：顶不掉，换句话说不落在文件上

| 工具 | 为什么顶不掉 |
| --- | --- |
| `library` | 目录存在 SQLite 的 artifacts 表里，文件工具碰不到。 |
| `write_checklist` `update_checklist` | 计划存在会话状态 `task_plan` 里并驱动界面，不是文件。 |
| `question` | 要阻塞当前一轮，等用户真正回答。 |
| `sub_agent` `sub_agent_message` | 独立会话、并发执行、上下文隔离。 |
| `mcp_activate` `mcp_tool` | MCP 协议客户端与服务器进程管理，激活后还要在下一轮注入工具。 |
| `generate_image` | 生图服务、配置读取、产物登记、界面预览。 |
| `get_knowledge_net` `build_knowledge_net` `sign` `exam` | 存在 SQLite，带事务、版本比对与评分证据归属。 |
| `goal` | 目标状态由操作目录管理。 |
| `arrange` | 定时与事件触发的调度器，必须常驻。 |
| `plugin_install` | 安装是事务：校验清单、解压、装依赖、写注册表。 |

### 三个连带事实

- `read_file` 不能列目录，传目录会直接报 `Not a directory`。所以 `list_dir` 的职能只能落到 command，或者扩展 read。
- 只读档 `access_tools.jsonc` 的名单里没有 `run_command`，只有 `read_file` `list_dir` `search_files` `search_content`。删掉这三个读取类工具，只读档就没法看目录和搜索。
- `loadtools.jsonc` 的 consider 模式白名单同样列了这三个，删之前要一起改。
