# Sunday Memory · 主动记忆与认知系统 PRD

> 来源：用户于 2026-11-25 在会话中发来的 PRD 原文（完整保留，未改写）。
> 实施记录：见 `方案/Sunday-Memory-主动记忆与认知系统-01-现状复核与实施报告.md`。
> 状态：**已实施（2026-11-25）** — L1 memory.md 注入、Dreaming 增量整理、开关/RPC/界面与测试均已落地；待决策项见实施报告第七节。

## 1. 产品目标

在 Sunday 现有记忆系统的基础上，引入以 "memory.md" 为核心的主动认知机制，使 Agent 能够持续积累、理解和更新对用户的认知，而不必在每次任务中重新检索、读取记忆文件。

实现以下目标：

- Agent 在新会话中天然具备对用户的基础认知。
- 用户无需反复介绍自己的偏好、习惯、项目背景和历史决策。
- 记忆能够随长期交流自然积累、修正和演进。
- 保留现有记忆系统的文件级可控性、可迁移性和信息完整性。
- 降低高频记忆读取产生的工具调用与交互成本。

## 2. 基础架构

采用 "memory.md" 作为核心认知载体，复用现有记忆系统，而非重新建设一套独立的记忆库。

层级| 内容| 使用方式
L1| memory.md：核心认知摘要| 自动注入
L2| INDEX.md：记忆索引| 沿用现有机制
L3| 独立记忆文件| 按需读取
L4| 历史会话与原始记录| 按需检索

"memory.md" 是 Agent 对用户及所属作用域形成的综合认知，不是记忆文件目录，也不是全部记忆文件的简单拼接。

现有记忆库负责保存知识，"memory.md" 负责让 Agent 直接掌握重要知识。

## 3. memory.md

### 3.1 内容范围

"memory.md" 应当以自然语言组织具有长期价值或持续价值的信息，包括但不限于：

- 用户个人背景与长期目标。
- 用户偏好、交流习惯、思维方式。
- 常用工具、技术栈与工作流程。
- 项目背景、核心架构和重要决策。
- 已确认的需求、约束及设计原则。
- 持续进行中的任务及阶段性进展。
- 历史经验、失败教训及已经形成的结论。
- 用户明确要求记住的信息。

不强制采用固定字段或僵化的分类模板。Agent 应根据实际内容自主组织结构。

### 3.2 信息选择原则

记忆价值主要取决于：

- 未来使用价值。
- 信息的稳定程度。
- 使用频率。
- 信息对决策和任务执行的影响程度。
- 用户明确表达的重要性。

不要求记住全部交流内容，也不应为了追求摘要简短而丢失重要事实、参数和决策依据。

完整信息应由独立记忆文件和历史记录承载。

### 3.3 作用域

沿用 Sunday 现有记忆作用域设计，在相应作用域下维护 "memory.md"。

作用域| 内容
全局| 用户认知、长期偏好、通用工作习惯
项目| 项目背景、技术架构、项目决策、持续任务

项目记忆不应无条件进入其他项目。

环境之间的记忆访问和同步沿用 Sunday 现有权限、存储及同步机制，不因引入 "memory.md" 而扩大访问权限。

## 4. 自动注入

### 4.1 基本行为

功能开启时，Agent 应自动获得当前作用域内适用的 "memory.md" 内容，无需主动调用 Memory Tool。

自动注入的内容应包括：

- 全局核心认知。
- 当前项目核心认知。
- 现有记忆索引。

Agent 在现有认知不足以完成任务时，再主动读取完整记忆或检索历史记录。

### 4.2 上下文管理

- 不重复注入相同内容。
- 不因每轮对话而无限累积记忆文本。
- 尽量保持注入内容稳定，避免不必要的 Prompt Cache 失效。
- 超出上下文预算时，优先保留重要认知，并通过记忆索引提供补充访问能力。
- 记忆发生更新后，确保后续请求能够获得更新后的认知。

记忆预算应结合模型上下文容量、实际任务需求及缓存成本设计，不在本 PRD 中限定固定 Token 数量。

### 4.3 信息优先级

记忆属于辅助认知信息，不具有系统指令的权限。

当记忆与用户当前明确表达的信息发生冲突时，应以当前信息为准，并在适当情况下修正记忆。

## 5. Dreaming：主动记忆维护

引入异步记忆整理机制，使 "memory.md" 能够随用户的长期使用持续演进，而不是仅依靠用户主动要求记忆。

### 5.1 职责

Dreaming 负责：

- 从新增会话中识别具有持续价值的信息。
- 提取用户偏好、事实、经验和重要决策。
- 将新增信息与已有记忆进行比较。
- 合并重复内容。
- 修正已经发生变化的信息。
- 处理相互矛盾的记忆。
- 将详细信息归入适当的独立记忆文件。
- 更新 "memory.md" 与相关记忆索引。

Dreaming 的目标是形成更准确、更有用的认知，而不是单纯压缩文本。

### 5.2 触发机制

允许采用以下触发条件：

- 会话结束或进入空闲状态。
- 积累足够的新交流内容。
- 发生重要记忆变更。
- 用户主动要求整理记忆。

具体调度策略由实际工程实现决定。

应避免每条消息均触发完整记忆整理，也不应长期积压导致记忆明显落后于实际情况。

### 5.3 执行要求

- 不阻塞正常对话和任务执行。
- 优先采用增量整理，避免反复处理全部历史记录。
- 控制额外模型调用和 Token 消耗。
- 整理失败时保留原有记忆。
- 避免并发整理导致更新丢失或文件覆盖。
- 不得因摘要更新而擅自删除原始历史记录。

### 5.4 记忆可靠性

应区分：

- 用户明确陈述的事实。
- 用户明确确认的决策。
- Agent 根据历史交流形成的推断。
- 尚未确认的信息。

不得将推断直接固化为确定事实。

对于具有时效性的信息，应保留必要的时间信息；对于已经被替代的决策，应更新当前结论，并根据价值保留历史记录。

## 6. 主动记忆操作

保留现有 Memory Tool 的能力，并支持 Agent 根据任务需要主动维护记忆。

用户明确要求"记住""更新记忆""忘记某项信息"时，应直接处理相应请求，不必等待 Dreaming。

用户主动修改 "memory.md" 后，系统应识别该修改，避免后续自动整理无故覆盖用户意图。

用户删除或要求忘记的信息，不应因 Dreaming 再次读取旧会话而被自动恢复为有效记忆。

## 7. 设置与用户控制

### 7.1 功能开关

设置中新增：

主动记忆（Memory）

说明：自动积累和整理用户认知，并在会话中使用相关记忆，使 Agent 更了解用户及其项目。

默认状态：开启。

行为| 开启| 关闭
memory.md 自动注入| 是| 否
Dreaming 自动整理| 是| 否
自动积累核心认知| 是| 否
现有 Memory Tool| 可用| 可用
手动读取、编辑记忆| 可用| 可用
已保存记忆| 保留| 保留

关闭后：

- 停止新增的主动记忆任务。
- 停止 "memory.md" 自动注入。
- 取消尚未完成的自动整理任务，避免关闭后继续写入。
- 不删除已有记忆文件。
- 不影响原有记忆系统的手动使用。

重新开启后，恢复主动记忆能力。

开关变更应在后续模型请求中生效。已经发送给模型的上下文无法撤回，必要时应通过重建上下文使关闭状态完整生效。

### 7.2 记忆管理

用户应能够：

- 查看当前 "memory.md"。
- 查看全局与项目记忆。
- 直接编辑记忆。
- 删除指定记忆。
- 清空指定作用域的核心认知。
- 导出、备份及恢复记忆。
- 查看最近一次自动整理时间。

不要求为每个记忆文件重新建设独立管理界面，优先复用现有能力。

## 8. 数据安全与可恢复性

- "memory.md" 使用可直接读取和编辑的 Markdown 格式。
- 记忆更新应具备原子性，避免中断造成文件损坏。
- 保留必要的历史版本或恢复机制。
- 记忆整理不得无故扩大数据访问范围。
- 不将密码、密钥、访问令牌等敏感凭据作为普通认知自动保存。
- 对于用户明确删除的信息，应防止自动记忆机制重新将其引入。

原则上，用户拥有对记忆数据的最终控制权。

## 9. 现有系统兼容

实施前应审查 Sunday 当前记忆系统的实际代码、存储结构、注入逻辑及 Memory Tool。

重点确认：

- 是否已有可复用的 memory.md 机制。
- INDEX.md 的生成与注入机制。
- 全局及项目记忆的作用域划分。
- 历史会话的读取与检索能力。
- 现有后台任务调度机制。
- Prompt Cache 与上下文构建机制。
- 并发会话下的记忆读写行为。

优先复用、扩展现有实现，避免产生两套彼此竞争的记忆系统。

本需求不要求废弃现有 Markdown 记忆库，也不要求更换存储后端或引入向量数据库。

## 10. 验收标准

场景| 预期结果
初次使用| 主动记忆默认开启
新会话| 无需工具调用即可掌握核心认知
新增长期偏好| 后续会话能够自然利用
用户修改旧决策| 不再持续使用已失效的结论
用户主动要求记忆| 直接更新相关记忆
用户要求忘记| 不被自动整理机制重新恢复
跨项目切换| 正确切换项目认知，不污染其他项目
普通短期闲聊| 不产生大量无价值记忆
长期持续使用| 认知有效积累，不无限膨胀
并发会话| 不发生记忆丢失或覆盖
Dreaming 执行失败| 原有记忆保持完整
关闭主动记忆| 停止自动注入与自动整理
重新开启| 恢复已有核心认知
手动编辑| 后续请求使用更新后的记忆

性能与成本| 不显著增加正常交互延迟，减少不必要的记忆读取调用

## 11. 实施原则

本需求的核心不是增加一个记忆文件，而是让 Sunday 从一个需要主动查找历史知识的 Agent，演进为一个拥有持续认知能力的 Agent。

以 "memory.md" 承载核心认知，以现有记忆库保存完整知识，以 Dreaming 持续维护两者之间的关系。

在信息完整性、认知准确性、上下文成本和用户控制权之间取得平衡。

具体实现路径由 Agent 在审查现有工程后自主确定，不因本 PRD 强制重构无关模块。
