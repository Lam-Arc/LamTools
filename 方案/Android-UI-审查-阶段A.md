## 二、结论摘要

1. **信息架构与 PRD 目标不一致**：手机没有常驻一级入口，导航藏在抽屉页脚的 6 个纯图标里（目标：4 个常驻入口）。这是结构问题，改样式解决不了。
2. **系统返回键只覆盖“分屏 / 整版页”两层**：抽屉开着按返回会直接把 App 退到后台；整版页里还存在“页面内返回 + shell 浮动返回”两个返回控件。
3. **切换一级页面会卸载会话线程**：从资料库/设置返回后，滚动位置、展开的过程、输入上下文全部重建；而分屏却用 `v-show` 保活，两者不一致。
4. **触控目标普遍偏小**：抽屉页脚 34px、抽屉开关 38px、整版返回 32px，均低于 48dp；提问卡辅助字号 10–11px。
5. **真机可见的视觉缺陷**：状态栏图标在浅色主题下几乎不可见；定时任务页出现两个返回箭头、标题与按钮错位；设置页 8 个横向标签挤成一条需横滑。

## 六、阶段 B 建议（待确认后实施）

### B1. 一级入口映射（把 6 个收敛成 4 个）

| 新入口 | 收纳的现有能力 |
|---|---|
| 对话 | 会话线程、输入栏、审批、提问卡 |
| 工作区 | 项目/会话入口、资料库（含本机文件）、Browser、文件预览 |
| 任务 | 定时任务 + 运行中/待审批/已完成/失败视图 |
| 功能 | 插件 / Easy Tools、远程连接与设备、设置 |

### B2. 结构改动（P0）

1. `WorkspaceShell` 增加常驻底部导航槽（mobile 专用），四个入口不随页面移动；整版页不再自带返回，统一由 shell 提供标题带。
2. 线程层改 `v-show` 常驻，一级切换不卸载；整版页保留在 DOM 中。
3. 返回栈统一：抽屉 → 分屏 → 整版页内层 → 整版页 → 后台；WebView `canGoBack` 让位给界面层。

### B3. 视觉与触控（P1）

- 所有一级导航与主要操作 ≥ 48dp；页脚改 48px 高 + 文字或更大图标。
- 状态栏/导航栏图标色随主题联动（浅色主题深色图标）。
- 整版页标题带：页名 + 返回，去掉浮动返回与组件内返回的重复。
- 设置页横向标签改分组下拉或两行网格。

### B4. 验证

- 每项改动先在模拟器截图核对，再回真机（需要 arm64 设备或重出 x86_64 包）。
- 回归用例：返回栈、键盘开合、切页保活、分屏、状态栏对比度。
