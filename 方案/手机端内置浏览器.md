# 手机端内置浏览器（原生网页通道）

## 需求与边界

上一轮把手机端的标签改成了“换页”：右上角抽屉进出页面、agent 打开的网页只收进抽屉不抢会话。但网页页本身是空的——安卓宿主没有桌面的原生网页通道，页面里只剩一句 `Command browser_bounds not found`。也就是说：**入口和切换已经通了，门里还没有房间。**

这一版要让人在手机上真正看到网页，并且让 agent 的网页搜索在手机上也能取到内容：

- 打开一个网址，网页显示在“页面”区域里（会话栏仍在，返回/抽屉都在原位）。
- 从会话切到别的页再切回来，网页还在原处，不会白屏、不会跑到会话上。
- 关掉这一页，网页随之销毁，不留后台噪音。
- agent 搜索时能按选择器读到网页内容（只读）。
- 桌面端行为一点不变。

这次不做（明确划在外面）：

- 让 agent 在网页里点、填、滚动、等待（`browser_snapshot` / `browser_act` / `browser_wait_for`）。
- 下载、站内权限弹窗、证书例外、站点数据清理、多账号 profile。
- 网页截图取字（`ocr_image` 那条通道）。
- 同一时刻并排两个网页：手机一次只显示一页。

## 取舍

**原生 WebView，而不是 iframe。**
iframe 便宜，但大量网站禁止被嵌入（`X-Frame-Options` / `frame-ancestors`），而且跨域后 agent 读不到 DOM——搜索会直接失效。原生 WebView 没有这两个限制。

**页面自己带地址栏，不复用桌面分屏组件。**
桌面那套 `CoreSplitBrowser` 默认“一个分屏里的一块”，在手机的整页容器里挂上后，创建时序与可见性判断都会误判（实测：界面拿到地址，原生网页始终没被创建）。手机页因此自己拥有：地址栏、矩形、创建/刷新/关闭。

**矩形用物理像素，前端乘一次 dpr。**
沿用桌面的约定；Kotlin 只认物理像素，不做第二次换算。

**正文提取用“页面回传”，不用 `evaluateJavascript`。**
回调在这台机器上不可靠；改成注入 JS 接口，脚本算完主动把结果交给宿主。

## 踩到的两个坑（留给后来者）

1. **同步 Tauri 命令会占住主线程。** `browser_html` 原本是同步命令，Tauri 在主线程执行；它在里面等页面回话，主线程被占住，页面回包只能排在超时之后才送达——表现为“每次都 6 秒超时，但 6 秒后立刻就有数据”。改成 `async` + `spawn_blocking` 后降到 20ms。
2. **WebView 的宽视口会让首次布局拿不到宽度。** `useWideViewPort=true` 时网页按桌面宽度排版，被缩放进小矩形里，`innerWidth` 实测为 0，画面只剩背景色。

## 风险

- **原生 View 永远压在界面之上**：回会话、关页都显式 `visible=false` / 销毁；页容器自带地址栏，矩形只覆盖地址栏以下。
- **一次只保留一张网页**：关页即销毁，避免后台网页吃内存。
- **JS 接口对页面可见**：页面可以调用 `__sundayBridge.deliver`，但随机请求号对不上就无事发生；后续若要做写操作，需按桌面那套“人/Agent 归属”再加闸门。

## 修复记录（网页收不起来）

**现象**：从网页页返回会话后，原生网页仍盖在会话上；关页后也一样。

**根因**：收起与关页都走前端的“分屏标签 → 原生标签”映射表。只要这一处映射缺失（例如这个网页不是由组件自己创建的），命令就在前端被吞掉，宿主从未收到“隐藏/销毁”。

**修法**：宿主按自己的 `key`（分屏标签 id）记账，新增 `browser_hide(key?)` 与 `browser_release(key)`：有 key 按 key 解析，没有就“全部收起”兜底。界面在回会话、回列表、关页时只发这两条命令，不再依赖前端映射。

**验收**：打开网页 → 返回会话（网页消失、会话与输入栏回来）→ 抽屉再进（网页仍在、不白屏）→ 抽屉关闭（网页销毁、计数 13→12）。
