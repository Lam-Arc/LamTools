# 统一工作区布局 V1 · 实现映射方案

> 目标：把「主工作区 + 辅助工作区（浮层 / 固定 Dock）」这条设计落到现有分屏代码上。
> 原则：**只演进，不重写**——`layout.ts` 的递归矩形树、`surfaceModes.ts` 的浮窗几何、`browserVisibility.ts` 的
> 「先隐藏再显示」全部复用；新增的只有「内容实例」「主槽位」「浮层层级」「固定/解除固定」。

## 一、V1 设计 → 现有代码（逐条映射）

| V1 设计要求 | 现状 | 结论 |
| --- | --- | --- |
| 主工作区始终存在、默认占满 | `SplitState.tree` 根上必有 `main` 叶，`layoutRects` 天然铺满 | 已具备 |
| 主内容可换成 Agent / Browser / Library | 主区内容由 `LamToolsApp.vue` 的聊天模板承担，`main` 叶没有标签 | **新增**：`state.mainTab` 主槽位 + 工作区主槽渲染 |
| 切换主内容 ≠ 关闭/停止其它内容 | 标签对象 `SplitTab` 就是内容身份，移动时不复制（`moveTab` 保留同一对象） | 增强：主槽位只搬同一个 `SplitTab` 引用 |
| 辅助区与主区同一套内容组件 | `split-tab-content` 按标签渲染，主区/辅助屏共用 `<slot>` | 已具备 |
| 浮层不参与矩形分屏、可多开 | `tab.surface='float'` + `tab.surfaceFrame` 已是「画在树外」 | **改造**：取消浮层互斥，加 z 序 |

| 关闭浮层 ≠ 销毁内容 | 关标签会 `closeTab` → `closePane`；内容实例随之丢失 | **新增**：浮层收起（`surface='hidden'` 语义由 `floatOrder` + 实例注册表承担） |

| 边界拖动 + 最小宽高 | `resizeSplit`/`minimumSize`/`dividerLimits`/`COMPACT_PANE_MINIMUM` | 已具备，直接复用 |

| 布局保存恢复 | `localStorage` + `restoreSplitState` 校验 | 已具备（新增字段需并入迁移/校验） |

## 二、内容实例 vs 布局状态

现有代码里 `SplitTab` 同时承担「内容身份」和「布局标签」。V1 把它们显式拆成两层，
但**不换数据结构**（换掉会让 40+ 份布局测试与两份存档格式同时改），而是把职责写死：

```
内容层（实例）                         布局层（只引用 id）
SurfaceInstance { id, kind, ref, stateOwner }   tree / panes / ratio / activePane
  ↑ 由 surfaces.ts 的注册表持有                    ↑ 只存 SurfaceId（= tab.id）
SplitTab（内容句柄 + 记住的浮窗几何）             floatOrder: SurfaceId[]（底→顶）
```

- `SurfaceId` = `SplitTab.id`（浏览器的原生 webview、Agent 会话、编辑器文档都按它做 key，
  所以**布局怎么变都不会换内容**）。
- `SurfaceInstance.ref`：浏览器 = 原生 webview 的 `tab.id`；Agent = `sessionId`；
  资料库/预览 = `resource`（路径或页面 key）。`stateOwner` 说明运行时状态归谁：
  `agent`（会话/滚动/草稿）、`browser`（webview 进程）、`library`/`preview`（文档 store）。
- **注册表给的是同一对象**：`ensure(surfaceId)` 对同一 id 永远返回首次创建的实例
  （引用相等），这是「不重建内容」的第一条证据；第二条是标签对象在
  pane ↔ 浮层 ↔ 主槽位之间搬移时始终是同一个 `SplitTab`。测试用 `toBe` 盯住这两条。

## 三、主槽位（P0-1）

`SplitState` 增加两个可选字段（v2 存档向后兼容：旧代码会忽略，新代码缺省即旧行为）：

- `mainTab: SplitTab | null`：主区当前承载的内容实例。`null` = Agent 本体（现状）。
- `floatOrder: SurfaceId[]`：浮层层级（底→顶）。

切换只改指针：

1. `moveSurfaceToMain(state, id)`：把标签从所在 pane 里摘出（pane 空了按既有语义 `closePane` 自动填满），
   写成 `state.mainTab`；Agent 本体**不卸载**，只是不再占主区。
2. `returnMainToAgent(state)`：`mainTab` 原路放回它来的 pane（记录在 `mainReturn` 约定上：
   优先原 pane → 当前活动辅助屏 → 新建右侧分屏 → 浮层），再把 `mainTab = null`。
3. 渲染：工作区在主区矩形上渲染一层不透明 `split-main-slot`（`<slot>` 同一套内容组件），
   盖住下面的聊天模板；聊天保持挂载（DOM 不销毁），所以「切回来还是原来那条会话」。
   主槽左上角一枚 `Agent ▾` 按钮 = 切换入口。

「没有辅助内容时只显示主区」不变：没有 `panes`、`mainTab=null` 时工作区什么都不画。

## 四、浮层层（P0-2）

- 多开：去掉 `exclusiveSurfaceOwners` 对 float↔float 的互斥，只保留 focus 的独占
  （focus 是「内容铺满」，两份无法解释；float 各自有矩形，可以并存）。
- z 序：`floatOrder` 存 id 顺序，`bringToFront`/`sendToBack` 只动这个数组；
  渲染时 `z-index: calc(var(--z-stage) + index)`。置底同时还必须让原生网页让位
  （沿用 `browserVisibility.suppressed`——网页永远画在 DOM 之上）。
- 关闭 ≠ 销毁：浮层头部「收起」把实例移出布局但留在注册表；从标签菜单重新唤起时
  用同一个 `SplitTab` 对象 + 原 `surfaceFrame`，浏览器不重载。
- 拖动/缩放沿用既有手势：`moveFloatFrame`/`resizeFloatFrame`/`fitFloatFrame`，
  手势期间 `interacting` 让网页让位，松手一次性提交 bounds（不新造闪烁逻辑）。

## 五、原地固定 / 解除固定（P0-3）

```
浮层矩形 ──▶ 目标 pane（重叠面积最大，其次中心最近）
        ──▶ 目标 edge（浮层中心相对 pane 中心的位移，主轴定方向）
        ──▶ ratio（浮层外沿在 pane 内的真实比例，按 minimumSize 夹紧）
        ──▶ 克隆布局 split 一遍 → layoutRects → 预览矩形（= 最终矩形，不另算一套）
```

- 放不下时（`minimumSize` 装不进、或超过 `SOFT_PANE_LIMIT`）按重叠面积顺序换下一个 pane；
  全都不行返回 `null`，界面给原因，布局一点不动。
- 只有两块区域时，`splitPane` 作用在根的一叶上，新区域自然贯穿整条边——「必须完整左右/上下」由树形结构保证。
- `applyPin`：`splitPane` → `moveTab`（同一标签对象）→ `surface='split'` → 记录 `surfaceFrame`（供解除固定用）。
- 解除固定：优先恢复上一次浮层尺寸（`tab.surfaceFrame`），落点贴当前区域左上角（保持视觉联系），
  再 `clampFloatFrame`；原区域空了走 `closePane`，树自动收拢 → 其余区域填满。
- 预览：固定前必须预览，复用工作区既有的 `split-split-preview` 覆盖层（只描矩形，不加遮罩文案）。

## 六、自动填充与最小尺寸

- 填满/无空洞/无重叠：`closePane` 的 `prune` 会把兄弟节点顶上来，树始终铺满根矩形；
  `layoutRects` 只在节点处留 `GAP=2` 的分隔缝。
- 最小宽高只有一套：`minimumSize` / `PANE_MINIMUM` / `COMPACT_PANE_MINIMUM`；
  `resizeSplit`、`dividerLimits`、`canFitSplit`、固定时的 ratio 夹紧全部读它，不新增阈值。
- 浮层最小尺寸继续用 `FLOAT_MIN_WIDTH/FLOAT_MIN_HEIGHT`（320×200）。

## 七、「不重建内容」在代码里怎么保证

1. `surfaces.ensure(id)` 幂等且返回同一对象；`kind` 一旦登记不随布局变化。
2. 搬移只做「数组摘出 / 放回」，从不对 `SplitTab` 做 `{...tab}` 复制（`moveTab` 已经如此）。
3. 渲染按 `tab.id` 做 `v-for :key`，主槽位/浮层/分屏三种宿主共用同一个 key，
   Vue 复用 DOM 与子组件（原生 webview 因此不重载）。
4. Agent 本体由应用模板持有，主槽位占用时只是被盖住，不 `v-if` 卸载。
5. 测试：注册表引用相等、标签对象引用相等、同一 id 的 DOM 节点复用（组件测试）。

## 八、P0 分阶段（每段独立可验）

- **P0-1 内容/布局分离 + 主内容切换**：`surfaces.ts` 注册表 + `mainTab` 槽位 + `Agent ▾` 入口。
  验证：切主内容后标签对象与注册表实例不变；`tree`/`panes` 不变；切回 Agent 时聊天仍在。
- **P0-2 浮层层（多开）**：`floatOrder` + 多浮层渲染 + 置顶/置底 + 收起不销毁。
  验证：两个浮层同时存在、各自矩形独立、z 序可变、背景可交互（无整块遮罩）。
- **P0-3 固定/解除固定 + 自动填充**：`planPin`/`applyPin`/`planUnpin`/`applyUnpin` + 预览。
  验证：预览矩形 = 应用后的真实矩形；两区时贯穿；最小尺寸不被突破；解除固定回到上次浮层尺寸且空间填满。

## 九、P1 / P2 前置与风险

- **主辅互换**：`swapPanes` 现在只换标签数组；主区没有标签栏，互换要先决定「Agent 本体能否成为辅助区」
  （P1 需要 `mainTab` 的对称槽位 `agentSurface`，否则主区永远是特例）。
- **多辅助区 / 区域移动重停靠**：`SOFT_PANE_LIMIT=8` 与 24 层深度校验是硬上限；
  重停靠要先有「区域 → 区域」的命中表（现在只有标签 → 区域）。
- **布局保存恢复**：新增 `mainTab`/`floatOrder` 已并入 `migrateSplitState`/`restoreSplitState` 校验；
  再往后要加版本号，否则旧版本会静默丢字段。
- **浮层层级焦点**：原生 webview 的 z 序由宿主窗口决定，DOM z 序管不到它；
  多层浮层且都含网页时，「谁盖谁」必须由 `browserVisibility.obscured` 显式让位，否则会互相穿模。
- **自由让位（可关）**：与矩形分屏是两套几何，不能共用 `ratio`；建议独立状态 + 独立手势，别塞进 `layout.ts`。
