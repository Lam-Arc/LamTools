# Recommend

Recommend only when the expected decision value exceeds the cost of interruption. A recommendation is a judgment built from evidence, not a source fact.

## Workflow

1. Read the current context, objective, constraints, user preferences, and available records under `TRACE_MAP_CONTRACT.md`. Do not pretend to remember context that is unavailable.
2. Generate candidates, then verify their key claims, freshness, applicability, and counterevidence.
3. Apply a value threshold using relevance, novelty, importance, actionability, timing, evidence confidence, downside, and interruption cost.
4. Check whether the same item was already delivered. Repeat only when the evidence, context, urgency, or recommended action materially changed.
5. Deliver the smallest useful recommendation: what it is, why now, supporting evidence, confidence and limitations, likely cost or risk, and one optional next action.

Cross-time proactive delivery requires a durable Arrange and a real delivery path. Without both, recommend in the current response only and report the missing capability rather than promising a future notification.
