LamImager 当前架构 vs 理想架构

用于清晰展示 Agent 模式与 Workbench 模式当前的独立/耦合关系、关键参数生命周期，以及从当前实现演进到理想执行内核的映射路径。

颜色图例

绿色：保留。现有能力正确，只需迁移到更合理的位置。
黄色：修改。方向正确，但职责边界或参数流有问题。
红色：删除。当前实现不应继续保留在理想架构中。
灰色：待定。需要按产品方向与性能目标决定。

参数生命周期表

参数 归属 含义与用处 当前创建位置 什么时候允许修改 当前谁可覆盖 理想状态
inputText / prompt 共享 用户原始任务描述，是所有路径的起点。 Sessions.vue 输入框 用户输入、编辑、发送前 用户 保留，作为 Agent 与 Workbench 共同输入源。
attachments 共享 上传附件，主要是图像来源。 Sessions.vue 上传 / 删除附件时 用户 保留。
reference_images 共享 传给生图模型的参考图 base64。 前端提交请求前从附件或精修模式整理 请求构造阶段 前端逻辑、用户 保留，但理想上在后端做统一归一化。
reference_labels 共享 多模态图标签，对应 [图N]。 前端构造请求时生成 请求发送前 前端逻辑 保留。
context_messages 共享 最近消息与上下文图，供优化或 Agent 参考。 前端提交前组装 切换上下文、会话状态时 前端逻辑 保留，进入统一 ExecutionContext。
agentMode Agent 决定是否走 Agent 模式入口。 Sessions.vue UI 开关 用户切换模式时 用户 保留，且只决定入口，不决定执行策略。
selectedPlanStrategy 工作台 Workbench 中用户显式选择的策略。 Sessions.vue Workbench UI 用户在规划区修改时 用户 仅 Workbench 保留，绝不传给 Agent。
agent_plan_strategy Agent 当前代码会把前端策略带入 Agent 请求，污染策略判断。 前端请求体 请求发送前 前端状态、用户间接影响 删除；若保留也仅作调试字段，默认忽略。
plan_strategy 工作台 非 Agent 请求中的计划策略字段，当前语义混乱。 前端请求体 请求发送前 前端 修改；并入 ExecutionPlan.strategy。
agent_tools Agent Agent 可用工具列表。 前端请求体 + 后端合并核心工具 请求发送前；后端合并时 前端、后端 保留，后端始终注入核心工具。
intent Agent 后端解析出的任务意图对象。 parse_agent_intent() 补 references、系统策略确认阶段 后端逻辑；当前受 agent_plan_strategy 污染 修改；只允许系统策略层修改。
intent.task_type Agent 任务类型，如 single / multi_item / iterative / radiate。 parse_agent_intent() 当前后端还会在策略覆盖时改写 后端、当前受 UI 泄漏影响 修改；理想上由 Intent Parser 唯一生成。
intent.strategy Agent 当前意图推荐策略。 parse_agent_intent() 当前可被显式策略覆盖 后端、当前有前端污染 修改；由 StrategyPolicy 决定。
messages Agent Agent loop 的 LLM 上下文消息。 handle_agent_generate() 历史拼接、tool result 回写、轮次推进时 后端 agent loop 保留。
AGENT_SYSTEM_PROMPT Agent Agent 的身份、路由原则、执行约束。 agent_service.py 常量 当前只能改代码 后端代码 修改；未来瘦身成“身份 + 原则”。
plan meta.strategy 共享 plan tool apply/create 返回的 strategy。 plan tool 输出 tool 结果生成时 plan tool / template 修改；并入统一 ExecutionPlan.strategy。
steps（当前 metadata） 共享 当前保存的 tool_call/tool_result 简易轨迹。 handle_agent_generate() 执行期间持续追加 后端 agent 消费层 修改；升级为 ExecutionTrace。
accumulated_images 共享 当前任务累计图像 URL。 handle_agent_generate() 每次生成后追加 后端消费层 修改；升级为 Artifact[]。
ExecutionPlan 共享 理想统一计划对象。 当前不存在 创建后仅 Planner / Workbench 编辑器可改 系统 Planner、Workbench 用户 新增并保留，作为统一执行入口。
Artifact 共享 理想统一产物对象。 当前不存在 step 完成时创建；重跑可标 superseded Executor 新增并保留。
ExecutionTrace 共享 理想统一执行轨迹对象。 当前不存在 执行期间持续追加 Executor / Runtime 新增并保留。
StrategyPolicy 共享 理想策略映射表，TaskType -> Strategy。 当前不存在 不应在运行时被随意改写 后端系统层 新增并保留。
关键问题：当前 selectedPlanStrategy 属于 Workbench，却会通过 agent_plan_strategy 污染 Agent 的意图判断；理想架构中，Agent 模式不应有用户显式策略选择权，策略应来自 TaskType + StrategyPolicy。

当前架构的核心问题不是功能不够，而是“前端页面状态、Agent 路由、Plan 元信息、执行器分派”共同争夺控制权。理想架构的关键是把两种入口都收敛到 ExecutionPlan -> PlanExecutionService -> Executor -> Artifact/Event。
