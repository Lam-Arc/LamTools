# 画布方向分析：版式设计 vs 图上编辑

日期: 2026-05-14  
状态: 已分析，未排期  
参考: Loomic (https://github.com/fancyboi999/Loomic)

---

## 背景

基于 Loomic 的画布式设计 agent 启发，分析两个画布方向在 LamImager 中的可行性。

---

## 方向一：版式设计画布（Loomic 式）

**定位**: 空白画布上自由摆放 AI 生成的内容，对话驱动排版设计。

**在 LamImager 里的形态**: 新增 session 类型——"设计 session"，跟现有"生成 session"并列。

**核心流程**:
```
用户: "做一张APP启动页"
  ↓
LLM 布局规划 → 产出: [{element: Hero图, pos: (0,320), size: 1080×400}, {element: 标题文字, pos: (80,60)}, ...]
  ↓
逐个生成元素（parallel 策略）→ 落在画布坐标上
  ↓
用户拖拽调整 → 重新推理上下文 → LLM 理解"把标题上移一点"
  ↓
导出整张合成图
```

**增量工作**:

| 层 | 需要加什么 |
|---|---|
| 前端 | 新画布组件（缩放/拖拽/图层），需要 canvas 库（Fabric.js 或自绘） |
| 后端 | 新 intent: `design`、layout_planner 节点、元素定位 model |
| 数据库 | 新表 `canvas_elements(session_id, artifact_id, x, y, w, h, z, layer_type)` |
| Agent | LLM 需要理解空间关系（"左边"、"上方"、"对齐右边"）|

**跟现有架构的关系**: 现有 radiate 策略的部分逻辑可复用（LLM 生成一组关联元素），但布局规划是全新的能力层。

**成本**: 一个完整的前端迭代 + 后端模型，约等于 P2 前端优化的 2-3 倍工作量。

---

## 方向二：精修画布（图上编辑）

**定位**: 扩容现有精修模式，把纯文字指令改成可视化标记 + 文字指令。

**在 LamImager 里的形态**: 精修模式下，选中图上圈选区域 → AI 只改这一块 → 追加到精修链。

**核心流程**:
```
用户选中精修图 → 进入画布视图
  ↓
用户在图上圈选区域 → 生成 mask（矩形/套索/画笔）
  ↓
输入指令: "把天空改成日落" → 只作用于 mask 区域
  ↓
chat_edit（传入 mask 描述 + 原始图）→ 只改指定区域
  ↓
返回新图 → 追加到精修链 → 用户可继续圈+改
```

**增量工作**:

| 层 | 需要加什么 |
|---|---|
| 前端 | 图片上叠加画布层 + 圈选工具（矩形/套索）+ 画笔。轻量，canvas 原生即可 |
| 后端 | mask 数据格式（base64 二值图）、chat_edit 接受 mask 描述参数 |
| Agent | 新 tool: `select_region(start, end, instruction)` → 对精修 pipeline 传 mask |
| 数据库 | 不需要新表，mask 作为 message metadata 存储 |

**跟现有架构的关系**: 直接对接 P3 mask 精修，底层 img2img 三梯队完全不变。这是现有路径的自然延伸。

**成本**: 前端交互工作量中等（圈选工具 + undo/redo），后端改动小。在 P3 范围内。

---

## 建议优先级

1. **方向二先做** — 跟 P3 mask 精修天然对齐，边际成本最低，精修模式立刻从"二流对话"升级成"专业编辑"
2. **方向一备选** — 等 LamImager 图像生成能力足够稳定后，作为"设计模式"单独上线。需要独立迭代周期，不是附加功能
