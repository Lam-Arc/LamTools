# Artist Realism Architecture Design

> **For agentic workers:** This is a design document, not an implementation checklist. Use it as the architectural target when refining Artist before P4.

**Goal:** Make Artist feel like a coherent creative subject instead of a persona-flavored image tool by adding continuity, artifact identity, feedback digestion, turn-based interaction, and a dedicated Artist runtime/UI boundary.

**Architecture:** Artist does not use LangGraph as its primary runtime. Artist becomes a turn-based runtime with explicit state, validated action schema, artifact lineage, feedback writeback, and Artist-specific streaming UI. Agent Mode remains on LangGraph.

**Tech Stack:** Python 3.14+ / FastAPI / SQLAlchemy async / Pydantic / SSE / Vue3 / Pinia

---

## 1. Problem Statement

Current Artist does not feel like a real creative subject because it lacks continuity.

Symptoms:

```text
1. No explicit turn state, so it does not know whether it is waiting, anchoring, packing, or refining.
2. Images are stored as URLs, not as artifacts with lineage and identity.
3. User feedback is not transformed into memory or future behavior.
4. Speech and action are loosely coupled through a fragile JSON plan.
5. Real-time Artist thinking is emitted but not truly rendered on the frontend.
6. Artist and Agent share too much transport and message vocabulary, so Artist still feels like a special-case Agent.
7. The UI does not present a true Artist conversation surface; it still feels like a tool panel with a mode toggle.
```

This cannot be solved by adding more prompt text alone. It requires runtime and data-model changes.

---

## 2. Design Principles

### 2.1 Continuity Over Cleverness

Artist should feel like it is continuing the same creative thread across turns.

### 2.2 Artifact Identity Over Raw URLs

Every image should know what role it plays: anchor, pack item, refinement, replacement, draft, or reference.

### 2.3 Feedback Must Change Future Behavior

If the user says `图3不错` or `图4换掉`, the system should digest that as state and memory, not just text.

### 2.4 Conversation Over Workflow Diagram

Artist should present itself as an ongoing creative dialogue, not as planner/executor/critic nodes.

### 2.5 Bounded Autonomy Over Free-Form Autonomy

Artist may choose anchor vs pack, ask for clarification, or propose a better direction, but it must do so through constrained actions.

### 2.6 Product First

The architecture must improve the user-facing product. It must not degrade generation reliability, latency, or Agent Mode.

---

## 3. Target Architecture

The target runtime:

```text
User input
  ↓
ArtistRuntime.handle_turn()
  ↓
ArtistSessionState load
  ↓
ImageContextResolver
  ↓
MEM / CON / prompt assembly
  ↓
LLM proposes ArtistTurn
  ↓
Schema validation and action normalization
  ↓
Action execution
  ↓
Artifact creation + feedback writeback + state save
  ↓
artist_* SSE events
  ↓
Frontend Artist stream rendering
```

This is a turn-based state machine, not a graph.

---

## 4. Missing Piece 1: Continuous State

### Current Issue

Artist has no first-class notion of `where I am in the creative process`.

### Design Fix

Add `ArtistSessionState`.

Suggested fields:

```python
session_id: str
phase: Literal["idle", "anchor_pending", "pack_ready", "refining", "waiting_clarification"]
anchor_group_id: str
last_group_id: str
last_target_url: str
pending_prompt: str
updated_at: str
```

### Why This Matters

It allows Artist to know whether it is:

```text
waiting for confirmation
expanding an anchor into a pack
refining a selected image
asking a clarification question
```

### Success Condition

- `对，就这个方向` can reliably move from `anchor_pending` to pack generation.
- `图4换一张` can reuse the current pack context.
- `图3线稿化` can attach to a known target.

---

## 5. Missing Piece 2: Artifact Identity

### Current Issue

Images are saved as generic URLs. There is no identity, role, or lineage.

### Design Fix

Add `ArtistArtifact` metadata.

Suggested fields:

```python
artist_turn_id: str
artifact_type: Literal["anchor", "pack", "refine", "replacement", "draft", "reference"]
url: str
group_id: str
index_in_group: int
parent_url: str
prompt: str
artist_comment: str
user_feedback: dict
status: str
```

### Why This Matters

Artist should know the difference between:

```text
the anchor
the full pack
the replaced fourth image
the refined line-art version of image three
```

### Success Condition

- Every image generated by Artist is persisted with artifact metadata.
- Replacement preserves pack index.
- Refinement preserves `parent_url`.

---

## 6. Missing Piece 3: Feedback Digestion

### Current Issue

User feedback does not become preference, lineage, or error memory.

### Design Fix

Create a feedback extractor and write back to memory.

Examples:

```text
图3不错 -> positive feedback on artifact 3
图4换掉 -> negative feedback + replacement intent on artifact 4
颜色太素了 -> color/style correction
```

Writeback targets:

```text
output_index
user_preferences
conversation_summaries
error_patterns
open_loops
```

### Why This Matters

Artist must not treat every turn as brand new. Feedback must leave traces.

### Success Condition

- Preferred and rejected images are traceable.
- Later generations can use past feedback.

---

## 7. Missing Piece 4: Fragile Action Protocol

### Current Issue

LLM outputs free-form JSON with `message` and `plan`, and the backend executes it loosely.

### Design Fix

Replace free-form `plan` with a validated `ArtistTurn` schema and constrained `ArtistAction` types.

Action types:

```text
chat_only
ask_clarification
generate_anchor
generate_pack
refine_target
replace_image
style_reference
```

### Why This Matters

Artist should have structured freedom, not uncontrolled output.

### Success Condition

- Unknown actions are rejected or normalized.
- Anchor generation cannot silently become pack generation.
- Replace/refine must include valid target context.

---

## 8. Missing Piece 5: Real-Time Voice

### Current Issue

`artist_token` exists, but the frontend does not meaningfully render it.

### Design Fix

Add `ArtistStreamState` to the frontend and dedicated Artist SSE event types:

```text
artist_turn_started
artist_reply_delta
artist_action_started
artist_image_ready
artist_turn_done
```

### Why This Matters

The user should see Artist forming thought, not just receiving a completed response after the fact.

### Success Condition

- Artist token deltas appear in the conversation stream.
- Artist images appear as conversation artifacts, not agent timeline images.

---

## 9. Missing Piece 6: Wrong UI Shape

### Current Issue

The UI still exposes Artist as a mode toggle inside a generic generation surface.

### Design Fix

Make Artist the default creative surface while preserving Agent as an alternative mode.

Expected UI shape:

```text
Left: session list
Center: Artist conversation stream
Right: empty or future workspace, not the main interaction surface
```

Requirements:

```text
Artist messages are conversational bubbles.
Images are inline conversation artifacts.
Lightbox is detail view, not the main browsing model.
Settings are folded near the composer.
Agent timeline remains visible only in Agent Mode.
```

### Success Condition

- Artist no longer feels like a tool panel with personality text pasted on top.

---

## 10. Missing Piece 7: Anchor-to-Pack Transition

### Current Issue

The system can generate one image or many images, but it does not actually understand the creative sequence.

### Design Fix

Use an explicit Artist state machine:

```text
idle -> anchor_pending -> pack_ready -> refining -> waiting_clarification
```

Core flow:

```text
1. User asks for a style / set / series.
2. Artist first produces one anchor.
3. Artist asks for confirmation.
4. User confirms.
5. Artist generates a pack.
6. User replaces or refines a single image.
```

### Why This Matters

This is the product version of a believable artistic workflow.

### Success Condition

- `先出锚点，再出套图` works reliably.
- `只换图4` does not regenerate the full pack.
- `图3线稿化` preserves target identity.

---

## 11. Missing Piece 8: Turn Memory

### Current Issue

Artist does not preserve enough meaning from one turn to the next.

### Design Fix

Treat `ArtistTurn` as the unit of meaning:

```python
reply_blocks: list[str]
actions: list[ArtistAction]
next_phase: ArtistRuntimePhase
memory_writes: list[dict]
```

### Why This Matters

Speech, action, and state transition become one coherent unit.

### Success Condition

- Each turn can be replayed or audited.
- The system can explain why phase changed.

---

## 12. Missing Piece 9: Bounded Autonomy

### Current Issue

Prompt gives Artist a voice, but the backend does not give it safe freedom.

### Design Fix

Give Artist bounded autonomy:

```text
It can ask clarification.
It can choose anchor vs pack.
It can refuse to continue blindly.
It can suggest a more vivid alternative.
It cannot silently ignore target identity.
It cannot override image lineage.
```

### Why This Matters

Artist feels like a subject without becoming an uncontrolled agent.

### Success Condition

- Artist can make creative decisions.
- Artist cannot break protocol invariants.

---

## 13. Missing Piece 10: Separation From Agent Mode

### Current Issue

Artist is still implemented as a persona branch in the shared generation route, so it feels like a reskinned Agent.

### Design Fix

Keep routing split, but make runtime split explicit:

```text
Agent Mode = graph runtime
Artist Mode = turn runtime
```

### Why This Matters

The two modes have different cognitive shapes and should not be forced into one runtime.

### Success Condition

- Artist does not rely on LangGraph nodes.
- Agent Mode still uses LangGraph.

---

## 14. Proposed Runtime Components

### 14.1 ArtistRuntime

Owns:

```text
state load/save
image context resolution
prompt assembly
LLM turn parsing
action normalization
artifact execution
feedback writeback
event emission
```

### 14.2 ArtistTurn Parser

Parses and validates LLM output before execution.

### 14.3 Artist Action Executor

Executes constrained Artist actions, not raw tool steps.

### 14.4 Artist State Store

Persists ArtistSessionState between turns.

### 14.5 Artist Artifact Builder

Creates normalized artifact metadata for every image result.

---

## 15. What This Design Does Not Try To Solve

This design does not try to make Artist philosophically human. It tries to make Artist product-real:

```text
continuous
responsive
traceable
bounded
memory-aware
visibly conversational
```

---

## 16. Implementation Order

Recommended order:

```text
1. Add schemas.
2. Add state store.
3. Add parser and action normalization.
4. Add artifact metadata.
5. Add runtime skeleton.
6. Move artist_orchestrate into runtime.
7. Add feedback extraction/writeback.
8. Add frontend artist stream state.
9. Add artist-specific UI components.
10. Add end-to-end and smoke tests.
```

---

## 17. Success Criteria

Artist is properly implemented when:

- The user can have a natural conversation with Artist.
- Artist can ask for clarification instead of guessing.
- Artist can anchor, pack, refine, and replace with visible continuity.
- Artist remembers user feedback in a meaningful way.
- Artist images have lineage.
- Artist output feels like a collaborator, not a form.
- Agent Mode remains intact.

---

## 18. Key Risk

The main risk is over-engineering Artist back into an Agent.

If the system becomes too graph-like, too procedural, or too node-driven, the product will lose the very thing it is trying to gain: the feeling of a coherent creative subject.

The design should favor:

```text
turn over graph
lineage over raw URL
feedback over stateless output
conversation over panel
bounded autonomy over uncontrolled freedom
```
