# Artist 多轮自然会话测试问题记录

## T3 问题

### 1. Reference 选择偏离用户认可图

- 现象：T3 生成 6 个物料时，直接传给生图 API 的 reference 全部是 `图1` 主视觉系统设定图，而不是用户在 T2.5 认可的 logo 强化图 `图0`。
- 影响：后续物料继承了整体黑白灰、故障、城市夜行风格，但 logo 圆环结构和品牌符号没有稳定体现。
- 状态：测试结束后统一处理。

### 2. Note 未进入生图 prompt

- 现象：T3 的 `generate_image.items` 里没有填写 `note`，最终生图 prompt 只有每个物料的 task。
- 影响：“保留圆环 logo / 强化品牌符号 / 不只借氛围”等补充约束没有传给生图 API。
- 状态：测试结束后统一处理。

### 3. 批量结果顺序按完成时间返回

- 现象：T3 六个物料的返回顺序是生成完成顺序，不是用户列出的顺序。
- 影响：后续用户说“第几张”时，可能和用户心里的物料顺序不一致，增加 reference 选择风险。
- 状态：测试结束后统一处理。

## T4 问题

### 1. “第 3 张豆袋”目标解析错误

- 现场：`e0709b1d-d409-42f9-950a-361f5740f611`
- 用户消息：`第 3 张豆袋有点像参考图，改原创点，只改它。`
- 现象：T3 返回顺序并不是用户要求顺序。实际 artifact 顺序中第 2 张是豆袋，第 3 张是豆卡；但用户短语同时包含“第 3 张”和“豆袋”。Runtime 没有明确处理这种序号与物料名冲突。
- 结果：候选图选择包含豆袋、会员卡、豆卡；最终第一张新图 `art-501b76e06142` 的父级是会员卡 `art-27d3da0426b5`，第二张新图 `art-692c192ea23f` 接在第一张新图后。没有准确接到原始豆袋 `art-e732eeb59ac7` 分支。
- 影响：局部修改目标错误，违反“只改第 3 张豆袋 / 只改它”的成功标准。
- 状态：阻塞继续 T5；需要修复目标解析和物料索引后重测。

### 2. T4 多生成了一次

- 现象：T4 内部执行了两次生图：先基于错误目标生成 `art-501b76e06142`，再基于该新图生成 `art-692c192ea23f`。
- 影响：用户要求“只改它”，但实际产生两级修改分支，谱系变复杂。
- 状态：和目标解析问题一起处理。

## T3 真实复测问题

### 1. 套图展开只引用了 logo 强化图，未携带完整设定稿

- 现场：`8236f301-7e0a-444d-85d6-489408e6b503`
- 保护副本：`e73c7f37-6a40-4f73-8d1a-023f1ea9290e`
- 用户消息：`就按这张，出一套 6 个：海报、杯子、豆袋、会员卡、豆卡、社媒图。`
- 现象：T3 六个物料全部 reference 到 `art-5d8db27b1950`，也就是 T2.5 的 logo 强化图；没有同时携带它的 parent/root 设定稿 `art-0335d42c6949`。
- 影响：套图会更偏向 logo/符号图的视觉信息，完整视觉系统设定稿里的应用体系、版式和物料信息没有作为显式 reference 进入生图。
- 状态：暂不阻塞后续测试，测试结束后统一处理；后续应让“套图展开”自动带上当前图的设定谱系。

## T5 真实测试问题

### 1. 连续修改目标正确，但自动多生成了一张

- 现场：`e55b7f75-a5e3-489f-820e-dc35943616bd`
- 保护副本：`188abdb2-f558-473f-8a1b-70b3229ae448`
- 用户消息：`接着改这张豆袋，蓝色少点，但科技感别丢。`
- 现象：候选图只选中了 T4 新豆袋 `art-3c8236ec388b`，目标识别正确；但 Runtime 第 1 轮生成一张后，验收认为蓝色仍多，又自动基于新图生成了第 2 张。
- 结果：本轮返回 2 张图，第二张接在第一张后；用户期望是继续改当前豆袋，通常应产出一个最终修改结果，或至少明确报告自动修复过程。
- 状态：记录问题，后续需优化“局部修改自动重试”的对外产物选择和完成状态。

### 2. 已验收通过但最终状态仍是 max_steps_reached

- 现象：最后 batch review 显示图2满足“蓝色少点，科技感别丢”，但 runtime status 是 `max_steps_reached`，phase 仍返回 `pack_ready`。
- 影响：内部状态和业务结果不一致，后续 turn 可能误判当前目标或完成状态。
- 状态：记录问题，后续需在验收通过后及时结束，而不是继续跑到步数上限。

### 3. 连续修改的 reference 没有沿用 T4 新图

- 现场：`0e04690c-c927-4cd6-8a8d-ff298011ee51`
- 保护副本：`0e04690c-c927-4cd6-8a8d-ff298011ee51` 的同源会话副本
- 用户消息：`接着改这张豆袋，蓝色少点，但科技感别丢。`
- 现象：目标选择是对的，但第一轮参考图仍回到了 T3 的旧豆袋 `art-9e66b6146345`，没有把 T4 的新豆袋作为连续修改的首要 reference。
- 影响：虽然最后结果能收住，但连续修改的谱系不够清楚，用户看到的是“继续改这张”，系统内部却没有严格沿着最近一次验收通过的修改结果前进。
- 状态：记录问题，后续需让连续修改优先继承上一轮通过验收的新图，而不是回落到更早的同名旧图。

## T7 真实测试问题

### 1. 连续修改的 reference 继续回落到更早的图

- 现象：这轮看到的 reference 是 `t3`，不是 `t6`。
- 影响：和前面“连续修改没有沿用最近一次通过验收的新图”是同一类问题，本质都是谱系回退。
- 状态：已记录，后续统一按“最近一次通过验收的图优先”处理。
