# LamImager E2E 测试

> Artist 多轮自然会话测试设计与问题记录。

## 测试设计

用一个真实用户逐步推进复杂任务的方式，验证 Artist 在同一个 session 内完成品牌视觉系统创作的连续能力。

### 测试脚本（12 轮）

| Turn | 用户消息 | 验证能力 |
|---|---|---|
| 1 | 定方向（不画图） | 意图识别、是否该画图 |
| 2 | 上传参考图 + 生成主视觉设定图 | anchor、设定来源 |
| 3 | 出一套 6 个物料 | 并行展开、anchor 继承 |
| 4 | 改第 3 张豆袋 | reference 选择、局部修改 |
| 5 | 继续改豆袋 | active target、连续修改 |
| 6 | 切到海报 | active target 切换 |
| 7 | 用豆袋质感改海报 | 风格参考和目标参考分离 |
| 8 | 看整体统一性（不画图） | 整体审查 |
| 9 | 查趋势（不画图） | 外部调研 |
| 10 | 按调研改杯子和豆卡 | 调研应用、选择性批量修改 |
| 11 | 再看一致性 | 最终一致性检查 |
| 12 | 整理最终稿 | 谱系检查、最终稿识别 |

## 测试问题记录

### T3 问题
1. **Reference 选择偏离**——套图全部引用 logo 强化图，未携带完整设定稿
2. **Note 未进入生图 prompt**——补充约束没传给生图 API
3. **批量结果顺序按完成时间返回**——与用户列出顺序不一致

### T4 问题（阻塞级）
1. **"第 3 张豆袋"目标解析错误**——序号与物料名冲突，误改了会员卡
2. **多生成了一次**——用户要求"只改它"，实际产生两级修改分支

### T5 问题
1. **自动多生成一张**——验收认为蓝色仍多，又自动生成
2. **状态不一致**——验收通过但 status 仍是 max_steps_reached
3. **reference 回落**——连续修改未沿用最近一次通过验收的新图

### T7 问题
1. **reference 继续回落**——和 T5 同一类问题，谱系回退

### T9 观察项
1. **趋势调研需接入 web fetch**——当前依赖模型内置知识，不是真实外部调研

## 核心问题模式

1. **谱系回退**——连续修改时 reference 回落到更早的图，而非最近一次通过验收的新图
2. **目标解析歧义**——序号与物料名冲突时无明确处理
3. **自动重试产物选择**——自动修复后未明确报告，用户不知道哪张是最终结果
4. **内部状态与业务结果不一致**——验收通过但 phase 仍返回 pack_ready
