# LamTools 生态设计

> 状态：✅ 有效 | 来源：lamtools-ecosystem.md, ecosystem-stories.md
>
> LamTools 是从 LamImager 演进而来的 AI 角色团队生态。做完 LamImager 后，作者意识到要做更深层的东西。

## 产品族

| 成员 | Slogan | 定位 |
|---|---|---|
| **LamButler** | 随口吩咐，我去办 | 管家统筹——对话式调度，不亲自干活 |
| **LamImager**（含 Artist） | 想法随手，艺术随后 | 图像/视觉——草率想法进去，完整艺术出来 |
| **LamCoder/Writer** | 你定义，我实现 | 代码/文本——Writer 是 Coder 的进化形态 |
| **LamMate** | 陪着你 | 陪伴——存在即价值，不需要任务 |
| **LamSage** | 你问，我知 | 知识库——搜一次，全员复用 |
| **LamCreator** | 已知已知，未知才知 | 创新合成——在事实之间画新连线 |

> 生态总 Slogan：**你想，我做。**

## 核心命题

**AI 不是你的工具，是跟在你旁边干活的人。** 这个命题在全行业没有竞品。

## Butler 十二条独立职能

| # | 职能 | 核心要点 |
|---|---|---|
| 01 | 掌控节奏 | 时间承诺追踪、提前提醒、冲突分析 |
| 02 | 环境打理 | 成员在线、API 连通、工作现场还原 |
| 03 | 记忆连续 | 画像收集，记忆权重最高 |
| 04 | 守门过滤 | 三层优先级：绝对拦截/不可拦截/灰色地带 |
| 05 | 预判先行 | 随口想法先做草案，提一嘴不强推 |
| 06 | 隐形劳动 | 后端静默执行，只说结果 |
| 07 | 关怀照看 | 超长工作降干扰，Butler 接行动 |
| 08 | 社交管理 | 日历、人际关系、基础编写 |
| 09 | 默而不瞒 | 不问不说，问了一定交代清楚 |
| 10 | 标准维护 | 三档评价（通过/需修改/推翻） |
| 11 | 错误恢复 | 成员挂→降级不崩，自己挂→重启恢复 |
| 12 | 团队建设 | 分析缺口根因，改进或招聘 |

## 画像体系

- **采集者**：Mate（原始信号）
- **精炼者**：Butler（聚合/交叉印证/加权/衰减）
- **消费者**：全体成员

权重机制：默认权重 0，只通过交叉印证增长，有天花板，长期未印证自动回落。

隐私防线不在采集端，在**交账端**：可问、可删、可纠。

## 成员间协作

### 共享上下文总线

| 层 | 职责 |
|---|---|
| 事件流 | 成员发布事件，订阅方立即感知（实时、轻量） |
| 结构化存储 | 持久化画像、知识库、任务历史、产物索引 |

### 执行层直连

Butler 不中转产物——规划层(Butler) → 执行层(Coder/Imager 直连) → 监控层(Butler 订阅状态)

### 跨成员切换

- 上下文同步延迟 < 0.5 秒
- 内容转发，人格不转发
- @ 召唤直接切换

## 网络效应

| 阶段 | 成员数 | 效应 |
|---|---|---|
| Imager 单独 | 1 | 独立价值 |
| + Coder | 2 | 执行层直连开始有价值 |
| + Butler | 3 | **拐点**——用户看到团队 |
| + Sage | 4 | 知识积累生效 |
| + Mate | 5 | **完整**——画像充分 |
